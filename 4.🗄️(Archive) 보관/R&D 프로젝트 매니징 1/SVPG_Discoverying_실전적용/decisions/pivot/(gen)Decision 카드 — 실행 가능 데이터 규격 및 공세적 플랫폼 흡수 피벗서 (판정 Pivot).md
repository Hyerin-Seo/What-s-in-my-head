## 2. 직전 피벗의 맹점 반성: 수동적 회피의 덫 (The Defensive Trap)

* **직전 피벗의 한계**:
  * 네이버·배민의 가두리가 단단하다는 이유로 B2C 일상 검색을 버리고 "사용자 주권 문서/오픈 사이언스"로만 숨어들려 했던 1차 피벗은 전형적인 **'수동적 도망(Defensive Retreat)'**이었음.
  * 그러나 토론 01-E에서 증명되었듯, 도메인을 바꾼다고 해도 **"시맨틱 서치(Vector RAG)의 구조적 결함(조건부 제약 및 논리 인과 붕괴)"**을 해결하지 못하면 똑같이 실패함.
* **본질의 재발견**:
  * 네이버와 배민이 강했던 이유는 그들이 영원불멸해서가 아니라, 2010년대 모바일 환경에 맞는 **'인간 시각용 텍스트·UI 규격'**을 선점했기 때문임.
  * 에이전트의 시대에는 인간용 UI를 스크래핑해서 싸우는 게 아니라, **"에이전트가 가장 씹어 먹기 좋은 차세대 데이터 규격"**을 선점하면 그들의 데이터를 우리 쪽으로 강제 흡수할 수 있음.

## 3. 피벗의 핵심 결단: '데이터의 차원 전환 (The Dimensional Shift)'

팀은 "포털의 화면을 긁어오는 방식"을 영구 폐기하고, **에이전트가 즉시 판정·실행할 수 있는 3대 신규 데이터 프리미티브(Data Primitives)**를 우리 제품의 헌법적 데이터 모델로 채택한다:

### 🛑 버려야 할 방식 (Deprecated Legacy)
1. **인간 시각용 텍스트 청크 및 단순 벡터 임베딩**:
   * 제약 조건(보험 약관 특약 가입 여부, 오늘의 실시간 라스트오더)을 걸러내지 못하는 시맨틱 서치 전면 배제.
2. **슈퍼앱의 기능 과적과 IoT식 설정 지옥 (Configuration Quagmire)**:
   * 모든 사람에게 맛집, 쇼핑, 뉴스를 무겁게 강요하거나 일일이 기기를 등록하게 하는 복잡한 모델 배제.

### 🎯 채택할 공세적 데이터 규격 (The 3 Agentic Primitives)
1. **실행 가능한 상태 머신 (Executable State & Rule)**:
   * 자연어 영업시간이 아닌, 에이전트가 0ms 만에 평가하는 **선언적 논리 규칙과 실시간 가용 상태(`ORDERABLE`, `CLAIMABLE`)**.
2. **자기 검증 명제 그래프 (Self-Verifying Claim Graph)**:
   * 200페이지짜리 줄글 약관이나 블로그 후기가 아닌, **`[전제 조건 ➔ 보장/결과 ➔ 면책 사유]`가 100% 인과 관계로 결속된 논리 노드**.
3. **자율 행동 인터페이스 (Action Primitive)**:
   * 정보 확인에서 끝나지 않고 데이터 자체가 에이전트 실행 도구(`reserve()`, `claim_document()`)를 내장한 완결 루프.

## 4. 파편화된 플랫폼을 흡수하는 메커니즘: 공급자 매출 떡상 & 소비자 100% 정답

네이버 플레이스뿐만 아니라 크몽, 숨고, 스페이스클라우드 등 파편화된 모든 버티컬 플랫폼에서 공급자와 소비자의 역학 관계는 동일하게 작동함:

### ① 공급자(사장님/전문가)의 유입 인센티브: "원클릭 이관 + 압도적 매출 상승"
* **기존 데이터의 무마찰 이관 (One-Click Migration)**:
  * 공급자가 플랫폼에 가입할 때 새로 입력할 필요 없이, 자신의 **네이버 플레이스/쇼핑몰 프로필 URL 하나만 넣으면 기본 정보가 1초 만에 자동 이관**됨.
* **추가적인 초간단 팩트 입력 ➔ 빈자리 매출 떡상**:
  * 사장님에게 네이버엔 없는 **'3대 틈새 가용 팩트(콘센트 좌석 비율, 14~16시 한가한 시간대 여유도, 1시간 틈새 방문 1,000원 할인권)'**만 가볍게 등록하게 함.
  * 결과: 사장님은 어차피 비어있던 유휴 시간대에 AI가 손님을 100% 매칭해 꽂아주므로 **비용 0원으로 추가 매출이 폭발**함.

### ② 소비자의 실질 질의: 100개의 검색 결과가 아닌 '100%의 단 1개 정답'
* **소비자의 현실 마찰**:
  * *"내일 석촌 쪽에 급하게 미팅이 잡혔는데, 미팅 시간 대비 1시간이 떠버렸네. 잠시 시간 떼우고 있을 곳이 필요한데 어디가 괜찮나?"*
  * 네이버 지도는 3년 전 블로그 후기나 광고 식당을 쏟아내어 사용자가 콘센트, 이동 시간, 영업 여부를 10분간 의심 검색해야 함.
* **AI의 100% 결정론적 교집합 매칭 (Constraint Intersection)**:
  * `[소비자 제약: 내일 14시 + 1시간 체류 + 도보 3분 이내 + 노트북 작업]` ∩ `[공급자 팩트: 14시 착석 확률 95% + 콘센트 완비 + 도보 90초 + 틈새 할인]`
  * ➔ **"14시 57분에 일어나도 미팅에 늦지 않는 도보 90초 거리 [카페 A]로 가세요 (1시간 작업 눈치 0%, 1,000원 할인권 적용)"**라는 100% 검증된 정답을 3초 만에 반환.

### ③ '관심사 렌즈(Interest Lens)'를 통한 시스템 초경량화
* **누구나 맛집을 즐기진 않는다**:
  * 모든 사용자에게 맛집, 배달, 쇼핑을 때려 박는 슈퍼앱 모델은 인지 부하와 인프라 비용을 폭증시킴.
* **선택적 렌즈 활성화 (Selective Lens Activation)**:
  * 사용자는 자신이 일상이나 업무에서 진짜 필요한 **[틈새 작업 공간], [급구 외주/기술 해결], [계약/보험 팩트체크]** 중 1~2개 렌즈만 가볍게 켜둠(Toggle).
  * 시스템은 사용자가 켜둔 렌즈에 해당하는 공급자 팩트만 초경량으로 동기화하여, **Zero-Setup & Zero-Clutter**를 달성.

## 5. 새로운 가두리 양식장 형성 메커니즘 (The Gravity Shift)

이 피벗을 통해 우리는 네이버·배민의 울타리를 밖에서 부수는 것이 아니라, **내부로부터 중력을 역전**시킨다:

```
[1단계: 소비자 에이전트의 쏠림]
소비자 에이전트는 네이버/배민의 광고와 긴 리뷰 텍스트 파싱을 거부하고, 
자신의 '관심사 렌즈'와 '상황적 제약'에 100% 정답을 주는 구조화 데이터 네트워크로 직행.

[2단계: 공급자의 강제 입점 압력 (FOMO & 생존 압력)]
점주, 보험사, 기업들은 깨달음:
"소비자들이 더 이상 네이버 앱을 직접 켜지 않고 에이전트에게 시킨다. 
그런데 내 매장/내 서비스가 저 '에이전트 실행 규격'으로 등록되어 있지 않으면, 
에이전트가 나를 '미검증/비가용 유령' 취급하여 손님을 아예 안 보낸다!"

[3단계: 데이터 독점의 완성 (The Inescapable Walled Garden)]
공급자들이 네이버·배민에만 올려두던 데이터를 원클릭으로 이관하고, 
추가 팩트를 스스로 밀어 넣어 유휴 매출을 챙김으로써 "안 끼면 망하는 새로운 가두리" 완성.
```

## 6. 전략적 포지셔닝 전환 대조

| 비교 축 | 1차 피벗 (수동적 회피) | 2차 피벗 (공세적 차원 전환 - 확정안) |
| :--- | :--- | :--- |
| **전략 기조** | 빅테크 피해 도망치기 (Defensive) | **데이터 형태를 재정의해 빅테크 흡수하기 (Aggressive)** |
| **공급자 가치** | 없음 (데이터 제공 유인 부재) | **원클릭 이관 + 유휴 자산 매칭을 통한 '압도적 매출 상승'** |
| **소비자 가치** | 긴 문서/논문 검증 한정 | **상황적 제약(시간/장소/목적)에 100% 부합하는 단 1개의 정답** |

| **네트워크 효과** | 없음 (개인 로컬에 갇힘) | **공급자 매출 욕망과 소비자 시간 결핍이 결합된 가두리 플라이휠** |
