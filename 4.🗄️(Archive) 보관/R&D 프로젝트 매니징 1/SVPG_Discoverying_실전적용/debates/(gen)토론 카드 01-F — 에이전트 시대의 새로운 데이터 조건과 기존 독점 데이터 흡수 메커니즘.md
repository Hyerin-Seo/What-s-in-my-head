# 토론 카드 01-F — 에이전트 시대의 새로운 데이터 조건과 기존 독점 데이터 흡수 메커니즘

> **SVPG 정본 헌법**:  
> **"기존 시장 지배자의 독점 체제를 깨뜨리는 유일한 길은, 그들과 똑같은 규칙으로 싸우는 것이 아니라 '데이터를 담고 다루는 근본적 형태(Primitive)'를 재정의하여 기존 데이터가 새로운 포맷으로 전환되지 않으면 도태되게 만드는 것이다."**

## 1. 쟁점 개요 (Background)

* **PM의 질문**:  
  > *"현재 벡터 검색을 제공하는 방식은 각각의 흩어진 개별 데이터들에 대해 전부 분절된 경험을 제공하고 있어서 '에이전트'의 진정한 능력이 발휘되기에는 제약이 있어. 배민도, 네이버도 '데이터의 형태'에 대해서 고민을 많이 했을 거야. 그렇다면 에이전트의 시대에 그들의 데이터를 '뺏어올 수 있는' 새로운 데이터의 조건은 무엇일까?"*
* **토론 목적**: 
  * 역사적으로 플랫폼 강자들이 경쟁자의 데이터를 흡수했던 데이터 진화 공식을 복기하고,
  * 에이전트가 완벽하게 추론·행동하고, 결과적으로 기존 포털·배달앱의 독점 데이터를 우리 생태계로 강제 유입시키는 **'새로운 데이터의 3대 조건(Data Primitives)'**을 정의함.

---

## 2. 역사의 복기: 플랫폼은 어떻게 '데이터 형태'를 바꿔 시장을 뺏었는가?

| 시대 / 전환 | 기존 강자의 데이터 형태 | 챌린저가 재정의한 '새로운 데이터 형태' | 결과 (데이터 흡수) |
| :--- | :--- | :--- | :--- |
| **전단지 ➔ 배민** | 종이에 인쇄된 정적 문자열 | **`[메뉴 - 옵션 - 가격 - 주문 상태]` 트랜잭션 스키마** | 동네 오프라인 상권 DB 완전 독점 |
| **디렉터리 ➔ 구글** | 포털이 수동 등록한 웹사이트 텍스트 | **`[웹페이지 간 인용·링크(PageRank Graph)]` 관계망** | 전 세계 웹 인덱스 독점 |
| **게시판 ➔ 네이버** | 자유 형식의 단방향 게시글 | **`[질문 - 답변 - 내공 - 채택]` 지식 네트워크** | 한국어 고유 Q&A DB 독점 |

> **핵심 법칙**:  
> **"새로운 강자는 언제나 '데이터를 표현하는 차원(Format & Structure)'을 한 단계 높여 기존 강자의 데이터를 낡은 쓰레기로 만들었다."**

---

## 3. 에이전트 시대에 데이터를 뺏어오는 3대 '새로운 데이터의 조건'

현재 네이버, 배민, 그리고 벡터 RAG의 데이터는 철저히 **"인간이 눈으로 보고 손가락으로 누르는 2010년대 모바일 UI"**에 갇혀 있어 에이전트가 소화하기에 극도로 비효율적임.

에이전트가 스스로 찾아오게 만드는 **차세대 데이터의 3대 조건**:

### ① 조건 1: [텍스트 ➔ '실행 가능한 상태 머신(Executable State & Rule)']
* **기존 데이터 (인간 시각용)**: 
  * *"매일 11:00~21:00 (브레이크타임 15~17시, 재료 소진 시 조기 마감)"* ➔ 단순 자연어 문자열.
* **새로운 데이터 형태 (에이전트용)**:
  * 에이전트가 0ms 만에 참/거짓을 판정할 수 있는 **선언적 논리 규칙과 상태(State Machine)**:
    ```json
    {
      "rules": {
        "isOpen": "Time.now.between('11:00', '21:00') && !Time.now.between('15:00', '17:00')",
        "hasStock": "inventory.current > 0"
      },
      "state": "ORDERABLE",
      "action": "execute_order(cart_id)"
    }
    ```
* **파괴력**: 에이전트는 광고 배너나 긴 리뷰를 읽지 않고, 이 상태 데이터 하나만 보고 즉시 행동함.

### ② 조건 2: [문서 ➔ '자기 검증 가능한 명제 그래프(Self-Verifying Claim Graph)']
* **기존 데이터 (보험 약관, 연구 논문)**:
  * 200페이지짜리 PDF 줄글 텍스트. (단어 검색하면 엉뚱한 특약이나 무관한 논문 결론이 걸림)
* **새로운 데이터 형태 (에이전트용)**:
  * 문서가 아니라, **[전제 조건 ➔ 보장/결론 ➔ 면책 사유]**가 인과 관계로 결속된 **구조적 명제 그래프**:
    * `[조건: 피보험자 질병코드 C00-C97] AND [특약 가입 상태: Active] ➔ [결과: 5,000만 원 지급]`
* **파괴력**: 에이전트가 단어 유사도로 찍는 게 아니라, 그래프의 조건 노드를 순회하며 100% 논리적으로 참인 조항만 발라내어 증명함.

### ③ 조건 3: [정보 ➔ '자율 행동 인터페이스(Actionable Primitive / Tool)']
* **기존 데이터**: 읽고 나면 끝나는 죽은 정보 (Information).
* **새로운 데이터 형태 (에이전트용)**:
  * 데이터 자체가 **에이전트가 호출할 수 있는 도구(Tool API)를 내장**한 형태.
  * 예: 약관 데이터 안에 `check_coverage(user_plan)` 함수가 내장되어 있고, 매장 데이터 안에 `verify_and_reserve()` 액션 엔드포인트가 결속됨.

## 4. 데이터 권력 이동과 중력의 역전 (Gravity Shift)

이 새로운 데이터 규격이 정립되면, 시장의 지각변동이 발생함:

```
[1단계: 소비자 에이전트의 이탈]
소비자 에이전트는 네이버 앱/배민 앱에 들어가 광고 끄고 스크롤하는 비효율을 거부함.
➔ "실행 가능한 규칙과 팩트 상태를 즉시 반환해 주는 새로운 데이터 네트워크"로 쿼리가 집중됨.

[2단계: 공급자의 강제 입점 (안 끼면 죽는 생태계)]
점주, 보험사, 기업들이 깨달음:
"소비자들이 더 이상 네이버 앱을 켜지 않고 에이전트한테 시킨다. 
그런데 내 매장/내 보험이 저 '에이전트용 실행 데이터 포맷'으로 등록되어 있지 않으면, 
에이전트가 나를 '미검증/비가용 유령' 취급해서 손님을 안 보내준다!"

[3단계: 데이터 흡수 완성]
공급자들이 네이버·배민에만 올려두던 데이터를, 
우리가 정의한 '에이전트용 구조화 팩트 규격'으로 앞다투어 변환하여 스스로 밀어 넣음(Push).
```

## 5. 토론 결론

* 에이전트 시대의 승부는 포털의 화면을 긁어오는 '크롤링 싸움'이 아님.
* **"인간용 정적 텍스트를 ➔ 에이전트가 즉시 판정·실행할 수 있는 [실행 상태 + 명제 그래프 + 행동 도구] 규격으로 재정의하는 것"**, 이것이 바로 기존 독점자들의 데이터를 뺏어오는 유일무이한 기술적 승부처임.
