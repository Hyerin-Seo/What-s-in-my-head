# 토론 카드 01-B — 빅테크의 출처 표기 기피와 법적 규제(데이터베이스권·부정경쟁방지법) 심층 분석

> **SVPG 정본 헌법**:  
> **"비즈니스 지속가능성(Viability) 리스크를 얕보는 팀은 제품을 법정에서 잃게 된다. '공개된 웹 데이터니까 마음대로 긁어와서 출처만 달면 된다'는 생각은 가장 위험한 법적 무지다. 법적 제약 조건이 명확할수록 합법적 우회로를 선점한 팀이 독점적 해자(Moat)를 얻는다."**

## 1. 쟁점 개요 (Background)

* **PM의 질문**: *"결국 저렇게 답변의 제한이 존재하는 것은 다른 IT 기업들이 구현을 못해서겠냐고. 오히려 법적 제약이나 그런 문제 때문에 제공 못 하는 거 아냐?"*
* **조사 및 토론 목적**: 빅테크(OpenAI, 구글, 네이버 등)가 답변에 정확한 실시간 원천 팩트 스냅샷을 1:1로 결속하지 못하고 두루뭉술하게 얼버무리는 **진짜 법적 장벽(Legal Viability Risk)**을 판례와 실정법 기준으로 파헤치고, 우리가 취해야 할 합법적 아키텍처를 확립함.

## 2. 빅테크를 가로막는 3대 법적 칼날 (The Legal Walls)

### ① 부정경쟁방지법 제2조 제1호 (카)목: '성과물 무단 사용'
* **대표 판례: 야놀자 vs. 여기어때 (크롤링 분쟁)**
  * **판결 요지**: 법원은 경쟁사의 서버에 기술적 침입을 하지 않았더라도(형사 무죄), 경쟁사가 막대한 비용과 노력을 들여 구축한 데이터를 크롤링하여 자신의 서비스에 활용한 행위를 **"공정한 상거래 관행이나 경쟁 질서에 반하는 무단 성과물 사용"**으로 보아 민사상 손해배상 및 불법행위 책임을 엄격히 인정함.
* **시사점**: 네이버 플레이스나 카카오맵, 배달의민족 같은 플랫폼의 영업시간/매장 정보는 단순 사실(Fact)이지만, 그 집합체는 **'상당한 투자와 노력으로 만들어진 타인의 성과'**임. 이를 AI가 무단 스크래핑하여 발췌 팝오버로 띄우면 즉각 부정경쟁방지법 위반 소송에 직면함.

### ② 저작권법 제93조: '데이터베이스제작자의 권리'
* **법리**: 데이터 개별 항목(예: 전화번호, 주소, 영업시간) 자체에는 창작성이 없어 저작권이 인정되지 않더라도, 이를 체계적으로 수집·배열한 **데이터베이스 제작자에게는 복제·배포·전송할 배타적 권리**가 부여됨.
* **시사점**: AI가 웹을 크롤링하여 특정 플랫폼의 DB 항목을 직접 스냅샷으로 복제·전송하는 행위는 데이터베이스제작자의 권리를 정면으로 침해함.

### ③ '출처 표기'의 치명적 역설 (Attribution ≠ Exemption)
* 많은 개발자가 *"출처(URL, 플랫폼명)를 명시하면 공정이용(Fair Use)으로 면책된다"*고 착각함.
* **법원의 냉혹한 판단**: 
  * 출처를 표기한다고 해서 타인의 성과물 무단 도용이나 데이터베이스권 침해가 합법화되지 않음.
  * 오히려 상업적 서비스에서 출처를 대놓고 박아두는 것은 **"우리가 저 플랫폼의 데이터를 무단으로 긁어와 쓰고 있습니다"를 자백하는 증거**가 됨.
* **빅테크의 전략적 침묵**: 바로 이 때문에 빅테크는 특정 출처를 1:1로 찍어주지 않고, *"AI의 답변은 부정확할 수 있습니다"*라는 면책 문구(Disclaimer) 뒤로 숨어 자연어로만 얼버무리는 것임.

## 3. 엔지니어링 및 비즈니스 방어 전략 (The Clean Defense)

우리는 빅테크가 처한 이 법적 리스크를 정면 돌파하기 위해 **'스크래핑 0%의 클린 파이프라인'**을 헌법으로 채택해야 함:

| 영역 | 위험한 방식 (소송 직행) | 우리가 채택할 합법적 돌파구 (Clean Pipeline) |
| :--- | :--- | :--- |
| **데이터 수집** | 네이버/카카오 웹페이지 비인가 무단 크롤링 | **공인 Open API 제휴 및 합법 라이선스 엔드포인트**만 사용 |
| **권리 귀속** | 자사 서버가 수집한 데이터를 중앙 DB에 저장 | **사용자 개인 클라이언트 런타임에서 API 호출 (BYOK)** 구조 |
| **학술/연구 데이터** | 유료 저널 사이트 무단 PDF 스크래핑 | **arXiv, PubMed, Semantic Scholar 등 완전 오픈 라이선스(CC)** 데이터 직결 |
| **인스펙터 렌더링** | 타사 웹페이지 UI를 불법 임베딩(Iframe) | API가 공식 제공하는 **구조화된 필드(Schema)만 추출하여 자체 팩트 카드로 렌더링** |

## 4. 토론 결론 및 가설 2.0 설계 가이드라인

1. **PM의 의심은 100% 사실이었음**:
   * 빅테크가 출처 스냅샷을 1초 만에 띄워주지 못한 진짜 이유는 '기술 부족'이 아니라 **'데이터베이스권 및 부정경쟁방지법 소송 공포'** 때문이었음.
2. **우리의 독점적 틈새(Moat)**:
   * 모든 웹을 다 긁어오려는 과욕(Over-reach)을 버리고, **"공인 API 계약이 체결된 신뢰 소스(공식 플레이스 API, 공공데이터, 오픈 학술 DB)"**에 한해서만 1초 어트리뷰션을 완벽히 보증하는 **'클린 팩트 존(Clean Fact Zone)'** 전략으로 승부한다.
