# (gen)Candidate 05 — '에이전트 시스템' 엔지니어링 기술 블로그 포스팅 챌린지 (빅테크 테크블로그 레퍼런스 기반 아키텍처·인사이트 스캐폴딩)

> **챌린지 정의**: UI·UX 디자이너(Rin)가 최근 화제가 된 빅테크(토스, 당근, 우아한형제들 등)의 에이전트 협업 기술 블로그 글을 레퍼런스로 삼아, 현재 팀에서 구축한 **'옵시디언 에이전트 온톨로지 시스템'의 개발 배경, 아키텍처 의사결정, 성과 지표를 표준 기술 블로그 포맷(TL;DR, 대안 비교표, 아키텍처 해부도, Key Takeaways)**에 맞추어 조립해보는 다섯 번째 실무 챌린지.

---

## 1. 챌린지 개요 및 선정 배경 (Why This Project)

1. **디자이너와 엔지니어 모두에게 친숙한 '기술 블로그' 양식**:
   * 토스 테크, 당근 테크, 우아한형제들 기술 블로그 등은 IT 업계 실무자라면 누구나 즐겨 읽는 가장 표준적인 전문 글쓰기 형태입니다.
   * 독자의 흥미를 끄는 도입부부터 기술적 문제 해결, 그리고 마지막 배운 점 정리까지 글의 흐름이 고도로 정형화되어 있습니다.
2. **'외부 레퍼런스의 톤앤매너'를 사내 데이터에 이식하는 작업**:
   * "잘 쓴 외부 기술 블로그의 글 구조와 톤"을 거울(Reference)로 삼고, "우리 시스템의 내부 실제 데이터"를 백데이터로 사용하여 결합하는 실전적인 콘텐츠 조립 경험입니다.
3. **추상적 미사여구와 기술적 팩트의 균형 난이도 관측**:
   * 기술 블로그는 겉보기엔 줄글 같지만, 실제로는 **"대안 기술 비교 매트릭스 표"**, **"아키텍처 파이프라인 구조도"**, **"정량적 지표 카드"** 같은 정밀한 시각적 팩트 블록이 핵심입니다.
   * 일반 채팅창에 "블로그 글 써줘"라고 했을 때, 챗봇이 그럴싸한 일반론만 주절거리고 실제 내부 아키텍처와 표 서식을 제대로 잡아내지 못하는 한계를 체감하기에 최적입니다.

## 2. 산출물 목표: 표준 엔지니어링 기술 블로그 레이아웃 (Visual Scaffold)

글의 70% 이상이 **핵심 요약 카드, 기술 비교 매트릭스 표, 아키텍처 블록, 지표 카드**로 구조화됩니다.

```text
┌────────────────────────────────────────────────────────┐
│ [헤더 메타 카드] 제목, 부제, 3줄 TL;DR 요약, 태그 배지   │
├────────────────────────────────────────────────────────┤
│ [1. 배경과 문제 정의 (Problem Context)] (콜아웃 블록)   │
│   → 단순 AI 챗창으로는 팀 지식베이스가 파편화되는 이유 │
├────────────────────────────────────────────────────────┤
│ [2. 기술적 의사결정 매트릭스] (3자 대안 비교 표)         │
│   → 일반 챗봇 vs 단순 RAG 검색 vs 온톨로지 스캐폴딩     │
├────────────────────────────────────────────────────────┤
│ [3. 시스템 아키텍처 해부도] (인간-에이전트 공존 파이프라인)│
│   → PARA 구역 ➔ 13종 메타데이터 주입 ➔ 린터 검증 루프  │
├────────────────────────────────────────────────────────┤
│ [4. 정량적 도입 성과 지표 (Impact Metric)] (숫자 카드)  │
│   → 문서 정리 시간 1/10 단축, 서식 파싱 에러 0건      │
├────────────────────────────────────────────────────────┤
│ [5. 마치며: 핵심 교훈 (Key Takeaways)] (체크포인트 블록)│
```

## 4. 작업 진행 및 정지 가이드 (Stop-on-Fatigue Protocol)

작업자는 기존 ChatGPT/Claude 웹 채팅창에 레퍼런스 글과 사내 백데이터를 넣고, **"이 레퍼런스 블로그의 어투와 구조(TL;DR, 대안 비교표, 성과 지표)를 살려서 우리 사내 에이전트 시스템에 대한 기술 블로그 포스팅을 작성해줘"**라고 요청해 봅니다.

결과물을 완벽히 뽑으려고 애쓸 필요가 전혀 없습니다.

> **🛑 즉시 정지 기준 (Stop Threshold)**:  
> AI가 우리 시스템의 구체적인 아키텍처 팩트를 무시하고 뻔한 일반론이나 두루뭉술한 미사여구로 도배하거나, **"원하는 기술 비교표나 서식이 잡히지 않아 작업이 너무 피로하다"**고 느껴지는 순간이 오면, **그 즉시 작업을 멈추십시오.**

* 10분을 시도했든, 3분을 시도했든 아무 상관 없습니다.
* 챗창이 블로그 글을 쓰다 중간에 요약해버리거나, 비교 매트릭스 표를 임의로 생략할 때 어느 지점에서 손을 놓고 싶어졌는지를 솔직하게 공유하면 그것으로 온보딩은 완벽하게 달성됩니다.
