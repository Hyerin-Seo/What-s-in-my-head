# 결정 카드 기록기 (meeting_decision_recorder)

> **정본은 여기(`skills/meeting_decision_recorder/`)입니다** — 2026-09-30 Rin 이 `2026.09.29 주간 회의록` 을 돌려 보고 만들자고 했습니다.
> 회의마다 `skills/meeting-notes` 가 이 폴더를 작업 공간 `A4.meta/` 로 **복사**하고, 튜닝은 그 사본에서만 합니다.
> 사본에서 나아진 규칙은 사람이 승인해야 여기로 올라옵니다 (`skills/meeting-notes/SKILL.md` 6절).

**왜 따로 있나** — 안건 카드(`pre_meeting_agenda_preparer`)는 **아직 안 정한 것**을 A · B 선택지로 펼칩니다.
그런데 회의에서는 "그래, 10월 30일까지 한 달 해 보자!" 처럼 **말하면서 정해 버리는 것**이 더 많습니다.
이걸 안건 카드로 만들면 이미 정한 걸 다시 묻게 되고, `카드 아님` 의 `〔정한 것〕` 한 줄로 두면 기한 · 목표 · 딸린 질문이 사라집니다.
결정 카드는 **정한 것을 정한 모양 그대로** 남깁니다 — 다시 묻지 않고, 무엇을 · 언제까지 · 왜 · 어디까지를 적습니다.

볼트 규칙(`../../CLAUDE.md`)과 회의 순서(`../meeting-notes/SKILL.md`)가 이 파일보다 먼저입니다. 부딪히면 알리고 멈추세요.

---

## 1. 무엇이 결정인가

**결정 = 회의에서 말로 못 박았고, 상대가 뒤집지 않고 넘어간 것.**

| 결정이다 | 결정이 아니다 → 어디로 |
| --- | --- |
| "~하자 · 해 보자 · ~로 가자 · ~까지 한다" 에 동의하거나, 반대 없이 다음 얘기로 넘어감 | "~할까? · ~면 좋겠다 · 생각해 볼게" — 제안 · 고민 → 안건 카드 |
| 목표 · 기한을 정함 ("한 달 동안만 해 보자", "10월 30일에 포인트 찍자") | 반대 · 되묻기가 이어지고 끝이 안 남 → 안건 카드 |
| 역할을 나눔 ("가치는 내가, 사용성은 네가") | 한 사람이 자기 일을 말함 ("내가 조만간 정리해서 공유할게") → 할 일 (`카드 아님 〔할 일〕` · 안건 카드의 할 일 후보) |
| 범위를 긋거나 버림 ("캔버스는 폐기", "스토리는 뺀다") | 책 · 남의 사례 소개 ("인스파이어드는 이렇게 하래") → 공유 |

- **확신은 두 단계로 적습니다** — `동의함`(상대가 "그래 · 좋아 · 맞아" 처럼 말로 받음) · `반대 없이 넘어감`(말한 사람만 있고 상대는 다음 얘기로 감).
  `반대 없이 넘어감` 은 사람이 고를 때 한 번 더 봐야 하는 결정입니다. **말투로 동의를 지어내지 않습니다.**
- **결정과 쟁점이 같은 줄에 있을 수 있습니다** — "한 달 해 보자"(결정) 안에 "주마다 뭘 할지"(쟁점)가 남아 있으면, 결정 카드의 `아직 안 정한 것` 에 적고 그 안건 카드를 링크합니다. 안건 카드를 따로 또 만들지는 않습니다(이미 있으면 링크만).

## 2. 카드로 만들까, 한 줄로 둘까

- **결정 카드** — 속기에 **기한 · 목표 · 이유 · 범위 · 역할 · 딸린 질문** 중 하나라도 있으면.
- **한 줄** — 결정 한 문장 말고 속기에 붙은 게 없으면 카드를 만들지 않고 `meeting-notes` 작업 기억 `카드 아님` 에 `〔정한 것〕` 한 줄로 둡니다.
- **같은 방향의 결정은 한 장으로 묶습니다** — "한 달 해 보자" 와 "10월 30일에 포인트" 는 같은 스프린트의 두 면이라 한 장. 다른 일을 정한 것은 따로.

## 3. 프론트매터 (볼트 13종 + `PARA정리: 끔`)

```yaml
---
유형: 메모
구역: 4.archive
분류:
  - 회의록
주제:
  - 결정 사항
  - <결정 핵심 키워드 — 볼트에 이미 있는 주제면 그 값>
상태: 검토 중
요약: "'<결정 한 문장>' 결정 카드"
작성일: <YYYY-MM-DD>
마감: <결정의 기한. 속기에 날짜가 있을 때만 — meeting-notes 7절로 절대 날짜. 없으면 비움>
커버:
상위: "[[<회의록 이름>]]"
링크:
  - "[[<딸린 안건 카드>]]"   # 없으면 비움
담당:
  - "[[<결정을 책임지는 사람>]]"   # 속기에 누가 맡는다고 나왔을 때만. 말한 사람 ≠ 책임자
작성자:
  - "[[<자기 이름>]]"
PARA정리: 끔
---
```

- 파일 이름: `D<번호>_<결정_한_문장_스네이크>.md` — 안건 카드(`1.1_…`)와 섞여도 `D` 로 갈립니다.
- `요약` 이 따옴표로 시작하므로 **값 전체를 큰따옴표로** 감쌉니다 (안건 카드 스킬 2.2 와 같은 이유).

## 4. 본문

```markdown
# D<번호> <결정 한 문장 — "~한다">

> **속기 원문**
> - <이름> (<시각>) *<발언 그대로>*
>
> **할 일 후보** — <이 결정 때문에 누가 손을 움직일 일이 속기에 나왔으면: 무엇 — 담당 · 마감. 없으면 두 줄을 지움>

---

## ✅ 정한 것

| | |
| --- | --- |
| **무엇을** | <한 문장> |
| **언제까지** | <날짜 · 기간 — 없으면 "속기에 없음"> |
| **누가** | <책임자 — 없으면 "속기에 없음"> |
| **확신** | 동의함 · 반대 없이 넘어감 — <근거 발언 시각> |

## 🎯 끝났다고 보는 기준

- <속기에 있는 목표 · 숫자 · 보여 줄 것. 없으면 "속기에 없음 — 정할 것" 한 줄>

## 💬 왜

- <속기에 나온 이유만. 없으면 "속기에 따로 없음">

## 🚧 어디까지

- **한다:** <속기에 나온 범위>
- **안 한다:** <속기에 나온 뺄 것 · 버릴 것. 없으면 이 줄 지움>

## ❓ 아직 안 정한 것

- <이 결정에 딸려 남은 질문 — 안건 카드가 있으면 [[카드]]. 속기가 흐려서 뜻을 모르는 말도 여기에 "확인 필요">

## 🔁 다시 볼 때

- <기한 · 조건 — "10월 30일", "사용자 5명 테스트 뒤". 속기에 없으면 "속기에 없음">
```

### 쓰는 규칙

- **지어내지 않습니다.** 칸마다 속기에 있는 것만. 빈 칸은 지우지 말고 `속기에 없음` 으로 둡니다 — 비어 있다는 것 자체가 회의 뒤에 사람이 채울 일입니다.
- **권장 · 모범 사례를 쓰지 않습니다.** 이미 정한 것이라 다시 고르게 하지 않습니다. 외부 사례가 필요하면 안건 카드의 일입니다.
- 속기 전사가 흐려서 뜻을 모르는 말("10월 30일은 그냥 딱 빌리지")은 **해석하지 않고** 원문 그대로 인용하고 `아직 안 정한 것` 에 `확인 필요` 로 둡니다.
- 사람 이름은 사람 명단(`.obsidian/plugins/claude/data.json` 의 `para.people`)에 있는 이름만. 화자를 모르면 `화자 A` 로 두고 `meeting-notes` 3절 4번대로 한 번 묻습니다.

## 5. 순서

1. 속기를 한 줄씩 보며 1절 표로 결정 후보를 표시합니다 (안건 카드 스킬과 **같은 분류표**를 씁니다 — `meeting-notes` 작업 기억).
2. 2절로 카드 · 한 줄을 가르고, 같은 방향은 묶습니다.
3. 카드마다 3 · 4절로 씁니다. 자리: `A1.collection/검토 중/` (안건 카드와 같은 곳 — 사람이 한 곳에서 고릅니다).
4. 딸린 안건 카드가 있으면 서로 `링크` 합니다 (안건 카드 쪽은 `meeting-notes` 가 그 줄만 더함).

### 사람이 고른 뒤 — 프로젝트로 갈 때 (2026-09-30)

에이전트는 여기까지입니다. 사람이 고른 결정은 **사람 말로 다듬어** 프로젝트로 갑니다. 에이전트가 옮기지 않습니다.

| | 99 의 결정 카드 | 프로젝트로 간 결정 |
| --- | --- | --- |
| 자리 | `A1.collection/검토 중/` | `<프로젝트>/discussions/<YY.MM.DD>/decisions/` (날짜 = 회의록 이름 앞 날짜) |
| `유형` · `상태` | `메모` · `검토 중` | `할일` · **`결정 사항`** — 칸반 11개 · 주간 리뷰가 이 값을 걸러서 안 뜹니다 |
| `분류` | `회의록` | 프로젝트 폴더 이름 하나 (`discussions` · 날짜 · `decisions` 는 넣지 않음) |
| 끈 | `상위` = 회의록 | **폴더가 끈** — `주제: 회의 할 일` · 회의록 링크 없어도 됨 |

다음 회의 점검은 `decisions/` 의 `마감` 을 보고 기한이 다가온 결정을 `📌 걸려 있는 결정` 에 보여 줍니다 (`meeting-notes` 5절 g).
