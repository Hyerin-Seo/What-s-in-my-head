# 1.1 LLM 파이프라인 토큰 초과와 포맷 깨짐 — 청크 분할 후 취합

> **속기 원문** (속기 2 · 3 · 4)
> - *엘엘엠 API 붙여서 자동으로 핵심 키워드 뽑고 구조화된 마크다운으로 뱉어주는 파이프라인을 짜야 되는데, 그 프롬프트 엔지니어링 쪽에서 지금 토큰이 자꾸 터지거나 포맷이 깨지는 이슈가 좀 있음.*
> - *그거 청크 단위로 잘라서 요약한 다음에 최종 취합하는 방식으로 스크립트 수정해야 될 것 같은데.*
> - *그 부분은 내가 오늘 내로 정규식 짜서 문단 단위로 끊기게 스크립트 수정해 볼게.*
>
> **할 일 후보** — 청크 분할 스크립트 수정 (정규식 · 문단 단위) — 담당 화자 B · 마감 2026-09-28

## 🎯 핵심 의사결정 포인트 (Decision Checkpoint)
> **[결정 질문] 긴 전사문을 문단 청크로 잘라 요약한 뒤 취합하는 방식으로 간다 — 속기에서 이미 둘이 동의한 듯. 확정인가?**
> - [ ] **[청크 분할 → 요약 → 취합 (권장)]**: 속기에서 화자 A 가 제안하고 화자 B 가 "좋네, 알겠어" 로 받음. 확인만 하면 됨
> - [ ] **[통째로 넣되 모델 · 컨텍스트만 키움]**: 스크립트는 단순하지만 전사가 길어질수록 같은 문제가 다시 옴

## 📌 기존엔 왜 이렇게 관리했을까? (현행 사양의 이유)

* **1. 가장 빨리 돌아가는 첫 구현**
  * 위스퍼 → 텍스트까지 로컬 테스트를 먼저 끝내느라, LLM 단계는 텍스트 덩어리를 한 번에 넣는 가장 단순한 모양으로 둔 것으로 보임

---

## 📌 핵심 분석

* **토큰 초과:** 녹음이 길면 입력이 한도를 넘음 — 화자 A 의 진단 ("텍스트 덩어리째로 한 번에 넣어서 그런 거 아니야?")
* **포맷 깨짐:** 속기에는 원인이 안 나옴. 청크 분할이 토큰은 풀어도 포맷 깨짐까지 푸는지는 따로 봐야 함

---

## 🌐 참조 자료 및 모범 사례 (다른 곳은 어떻게 하는가?)

* **1. Map-Reduce 요약** — 긴 문서를 조각마다 요약(map)한 뒤 요약들을 다시 합치는(reduce) 방식. LangChain 등 LLM 도구들이 기본 패턴으로 제공
* **2. 구조화 출력** — 출력 모양을 JSON 스키마로 강제하고 마크다운은 코드에서 조립. 포맷 깨짐을 모델에 맡기지 않는 방식

---

## ⚖️ 핵심 쟁점 (회의에서 답을 내려야 할 질문)

* **1. 끊는 단위**
  * **[선택 A]:** 문단 (정규식) — 화자 B 안
  * **[선택 B]:** 토큰 수 기준 + 조금씩 겹치기
* **2. 포맷 깨짐도 같이 푸나**
  * **[선택 A]:** 청크 분할로 충분한지 먼저 보기
  * **[선택 B]:** 출력 형식을 따로 고정
