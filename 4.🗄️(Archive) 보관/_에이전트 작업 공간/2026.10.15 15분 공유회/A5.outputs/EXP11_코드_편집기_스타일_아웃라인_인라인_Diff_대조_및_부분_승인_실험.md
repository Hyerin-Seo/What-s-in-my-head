# EXP11 코드 편집기 스타일 아웃라인 인라인 Diff 대조 및 부분 승인 실험

## 🧐 1. 왜 이런 UI·사양이 필요하다고 느꼈는가? (현행 작업의 고통과 문제의식)

* **재작성 결과 대조 시 발생하는 극심한 인지 독해 비용:**
  * AI에게 아웃라인의 특정 문단이나 하위 노드를 다시 쓰게 하면 매번 전체 문장을 새로 쏟아냅니다.
  * 이전 버전과 무엇이 달라졌는지, 어느 단어가 바뀌었는지 확인하기 위해 작업자가 앞뒤 텍스트를 숨은그림찾기하듯 전부 읽어 내려가야 하므로 피로도가 극에 달합니다.
* **부분 채택(Cherry-pick)의 어려움:**
  * 새로 뽑힌 결과 중에서 *"요 문장 하나만 마음에 들고 나머지는 이전 버전이 나은 경우"*가 빈번합니다.
  * 그러나 현재는 전체를 다 덮어쓰거나 수동으로 복사-붙여넣기 해야만 해서 이전의 좋은 결과물이 유실됩니다.
* **검증된 개발 도구(Cursor/Antigravity) 인터랙션의 부재:**
  * 코드 편집기에서는 AI 제안을 인라인 녹색(추가)/적색(삭제) Diff로 보여주고, 변경 블록마다 `[Accept]` / `[Reject]` 버튼을 눌러 확정합니다.
  * 이 직관적인 피드백 루프가 문서 작성 화면에도 필수적입니다.

## 🔬 2. 실험 가설 (Hypothesis)
* **가설:** "AI가 수정한 아웃라인 결과를 노드 내에서 **초록색(추가)과 빨간색(삭제) 인라인 Diff로 시각화**하고, 노드 우측에 **`[✓ 승인]` / `[✗ 거절]` 버튼을 제공**하면, 변경점 파악 시간이 80% 단축되고 이전 버전의 손실 없이 최적의 문장만 선별 채택할 수 있을 것이다."

## 🛠️ 4. 프로토타입 구현 명세 (UI/UX Prototype Spec)
1. **노드 인라인 Diff 하이라이팅:**
   - AI 수정 실행 시, 기존 노드 아래에 변경 제안이 인라인으로 오버레이 표시.
   - 삭제된 문구는 붉은색 취소선(`strikethrough`), 추가된 문구는 녹색 배경 하이라이트.
2. **노드/청크 단위 승인 인터랙션:**
   - 각 변경 노드 우측에 미니 액션 툴바 (`[✓ Accept]` `[✗ Reject]`) 표시.
   - 단축키 지원: `Tab` (승인), `Esc` (거절).
3. **스냅샷 롤백 히스토리 (History Mini-drawer):**
   - 수락 후에도 우측 미니 서랍에서 이전 버전 스냅샷을 원클릭으로 열어보고 단일 노드 롤백 가능.
