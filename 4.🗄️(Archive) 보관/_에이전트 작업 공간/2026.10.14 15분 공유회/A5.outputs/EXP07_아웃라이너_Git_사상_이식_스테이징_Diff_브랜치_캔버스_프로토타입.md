## 🧐 1. 왜 이런 UI·사양이 필요하다고 느꼈는가? (현행 작업의 고통과 문제의식)

* **아웃라이너 본연의 작업에서 Git 사상의 본질적 필요성:**
  * 목차와 문단 구조를 설계할 때 수시로 갈아엎고 되돌아가는 과정이 필수적인데, 어디가 추가되고 빠졌는지 모르면 수정 포인트를 찾기 위해 텍스트 전체를 재독독해야 합니다.
  * 회의 초기부터 *"제일 먼저 넣었던 사양이 깃이며, 깃의 사상을 넣어 캔버스에 뿌려줘야 맛이 난다"*는 발상이 확고했습니다.
* **전체 트리 롤백의 실패와 국소 스테이징으로의 우회:**
  * 프로젝트 전체를 Git처럼 다루려 했을 때는 사양이 꼬이고 무거워져 걷어낼 수밖에 없었습니다.
  * 하지만 실패했던 것은 "무거운 전체 트리 Git"이지 "Git의 사상(스테이징, diff, 브랜치)" 그 자체가 아닙니다.
* **노드 단위 로컬 스테이징 + 시각적 Diff 결합의 절실함:**
  * 작업자가 줌 인하여 작업 중인 노드 범위 안에서 임시 커밋(Staging)을 두고, 초록/빨강 Diff로 변경점을 확인하며, 캔버스에서 브랜치 형태로 가지를 치는 경량 Git 인터랙션이 강력히 요구됩니다.

## 🔬 2. 실험 가설 (Hypothesis)

* **가설:** "무거운 전체 파일 단위 형상관리 대신, **'노드 단위 로컬 스테이징 바'와 '초록/빨강 인라인 Diff 가시화'를 제공하고 이를 '캔버스 브랜치 뷰'로 연결**하면, 시스템 부하 없이도 Git의 핵심 가치(비파괴 실험, 전후 변경점 즉시 파악, 안전한 롤백)를 아웃라이너 상에서 100% 체감할 수 있을 것이다."

## 🛠️ 4. 프로토타입 구현 명세 (UI/UX Prototype Spec)

1. **노드 로컬 스테이징 바 (Local Staging Bar):**
   - 줌 인된 노드 상단에 경량 스냅숏 기록 인터페이스(`[임시 저장 / Staged] [비교 / Diff] [되돌리기 / Revert]`) 노출.
   - 현재 작업 중인 하위 트리의 체크포인트를 단축키(`Ctrl + S`)로 즉시 스테이징.
2. **초록/빨강 인라인 Diff 오버레이 (Green/Red Diff Highlighting):**
   - 이전 스테이징 대비 새로 추가된 노드/문장은 연한 초록색 배경(`+`), 삭제된 노드는 취소선과 연한 붉은색 배경(`-`)으로 인라인 표시.
   - Diff 토글 스위치로 원본만 보기 / 수정본만 보기 / Diff 모아보기 3단 전환.
3. **캔버스 브랜치 시각화 (Visual Branching on Canvas):**
   - 여러 버전 대안을 나란히 분기했을 때, 캔버스 보드 뷰에서 Git 브랜치 그래프 형태로 시각적 노드 연결선 표출.
   - 어떤 버전에서 갈라져 나왔는지 부모-자식 히스토리를 2차원 공간에서 직관적으로 조망.
4. **비파괴 체크아웃 & 확정 (Non-destructive Checkout):**
   - 실험적 목차 변경이 마음에 들지 않을 경우 원클릭으로 직전 스테이지 상태로 즉각 롤백.
