# EXP02 아웃라인 캔버스 보드뷰 플립 전환 프로토타입

## 🧐 1. 왜 이런 UI·사양이 필요하다고 느꼈는가? (현행 작업의 고통과 문제의식)

* **1차원 수직 트리의 시각적 한계와 멘탈 모델 불일치:**
  * 아웃라이너의 텍스트 불릿 트리는 위에서 아래로만 흐르기 때문에, 아이디어나 버전이 2~3갈래 이상으로 분기(Branching)될 때 전체 구조를 한눈에 조망하기 어렵습니다.
  * 머릿속에서는 여러 갈래를 사방으로 펼쳐놓고 비교하고 싶은데, 화면에서는 텍스트 줄들이 빽빽하게 이어져 있어 갈래 간의 관계가 직관적으로 와닿지 않습니다.
* **과감한 가지치기(Pruning) 인터랙션의 부재:**
  * 이전 경험(헵타베이스 등 화이트보드 캔버스)에서는 *"가지가 쭉쭉 뻗어나가는 걸 시각적으로 보고, 아니다 싶은 덩어리를 뭉텅 잘라버리는"* 방식이 훨씬 편하고 직관적이었습니다.
  * 그러나 현재 아웃라이너에서는 노드를 하나하나 백스페이스나 딜리트로 지워야 하므로 과감한 가지치기가 어렵고 작업 흐름이 끊깁니다.
* **발산과 수렴을 넘나드는 전환 브릿지 필요:**
  * 캔버스만 쓰면 자유도가 너무 높아 완성도 높은 글로 정리하기 어렵고, 아웃라이너만 쓰면 발산이 답답합니다.
  * 따라서 **"아이디어를 발산하고 가지칠 때는 2차원 캔버스로 펼쳤다가, 정리가 끝나면 다시 1차원 아웃라인으로 돌아오는 스위칭 사양"**이 필수적이라고 판단했습니다.

---

## 🔬 2. 실험 가설 (Hypothesis)
* **가설:** "아웃라인의 1차원 수직 트리에서 아이디어나 버전이 여러 갈래로 분기될 때, **버튼 하나로 2차원 캔버스(보드뷰)로 화면을 플립(Flip) 전환**할 수 있다면 갈래 간 관계를 조망하고 불필요한 가지를 쳐내는(Prune) 작업이 훨씬 직관적일 것이다."

* **발화자 1 (01:03:29):** *"그래서 이 보드뷰를 만들어 놓은 게 이거를 다른 어떤 사양으로 바꿀 작업을 많이 하려고 스켈레톤만 잡아 놓으라고 하긴 했거든."*

## 🛠️ 4. 프로토타입 구현 명세 (UI/UX Prototype Spec)
1. **상단 원클릭 뷰 토글 스위치:**
   - 툴바에 `[ 아웃라인 뷰 ⇋ 캔버스 뷰 ]` 전환 토글 배치 (단축키 `Ctrl + Space` 또는 `Tab` 지원).
2. **기존 스켈레톤 보드뷰 활용 브랜치 시각화:**
   - 동일한 아웃라인 데이터 트리를 React Flow 기반 캔버스에 가로 브랜치 카드 형태로 자동 레이아웃 배치.
   - 각 버전별 노드가 열(Column)이나 갈래 노드로 시각화되어 병렬 대조 가능.
3. **시각적 가지치기 (Pruning) 인터랙션:**
   - 캔버스 상에서 마음에 들지 않는 갈래나 노드를 원클릭으로 비활성화/삭제(잘라내기)하면, 다시 아웃라인 뷰로 돌아왔을 때 트리에도 실시간 동기화 반영.
