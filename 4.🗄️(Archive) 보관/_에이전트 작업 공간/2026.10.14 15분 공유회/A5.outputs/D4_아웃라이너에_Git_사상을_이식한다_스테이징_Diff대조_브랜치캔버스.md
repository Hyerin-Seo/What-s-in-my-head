## 🎯 끝났다고 보는 기준

- 아웃라인 문서 목차 및 골격 수정 시, 이전 판과의 변경점(추가/삭제)이 초록/빨강 Diff로 한눈에 대조됨
- 작업자가 수정한 노드 안에서 이전 상태를 안전하게 임시 커밋(스테이징)하고, 필요 시 비파괴 롤백이 가능함
- 복수 대안(Branch)을 2차원 캔버스 상에서 시각적 트리 갈래로 펼쳐 조망하고 채택할 수 있음

## 💬 왜

- 아웃라이너로 문서 구조를 잡을 때 '세 번 이상 갈아엎기'가 필수적인데, 어디가 어떻게 바뀌었는지 대조(Diff)되지 않으면 극심한 피로도와 불안감 발생 (28:26, 29:05)
- 텍스트 줄글만으로는 복수 버전의 갈래(Branch)를 파악하기 어려워 시각적인 2차원 캔버스 공간 배치가 결합되어야 "맛이 살아남" (28:26)
- 과거 전체 트리를 대상으로 Git 라이브러리를 직접 엮으려 했을 때 겪었던 난이도/사양 꼬임 문제는 '국소 노드 스테이징'과 'UI 렌더링 레이어 분리'로 우회·해결 가능함을 확인 (01:02:06)

## 🚧 어디까지

- **한다:** 노드 레벨 로컬 스테이징 · 텍스트/불릿 단위 초록/빨강 인라인 Diff 하이라이트 · 캔버스 기반 브랜치 트리 시각화 · 무손실 스냅숏 보존
- **안 한다:** 백엔드 전체 파일시스템을 통째로 묶는 무거운 Git 바이너리 직결이나 충돌 머지(Conflict Merge) 같은 극단적 엔지니어링 사양 도입

## ❓ 아직 안 정한 것

- Diff 계산을 문자열(Levenshtein/Myers) 단위로 할지, 아웃라인 노드 ID 계층 매핑 단위로 할지
- 브랜치 갈래를 캔버스 상에서 직접 머지(Merge)할 수 있게 할지, 단순 채택(Switch)으로 갈지
- 기한
