# 1.1.2 액션 플랜 — 줌 안 버전 탭 및 캔버스 전환 단계별 PoC 실행 계획

> 기준 문서: [[1.1_버전업을_화면에서_무엇으로_받칠까_줌_안_버전_탭이냐_캔버스_전환이냐]]

---

## 🚀 1. 기본 실행 전략 (회의 안건 ➔ 빠른 인터랙션 스파이크)

* 회의실에서 "탭이 맞냐, 캔버스가 맞냐"를 말로 논쟁하지 않고, **가장 가벼운 최소 프로토타입(PoC)을 1~2일 내로 제작하여 직접 만져보고 검증**합니다.
* 3단계 점진적 프로토타입 파이프라인을 통해 리스크를 낮추고 손맛을 확정합니다.

---

## 🛠️ 2. 단계별 프로토타입 실행 로드맵

### Phase 1: [줌 인 버전 탭] 최소 기능 프로토타입 (1순위 타겟)
* **목표:** 현재 겪고 있는 수동 듀얼 줌 노가다를 즉시 제거할 수 있는 가장 단순한 인터랙션 검증.
* **구현 범위:**
  * 줌 인(Zoom In) 진입 시 헤더 하단에 초경량 탭 바 렌더링 (`[v1] [v2] [+]`).
  * 탭 추가 시 현재 자식 노드 트리를 복제하여 새 탭(v2)으로 격리 분기.
  * 탭 클릭 또는 단축키로 자식 트리를 스위칭하여 즉시 다른 버전으로 교체 표시.
* **복잡도 차단:** Diff(차이점 강조)나 Git 엔진 없이, 단순 트리 렌더링 교체로만 1차 체감 확인.

### Phase 2: [보드뷰/캔버스 전환] 브랜칭 시각화 스파이크 (2순위 타겟)
* **목표:** 이미 스켈레톤이 잡혀 있는 보드뷰를 활용하여 버전 갈래를 2차원 판 위에 펼쳐보는 경험 검증.
* **구현 범위:**
  * 상단 뷰 토글 버튼 (`[아웃라인] ↔ [캔버스/보드뷰]`).
  * 각 버전(v1, v2)이 캔버스 위의 열(Column)이나 카드로 나란히 펼쳐져 한눈에 비교 가능하게 구성.
  * 불필요해진 버전 갈래를 시각적으로 잘라내는(Delete/Prune) 인터랙션 테스트.

### Phase 3: [정밀 비교 Diff] 필요성 최종 판정 (3순위)
* **목표:** 텍스트 라인 단위 초록/빨강 하이라이트가 과연 필수적인지 검토.
* **구현 범위:**
  * Phase 1(탭)과 Phase 2(캔버스)를 써본 후에도 "바뀐 줄을 못 찾아서 여전히 불편한가?"를 도그푸딩으로 점검.
  * 필요성이 입증될 경우에만 선택한 두 탭 간의 텍스트 diff 오버레이 기능을 부가적으로 도입.
