# 🎯 [사전 준비] 완료 및 히스토리 아카이빙 기준 정비 (외부 레퍼런스 벤치마킹 버전)

> **목표:** "외부 시장과 글로벌 서비스는 이 문제를 어떻게 풀었는가?" — 공인된 도구와 프레임워크의 실제 기준을 대조하여 **우리 팀의 완료 데이터 보관 기준 3가지**를 찍고 끝냅니다.

## ⚖️ 3대 쟁점별 외부 레퍼런스 조사 및 벤치마킹 체크포인트

### 쟁점 1. 완료된 할 일을 보드에서 언제 숨길 것인가?

```
[A안: 완전 즉시 숨김]  ─────────▶  체크하는 순간 보드에서 사라짐 (초깔끔 / 필요시 '완료 보드'에서 조회)
[B안: 3일 유예 후 숨김 (권장)] ──▶  3일간은 취소선으로 노출(성취감/확인용), 3일 지나면 자동 필터 아웃
```

#### 🌐 회의 전 외부 레퍼런스 체크포인트 (External Service Checkpoints)
- [ ] **글로벌 PM 서비스(Linear, Jira, Asana, ClickUp)의 기본 동작 기준:**
  - 각 도구는 완료(Done) 티켓을 메인 보드에서 어떻게 처리하고 있는가? (즉시 숨김 vs 당일 유지 vs 주간 스프린트 종료 시 자동 아카이브)
  - 완료된 항목을 기본 뷰에 계속 노출하도록 권장하는 서비스가 실제로 존재하는가?
- [ ] **성취감(Motivation) 보완 장치 조사:**
  - 완료 항목을 화면에서 숨기는 대신, 다른 서비스들은 어떤 대체 인터랙션(예: 완료 통계 대시보드, 주간 다이제스트, 완료 애니메이션)으로 사용자에게 피드백을 주는가?
- [ ] **Notion 및 GitHub Projects 공식 템플릿의 필터 기준:**
  - 공식 프로젝트 템플릿에서 '완료된 작업'을 뷰에서 걸러내기 위해 사용하는 표준 필터링 규칙은 무엇인가?

### 쟁점 2. 끝난 프로젝트 폴더는 어떻게 격리할 것인가?

| 선택지 | 동작 방식 | 장점 | 주의점 |
| :--- | :--- | :--- | :--- |
| **A안 (권장)** | 폴더째로 `4.🗄️(Archive) 보관`으로 드래그 이동 | `1.project` 최상단이 항상 클린하게 유지됨 | 링크 깨짐 방지를 위해 폴더명 유지 필수 |
| **B안** | 위치는 그대로 두고 상태값만 `완료`로 변경 | 이동 작업이 없음 | 폴더 목록에는 계속 남아 시각적 노이즈 잔존 |

#### 🌐 회의 전 외부 레퍼런스 체크포인트 (External Service Checkpoints)
- [ ] **PARA 원작 프레임워크(Tiago Forte)의 공식 가이드라인:**

  - 활성 프로젝트 폴더(`Projects`)에 머무는 최대 권장 개수(10~15개) 제한 기준은 어떻게 정의되어 있는가?
- [ ] **Basecamp(Shape Up) 및 Linear의 프로젝트 아카이빙 방식:**
  - 스프린트/사이클이 종료된 프로젝트를 작업 공간에서 어떻게 동결(Freeze)하고 콜드 스토리지로 분리하는가?
- [ ] **옵시디언 파워 유저 커뮤니티의 아카이브 모범 사례:**

- [ ] **'일시 중단(Paused)'과 '완전 종결(Closed)'의 분리 기준:**

* **[선택 A] 30일 수명 주기 (TTL - 권장):** 생성 후 30일 지난 `history` 파일은 주기적으로 정리/폐기
* **[선택 B] 태스크 종결 시 즉시 수동 정리:** 사람이 결과물 승격 시 수동으로 정리

- [ ] **에이전트 작업 공간/히스토리를 전문적으로 관리하는 프레임워크 및 서비스가 있는가?**

## 💡 컨센서스 포인트 (Consensus Points: 사전 지식 및 배경 설명)

> *회의 중 불필요한 논쟁을 줄이고, 참석자 간 논의의 눈높이를 맞추기 위한 핵심 가이드입니다.*

### 1. "보드에서 숨긴다" vs "파일을 삭제한다"는 완전히 다릅니다
* 옵시디언의 보드(`.base`)는 엑셀 파일이 아니라 **"조건에 맞는 파일만 모아서 보여주는 렌더링 렌즈"**입니다.
* 보드에서 필터를 걸어 완료된 할 일을 숨긴다고 해서 파일이 지워지는 것이 아닙니다. 언제든 '완료 모아보기' 뷰를 켜면 그대로 다 살아 있습니다.

### 2. `4.🗄️(Archive)`는 휴지통이 아니라 '영구 도서관'입니다
* PARA 철학에서 Archive는 버리는 곳이 아닙니다. **"지금 당장 마감이 있는 일이 아니어서 책상 위에서 치워두는 서고"**입니다.
* `4.archive`로 옮겨진 프로젝트나 문서도 검색(`Ctrl+O`), 그랩(`grep`), 위키링크 연결이 완벽하게 지원됩니다.

### 3. 에이전트 샌드박스(`99번`)를 볼트 본문과 격리하는 기술적 이유
* 에이전트가 복잡한 일(멀티스텝 작업 기억, 아이데이션 스크래치)을 할 때 생기는 중간 메모리들이 `1.project`나 `0.inbox`에 직접 생기면, 볼트 자동화 플러그인이 이를 '진짜 할 일'이나 '진짜 문서'로 오인하여 보드에 마구 띄웁니다.
* 따라서 `99.🥸 작업 공간`에 `PARA정리: 끔`을 걸고 격리하는 것은 볼트의 질서를 지키기 위한 필수적인 완충 지대(방화벽)입니다.

### 4. 볼트의 절대 원칙: "삭제는 사람이 한다"
* 에이전트나 자동화 스크립트는 볼트 내 파일을 영구 삭제할 권한이 없습니다.
* 모든 정리는 '보관 구역(`4.archive`)으로 이동'하거나 '보드 필터 숨김'으로 처리되며, 최종적으로 파일 자체를 지우는 것은 사람(민규 서/Rin)이 직접 휴지통으로 보낼 때만 일어납니다.
