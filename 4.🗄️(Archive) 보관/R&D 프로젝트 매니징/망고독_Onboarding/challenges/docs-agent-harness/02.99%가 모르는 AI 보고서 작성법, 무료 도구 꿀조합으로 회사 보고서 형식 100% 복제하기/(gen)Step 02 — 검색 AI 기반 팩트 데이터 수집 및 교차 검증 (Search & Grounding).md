# (gen)Step 02 — 검색 AI 기반 팩트 데이터 수집 및 교차 검증 (Search & Grounding)

> **Step 02 헌법**:  
> *"일반 챗봇(ChatGPT/Claude)에게 최신 통계와 숫자를 묻지 마라.  
> 검색 특화 AI(Perplexity, Liner 등)를 별도 하네스로 가동하여 **[실제 통계 수치 + 조사 기관 + 출처 URL]을 먼저 확보하고 교차 검증(Cross-check)**하라."*

---

## 1. 왜 '검색 특화 AI 분리'가 필수적인가?

일반 LLM 챗봇은 "그럴싸한 문장을 지어내는 기계"이지 "정확한 팩트를 검색하는 검색 엔진"이 아닙니다.  
일반 챗봇에게 시장 규모나 설문 수치를 물어보면 십중팔구 **존재하지 않는 가짜 논문이나 왜곡된 통계(환각)**를 지어냅니다.

보고서의 신뢰도는 **'숫자의 출처'**에서 나옵니다:
* 기획 단계(Step 01)가 끝나면, 즉시 검색 엔진과 실시간 인덱싱이 결합된 **검색 특화 AI(Perplexity AI 등)**로 자리를 옮깁니다.
* 각 목차 항목을 뒷받침할 **진짜 팩트 데이터와 URL 링크**를 먼저 수집합니다.

---

## 2. 팩트 데이터 수집 및 교차 검증 3대 수칙

```text
┌────────────────────────────────────────────────────────┐
│ [수칙 1] 출처 없는 수치 전면 폐기                       │
│   → "통계청, 가트너, 맥킨지" 등 조사 주체 없는 데이터 차단 │
├────────────────────────────────────────────────────────┤
│ [수칙 2] 2개 채널 교차 검증 (Cross-Verification)        │
│   → Perplexity 결과와 원문 기사/공식 보도자료 일치 확인   │
├────────────────────────────────────────────────────────┤
│ [수칙 3] 1:1 팩트 앵커 카드화                           │
│   → [주장 키워드] ➔ [실측 수치] ➔ [출처 URL] 3종 세트 정리│
└────────────────────────────────────────────────────────┘
```

---

## 3. 실전 하네스 프롬프트 템플릿 (Perplexity 전용 검색 하네스)

Perplexity 검색창에 모호한 질문 대신, 아래와 같이 **데이터 추출 규격**을 명시합니다.

```text
[Step 02 팩트 수집 프롬프트 (Perplexity)]
"아래 주제에 대해 최근 1~2년 이내의 신뢰할 수 있는 통계 데이터와 공식 출처를 찾아주십시오:

[조사 항목]: (예: 국내 기업의 생성형 AI 도입률 및 실무 마찰 통계)

요구 형식 (표 형태로 정리):
| 핵심 지표 | 실측 수치 | 조사 기관 / 발표 연도 | 원문 출처 URL |
| :--- | :--- | :--- | :--- |

주의:
- 추정치나 개인 블로그 의견은 배제하고, 공식 리서치 기관(IDC, 가트너, KISDI 등) 보고서와 제도권 언론 보도만 인용할 것."
```

## 4. 효과 및 망고독(Scaffolding) 연결점

* **효과**: 본문을 쓸 때 AI가 숫자를 지어낼 틈을 주지 않고, **100% 검증된 팩트 앵커(Reference)**를 손에 쥔 채 작성을 시작할 수 있음.
* **망고독 연결**: 망고독의 **Reference Panel(참고자료 패널)**에 이 수집된 팩트 파일들이 장착되어, 에디터의 빈칸으로 1:1 주입되는 백데이터 원천이 됩니다.
