## 1. Problem Statement (에이전트 시대의 실질적 양면 마찰)

*(출처: [`(gen)토론 카드 01-F — 에이전트 시대의 새로운 데이터 조건과 기존 독점 데이터 흡수 메커니즘`](file:///c:/망고독%20관련%20자료/프로젝트_매니지먼트/What-s-in-my-head/3.📦(Resource)%20자료/R&D%20프로젝트%20매니징/SVPG_Discoverying_실전적용/debates/(gen)토론%20카드%2001-F%20—%20에이전트%20시대의%20새로운%20데이터%20조건과%20기존%20독점%20데이터%20흡수%20메커니즘.md))*

### 📌 소비자 & 소비자 에이전트 관점의 마찰 (Consumer & Agent Friction)
* **현재의 상태 (As-Is)**:
  * 네이버, 구글, 익스피디아, 배민, 학술 DB의 데이터는 철저히 **"인간이 눈으로 보고 손가락으로 누르는 2010년대 모바일 UI/자연어 텍스트"**에 갇혀 있음.
  * 출장 숙소의 새벽 체크인 여부, 카페의 콘센트/영업시간, 오픈소스 라이브러리의 Python 3.12 지원, 논문의 이중맹검 데이터 등 모든 핵심 팩트가 줄글 리뷰와 광고 블로그 속에 파묻혀 있음.
* **에이전트와 사용자가 겪는 핵심 고통 (Core Pain Point)**:
  * **에이전트 실행 불능 및 환각(Hallucination)**: LLM 에이전트가 웹을 크롤링해도 "재료 소진 시 조기 마감", "주차 협소" 같은 비정형 텍스트를 0ms 만에 확정할 수 없어 환각을 일으키거나 의사결정을 멈춤.
  * **수작업 대조 지옥 (Comparison Hell)**: 결국 인간 사용자가 10~30개 탭을 열고 `Ctrl+F`로 리뷰를 뒤지며 **10~30분의 인지 노동을 낭비**함.

### 📌 공급자 관점의 마찰 (Supplier Friction)
* **현재의 상태 (As-Is)**:
  * 공간 운영자, 숙박업주, 연구자, 개발사, 프리랜서 등 공급자들은 자신의 실질적 강점(방음, 콘센트, 특수 API 지원, 유휴 슬롯)이 포털의 키워드 광고 입찰 경쟁에 밀려 파묻힘.
* **공급자가 겪는 핵심 고통 (Core Pain Point)**:
  * **유휴 자산의 영구 증발**: 비싼 수수료와 파워링크 광고비를 내지 못하면, 조건이 완벽히 들어맞는 진성 수요가 존재함에도 자산이 썩어남.
  * **에이전트 시대의 유령화 공포**: 소비자가 점차 에이전트에게 탐색과 예약을 위임하면서, **"에이전트가 읽을 수 없는 구시대 포맷으로 남아 있으면 영원히 선택받지 못한다"**는 위기감에 직면함.

## 2. Target Metrics (목표 정량 성과 지표)

단순한 기능 출시가 아니라, **소비자 에이전트의 의사결정 해방**과 **공급자의 실질 유휴 자산 매출 전환**만을 측정합니다:

| 지표 구분 | 지표 명칭 | 현재 수준 (Baseline) | 목표 수준 (Target) | 측정 방식 |
| :--- | :--- | :--- | :--- | :--- |
| 🎯 **Primary Metric**<br>(최우선 지표) | **에이전트 제약 검증 리드타임<br>(Agent Decision Latency)** | 건당 평균 **10~30분 (수작업 대조)** | **1.0초 이내 (0ms 비트셋 연산)** | 사용자 상황 제약 입력 후 에이전트가 100% 검증된 단일 결정을 확정하기까지의 시간 |
| 📈 **Secondary Metric A**<br>(에이전트 자율 완수율) | **에이전트 행동 채택 완수율<br>(Agent Action Adoption Rate)** | **12%** (포털 수동 재검색 이탈) | **85% 이상** | 에이전트의 첫 번째 검증 결과를 보고 인간 사용자가 크로스체크 없이 즉시 액션을 확정하는 비율 |
| 📈 **Secondary Metric B**<br>(공급자 유휴 전환율) | **공급자 등록 유휴 자산 거래율<br>(Supplier Asset Liquidity)** | **0%** (광고 미집행 시 증발) | **월평균 40% 이상 전환** | 공급자가 '실행 가능 상태'로 등록한 유휴 슬롯/스펙이 실제 거래와 매칭된 비율 |
| 🛡️ **Guardrail Metric**<br>(절대 방어선) | **비결정론적 오탐/환각율<br>(False Positive / Error Rate)** | 35% (LLM 텍스트 추론 오탐) | **0.0% (100% 불리언 팩트 보증)** | 조건 불일치, 허위 스펙, 폐업/불가로 인한 트랜잭션 실패 비율 |

## 3. Scope Boundary & Core Primitives (에이전트 시대의 3대 데이터 조건)

*(출처: [`(gen)토론 카드 01-F`](file:///c:/망고독%20관련%20자료/프로젝트_매니지먼트/What-s-in-my-head/3.📦(Resource)%20자료/R&D%20프로젝트%20매니징/SVPG_Discoverying_실전적용/debates/(gen)토론%20카드%2001-F%20—%20에이전트%20시대의%20새로운%20데이터%20조건과%20기존%20독점%20데이터%20흡수%20메커니즘.md) Section 3)*

```text
[기존 빅테크 텍스트 웹]                         [차세대 에이전트 데이터 네트워크]
인간 시각용 비정형 줄글 텍스트  ──────────────▶  1. 실행 가능한 상태 머신 (Executable State)
200페이지 규정집/논문 PDF       ──────────────▶  2. 자기 검증 명제 그래프 (Claim Graph)
읽고 끝나는 죽은 정보 UI         ──────────────▶  3. 자율 행동 도구 인터페이스 (Action Tool)
```

1. **Primitive 1: [텍스트 ➔ 실행 가능한 상태 머신 (Executable State Machine)]**
   - 영업시간, 잔여 수량, 콘센트, 체크인 시간 등 비정형 텍스트를 에이전트가 0ms 만에 평가할 수 있는 선언적 불리언 규칙(`rules: isOpen, hasStock`)으로 표준화.
2. **Primitive 2: [문서 ➔ 자기 검증 가능한 명제 그래프 (Self-Verifying Claim Graph)]**
   - 보험 약관, 연구 논문, 하드웨어 호환 규격 등 복합 조건을 `[전제 조건 ➔ 보장/결론 ➔ 면책 사유]`의 인과 노드로 구조화하여 환각 0%의 논리 순회 보장.
3. **Primitive 3: [정보 ➔ 자율 행동 인터페이스 (Actionable Primitive / Tool)]**
   - 매칭된 결과 데이터 안에 `execute_transaction()` 또는 `verify_and_reserve()` API가 내장되어, 에이전트가 탐색 즉시 행동을 완결하는 규격.

## 4. 🌀 중력의 역전 메커니즘 (Gravity Shift Dynamics)

기존 플랫폼 지배자의 독점을 무너뜨리는 3단계 데이터 흡수 로드맵:

```text
[1단계: 소비자 에이전트의 이탈]
에이전트는 광고와 비정형 텍스트로 가득 찬 포털을 거부하고, 
0ms 만에 즉시 실행 가능한 '상태 머신 데이터 레일'로 쿼리를 집중시킴.
                           ▼
[2단계: 공급자의 강제 입점 (자발적 데이터 푸시)]
공급자들은 "에이전트용 규격으로 내 자산과 팩트를 등록하지 않으면 
에이전트에게 유령 취급 당해 손님을 완전히 빼앗긴다"는 절박함에 직면함.
                           ▼
[3단계: 독점 데이터의 완전 흡수]
공급자들이 네이버·배민·익스피디아에 묶여있던 자신의 핵심 데이터를 
우리의 '에이전트 실행 가능 규격'으로 앞다투어 변환하여 스스로 밀어 넣음(Push).
```
