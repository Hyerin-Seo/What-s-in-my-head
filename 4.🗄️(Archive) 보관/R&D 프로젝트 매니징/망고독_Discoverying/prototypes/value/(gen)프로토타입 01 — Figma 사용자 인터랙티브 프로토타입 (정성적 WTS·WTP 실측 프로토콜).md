# (gen)프로토타입 — Figma 사용자 인터랙티브 프로토타입 (정성적 WTS·WTP 실측 프로토콜)

> **SVPG 정본 헌법 (Marty Cagan)**:  
> *"User prototypes are very quickly created simulations of the product you're proposing to build... they don't require developer resources to create; and we can get significant qualitative insights into whether people would actually choose to use it or not."*  
> *(사용자 프로토타입은 만들고자 하는 제품을 매우 신속하게 시뮬레이션한 것이다. 개발자 자원을 쓸 필요가 없으며, 고객이 실제로 이 제품을 선택해서 쓸 것인가에 대한 결정적인 정성적 인사이트를 제공한다.)*

---

## 1. 프로토타입 개요 및 검증 목표

* **유형**: User Prototype (고해상도 인터랙티브 클릭 목업)
* **제작 기간**: **최대 2일 이내** (백엔드 코딩 0줄, Figma 인터랙션 설계)
* **주관 R&R**: Product Designer + PM 주도
* **핵심 검증 목표**:
  1. **전환 의향 (WTS)**: 기존 대안(Word + ChatGPT 복붙)을 영구히 닫고 주력 도구로 갈아탈 의향이 있는가?
  2. **지불 의향 (WTP)**: 미완성 상태의 솔루션임에도 사전 할인가에 신용카드를 즉각 등록할 만큼 절박한가?

---

## 2. 프로토타입 상세 스펙 (Figma 3단 레이아웃)

실제 작동하는 것처럼 완벽하게 시뮬레이션되는 고해상도(High-Fidelity) 3단 화면 구성:

```text
┌───────────────────┬───────────────────────────────────────┬───────────────────┐
│  좌측: @Reference  │             중앙: Document             │   우측: Composer   │
├───────────────────┼───────────────────────────────────────┼───────────────────┤
│ • 100쪽 PDF 목업   │ • 30장 완제품 제안서 실시간 직조 뷰   │ • 직조 지시어 입력│
│ • 원문 팩트 하이라이트│ • 본문 문장마다 [쪽수·좌표 앵커] 부착   │ • 인터랙션 버튼   │
│ • 인덱싱 시각화   │ • 실제 Word 복사/내보내기 클릭 지원   │ • 직조 진행 바    │
└───────────────────┴───────────────────────────────────────┴───────────────────┘
```

* **인터랙션 구현 범위**:
  * 백엔드 API 연동 없이 Figma Smart Animate 기능으로 "지시어 입력 ➔ 앵커 분석 ➔ 본문 실시간 타이핑 직조" 연출.
  * 테스터가 마치 실제 AI 엔진이 자신의 백데이터를 딥리딩하여 직조하는 것처럼 체감하도록 인터랙션 완성도 극대화.

---

## 3. 테스팅 대상자 선정 요건

* **필수 선정 조건 (3명)**:
  * 향후 2주 이내에 정부 지원사업, 투자 제안서, 연구 계획서 등 **실제 제출 마감 과제를 쥐고 야근 중인 창업가·연구원 3명**.
* **엄격한 배제 조건**:
  * 마감 과제가 없거나, 호기심에 "구경해보겠다"는 관전자.
  * 구두 칭찬만 남기고 사라질 지인/동료.

---

## 4. 4단계 실측 실행 시나리오

### Step 1: 타깃 백데이터 사전 주입 (테스트 전날)
* 테스터가 현재 작성 중인 과제의 실제 백데이터 1~2건(사업계획서 요약본, 원천 통계 등)을 미리 전달받음.
* Figma 프로토타입의 데이터셋 텍스트를 테스터의 실제 백데이터 주제로 10분 만에 치환.

### Step 2: 자가 조작 유도 (무설명 관찰)
* 테스터에게 마우스를 넘기고 설명 없이 "이 3단 화면에서 제안서를 한 번 직조해 보세요"라고만 요청.
* 좌측 Reference 뷰어에서 우측 Composer를 거쳐 중앙 Document로 직조되는 과정을 스스로 클릭하며 체험하게 함.

### Step 3: 행동 강제 질문 2개 투여 (The Decisive Questions)
* 조작 직후 "어떠세요?", "마음에 드시나요?" 같은 주관적 감상은 일체 묻지 않음.
* 아래 2가지 행동 질문을 직격으로 던져 고객의 결속(Commitment)을 실측함:

```text
[질문 1: WTS 전환 의향 실측]
"이 제품이 다음 주 화요일에 오픈합니다.
 지금 작성하시던 Word 창을 끄고, 다음 주 마감 과제를 진짜로 이걸로 작성하시겠습니까?"

[질문 2: WTP 지불 의향 실측]
"오늘 사전 예약하시는 분들께만 첫 6개월을 50% 할인(월 19,000원)해 드립니다.
 지금 카드 번호를 등록하시겠습니까?"
```

## 5. 승패 판정 기준 (Kill Criteria)

| 판정 결과 | 고객 행동 양식 | 후속 조치 |
| :--- | :--- | :--- |
| **합격 (Pass)** | 망설임 없이 지갑에서 신용카드를 꺼내 번호를 등록하고, *"오픈 당일 오전 9시에 바로 열어달라"*고 요구할 때 | **가치 검증 1차 통과 ➔ 상용 소프트웨어 코딩 승인** |
| **보류 (Warning)** | "Word로 쓰긴 할 텐데, 결제는 첫 달 써보고 결정할게요"라며 결제를 미룰 때 | 가치 제안 및 온보딩 혜택 재설계 후 재테스트 |
| **사망 (Fail)** | "신기하긴 한데, 다음 과제는 익숙한 Word로 그냥 쓸게요", "출시되면 알려주세요" | **가치 검증 실패 ➔ 제품 콘셉트 즉각 피봇 (매몰비용 0원)** |

---

## 6. 금기 사항 (Anti-Patterns)
1. **기능 설명 늘어놓기**: 테스터가 조작할 때 옆에서 "이건 이런 기능이고 저건 저런 기능입니다"라고 설명하지 않는다.
2. **구두 호평에 취하기**: "너무 편리하네요!", "대박입니다!"라는 말은 신용카드를 꺼내기 전까지 전부 쓰레기 신호(Level 1)로 폐기한다.
