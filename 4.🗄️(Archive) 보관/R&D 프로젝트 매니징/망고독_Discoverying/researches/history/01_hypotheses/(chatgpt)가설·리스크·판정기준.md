# 가설·리스크·판정기준

> 이 문서의 가설은 제품 요구사항이 아니다. 증거가 나오면 번호를 유지한 채 상태와 근거만 바꾼다.

| ID | 리스크 | 검증할 가설 | 주요 반증 | 허용 가능한 판정 |
| --- | --- | --- | --- | --- |
| H1 | Value | 여러 근거와 형식 제약을 가진 실제 문서 작업에서 반복되는 마찰이 있다 | 최근 사례가 없거나 현재 흐름으로 충분히 해결됨 | Supported / Mixed / Not supported / Insufficient evidence |
| H2 | Value | 그 마찰은 돈·시간·인력·품질 위험을 써서 우회할 만큼 심각하다 | 불편하지만 업무 결과·행동에 영향을 주지 않음 | 동일 |
| H3 | Value | 현재 도구 조합으로도 해결되지 않는 구체적 Job이 있다 | 기존 에디터·템플릿·검토 절차가 충분함 | 동일 |
| H4 | Value | 레퍼런스 구조 재사용 또는 근거 추적이 실제 작업을 개선한다 | 참여자가 이 기능을 선택하지 않거나 다른 문제가 더 큼 | 동일 |
| H5 | Usability | 2D Workspace는 에디터형·분할 화면형보다 특정 Job에서 더 잘 작동한다 | 더 느리거나 혼란·도움 요청·형식 오류가 더 많음 | 동일 |
| H6 | Viability | 해결안이 다음 실제 업무의 파일럿·유료 약정 같은 비용 있는 행동을 만든다 | 칭찬은 있지만 실제 업무·후속 일정·약정이 없음 | 동일 |
| H7 | Feasibility | 선택된 해결안이 근거 연결과 형식 제어를 측정 가능한 정확도·비용으로 제공한다 | 고정된 시험에서 오류·지연·비용이 허용 범위를 넘음 | 동일 |

## 사전 규칙

- `H1 → H2 → H3 → H4 → H5 → H6 → H7` 순서가 기본이다. 앞선 가설이 약하면 뒤 가설을 건너뛴다.
- `H5`의 2D Canvas는 경쟁 솔루션 후보 중 하나다. H1~H4의 답으로 미리 정하지 않는다.
- 상태는 AI가 자동으로 바꾸지 않는다. 조사자와 PM·디자이너·엔지니어가 Evidence Matrix의 원자료 ID를 보고 합의한다.
- “100%”, “모든 사용자”, “시장 수요” 같은 표현은 표본·방법·분모가 충분히 공개될 때까지 사용 금지다.
