# 후보 F — 방법론별 (취한 것 · 버린 것)

> **한 줄**: 한 편이 방법론 하나. 책에서 말하는 것 ↔ 우리가 취한 것 · 바꾼 것 · 버린 것을 표 하나로 놓고 시작합니다.

## 편 목록

| 편 | 가제 | 취한 것 | 버린 것 · 바꾼 것 |
| --- | --- | --- | --- |
| 0 | 셋을 한 볼트에 얹으려던 이유 | (왜 셋이었나 — 문서에 없음. 사람이 써야 함) | — |
| 1 | PARA — 네 서랍은 남기고 "매번 고르기" 는 버렸다 | 네 구역 · 네 질문 | 만들 때마다 구역 고르기 · Area 의 티어 · 회의록의 자리 |
| 2 | GTD — 인박스와 다음 행동은 남기고 칸은 줄였다 | 수집과 처리의 분리 · 다음 행동 | `위임함` · `일정 있음` · `기한만` 칸 · 상태 폴더 · 컨텍스트 |
| 3 | 제텔카스텐 — 링크보다 이름표를 골랐다 | `상위` · `링크` 위키링크 | (근거 없음 — 사람이 말해 줘야 함) |
| 4 | 에이전트 — 맡긴 것과 다시 가져온 것 | 입구 + `docs/` · 스킬 · 작업 공간 | 그대로 반영 · 유형 추측 · 통짜 설명서 |
| 5 | 넷이 만나는 자리 — 속성 열세 개 | 한 노트가 네 방법론의 값을 다 가짐 | — |

## 한 편 안의 소제목 (2편을 예로)

```
개요        칸반에 칸이 아홉 개였다. 카드를 어디 놓을지부터 막혔다
한눈에      GTD 가 말하는 것 ↔ 우리 볼트 (취함 · 바꿈 · 버림 표)
취한 것     인박스 · 다음 행동 — 실제 노트 한 장
바꾼 것     일정표와 인큐베이팅을 `일정` 속성 하나로 — 전/후
버린 것     위임함 · 일정 있음 · 기한만 칸, 상태 폴더 — 왜 버렸나
잃은 것     버려서 불편해진 것 (솔직하게)
언제 이렇게 하면 좋은가
마무리      다음 편 — 제텔카스텐
```

## 잘 맞는 경우

- PARA · GTD · 제텔카스텐을 **이미 아는 사람**이 "남들은 어디까지 따랐나" 를 보러 올 때. 검색어가 분명합니다.
- "취함 · 바꿈 · 버림" 표가 레퍼런스의 Before/After 자리를 대신합니다.
- 근거표가 이미 방법론별로 나뉘어 있어 바로 쓸 수 있습니다.

## 약점

- **3편(제텔카스텐)은 볼트에 근거가 거의 없습니다.** 사람이 기억으로 써야 하고, 쓸 것이 없으면 "안 썼다" 한 편이 됩니다.
- 방법론을 설명하는 분량이 붙어 길어집니다. 에이전트 이야기는 4편에만 몰립니다.
