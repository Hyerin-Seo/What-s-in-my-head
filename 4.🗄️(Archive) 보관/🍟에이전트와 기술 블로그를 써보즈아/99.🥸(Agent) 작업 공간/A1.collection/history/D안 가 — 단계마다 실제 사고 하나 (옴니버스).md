# D안 가 — 단계마다 실제 사고 하나 (옴니버스)

## 1편의 제목과 뼈대

**인박스에 던진 노트의 주제가 바뀌어 있었다 — 노트 한 장의 일생 1편: 던진다**

```
개요          옮겨 온 회의록의 주제가 사라졌다. 바꾼 것은 요약기였다 → 던지기만 해도 되게 하려면 무엇까지 맡겨야 하나
지도          노트의 일생 여섯 단계 (매 편 같은 그림, 지금 자리만 표시)
던지면 생기는 일   파일을 던지면 1.5초 뒤 노트로 감싸짐 — 실제로 붙는 속성 세 줄
Before / After   사람이 적은 주제가 덮인 노트 ↔ 빈 칸만 채운 노트
맡긴 것과 안 맡긴 것  요약 · 주제는 맡김 / 작성자 · 유형은 안 맡김
이 단계의 규칙 한 줄  에이전트는 이 단계에서 무엇을 읽나 (`docs/inbox.md`)
언제 이렇게 하면 좋은가
마무리          다음 편 — 이름표가 붙는다
```

## 쉽고 재밌나

- **쉽습니다.** 편마다 "무슨 일이 났나 → 왜 → 어떻게 막았나" 가 버그 리포트에 이미 적혀 있습니다. 옮겨 쓰면 됩니다.
- **재밌습니다.** 편 제목이 전부 사고입니다. 옵시디언을 몰라도 읽힙니다.
- 레퍼런스의 한 편 구조(장면 → Before/After → 기준 → 언제)는 편마다 그대로 씁니다.

## 약점

- "한 장을 끝까지 따라간다" 는 D 의 원래 맛은 없습니다. 지도 그림이 그 역할을 대신해야 합니다.
- 1편과 6편은 코드가 약합니다. 1편이 약하면 시리즈가 약하게 시작합니다 → 2편(작성자가 Claude)을 1편으로 당기는 길이 있습니다.
- 사고만 여섯 번이면 볼트가 엉망으로 보입니다. 편마다 "지금은 이렇게 된다" 를 꼭 보여 줘야 합니다.
