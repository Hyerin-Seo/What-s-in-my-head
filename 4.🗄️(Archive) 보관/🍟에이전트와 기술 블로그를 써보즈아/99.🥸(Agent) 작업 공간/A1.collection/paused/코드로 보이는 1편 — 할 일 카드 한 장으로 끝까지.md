# 코드로 보이는 1편 — 할 일 카드 한 장으로 끝까지

레퍼런스는 "user 조회 훅 만들어 줘" 라는 부탁 하나로 Rules · Before/After · 심화까지 갔습니다.
우리 쪽에서 그 자리에 놓을 환경은 **할 일 카드 한 장의 프론트매터**입니다.
아래 코드는 전부 **git 기록에 남은 실제 파일**입니다. 지어낸 것은 없고, 길어서 줄인 곳은 `…` 로 표시했습니다.

| 레퍼런스 | 우리 |
| --- | --- |
| 환경: React Query 훅 | 환경: 할 일 카드의 프론트매터 |
| Rules 코드: `.cursor/rules` 파일 | 규칙 코드: `docs/properties.md` 의 YAML 규칙 |
| Before/After: 틀린 훅 ↔ 맞는 훅 | Before/After: `작성자: Gemini` ↔ `- "[[Gemini]]"` |
| Skills: Swagger → 타입 → 훅 | 스킬: 회의 속기 → 카드 → 할 일, 그리고 스킬에 더한 줄 |
| 심화: 원본 코드 ↔ 요약 JSON | 심화: 1,404줄 통짜 ↔ 입구 147줄 + 맞는 문서 |

## 규칙 — 에이전트가 만든 할 일 다섯 장에 작성자 칩이 안 떴다

### 상황

2026-09-17, Gemini 가 스킬(`editor_mockup_todo_manager`)로 기획 노트 하나를 할 일 다섯 장으로 쪼갰습니다 (커밋 `eb6592e`).
칸반에 카드는 떴는데 **작성자 칩이 다섯 장 모두 비어 있었습니다.** 오류는 없었습니다.

### 규칙은 이렇게 적혀 있었다 (`docs/properties.md` 의 YAML 공통 규칙)

```markdown
- **위키링크는 반드시 따옴표로.** `- [[Claude]]` 는 YAML이 중첩 리스트로 읽습니다.
  항상 `- "[[Claude]]"` 로 씁니다. `담당` `작성자` `커버` `상위` 전부 해당합니다.
- **여러 값 속성은 블록 리스트로.** `분류` `주제` `담당` `작성자` 는 `.obsidian/types.json` 에
  `multitext` 로 못박혀 있습니다. 스칼라(`분류: 웹소설`)로 쓰면 옵시디언이 되돌립니다.
```

### Before — 에이전트가 만든 카드 (`[할일] 속성 패널 및 속성 뷰 인스펙터 구축.md`)

```yaml
---
유형: 할일
구역: 1.project
…
상위: "[[(seo) editor-workspace 실험]]"
링크:
담당:
작성자: Gemini
---
```

### After — 같은 카드 (커밋 `cad7ba4`)

```yaml
---
유형: 할일
구역: 1.project
…
상위: "[[(seo) editor-workspace 실험]]"
링크:
담당:
작성자:
  - "[[Gemini]]"
---
```

### 그때 더한 줄 — 원인은 스킬의 양식이었다

카드 다섯 장만 고치면 다음에 또 납니다. 스킬의 양식 · 설명 · 예시 셋이 전부 한 줄 모양이었습니다.

```diff
  # skills/editor_mockup_todo_manager/templates/todo_template.md
- 작성자: Gemini
+ 작성자:
+   - "[[{{AGENT_NAME}}]]"
```

```diff
  # skills/editor_mockup_todo_manager/SKILL.md
-    * AI가 기획/분해 작업을 수행하여 작성했으므로 `작성자: Gemini`를 명시합니다.
+    * AI가 기획/분해 작업을 수행하여 작성했으므로 `작성자` 에 **작업한 에이전트 자기 이름**을 넣습니다.
+    * 모양은 반드시 목록 + 따옴표 친 위키링크입니다 — `작성자:` 다음 줄에 `  - "[[Gemini]]"` (Claude 면 `"[[Claude]]"`).
+      `작성자: Gemini` 처럼 한 줄 글자로 쓰면 칸반의 작성자 칩이 안 뜨고, 따옴표를 빼면(`- [[Gemini]]`)
+      YAML 이 중첩 목록으로 읽어 값이 깨집니다 (`CLAUDE.md` 의 YAML 공통 규칙).
```

그리고 문서에 한 줄이 남았습니다 — "스킬이 만드는 노트도 볼트 규칙을 그대로 따릅니다." (`docs/meetings-and-skills.md`)

### 솔직하게 적을 것

- 레퍼런스의 Before/After 는 "규칙이 없을 때 ↔ 있을 때" 입니다. 이 예시는 조금 다릅니다 — **규칙은 있었는데 스킬의 양식이 규칙과 다르게 적혀 있었던 것**입니다. 그대로 쓰면 "규칙만 적어서는 모자랐다" 는 이야기가 됩니다.
- 스킬은 그때 `.agents/skills/` 에 있었고 지금은 `skills/` 입니다. 위 경로는 지금 자리로 적었습니다.

## 스킬 — 회의에서 나온 할 일이 다음 회의 점검에서 빠졌다

### 상황

2026-09-29 회의 뒤, 사람이 회의에서 나온 할 일 여섯 장을 인박스를 안 거치고 **프로젝트에 바로** 만들었습니다.
회의 스킬은 다음 회의 전에 "지난 회의에서 하기로 한 것" 을 찾아 점검표를 까는데, 이 여섯 장은 거기 안 잡혔습니다.
스킬이 `상위` 가 회의록인 할 일만 찾고 있었기 때문입니다.

### Before — 사람이 만든 할 일 (2026-09-29 18:44)

```yaml
주제:
  - 망고독_USABILITY_RISK_검증
상위: "[[usablility_사용성 담당 첫 실전 테스트 문서 및 백데이터 요건]]"
링크:
  - "[[1.5_사용성_담당이_직접_써_볼_첫_문서]]"
```

`상위` 에는 프로젝트의 부모 할 일이, `링크` 에는 그 할 일이 나온 안건 카드가 들어 있습니다. 사람에게는 이게 자연스럽습니다.

### 스킬에 더한 줄 (`skills/meeting-notes/SKILL.md`, 2026-09-30)

```diff
-    | a. 회의 할 일 | `유형: 할일` · `주제` 에 `회의 할 일` · `상위` 가 P | P |
+    | a. 회의 할 일 | `유형: 할일` · `주제` 에 `회의 할 일` · `상위` **또는 `링크`** 가 P | P |
+    - **회의 끈은 `상위` 또는 `링크`** 입니다 (2026-09-30 Rin). 프로젝트에서 부모 할 일을 `상위` 로 쓰는 할 일은
+      회의록을 `링크` 에 넣습니다 — `상위` 를 회의록으로 바꾸면 부모 → 자식 구조가 끊깁니다.
+    - `상위` 가 다른 노트(부모 할 일 등)면 → **`상위` 는 그대로**, `링크` 목록에 `"[[<회의록>]]"` 한 줄 더함
```

### After — 에이전트가 끈을 맞춘 뒤 (2026-09-30 12:50, 여섯 장)

```yaml
주제:
  - 망고독_USABILITY_RISK_검증
  - 회의 할 일
상위: "[[usablility_사용성 담당 첫 실전 테스트 문서 및 백데이터 요건]]"
링크:
  - "[[1.5_사용성_담당이_직접_써_볼_첫_문서]]"
  - "[[2026.09.29 주간 회의록]]"
```

사람이 쓴 `상위` 는 그대로 두고 두 줄만 더했습니다. 사람에게 맞추라고 하지 않고 스킬이 맞췄습니다.

### 한계 인정 — 같은 날 이 방식도 접었다

같은 날 오후에 끈을 속성이 아니라 **폴더**로 바꿨습니다. 회의에서 나온 것은 `<프로젝트>/discussions/<날짜>/` 에 두면 됩니다.
이유는 문서에 그대로 적혀 있습니다 — "그걸 적는 게 귀찮아서 바꿈" (`docs/meetings-and-skills.md`).

### 덤

- 이 할 일 카드는 지금 **이 블로그 프로젝트 폴더에 있습니다** (`empowered_유튜브·하네스 기반 에이전트 협업…`).
- 회의 한 번의 숫자도 있습니다 — 376발화 → 카드 6 → 고름 3 ([[예시 후보 6 — 회의 376발화가 카드 여섯 장이 됐고 셋을 골랐다]]).

## 심화 — 읽는 양 줄이기 (뼈대 초안 그대로)

코드는 두 가지입니다. 입구 표 세 줄과, 속성으로 찾는 명령 한 줄.

```markdown
| 하려는 일 | 읽을 문서 |
| --- | --- |
| 노트를 찾는다 | 이 파일의 **자료를 찾을 때** 로 충분합니다 |
| 새 노트를 만든다 · 본문을 써 넣는다 · `작성자`·`커버` | `docs/new-notes.md` |

```

grep -rl '^유형: 할일' --include='*.md'
