# 예시 후보 8 — 이 글을 쓰는 과정 그대로

> **한 줄**: 이 글도 같은 하네스로 썼다. 무엇을 시켰고, 에이전트가 무엇을 냈고, 사람이 무엇을 버렸는지가 작업 공간 폴더에 그대로 있다.

## 실제 재료 (2026-10-01 하루, 이 프로젝트의 작업 공간)

```
99.🥸(Agent) 작업 공간/
  A1.collection/검토 중/   ← 지금 보는 예시 후보들
  A1.collection/history/   ← 안 고른 목차 후보 8장 (B · C · E · F~J)
  A5.outputs/              ← 사람이 고른 것 2장 (A · D)
  A3.working memory/       ← 작업 기억 (튜닝 기록 1~3회차)
```

- 에이전트가 낸 목차 후보 10장 → 사람이 고른 것 2장 → 그중 A 로 정함.
- 사람이 한 말 (대화 그대로):
  - 구조 분석만 시켰는데 목차까지 써 온 것을 보고 — "흠 좀 많이 앞서나간거 같긴 한데"
  - 레퍼런스와 1:1 로 맞춘 뼈대를 보고 — "개심심하고 개별론데 직접적 예시가 없어서 그런가"
- 그날 생긴 규칙: "시킨 단계까지만 한다. 제안은 작업 공간의 검토 중에 종류가 다른 후보 여러 장으로."
- 그날 드러난 구멍 둘: 프로젝트 안에 만든 작업 공간은 제외 설정에 안 걸렸다 · 다른 세션의 작업 사본이 동기화에 딸려 갈 뻔했다.

## 글에서 이렇게 보인다

> 이 글도 같은 방법으로 썼습니다. 에이전트는 목차 후보를 열 장 냈고, 우리는 여덟 장을 버렸습니다.
> 레퍼런스의 구조를 그대로 옮긴 첫 뼈대에는 이런 평이 달렸습니다. "개심심하고 개별론데."
> 그래서 지금 읽고 계신 예시들을 다시 골랐습니다. 버린 여덟 장은 지우지 않고 `history` 폴더에 있습니다.

## 뼈대의 어느 칸에

- **스킬 단원** — "작업 공간에 내고 사람이 고른다" 를 회의 말고 이 글로 보여 줍니다.
- **마무리** — 글 전체를 한 번 접는 자리.
- 상위 카드의 `걸린 시간 적기 — 1단계 vs 2단계` 표와 이으면 **이 글이 첫 실측**이 됩니다.

## 왜 괜찮은가

- 읽는 사람이 지금 읽는 글이 증거입니다. 다른 예시는 다 지난 일인데 이것만 현재입니다.
- 버린 것의 수(10장 중 8장)와 사람의 평이 그대로 있어 자랑으로 안 읽힙니다.

## 약점 · 확인할 것

- 자기 얘기를 하는 글은 잘못 쓰면 재주 부리기로 읽힙니다. 한 단락을 넘기지 않는 편이 낫습니다.
- 대화의 말투가 그대로 나갑니다. 써도 되는지, 다듬을지 정해야 합니다.
- 걸린 시간은 아직 안 적었습니다. 쓰려면 지금부터 적어야 합니다.
