# D1 인스파이어드 디스커버리 방식으로 리스크별로 검증하고, 아니면 버린다

> **속기 원문**
> - 민규 서 (01:05) *그래서 다른 방법론이나 이런 것들도 있는데 그냥 요거를 픽을 했고.*
> - 민규 서 (08:33) *이거별로 다 쪼개라. 이 사람이 하는 말에. 청킹을 해라.*
> - 민규 서 (39:54) *그 싫다면 뭐 어쩔 수 없지. 그래서 과수 검증해 봤는데 어 싫대요.*
> - 민규 서 (40:04) *그때는 우리 폐기하자. 검증이고.*
> - Rin (53:43) *그래서 좀 거리가 있다고 생각했거든.*
> - 민규 서 (53:46) *맞아. 이게 확실히 팀원들도 있고.*

## ✅ 정한 것

| | |
| --- | --- |
| **무엇을** | 망고독은 인스파이어드의 디스커버리 방식으로 간다 — 가치 · 사용성 · 기능 · 비용 리스크를 쪼개 따로 검증하고, 반응이 싫으면 폐기한다 |
| **언제까지** | 속기에 없음 |
| **누가** | 속기에 없음 (방법론을 고른 사람은 민규 서) |
| **확신** | 반대 없이 넘어감 — 민규 서가 고르고 설명 (01:05 · 08:33 · 40:04). Rin 은 책을 거의 안 읽었다고 했고 (03:31), 개정판이 규모 있는 기업 얘기라 **거리가 있다**고 함 (53:43) — 민규 서도 "맞아" (53:46) |

## 🎯 끝났다고 보는 기준

- 속기에 없음 — 무엇을 보면 "싫대요 → 폐기" 인지 정할 것 (→ [[1.2_첫_타겟과_가치_신호_누구에게_먼저]] · [[1.3_북극성_10분의_1_무엇과_비교해_잴까]])

## 💬 왜

- Rin 이 이미 내용을 알고, 책의 정리가 잘 돼 있어서 (속기 01:05)
- 요구사항대로 바로 만드는 딜리버리로 넘어가면 나중에 고치는 비용이 훨씬 크다 (속기 06:08)
- 아이디어의 절반은 버려진다 — 그래서 검증해 봐야 한다 (속기 55:22 · 55:30)

## 🚧 어디까지

- **한다:** 리스크별로 따로 프로토타입을 만들어 빠르게 확인하고 버림 (속기 08:48)
- **한다:** 딜리버리로 넘어가기 전에 가치 검증은 반드시 (속기 11:42)
- **안 한다:** 검증 결과가 싫으면 이어 가지 않음 — 폐기 (속기 40:00 · 40:04)

## ❓ 아직 안 정한 것

- 가치 테스트를 항목으로 쪼개는 방법 — 책은 윤곽만 다룬다, "더 자세히 파야 돼요" (속기 01:01:06) · ⏭ 다음 회의로
- 개정판(규모 있는 기업 기준)과 둘뿐인 팀 사이의 거리를 어떻게 메울지 (속기 53:13–53:46)
