# 2.1 PARA 분류 기준 — 지금 실행 중인 액션이 있나

> **속기 원문** (속기 4 · 5 · 6)
> - *막상 노트를 쌓으려니까 데일리 노트랑 프로젝트 노트가 자꾸 꼬여. 어디에다 짱박아야 될지 애매한 자료들이 너무 많아.*
> - *핵심은 지금 당장 실행 중인 액션이 있냐 없냐야. 액션이 있으면 프로젝트, 그냥 계속 관리해야 되는 영역이면 에어리어스, 단순 참고용 자료면 리소스.*
> - *그냥 귀찮아서 다 리소스에 처박으니까 악순환 생기는 거라고.*

## 🎯 핵심 의사결정 포인트 (Decision Checkpoint)
> **[결정 질문] 데일리 노트는 PARA 어디에 두나?**
> - [ ] **[데일리는 기록만, 내용은 프로젝트 노트로 백링크 (권장)]**: 화자 B 가 "프로젝트 단위로 데일리 노트랑 백링크 걸어두니까 … 편하긴 하더라" 라고 함
> - [ ] **[데일리 노트도 PARA 폴더에 넣음]**: 한곳에 모이지만 날마다 어디 넣을지 또 고민

---

## 📌 기존엔 왜 이렇게 관리했을까? (현행 사양의 이유)

* **1. 폴더만 PARA 로 갈아엎음**
  * 분류 기준 없이 폴더부터 바꿔서, 애매한 건 리소스로 몰림

---

## 📌 핵심 분석

* **기준은 합의됨, 적용이 안 됨:** 화자 A 의 기준(액션 유무)에 화자 B 가 반대하지 않음. 문제는 "손이 안 갔지" — 가이드라인을 봤는데 안 씀
* **데일리 노트 자리가 비어 있음:** 기준 세 칸(P · A · R)에 데일리가 안 들어감

---

## 🌐 참조 자료 및 모범 사례 (다른 곳은 어떻게 하는가?)

* **1. PARA 의 실행 가능성 기준** — 티아고 포르테의 PARA 는 주제가 아니라 "얼마나 실행에 가까운가" 로 나눔. 속기의 화자 A 기준과 같음
* **2. 이 볼트의 기준** — `CLAUDE.md` 의 "마감이 있고 지금 집중하는 일인가? → project …" 네 질문. 같은 고민을 먼저 풀어 둔 것
* **3. 데일리는 입구** — 데일리 노트에 적고 링크로 프로젝트에 붙이는 방식이 옵시디언에서 흔함

## ⚖️ 핵심 쟁점 (회의에서 답을 내려야 할 질문)

* **1. 데일리 노트**
  * **[선택 A]:** PARA 밖 (입구)
  * **[선택 B]:** PARA 안
* **2. 애매한 자료**
  * **[선택 A]:** 일단 인박스 → 주기적으로 분류
  * **[선택 B]:** 바로 리소스
