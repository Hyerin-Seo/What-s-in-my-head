# 1.1 회의록 자동화 LLM 파이프라인 안정화 — 청크 분할과 포맷 깨짐

> **속기 원문**
> - *근데 문제는 그 다음이야. 이걸 그냥 텍스트 덩어리로 두니까 나중에 검색하거나 요약할 때 개판 되더라고. 그래서 엘엘엠 API 붙여서 자동으로 핵심 키워드 뽑고 구조화된 마크다운으로 뱉어주는 파이프라인을 짜야 되는데, 그 프롬프트 엔지니어링 쪽에서 지금 토큰이 자꾸 터지거나 포맷이 깨지는 이슈가 좀 있음.*
> - *아, 토큰 제한 걸리는 거? 그거 텍스트 덩어리째로 한 번에 넣어서 그런 거 아니야? 스크립트 길어지면 당연히 오버되지. 그거 청크 단위로 잘라서 요약한 다음에 최종 취합하는 방식으로 스크립트 수정해야 될 것 같은데.*
> - *너는 파이프라인 에러 핸들링이랑 프롬프트 최적화 쪽 좀 더 파줘.*
> - *오, 그 청크 분할 방식 좋네. 알겠어. 그 부분은 내가 오늘 내로 정규식 짜서 문단 단위로 끊기게 스크립트 수정해 볼게.*

## 🎯 핵심 의사결정 포인트 (Decision Checkpoint)
> **[결정 질문] 토큰 초과와 포맷 깨짐을 '청크 분할 → 요약 → 취합' 하나로 같이 풀 것인가, 포맷 깨짐은 출력 형식을 따로 고정해서 풀 것인가?**
> - [* ] **[청크 분할 + 출력 형식 고정 (권장)]**: 토큰은 청크로, 포맷은 출력 모양(스키마)을 정해 코드가 마크다운을 조립. 원인이 다른 두 문제를 각자 막음.
> - [ ] **[청크 분할만 먼저]**: 오늘 마감 안에 끝낼 수 있음. 포맷 깨짐이 남는지는 오후 2시 싱크에서 확인하고 그때 정함.

## 📌 기존엔 왜 이렇게 관리했을까? (현행 사양의 이유)

* **1. 앞 단계부터 확정하는 순서 (단계별 검증)**
  * 위스퍼 → 텍스트 전사를 로컬에서 먼저 테스트해 끝냈음. 입력이 믿을 만해진 뒤에 LLM 단계로 넘어가는 순서였음.
* **2. 가장 단순한 첫 구현 (빠른 확인)**
  * 텍스트 덩어리를 한 번에 넣는 것은 코드가 가장 짧고, 짧은 회의에서는 문제가 드러나지 않음.
* **3. 원문 보존 (맥락 유지)**
  * 통째로 넣으면 잘리는 곳 없이 모델이 대화 전체를 봄. 자르면 문단 경계에서 앞뒤 맥락이 끊길 수 있음.

## 📌 핵심 분석

* **두 문제의 원인이 다름:**
  * 토큰 초과는 **입력 길이** 문제 (화자 A 진단: "텍스트 덩어리째로 한 번에 넣어서"). 포맷 깨짐은 **출력 모양** 문제. 청크 분할은 앞의 것만 직접 풂.
* **오늘 한 사람에게 몰림:**
  * 청크 분할 · 에러 핸들링 · 프롬프트 안정화가 모두 화자 B 에게, 모두 "오늘" 안. 끝났다는 기준이 속기에 없음.

## 🌐 참조 자료 및 모범 사례 (다른 곳은 어떻게 하는가?)

* **1. Map-Reduce 요약 (LLM 도구의 표준 패턴)**
  * 긴 문서를 조각마다 요약(map)하고, 요약들을 다시 합침(reduce). LangChain 등 요약 체인이 기본으로 제공하는 방식. 조각이 작아 토큰 한도를 넘지 않음 — 화자 A 가 말한 방식과 같음.
* **2. 구조화 출력 (Structured Outputs · 도구 호출)**
  * 모델이 정해진 JSON 스키마로만 답하게 강제하고, 마크다운은 코드가 조립. 포맷 깨짐을 모델 손에서 빼는 방식.
* **3. 재시도 + 검증 (엔지니어링 관례)**
  * API 실패 시 간격을 늘려 다시 부르고(백오프), 출력이 스키마에 안 맞으면 오류를 붙여 한 번 더 요청. 이 볼트의 인박스 요약(agy)도 6 · 12초 백오프로 세 번 재시도함 (`docs/inbox.md`).

## ⚖️ 핵심 쟁점 (회의에서 답을 내려야 할 질문)

* **1. 어디서 자를까? (단위)**
  * **[문단 · 정규식]:** 화자 B 안. 구현이 빠름. 대화체 속기는 문단 경계가 곧 발화 경계라 잘 맞을 수 있음.
  * **[토큰 수 + 조금씩 겹치기]:** 조각 길이가 고르고, 경계에서 맥락이 덜 끊김.
* **2. 포맷 깨짐은 무엇으로 막을까? (방식)**
  * **[프롬프트 다듬기]:** 지금 구조 그대로, 지시문만 고침.
  * **[출력 형식 고정]:** 스키마로 받고 코드가 마크다운을 만듦.
* **3. '안정화 끝' 의 기준은? (완료 조건)**
  * **[샘플 녹음 N개가 깨지지 않고 통과]:** 2시 싱크에서 둘이 같은 기준으로 확인 가능.
  * **[화자 B 판단]:** 빠르지만 됐다 / 안 됐다가 말로만 남음.
