# 🗂️ [카드] 회의 필수 항목 구조화 및 템플릿 설계 스펙

> **카드 목적:** 회의(Meeting)의 목적 달성과 실질적인 실행(Action)을 담보하기 위해 회의 전·중·후 전 과정에서 누락되어서는 안 될 **가장 중요한 필수 항목**들을 정의하고, 이를 표준 회의록 템플릿으로 조립할 수 있도록 컴포넌트화한 스펙 카드입니다.

---

## 📌 회의 필수 4대 핵심 축 (Core Pillars)

회의록은 단순한 '속기 저장소'가 아닌, **사전 준비(Input) → 회의 진행(Throughput) → 실행 및 배포(Output)**를 관통하는 파이프라인이어야 합니다.

```
[1. 사전 준비 (Pre)]  ──▶  [2. 회의 진행 (Live)]  ──▶  [3. 의사결정 (Post)]  ──▶  [4. 실행 배포 (Action)]
  • 목표/원하는 결과물           • 실시간 속기/논의              • 결정된 사항 (Decisions)         • 할 일 (Who/When/What)
  • 타임박싱 안건                • 참고 자료/자산                • 보류 안건 (Next)               • 프로젝트 연결 보드
```

---

## 1. 사전 준비 필수 항목 (Pre-Meeting)

> *"준비되지 않은 회의는 시간을 낭비한다."* 회의 시작 전에 명확히 채워져야 하는 항목입니다.

| 필수 항목 | 설명 및 기입 기준 | 누락 시 발생하는 문제 |
| :--- | :--- | :--- |
| **회의 목표 (Goal / Purpose)** | 이번 회의의 성격(정보 공유, 브레인스토밍, 의사결정, 문제 해결)과 달성 목적 | 목적 없이 모여 잡담으로 흐르거나 결론 없이 끝남 |
| **원하는 결과물 (Expected Outcome)** | 회의 종료 시 손에 쥐어야 하는 구체적 산출물 (예: "A안/B안 중 택1 결정", "와이어프레임 합의") | 회의가 잘 끝났는지 평가할 기준이 없음 |
| **타임박싱 안건 (Agenda & Timebox)** | 논의할 안건 목록 및 각 안건당 할당 시간 (예: `안건 1 (15m)`) | 특정 안건 하나에 시간이 끌려 뒷부분 논의 불가 |
| **사전 참고 자료 (Pre-read / Context)** | 참석자가 미리 읽고 와야 하는 링크, 문서, 기획안, 시안 | 회의 시간에 문서를 읽느라 논의 시간이 증발함 |
| **참석자 역할 구분** | - **진행자(Facilitator)**: 시간 관리 및 논의 조율<br>- **서기(Scribe)**: 실시간 속기 및 AI 보조 프롬프팅<br>- **필수/선택 참석자**: 의사결정권자 및 관련 실무자 | 누가 발언을 이끌고 누가 기록하는지 모호해짐 |

---

## 2. 회의 진행 필수 항목 (In-Meeting)

> *"회의 중에는 형식보다 맥락 보존이 우선이다."* 실시간으로 빠르고 왜곡 없이 기록되어야 하는 항목입니다.

| 필수 항목 | 설명 및 기입 기준 | 에이전트/도구 활용 팁 |
| :--- | :--- | :--- |
| **실시간 속기 (Raw Notes)** | 가공이나 요약 없이 발언 흐름을 날것 그대로 빠르게 받아 적는 공간 | 불릿(`-`) 단위로 줄글 기록, 할 일 발생 시 즉시 `→` 접두사 표기 |
| **참고자료/데이터 (Attachments)** | 회의 도중 화면 공유되거나 논의된 이미지, 링크, 문서 경로 | 이미지 붙여넣기, 볼트 내부 위키링크(`[[...]]`)로 즉시 연결 |
| **인라인 코멘트/질의 (Comments & Q&A)** | 발언 중 튀어나온 이견, 추가 확인 필요 사항, 반론 기록 | 본문 내 별도 콜아웃이나 각주/코멘트로 논의 맥락 보존 |

---

## 3. 사후 결과 및 의사결정 필수 항목 (Post-Meeting / Outcome)

> *"회의가 끝난 즉시 합의된 결론을 고정한다."* 회의록의 핵심 가치가 발현되는 영역입니다.

| 필수 항목 | 설명 및 기입 기준 | 체크포인트 |
| :--- | :--- | :--- |
| **확정된 결정 사항 (Decisions Made)** | 회의를 통해 공식 합의·확정된 정책, 방향성, 규약 (명확한 두괄식 문장) | "무엇을 하기로 했는가"뿐만 아니라 "무엇을 하지 않기로 했는가"도 명시 |
| **보류 및 차기 안건 (Deferred Topics)** | 시간 부족이나 추가 데이터 필요로 결론을 내리지 못한 안건 | 차기 회의 날짜 또는 안건 담당자 지정 |
| **핵심 논점/이유 (Rationale)** | 해당 결정이 내려진 핵심 배경과 논리적 근거 요약 | 훗날 "왜 이렇게 결정했지?" 번복 방지 |

---

## 4. 실행 및 배포 필수 항목 (Accountability & Action Items)

> *"회의는 할 일을 낳지 않으면 회의가 아니다."* GTD/PARA와 연결되는 실질적 실행 엔진입니다.

| 필수 항목 | 필수 4대 요소 | 옵시디언/볼트 구현 기준 |
| :--- | :--- | :--- |
| **실행 주체 (Who)** | 책임을 지는 단 한 명의 담당자 (`담당: "[[이름]]"`) | "공동 담당" 금지 (미할당 처리됨) |
| **완료 기한 (When)** | 구체적인 마감일 또는 실행 날짜 (`마감: YYYY-MM-DD`, `일정`) | "최대한 빨리", "다음 주" 같은 모호한 표현 금지 |
| **명확한 행동 (What)** | 행동으로 옮길 수 있는 명확한 동사형 업무 문장 | 단순 단어가 아닌 "A 기능 B 버그 원인 분석 및 패치" 꼴 |
| **귀속 프로젝트 (Where)** | 해당 할 일이 귀속되어야 하는 정규 프로젝트 위치 | 프로젝트 보드(`.base`)와 연동되어 칸반/테이블에 자동 수집 |

---

## 6. 검토 및 개선 제안 사항 (Review Notes)

1. **기존 볼트 템플릿과의 차이점:**
   - 기존 템플릿(`!(Template) 회의록.md`)은 `속기 → 자료 → 결정 → 다음안건 → 할일` 구조로 **사전 준비(목표, 사전 읽을거리, 안건별 시간 배분)** 항목이 누락되어 있음.
2. **개선 권장 포인트:**
   - 회의 전 상단에 `회의 목표`와 `원하는 결과물`을 기입하도록 템플릿 상단에 컴포넌트 추가 배치 필요.
   - 인라인 코멘트 및 회의 전 사전 질문을 남길 수 있는 메모 블록 도입 검토.
