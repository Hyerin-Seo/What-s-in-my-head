# 📌 [기획 벤치마크] 우리 서비스 도입용 핵심 벤치마크 포인트 목록 (노션 · 미로 · MemGPT)

> **속기 원문**
> - *노션에서 하고자 했던것 / 미로에서 하고자 했던것 이 리스트를 가져오세요. mem gpt  하 샤갈!*

---

## 🎯 문서 개요 및 목적

본 문서는 형식적인 회의 안건 카드가 아닌, **과거 프로젝트 스토리보드와 기획 논의에서 "우리 서비스로 꼭 가져오자"고 합의했던 3대 핵심 벤치마크(노션, 미로, MemGPT)의 실제 기능 및 UX 포인트들을 전수 추출하여 정리한 [프로덕트 벤치마크 스펙 리스트]**입니다.

우리 프로젝트는 **'범용 문서 빌더/스캐폴딩 엔진' + '리치 텍스트 및 캔버스 시각화' + '도메인 중립 Agent 런타임'**의 결합을 지향하며, 각 도구의 엣지를 다음과 같이 차용합니다:

```text
[우리 서비스의 3대 핵심 기둥]
   ├─▶ 1. 노션(Notion)   : 블록(Block) 기반 구조화된 문서 빌딩 & 메타데이터 바인딩
   ├─▶ 2. 미로(Miro)     : 무한 캔버스(Infinite Canvas) 기반 시각적 템플릿 & 공간 매핑
   └─▶ 3. MemGPT(Letta)  : 단기 세션을 넘어선 에이전트의 영구 장기 기억(Memory Tiering)
```

---

## 1. 📝 노션(Notion)에서 가져올 벤치마크 포인트 리스트 (문서 빌더)

과거 스토리보드(`(draw) 볼트 칸반을 참고해 비동기 지시 스토리보드 VER2 이어 그리기` 등)에서 논의된 블록 에디터 핵심 UX:

| 벤치마크 항목 | 노션의 원형 UX | 우리 서비스에 적용할 핵심 스펙 |
| :--- | :--- | :--- |
| **① 원자적 블록 아키텍처<br>(Atomic Block)** | 모든 문단, 헤딩, 콜아웃, 코드, 이미지가 독립된 객체(Block)로 존재 | • 문서를 줄 단위가 아닌 **드래그 앤 드롭 가능한 블록 단위**로 관리<br>• 에이전트가 특정 블록만 정확히 타겟팅하여 수정/치환할 수 있는 구조 확보 |
| **② 슬래시(/) 퀵 커맨드<br>(Slash Command)** | `/` 타이핑 시 서식 및 컴포넌트 삽입 팝업 호출 | • 타이핑 도중 `/` 입력 시 **서식 변환 + 에이전트 즉시 호출(스킬 트리거)**<br>• 예: `/요약`, `/안건변환`, `/체크리스트생성` 등 인라인 인터랙션 |
| **③ 속성 기반 메타데이터<br>(Properties Schema)** | 문서 상단에 태그, 담당자, 상태, 날짜 등 정형 데이터 부착 | • 볼트의 13종 속성과 연동되는 **시각적 프로퍼티 에디터 바** 제공<br>• 문서의 메타데이터를 기반으로 필터링/정렬되는 다이나믹 뷰 지원 |
| **④ 양방향 링크 & 멘션<br>(Bi-directional Link)** | `@` 멘션 및 `[[문서명]]` 링크를 통한 지식 연결 | • 텍스트 작성 중 다른 카드, 태스크, 에이전트 프롬프트를 자유롭게 인라인 멘션<br>• 문서 간의 연결망을 백링크로 추적 |

## 2. 🎨 미로(Miro)에서 가져올 벤치마크 포인트 리스트 (캔버스 시각화)

과거 기획(`(draw) 구현 대상 스토리보드 작성`, `미로 - 크리에이티브 리스트업` 등)에서 다룬 시각화 인터랙션:

| 벤치마크 항목 | 미로의 원형 UX | 우리 서비스에 적용할 핵심 스펙 |
| :--- | :--- | :--- |
| **① 2D 무한 캔버스<br>(Infinite Canvas)** | 텍스트의 수직 스크롤을 벗어난 자유로운 2차원 공간 배치 | • 문서를 '세로로 긴 글'뿐만 아니라 **'공간에 펼쳐진 카드 군집'**으로 조망<br>• 줌인/줌아웃을 통해 전체 조망(Macro)과 세부 편집(Micro)을 넘나드는 UX |
| **② 템플릿 기반 스캐폴딩<br>(Template Gallery)** | 빈 캔버스에 마인드맵, 칸반, 플로우차트 템플릿 원클릭 배치 | • 사용자가 백지 상태에서 고민하지 않도록 **사전 정의된 템플릿 묶음** 제공<br>• 회의 준비, 작업 흐름도, 시스템 아키텍처 템플릿을 캔버스에 즉시 전개 |
| **③ 노드 연결 및 관계 시각화<br>(Connector & Arrows)** | 포스트잇과 도형 사이를 화살표와 선으로 직관적 연결 | • 안건과 안건, 작업과 작업 사이의 **선후 관계 및 의존성을 화살표로 렌더링**<br>• "이 결정이 왜 나왔는가?"의 인과 흐름을 시각적 그래프로 추적 |
| **④ 크리에이티브 카드 클러스터링<br>(Card Grouping)** | 흩어진 아이디어 카드를 카테고리별로 묶고 색상 분류 | • 에이전트가 인박스의 거친 속기들을 캔버스 위에 흩뿌려 두고, 사용자와 함께 드래그하여 **유사 주제별로 군집화(Clustering)**하는 협업 작업대 |

## 3. 🧠 MemGPT (Letta)에서 가져올 벤치마크 포인트 리스트 (에이전트 장기 기억)

에이전트가 매 세션마다 맥락을 잊는 '기억 상실' 문제를 해결하기 위한 시스템 아키텍처:

| 벤치마크 항목 | MemGPT의 원형 아키텍처 | 우리 서비스에 적용할 핵심 스펙 |
| :--- | :--- | :--- |
| **① 3단계 계층 메모리<br>(Memory Tiering)** | OS의 가상 메모리처럼 Core, Working, Archival 메모리 분리 | • **Core Memory:** 사용자의 고유 취향, 불변 원칙, 절대 규칙 (상시 프롬프트 주입)<br>• **Working Memory:** 현재 작업 폴더(`A3.working memory` 등)의 단기 세션 맥락<br>• **Archival Memory:** 과거 회의록, 볼트 전체 문서의 인덱스 검색(Recall) |
| **② 자기 주도적 기억 편집<br>(Self-Editing Memory)** | 에이전트가 스스로 "이 정보는 기억해야겠다"고 판단하여 저장 | • 대화 중 사용자가 규칙을 정하거나 피드백을 주면, 에이전트가 알아서 **지식 카드(KI/규칙 문서)를 업데이트**하도록 도구(`save_memory`) 제공 |
| **③ 세션 간 맥락 영속성<br>(Stateful Persistence)** | 대화 창을 닫아도 에이전트의 상태와 과거 합의 사항이 유지됨 | • 새로운 세션이 열려도 *"지난번 회의에서 합의된 1.1 아카이빙 룰에 따르면..."*처럼 **과거의 결정을 즉시 인출하여 현재 작업에 일관되게 반영** |

## 4. 🚀 우리 서비스 종합 융합 시나리오 (To-Be Workflow)

과거에 논의했던 세 가지 벤치마크가 하나로 작동할 때 사용자가 겪게 될 실제 작업 흐름:

```text
1. [미로 캔버스] ──▶ 날것의 생각과 속기를 캔버스 위에 카드로 자유롭게 브레인스토밍
2. [MemGPT 기억] ──▶ 에이전트가 과거의 벤치마크 및 회의 이력을 스스로 회상하여 맥락 보정
3. [노션 빌더]  ──▶ 확정된 생각을 완결된 블록 단위 문서로 1초 만에 스캐폴딩 및 메타데이터 바인딩
```

* [ ] **[스프린트 우선순위]:** 세 가지 축(노션형 블록 빌더 vs 미로형 캔버스 시각화 vs MemGPT형 장기 기억) 중 **다음 스프린트에 가장 먼저 프로토타입으로 찍어낼 1순위 핵심 엣지**를 확정.
