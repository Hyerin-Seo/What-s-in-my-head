# ✍️ 김사라 렌즈 — 뽑은 카드가 우리 작업 흐름에 맞나

**보는 곳**: 검토 대상의 7장 · 핀셋 카드 (`[CARD-…]` 나 질문 틀 7장의 `🏷️ 핀셋 카드`).
**묻는 것**: 이 카드가 `.outline` 을 쓰는 사람(주인공)의 고통 하나를 풀고, C라인의 제자리에 들어가고, 흐린눈을 지켰나.

먼저 읽을 것
- 닻: `1.🎯(Project) 프로젝트/🍽️래퍼런스 뜯어보기/비슷한 작업을 이전에 했었지. 그땐 그랬지.md` — 고통 셋, C1~C5 의 갈증, 흐린눈 원칙
- 책 노트: `4.🗄️(Archive) 보관/(Library) 망고네 도서관/(Book) 서적/아이디어에서 완성까지, 캐릭터 줄거리 단계별 가이드/📖 아이디어에서 완성까지, 캐릭터 줄거리 단계별 가이드.md`
- 기준: Scaffold Manager의 답 7장 (지금 있는 컴포넌트 목록)

닻 노트의 고통 셋은 이것입니다. 노트가 바뀌었으면 노트를 따릅니다.
1. Git 안전망이 없다 — 크게 고치면 되돌아갈 곳이 없다
2. 캔버스로 펼칠 수 없다 — 대안을 나란히 놓고 비교할 수 없다
3. AI 재생성에 다듬은 노드가 날아간다

---

## K1. 닻 — 카드마다 고통 하나

- 카드가 위 고통 중 **어느 것**을 없애는지 적혀 있나. 안 적혀 있으면 → **고칠 것**
- 적힌 고통이 **닻 노트에 없는 것**이면 → **막힘**
  예: "볼트 에이전트 협업 체계" 처럼 `.outline` 밖으로 닻을 넓힌 카드. 닻을 넓힐지는 사람이 정합니다. 보고서에 그 질문을 그대로 적습니다.

## K2. 흐린눈 — 레퍼런스 하나에 카드 1~2장

닻 노트의 원칙은 "첫 프로토타입에 필요한 인터랙션 1~2개만" 입니다.

- 1~2장 → 통과
- 3장 이상 → **고칠 것**. 가장 약한 카드부터 몇 장을 빼야 하는지 적습니다 (K1 · K3 에 걸린 카드가 먼저)
- C1~C5 **다섯 칸을 다 채웠으면** → **막힘**. 레일을 채우려고 카드를 만든 신호입니다

## K3. 자리 — 앞 단계에서 받은 것으로 움직이나

C라인은 시간 순서입니다: `C1 포집 → C2 구조화 → C3 Git 안전망 → C4 캔버스 변환 → C5 노드 잠금`.

- 카드가 꽂힌 자리 C(n) 에서 쓰는 입력이 C(n-1) 까지 만들어진 것인가. 뒤 단계의 결과가 있어야 돌아가는 카드면 → **고칠 것** (맞는 자리를 적게)
- 어느 자리에도 들어가지 않는 카드면 → **막힘**

## K4. 주인공 — 확정하는 것은 사람

- 카드의 동작 중 **사람이 승인 · 확정하는 순간**이 있나 (Accept/Reject, 체크포인트 찍기, 잠그기 등)
- AI 나 시스템이 사람 승인 없이 노드를 확정 · 덮어쓰는 구간이 있으면 → **막힘**. 고통 3을 다시 만드는 카드입니다
- 사람이 하는 일이 "지켜보기" 뿐이면 → **고칠 것**

## K5. 부품 수 — 있는 것에 보태나, 새로 만드나

- 카드가 답 7장의 기존 컴포넌트에 **보태는** 것이면 → 통과
- **새 컴포넌트**를 만들면, 기존 것으로 안 되는 까닭이 적혀 있어야 합니다. 없으면 → **고칠 것**
- 보고서 맨 위 카드 판정 아래에 "채택 후보를 다 받으면 컴포넌트가 지금 N개 → M개" 를 적습니다

## K6. 끝났다는 신호

- 사람이 카드의 동작을 마쳤을 때 **무엇을 보고 끝났다고 아는지**(초록 하이라이트가 본문으로 붙음, 잠금 표시 등) 적혀 있나
- 없으면 → **고칠 것**. 연출을 지어 주지 않습니다. 비어 있다는 것만 적습니다

## K7. 맞대 보기

- 질문 틀 7장의 "우리 답과 부딪치는 칸" 을 채웠나. 비었으면 → **고칠 것**
- "우리 답을 고치자" 고 했다면 그 근거가 R 렌즈에서 통과한 사실인가. 확인 안 된 사실로 우리 답을 바꾸자고 했으면 → **막힘**
  (론 프리드먼 렌즈 결과가 없으면 `확인 불가` 로 둡니다)
