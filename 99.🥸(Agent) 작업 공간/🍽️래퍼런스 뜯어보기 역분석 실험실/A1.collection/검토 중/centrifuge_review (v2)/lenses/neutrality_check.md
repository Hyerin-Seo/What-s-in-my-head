# 객관성 확인 — 답에 판단이나 특정 관점이 섞였는가

질문 틀은 **본 것**만 적는 틀입니다. 이 확인은 원본 없이도 할 수 있습니다.
보고서의 "판단이 섞인 답" · "억지로 채웠거나 빈 칸" · "질문 틀에 알릴 것" 절을 채웁니다.

## 1. 평가하는 말

좋고 나쁨을 매기는 말이 답에 있으면 **"판단이 섞인 답"** 에 적습니다.
예: 좋다 · 훌륭한 · 강력한 · 완벽히 · 혁신적 · 킬러 · 최고 · 압도적 · 유일무이한 · 쓰레기 · 망작.
"대신 적을 것" 에는 그 말이 가리키는 **관찰 가능한 사실**이 무엇인지 적습니다.
예: "강력한 검색" → 어떤 조건으로 찾을 수 있는지.

## 2. 우리 관점

레퍼런스가 아니라 **우리 쪽 이야기**가 답에 들어가 있으면 "판단이 섞인 답" 에 적습니다.
예: Scaffold Manager · `.outline` · 우리 · 이식 · 가져올 · 카드 · C1~C5 · 흐린눈.
이 단계에서는 우리에게 쓸모 있는지 묻지 않습니다. 빼도록 적습니다.

## 3. 특정 이론 · 인물의 틀

특정 이론이나 인물의 개념으로 레퍼런스를 해석한 답도 "판단이 섞인 답" 에 적습니다.
예: 80% 전형성 · 20% 변주 · MAYA · 시그니처 무기 · 도파민 · 카타르시스 · A라인 · B라인 · 주인공 · 종족.
이런 해석은 여러 장을 나란히 놓고 비교할 때 합니다. 지금은 그 해석의 바탕이 된 관찰만 남기도록 적습니다.

## 4. 단정한 추측

원본에 없는 **까닭 · 의도 · 효과**를 사실처럼 적은 답을 찾습니다.
예: "~하기 위해 일부러 뺐다", "그래서 사용자가 불안하지 않다", "그래서 성공했다".
원본이 그렇게 밝혔으면 원문 인용으로 바꾸게 하고, 밝히지 않았으면 빼도록 "판단이 섞인 답" 에 적습니다.

## 5. 칸 확인 (검토 대상이 질문 틀 모양일 때만)

- **질문과 다른 것을 답한 칸** → "억지로 채웠거나 빈 칸".
  예: 화면 없는 도구에 화면 영역을 지어내 적음, "되돌릴 수 있는 범위" 에 저장 방식을 적음.
  이 칸은 "질문 틀에 알릴 것" 에도 적습니다. 질문이 이 레퍼런스에 안 맞았다는 뜻일 수 있기 때문입니다.
- **아무것도 안 적은 칸** → "억지로 채웠거나 빈 칸" 에 "빈 칸" 으로 적습니다. 빈 칸 · '모름' · '해당 없음' 은 비교할 때 뜻이 다릅니다.
- 질문 괄호 안의 **보기**(예: "트리 / 그래프 / 목록")가 있는데 보기 밖의 말로 답했으면 그대로 둡니다. 다만 보기 중 하나로 옮길 수 있는데 안 옮겼으면 "억지로 채웠거나 빈 칸" 에 적습니다. 나란히 비교하려면 답 모양이 같아야 합니다.
