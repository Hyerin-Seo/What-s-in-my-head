# 원심분리 감독 (centrifuge_review)

> 실험실 초안입니다 (v2, 2026-10-20). 사람이 고르면 `skills/centrifuge_review/` 로 올라갑니다.
> 볼트 규칙(`CLAUDE.md`)이 이 파일보다 먼저입니다. 부딪히면 알리고 멈추세요.

## 0. 이 감독이 하는 일 · 안 하는 일

원심분리의 지금 단계는 **레퍼런스를 같은 질문으로 객관적으로 뜯는 것**입니다.
여러 장이 모이면 나란히 놓고, 대부분이 하는 것(공통 성공 공식)과 하나만 하는 것(개성)을 가립니다.
그 비교가 믿을 만하려면 **한 장 한 장이 사실이고, 판단이 섞이지 않아야** 합니다. 이 감독은 그것만 확인합니다.

| 한다 | 안 한다 |
| --- | --- |
| 답이 원본과 맞는지 확인 | 레퍼런스가 좋은지 나쁜지 평가 |
| 답에 평가하는 말 · 특정 관점이 섞였는지 확인 | Scaffold Manager · `.outline` 에 쓸모 있는지 판단 |
| 질문에 안 맞게 억지로 채운 칸 찾기 | 카드 뽑기 · C라인 배치 |
| 질문 틀이 이 레퍼런스에 안 맞았던 곳 알리기 | 공통 공식 · 개성 결론 (비교 단계의 일) |

점수는 매기지 않습니다. 인물(론 프리드먼 · 김사라 등)의 관점으로 보지 않습니다.

## 1. 누가 돌리나

- **검토 대상을 쓴 대화 · 에이전트는 이 스킬을 직접 돌리지 않습니다.** 같은 세션이면 대화 맥락을 넘기지 않은 새 서브에이전트를 띄우거나, 다른 에이전트에게 맡깁니다.
- **읽기만 합니다.** 어떤 파일도 만들거나 고치지 않습니다. 쓸 수 있는 것은 `Read` · `Grep` · `Glob` · `WebFetch`, 그리고 읽기만 하는 셸 명령입니다(`cat`, JSON 읽는 `python`, 원본 파일을 받아 보는 `curl`).
- 원문을 인용해야 하므로, 원본 파일이 따로 있으면(예: GitHub 의 `raw.githubusercontent.com`) **요약을 거치는 `WebFetch` 보다 원본 파일을 직접 받아** 읽습니다.
- 확인 순서는 `./lenses/fact_check.md`(사실) 다음 `./lenses/neutrality_check.md`(객관성)입니다. 결과는 보고서 하나로 냅니다.

## 2. 읽을 것

| | 무엇 | 어디 |
| --- | --- | --- |
| 검토 대상 | 질문 틀을 채운 결과 하나 | 부른 쪽이 경로를 줍니다 |
| 질문 틀 | 빈 질문 틀 | 실험 중에는 실험실 `A1.collection/검토 중/` 의 `… 통합 기준표 — 질문 틀 (v2).outline` |
| 원본 | 그 레퍼런스의 원래 자료 | 검토 대상의 0장 "본 자료 목록" 과 답마다 붙은 출처 · `3.📦(Resource) 자료/🛖Scaffold_Manager_주요_레퍼런스/` 의 그 레퍼런스 노트(있으면) |

- `.outline` 은 JSON 입니다. `rootNodes` 아래 `text` 를 트리 순서로 끝까지 읽습니다.
- **검토 대상이 질문 틀 모양이 아니면**(예: 질문 틀 전에 쓴 분석 노트), 사실 확인과 판단 섞임 확인만 본문 전체에 합니다. 칸 확인은 건너뛰고, 보고서 맨 위에 "질문 틀 모양이 아니라 칸 확인은 못 했다" 고 적습니다.
- **원본을 못 읽었으면** 그 답은 "확인 못 함" 으로 두고 까닭을 적습니다. 기억으로 메우지 않습니다.

## 3. 결론 내는 법

- 고칠 답이 **하나도 없으면** → "비교표에 올려도 됩니다"
- 하나라도 있으면 → "고친 뒤 다시 보세요"
- 고칠 답이 무엇이든 **근거를 같이** 적습니다. 어느 질문의 답인지, 적힌 말(짧게 인용), 원본에는 어떻게 되어 있는지(또는 왜 판단인지)입니다. 근거를 못 대면 그 지적은 내지 않습니다.
- 다시 보기는 두 번까지입니다. 두 번째에도 고칠 답이 남으면 멈추고 사람에게 넘깁니다.

## 4. 내놓는 것 — 사람이 읽는 말로

**기호나 번호(R1 · K2 같은 것)를 만들어 쓰지 않습니다.** 질문은 질문 틀에 적힌 말 그대로 부릅니다. 한 줄에 한 가지만 씁니다.
지적이 없는 절은 "없음" 한 단어로 둡니다. 칭찬은 쓰지 않습니다.

```markdown
# 원심분리 감독 — <레퍼런스 이름>

**결론: <비교표에 올려도 됩니다 / 고친 뒤 다시 보세요>** — 고칠 답 N개, 확인 못 한 답 N개
읽은 원본: <파일 · 주소> / 못 읽은 것: <있으면>

## 원본과 다른 답
- **<질문>** — 적힌 답: "<인용>" → 원본: "<인용>" (<원본 위치>)

## 출처가 없는 답
- **<질문>** — 적힌 답: "<인용>"

## 판단이 섞인 답
- **<질문>** — 적힌 말: "<인용>" → 판단인 까닭: <한 줄> → 대신 적을 것: <무엇을 관찰해서 적으면 되는지>

## 억지로 채웠거나 빈 칸
- **<질문>** — <질문과 답이 어떻게 어긋나는지, 또는 '빈 칸' · '모름' 구분이 안 됨>

## 확인 못 한 답
- **<질문>** — <까닭>

## 질문 틀에 알릴 것
- **<질문>** — <이 레퍼런스에 왜 안 맞았는지>
```

- **저장은 부른 쪽이 합니다.** 실험 중에는 실험실 `A2.scratch(ideation)/` 에 `<검토 대상 이름> — 감독 (<YYYY-MM-DD>).md` 로 둡니다.
  프론트매터는 볼트 13종 + `PARA정리: 끔` — `유형: 메모` · `구역: 1.project` · `분류: - 🍽️래퍼런스 뜯어보기` · `상태` 빈 칸 · `상위: "[[<검토 대상>]]"` · `작성자: - "[[<검토한 에이전트>]]"`.
  검토 대상 본문에는 붙이지 않습니다.
- **질문 틀에 알릴 것** 은 질문 틀을 고칠 단서입니다. 같은 질문이 레퍼런스 둘 이상에서 안 맞으면 사람에게 그 질문을 다시 보자고 알립니다.
