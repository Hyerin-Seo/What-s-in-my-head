# 2.1 수동 PARA 분류 스트레스 및 Inbox 던지기 위임

> **속기 원문**
> - *para 넣는거 부터 짜증나. 아니래 다. 아니래 . 어쩌라고. 그럼 skill 써가지고 나는 inbox에만 넣을테니까 말잘통하는 에이전트와 마음에 드는 분류 하ㅔ세요!!!!! - 담당자 정하기 그냥 인박에서 둘게. 매뉴얼.*

---

## 🎯 핵심 의사결정 포인트 (Decision Checkpoint)
> **[결정 질문] 사용자의 PARA 수동 분류 의무를 완전히 폐지하고, `0.📥 인박스`에 생각만 던져두면 에이전트/담당자가 비동기로 1차 분류하도록 작업 룰을 전환할 것인가?**
> - [ ] **[인박스 전면 위임 (권장)]**: 사람은 날것의 텍스트만 인박스에 던지고, 에이전트/정리 담당자가 PARA 및 13종 메타데이터를 1차 채움.
> - [ ] **[수동 분류 유지 + 룰 완화]**: 사람이 직접 분류하되, 폴더 강제나 경고 규칙을 유연하게 풀어 기록 마찰을 완화.

---

## 📌 기존엔 왜 이렇게 관리했을까? (현행 사양의 이유)

* **1. 사용자 주도의 엄격한 분류 정확도 (Accuracy)**
  * AI나 자동화 규칙의 오분류(환각)를 차단하고, 문서를 직접 작성한 본인이 4대 서랍(0~4) 중 어디에 둘지 책임지고 결정하도록 설계함.
* **2. 속성 13종의 완결성 유지 (Data Consistency)**
  * 옵시디언 베이스 보드(`.base`)가 속성을 기반으로 테이블과 칸반을 그리므로, 노트를 만들 때 사람이 13종 속성을 빈틈없이 채우도록 유도함.
* **3. 플러그인의 양방향 자동 동기화 (`plugins/claude`)**
  * 사람이 구역/분류 속성을 고르면 플러그인이 알아서 해당 폴더로 물리적 이동을 처리해 주는 구조를 정착시키고자 했음.

---

## 📌 핵심 분석

* **기록 순간의 판단 마찰(Cognitive Friction) 누적:** 
  * 아이디어를 떠올리거나 메모를 적는 순간마다 "이게 P인가, A인가, R인가?"를 따지느라 정작 기록의 본질(생각의 흐름)이 끊김.
* **경직된 룰에 대한 피로도 ("아니래 다"):** 
  * 정해진 구역 규칙에 조금이라도 어긋나면 경고가 뜨거나 엉뚱한 폴더로 튕겨 나가는 경험이 반복되면서 도구 사용 자체에 거부감이 발생함.

---

## 🌐 참조 자료 및 모범 사례 (다른 곳은 어떻게 하는가?)

* **1. GTD 방법론의 절대 원칙: "수집(Collect)과 처리(Process)의 엄격한 분리"**
  * 데이비드 알렌은 아이디어가 발생한 순간에는 '오직 수집함(Inbox)에 던져 넣는 행위'만 해야 하며, 분류나 우선순위 판단은 나중에 정기 정리 시간에 수행해야 인지 부하가 걸리지 않는다고 규정함.
* **2. 스마트 인박스 툴(Readwise Reader, Omnivore)의 Auto-Triage:**
  * 사용자는 단 하나의 '수집함'으로 원본을 모으고, 백그라운드 AI가 태그·요약·카테고리를 1차 제안해 두면 사용자는 클릭 한 번으로 확정함.
* **3. 에이전트 기반 비동기 분류 파이프라인:**
  * 사람은 날것의 텍스트만 인박스에 던져두고, 비동기 스케줄러(또는 Inbox CLI/스킬)가 돌면서 13종 속성을 채워 적절한 PARA 폴더로 이관을 제안하는 체계 도입.

## ⚖️ 핵심 쟁점 (회의에서 답을 내려야 할 질문)

* **1. 인박스 투척 후 에이전트의 이동 권한 수준**
  * **[A안: 완전 자동 이동]:** 에이전트가 문서를 분석하자마자 적절한 PARA 폴더로 즉시 이동시킴 (초간편 / 오분류 시 수동 복구 필요).
  * **[B안: 1차 제안 후 사람 승인 (권장)]:** 인박스 안에서 속성과 추천 폴더만 태깅해두고, 최종 '보내기' 승인은 사람이 확인 후 클릭.

* **2. 오분류 발생 시의 대응 원칙**
  * 사람이 화내거나 스트레스받지 않고, **"에이전트 스킬의 룰 규칙을 수정"**하여 점진적으로 정확도를 높여가는 피드백 루프에 합의할 것인가?
