# 2.3 에이전트 협업형 PARA 체계(PARAA / PARAI) 네이밍 구상

> **속기 원문**
> - *para 말고 새로운 에이전트와의 협업 이름 네이밍 해보도록. paraa 퍄랴~~ parai 파라이~~*

---

## 📌 기존엔 왜 이렇게 관리했을까? (현행 사양의 이유)

* **1. 전통적인 PARA 프레임워크의 순수성 준수**
  * 0.inbox ~ 4.archive는 티아고 포르테가 정립하여 전 세계적으로 검증된 4단계 지식 관리 구조이므로, 표준을 그대로 유지하여 안정성을 꾀함.
* **2. 인간 단독 사용자 전제**
  * 기존 볼트는 인간 사용자 중심의 정제된 노트 서랍으로 설계되었기 때문에, AI 에이전트의 실시간 스크래치나 중간 작업 기억을 수용할 별도 구역이 정의되어 있지 않았음.

---

## 📌 핵심 분석

* **인간 전용 서랍과 에이전트 활동의 충돌:** 
  * PARA(0~4)는 정제된 결과물이 들어가는 곳인데, 에이전트가 생각하는 과정(Scratch, Working Memory, Raw Data)이 기존 서랍에 뒤섞이며 볼트 전체의 질서가 흐트러짐.
* **에이전트 공간의 공식 지위 부여 필요성:** 
  * 에이전트가 볼트의 당당한 협업 주체로 참여함에 따라, `99.🥸 작업 공간` 같은 샌드박스를 임시 폴더가 아닌 볼트의 정식 체계(5번째 축)로 브랜딩하고 규약화할 필요성 대두.

---

## 🌐 참조 자료 및 모범 사례 (다른 곳은 어떻게 하는가?)

* **1. Agent Runtime의 Sandbox / Staging 아키텍처:**
  * 모든 엔터프라이즈 AI 시스템은 본 프로덕션 DB와 격리된 전용 스크래치패드/스테이징 구역을 공식 아키텍처로 둠.
* **2. PARAA 모델 (Projects - Areas - Resources - Archives - Agents):**
  * 기존 PARA 4대 서랍 뒤에 5번째 서랍으로 **'Agents (에이전트 샌드박스)'**를 추가하여 인간 구역과 에이전트 구역을 완벽히 공존시키는 확장 모델.
* **3. PARAI 모델 (PARA + AI Pipeline):**
  * PARA 체계의 각 서랍에 AI 에이전트의 자동화 파이프라인(인박스 요약, 프로젝트 할일 분해, 아카이브 정리 등)을 결합한 통합 개념.

---

## ⚖️ 핵심 쟁점 (회의에서 답을 내려야 할 질문)

* **1. 우리 팀 고유의 에이전트 협업 체계 명칭 선정**
  * **[PARAA (파랴)]:** PARA 4대 구역 + `Agent Workspace` (5개 구역으로 공간 확장)
  * **[PARAI (파라이)]:** PARA 4대 구역 + `AI Intelligence/Pipeline` (기능적 융합)

* **2. 99번 작업 공간의 볼트 공식 규약 승격 여부**
  * `99.🥸 작업 공간`을 볼트 최상단의 임시 공간이 아니라, `docs/para.md`와 `CLAUDE.md`에 **공식 구역(에이전트 전용 완충 지대)**으로 정식 명문화할 것인가?
