# EXP01 줌 안 버전 탭 인터랙션 프로토타입

## 🧐 1. 왜 이런 UI·사양이 필요하다고 느꼈는가? (현행 작업의 고통과 문제의식)

* **세 번 갈아엎기가 일상인데 이를 받쳐주는 UI가 전무함:**
  * 아웃라이너로 문서 구조를 잡을 때 한 번에 완성되는 경우는 거의 없으며, *"세 번은 디폴트로 다 갈아엎는"* 작업이 필수적입니다.
  * 그러나 현재 화면에는 이전 구조를 임시 보관하거나 대조할 장치가 없어, 작업자가 마음 놓고 갈아엎지 못하고 불안해합니다.
* **수동 듀얼 줌(Dual Zoom) 분할 뷰의 극심한 피로도:**
  * 이전 버전(8·9번 노드)과 새 버전(2·3번 노드)을 비교하기 위해 현재는 화면을 반으로 쪼개 각각 줌 인해 두고 사람 눈으로 대조하고 있습니다.
  * 이는 화면 작업 영역을 반토막 낼 뿐 아니라, *"바뀐 포인트를 찾기 어렵고 전혀 편해졌다는 느낌을 받을 수가 없는"* 극심한 시각적·인지적 피로도를 초래합니다.
* **무거운 Git 대신 작업 스코프에 맞는 초경량 장치 갈망:**
  * Git 형태의 전체 트리 되돌리기는 개발 난이도가 높고 사양이 꼬여 걷어냈습니다.
  * 따라서 화면 전체가 아니라 **"작업자가 지금 집중하고 있는 바로 그 노드 안에서 버전을 손쉽게 갈아 끼우며 작업할 가벼운 인터랙션"**이 절실히 필요하다고 느꼈습니다.

## 🔬 2. 실험 가설 (Hypothesis)
* **가설:** "화면을 좌우로 분할해 두 개의 줌 노드를 나란히 띄우는 대신, **줌 인(Zoom In)된 노드 헤더 밑에 버전 탭(`[v1] [v2] [+]`)을 제공**하면 시선 분산 없이 한 화면에서 이전 판과 현재 판을 가장 빠르고 피로도 적게 대조·교체할 수 있을 것이다."

## 🛠️ 4. 프로토타입 구현 명세 (UI/UX Prototype Spec)
1. **줌 인 진입 시 탭 바 노출:**
   - 특정 노드 클릭 후 줌 인 화면 진입 시, 상단 헤더 바로 아래에 초경량 탭 바 (`[v1] [v2] [+]`) 표시.
2. **버전 분기 및 스테이징:**
   - `[+]` 버튼 클릭 시 현재 탭의 하위 자식 노드 트리를 복제하여 새 버전 탭 생성.
   - 새 탭에서 자식 노드를 과감하게 수정하거나 갈아엎어도 이전 탭의 내용은 그대로 보존.
3. **빠른 키보드 전환 단축키:**
   - `Alt + 1`, `Alt + 2` 또는 `Ctrl + [` / `]` 단축키로 탭 간 즉시 스위칭.
   - 복잡한 Git diff 엔진 없이, 탭 전환만으로 전후 상태의 시각적 변화를 깜빡임 없이 체감.
