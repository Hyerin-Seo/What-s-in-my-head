# 에디터 목업 실험 세부 ToDo 매니저 (editor_mockup_todo_manager)

본 스킬은 `What-s-in-my-head` 볼트의 **GTD / PARA 프로젝트 관리 방침**과 **13대 표준 프론트매터 규정**을 기반으로 작동합니다.  
특정 문서 경로를 하드코딩하지 않고, **사용자가 프롬프트에서 전달한 기획/실험 노트(`@[경로/문서.md]`) 또는 대상 디렉터리(`@[경로]`)를 외부 입력으로 동적으로 수신**하여 실행 단위의 세부 ToDo를 도출하고 표준 규격의 할 일 노트로 등록합니다.

---

## 1. 발동 조건 및 동적 입력 수신 (Dynamic Inputs)

### 1.1. 발동 트리거
* 기획/실험 노트를 멘션하며 **"세부 todo로 분해/생성해줘"**라고 요청할 때
* 특정 마크다운 문서를 지정하며 **"todo-list를 뽑아 등록해줘"**라고 요청할 때
* 생성된 세부 ToDo들을 해당 프로젝트 폴더 하위에 **정식 할 일 노트 파일로 생성**하라고 지시할 때

### 1.2. 외부 입력 수신 및 경로 해석 규칙 (절대 원칙)
1. **분석 원본 문서 (`Source Document`)**:
   * 사용자가 프롬프트에서 전달한 `@경로/파일명.md`를 최우선 분석 대상으로 삼습니다.
   * 별도 지정이 없을 경우 최근 대화 맥락에서 활성화된 기획 노트를 파악하며, 불명확할 경우 사용자에게 대상 입력을 요청합니다.
2. **생성 대상 디렉터리 (`Target Directory`)**:
   * 기본적으로 **전달받은 원본 문서가 위치한 상위 디렉터리**를 할 일 노트의 생성 위치로 자동 지정합니다.
   * 사용자가 별도의 생성 대상 디렉터리(`@[디렉터리 경로]`)를 함께 전달한 경우 해당 경로를 최우선 적용합니다.
3. **메타데이터 동적 바인딩**:
   * `상위:` 속성은 전달받은 원본 마크다운 파일의 이름(확장자 제외)을 위키링크로 자동 지정합니다 (`상위: "[[(파일명)]]"`).
   * `분류:` 속성은 대상 디렉터리의 폴더명(또는 프로젝트명)으로 자동 바인딩합니다.
     **이모지까지 글자 그대로** 씁니다 (예: `✏️문서 어시스턴트 에디터 목업`). 이모지를 떼고 적은 분류 때문에
     `📤 PARA로 보내기` 가 프로젝트 폴더를 못 찾던 적이 있습니다 (2026-09-17).

## 2. 볼트 표준 프론트매터 관리 방침 (절대 규칙)

볼트의 `!(Template) 새 할 일.md` 및 `CLAUDE.md`에 명시된 원칙을 100% 준수합니다.

### 2.1. 필수 13대 속성 규격 (동적 템플릿)
```yaml
---
유형: 할일
구역: 1.project
분류:
  - <대상 디렉터리 폴더명>
주제:
  - <관련 키워드 1>
  - <관련 키워드 2>
상태: to do
요약: <할 일의 목적을 드러내는 명확한 한 줄 요약>
작성일: <YYYY-MM-DD>
마감: <YYYY-MM-DD>
커버: <본문 내 대표 이미지가 있을 경우 위키링크, 없으면 비움>
상위: "[[<전달받은 원본 문서명>]]"
링크: 
담당: 
작성자:
  - "[[<작업한 에이전트 이름>]]"
# ── 이외 속성 (유형별 고유값) ──
일정: 
---
```

### 2.2. 금지 및 주의사항
1. **폐기된 속성 생성 절대 금지**:
   * `중요도`, `수정일`, `제목`, `notion_db`, `notion_url`, `이동버튼` 등은 절대 프론트매터에 넣지 않습니다.
2. **파일명이 곧 제목**:
   * 프론트매터에 `제목:`을 넣지 않고, 마크다운 파일명 자체를 직관적인 할 일 제목으로 정의합니다.
   * *예시: `[할일] 페이지 뷰 수평 스크롤 및 그리드 뷰 모드 구현.md`*
3. **상위 노트 위키링크 동적 연결**:
   * 세부 ToDo의 부모 문맥이 유실되지 않도록 전달받은 원본 문서를 `상위: "[[...]]"`로 필수로 지정합니다.
4. **작성자 명시**:
   * AI가 기획/분해 작업을 수행하여 작성했으므로 `작성자` 에 **작업한 에이전트 자기 이름**을 넣습니다.
   * 모양은 반드시 목록 + 따옴표 친 위키링크입니다 — `작성자:` 다음 줄에 `  - "[[Gemini]]"` (Claude 면 `"[[Claude]]"`).
     `작성자: Gemini` 처럼 한 줄 글자로 쓰면 칸반의 작성자 칩이 안 뜨고, 따옴표를 빼면(`- [[Gemini]]`)
     YAML 이 중첩 목록으로 읽어 값이 깨집니다 (`docs/properties.md` 의 YAML 공통 규칙).

## 3. 본문 구조 원칙 (GTD 기반)

각 세부 ToDo 노트의 본문은 GTD 원칙에 따라 명확한 실행 지침을 포함해야 합니다:

```markdown
## 뭘 해야 하나
<이 작업이 왜 필요하며, 구현해야 할 핵심 기능 및 화면 동작을 명확히 서술>

## 다음 행동
- [ ] <즉시 착수 가능한 구체적 액션 1>
- [ ] <구체적 액션 2>
- [ ] <구체적 액션 3>
```

## 5. 실행 워크플로우

1. **외부 입력 파싱 및 대상 식별**:
   * 사용자가 전달한 `@문서경로.md` 및 생성 대상 디렉터리를 파악하고, 문서 내 미완료 항목 및 세부 요구사항을 식별합니다.
2. **세부 ToDo 분해**:
   * 모호한 기획 문구를 개발/실험이 가능한 구체적인 단위 과업으로 나눕니다.
3. **프론트매터 및 메타데이터 동적 구성**:
   * 볼트 관리 방침에 따라 대상 폴더(`분류`), 원본 파일(`상위`), 작성일 등을 자동으로 채웁니다.
4. **파일 생성 및 보드 연동**:
   * 식별된 대상 디렉터리 하위에 마크다운 파일(`.md`)을 생성합니다.
   * 생성된 노트는 해당 디렉터리의 `.base` 칸반 보드 `to do` 열에 자동으로 연동됩니다.
