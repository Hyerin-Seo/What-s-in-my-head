# 인수인계 사양 기록기 (handover_spec_recorder)

> 2026-11-13 민규 서 요청으로 만들었습니다. 첫 실행: `2026.11.13 UI 인수인계` (발화 130 · 크로스체크 통과).
> 볼트 규칙(`../../CLAUDE.md`) · 회의 한 바퀴(`../meeting-notes/SKILL.md`) · 아웃라인 규격(`../outline_file_manager/SKILL.md`)이 이 파일보다 먼저입니다. 부딪히면 알리고 멈추세요.

## 왜 따로 있나

회의 한 바퀴의 안건 카드 · 결정 카드는 **결정하는 회의**를 위한 틀입니다. 인수인계 회의는 다릅니다.

| | 결정 회의 (`meeting-notes`) | 인수인계 회의 (이 스킬) |
| --- | --- | --- |
| 남길 것 | 무엇을 정할까 · 정했나 | **지금 무엇이 어떤 상태인가** — 바뀐 것 · 동작함 · 목업 · 손 안 댐 · 버그 |
| 정리 축 | 안건 | **화면 구역** (Part → View → Widget) |
| 입력 | 손 속기 | **STT 녹취** — 발화자 번호 · 시각 · 오인식 · 지시어("여기 · 이거") 투성이 |
| 위험 | 이미 정한 걸 다시 묻기 | **빠뜨리기** — 녹취는 다시 듣지 않으므로 사양서에서 빠지면 사라집니다 |

그래서 이 스킬은 **원문을 항목 밑에 그대로 달고, 스크립트로 녹취 전체와 대조**합니다. 사람이 "이거 어디서 나온 말이지?" 할 때 하위 불릿이 답입니다.

## 0. 이 스킬을 쓰는지 가르기

- 녹취의 대부분이 "여기 바뀌었고 · 이건 원래 있던 거고 · 이건 목업이야" 처럼 **화면을 짚으며 넘기는 말** → 이 스킬
- "A 로 할까 B 로 할까 · 언제까지 하자" 가 대부분 → `meeting-notes` 의 안건 · 결정 카드
- 반반이면 **둘 다** — 이 스킬로 사양서를 만들고, `# 3. 열린 질문` 중 무거운 것만 안건 카드로 (meeting-notes 3절)
- 헷갈리면 사람에게 한 번 묻습니다

## 1. 세계

| 무엇 | 어디 |
| --- | --- |
| 녹취 원본 | 사람이 주는 `.txt` (예: `Downloads/망고독_회의록_원본_모음/<YYMMDD_HHMM-제목>_original.txt`). 클로바노트 꼴 `발화자 N  (mm:ss)` · 인코딩은 UTF-16 BE 가 흔함 |
| 회의록 노트 | `4.🗄️(Archive) 보관/_회의록/<YYYY.MM.DD 제목>.md` — 회의록 양식 그대로. 없으면 양식(`!(Template) 회의록.md`)의 프론트매터 + **본문 맨 위 `%%` 블록을 뺀** 본문으로 만들고, `## 속기` 에 녹취를 그대로 붙입니다 (2026.10.26 15분 공유회와 같은 모양) |
| 작업 공간 | `99.🥸(Agent) 작업 공간/<회의록 이름>/` — `!(Template) 회의 작업 공간/` 통째 복사 (meeting-notes 1절 · 3절 2). 회의판 이름 · 제목 노드도 바꿈 |
| 원문 사본 · 발화 목록 | `<작업 공간>/A3.working memory/원문/` — 원본 사본 · `utterances.json` · `발화 목록.md` |
| 산출물 | `<작업 공간>/A1.collection/검토 중/(인수인계) <무엇> — <YY.MM.DD>.outline` + 짝꿍 `.md` |
| 크로스체크 보고 | `<작업 공간>/A3.working memory/크로스체크 보고.md` |
| 작업 기억 | `<작업 공간>/A3.working memory/<회의록 이름> — 작업 기억.md` |
| 스크립트 | `./scripts/normalize.py` · `./scripts/build_outline.py` · `./scripts/crosscheck.py` — 파이썬 표준 라이브러리만. `python -I` 로 실행 |
| 양식 | `./templates/!(Template) 인수인계 초안.md` (초안 문법) · `./templates/!(Template) 인수인계 사양.outline` (사람이 아웃라이너로 여는 빈 틀) |
| UI 위계 | `1.🎯(Project) 프로젝트/👩‍🎨사용성 검증용 디자인 목업시스템 구축/pro-tool의 구조 위계화.outline` — Level 1 Workbench · 2 Part · 3 View · 4 Widget |

**프로젝트로 올리는 건 사람입니다** (meeting-notes 2절). 에이전트는 `검토 중` 까지만 냅니다.

## 2. 순서

1. **회의록 · 작업 공간** — 1절대로. 이미 있으면 그대로 씁니다. 회의록 `## 🥸 작업 공간` 칸에 회의판 · 작업 기억 · 산출물 링크 세 줄. `✅ 정한 것` · `자료` · `⏭` 칸은 사람 칸이라 비워 둡니다.
2. **정규화** — `python -I scripts/normalize.py <원본.txt> "<작업 공간>/A3.working memory/원문"`.
   발화마다 `U001`… 번호가 붙습니다. **이 번호가 모든 대조의 기준**입니다. `발화 목록.md` 에 속성 13종(유형 메모 · 구역 4.archive · 주제 작업 기억 · 상위 회의록 · `PARA정리: 끔`)을 얹습니다.
3. **화면 지도** — `발화 목록.md` 를 처음부터 끝까지 읽고 Part · View 약어표를 정합니다 (3.2). 녹취가 화면을 도는 순서대로 Part 가 나옵니다.
4. **초안** — `templates/!(Template) 인수인계 초안.md` 문법으로 스크래치에 씁니다 (볼트 밖, 에이전트 스크래치 폴더). **발화를 U001 부터 순서대로 한 개씩** 어느 항목에 갈지, 버릴지 정합니다. 건너뛰지 않습니다.
5. **빌드** — `python -I scripts/build_outline.py <초안.md> "<검토 중>/<이름>.outline" "<제목>"`. 루트 `createdAt` · `updatedAt` 은 스크립트가 넣습니다.
6. **크로스체크** — `python -I scripts/crosscheck.py <utterances.json> <이름>.outline "<작업 기억 폴더>/크로스체크 보고.md"` (5절). **통과할 때까지 4 → 5 → 6 을 되풀이**합니다. 통과 전에는 사람에게 "다 했다" 고 하지 않습니다.
7. **결과 노드** — `# 6. 커버리지 점검` 의 `결과:` 줄을 숫자로 채웁니다 (JSON 의 그 노드 `text` 만 바꿈).
8. **짝꿍 `.md`** — 속성 13종 + `PARA정리: 끔` · `상태: 검토 중` · `분류: 회의록` · `상위` 회의록 · `작성자` 자기 이름 · 본문은 outline_file_manager 4절 모양.
9. **작업 기억** — TL;DR 세 줄(녹취에 있는 것만) · 진행 표 · 사람이 확인할 것(화자 · 위치 불명 · ❓ 항목).
10. **보고** (7절).

## 3. 아웃라인 모양

### 3.1 큰 칸 (h1 — 이름 앞 번호가 약속, 크로스체크가 봅니다)

| h1 | 무엇 |
| --- | --- |
| `0. 메타` | 회의 성격 · 넘김 → 받음 · 원본 · 한 줄 형식 · 상태 범례 · 출처 범례 · UI ID 약어표 |
| `1. UI 사양` | h2 = Part · h3 = View · 불릿 = 위젯 하나 (UI ID 항목) |
| `2. 정한 것` | `D1` … — 말로 못 박은 것. `→ <UI ID>` 로 사양과 잇기 |
| `3. 열린 질문` | `Q1` … — 누가 어느 쪽인지까지. 하위에 `[ ] 정하기` todo |
| `4. 할 일` | `T1` … — 누가 누구에게. 하위에 `[ ] 할 일` todo |
| `5. 용어 해석` | STT 오인식 → 추정 원어 (확실하지 않으면 `?` · 모르면 `❓`) |
| `6. 커버리지 점검` | `결과:` 한 줄 + h2 `버린 발화` 목록 |

### 3.2 UI ID

- **`<Part>-<View>-<번호>`** — `LS-SCM-03`. View 가 없는 Part 는 `<Part>-<번호>` — `HD-01`. 번호는 두 자리, View 안에서 녹취에 나온 순서대로.
- Part = Level 2 화면 대구역 · View = Level 3 개별 창 · 항목 = Level 4 위젯 (pro-tool의 구조 위계화).
- 약어는 대문자 2~4자(Part) · 2~5자(View). 첫 실행에서 쓴 것 — 같은 화면이면 그대로 씁니다:

  | Part | View |
  | --- | --- |
  | `HD` 헤더 | — |
  | `LS` 좌측 사이드바 | `TAB` 탭바 · `EXP` 파일 트리 · `SCM` Git |
  | `TB` 툴바 | `PAGE` 페이지 탭 · `MODE` 편집 · 읽기 · `SEC` 섹션 → 템플릿 · `BLK` 블록박스 |
  | `HUB` 템플릿 허브 | — |
  | `ED` 에디터 · `RS` 우측 사이드바 · `PG` 새 페이지(제안) | — |

- **화면 위치를 녹취로 알 수 없으면 짐작해 끼우지 않습니다** — Part 를 따로 두고 이름에 `(화면 위치 ❓)`.
- 한 ID 는 한 번만 정의합니다 (크로스체크 F). 다른 칸에서는 `→ LS-SCM-05` 로 가리킵니다.
- 프로젝트에 이미 쓰는 ID 규칙이 생기면 그걸 따르고 이 표를 고칩니다.

### 3.3 항목 한 줄 — 사람이 고른 모양 (2026-11-13)

```
TB-SEC-03 생성된 섹션 목록 · 🟡 · ⏱08:26
  > U073 ⏱08:26 발화자 2: "그래서 여튼 생성된 섹션 엑셀이라고 해 가지고 이렇게 있고"
```

- 본문: `<ID> <무엇> · <상태> · ⏱<처음 나온 시각>`. 무엇은 사람 말로 짧게 — 원문을 다듬은 것이지 원문이 아닙니다.
- 상태: ✅ 동작함 · 🟡 목업 · 자리만 · ⚪ 손 안 댐 · 🐞 버그 의심 · ❓ 정체 · 위치 불명 · 🗑 버려도 됨 · 🎨 디자인만 바꾸면 됨 · 💬 의견. 둘까지 겹쳐 씀 (`✅🐞`). 출처는 상태 뒤에 `AG` · `FG`.
- `note` (초안의 `| `) 에는 STT 오인식 · 출처 · 다른 항목과의 관계 · 사람이 남긴 단서.
- 정한 것 · 질문 · 할 일도 같은 모양: `D1 <한 문장> → <UI ID> · ⏱10:35`.

### 3.4 원문 불릿 (quote) — 틀리면 크로스체크가 막습니다

```
> U090 ⏱10:35 발화자 2: "여튼 그러면 여기 툴바에 블록박스 내려가는 걸로 확정한다."
```

- 따옴표 안은 **그 발화의 부분 문자열 그대로** — 띄어쓰기 차이만 봐 줍니다. 오인식도 고치지 않습니다 (해석은 `note` · `5. 용어 해석` 에).
- 한 발화를 여러 항목이 나눠 인용해도 됩니다. 한 발화에 항목이 셋이면 세 조각으로 나눕니다.
- 시각은 그 발화의 시각 그대로. 화자는 `발화자 N` 그대로 — 이름은 사람이 확인해 준 뒤에만 바꿉니다 (바꿀 땐 `utterances.json` 은 그대로 두고 아웃라인의 화자 칸만).
- 맞장구 하나로 흐름이 이어지는 말(받는 사람의 확인 · 반론)도 인용합니다 — 누가 동의했는지가 사양입니다.

### 3.5 버린 발화

```
- ## 버린 발화
  - U007 ⏱01:08 맞장구 — "어허"
```

- 사유는 `맞장구` · `진행` · `잡담` · `중복` · `반복` · `기타` 중 하나 + `—` 뒤 한마디.
- **내용이 있는 말은 버리지 않습니다.** 확신이 없으면 인용하고 `❓` 를 답니다. 버림은 빠뜨림을 숨기는 자리가 아닙니다.

## 4. 녹취에서 자주 빠지는 것 — 4 단계에서 일부러 찾습니다

첫 실행(2026.11.13)에서 손으로 먼저 정리했을 때 **7개가 빠졌습니다**. 모양이 정해져 있습니다:

- 지나가듯 한 상태 말 — "탭바가 추가됐는데 눌러도…" · "변경된 거 몇 개인지" (문장이 끝나지 않음)
- 받는 사람의 짧은 의견 — "탭이 너무 애매하고" (다음 주제 앞에 붙어 있음)
- 이어 놓은 링크 · 동선 — "허브 열기 하면 일로 가게 만들어 놨네"
- "아까 ~해도 된다고 해서" — 지난 대화에서 정한 걸 되짚는 말 (인라인 대화창 아이콘)
- 이유가 붙은 유지 결정 — "이게 있어야 추가하라고 할 수 있으니까 그대로"
- 끝에 붙은 부탁 — "확정된 상황 나중에 좀 알려줘" → 할 일

## 5. 크로스체크 — `scripts/crosscheck.py`

| 점검 | 무엇을 | 통과 조건 |
| --- | --- | --- |
| A 역방향 | 모든 발화가 원문 불릿에 인용됐거나 `버린 발화` 에 있나 | **빠짐 0** |
| B 글자 커버리지 | 인용된 발화에 인용 안 된 덩어리(군말 빼고 12자 초과)가 남았나 | 남으면 하나씩 보고 항목을 더하거나 인용을 늘립니다 (권고 — 통과를 막지는 않음) |
| C 순방향 | 인용이 그 발화에 글자 그대로 있나 · 시각이 맞나 | **오류 0** (지어냄 · 고쳐 씀 금지) |
| D 근거 | 1~4 칸의 ID 항목마다 원문 불릿이 있나 | **0** |
| E 신호어 | 결정 · 할 일 · 질문 · 상태 말이 든 발화가 인용됐나 | 권고 |
| F ID | 같은 ID 두 번 · 모양 | **0** |

- 종료 코드 0 = 통과. 통과 못 하면 보고서의 목록을 메우고 다시 빌드 · 점검합니다.
- **스크립트가 못 보는 것**: 인용을 *엉뚱한 항목*에 단 것 · 무엇 한 줄을 원문보다 부풀린 것 · 상태를 잘못 고른 것. 그래서 통과 뒤에 **항목마다 "무엇 · 상태가 아래 원문으로 뒷받침되나" 를 한 번 더 읽습니다.**
- **독립 재검**(권장) — 사람이 허락하면 다른 에이전트에게 `발화 목록.md` 만 주고 항목을 따로 뽑게 해 대조합니다. 안 했으면 작업 기억 진행 표에 "안 함" 이라고 적습니다.
- 스크립트를 고치면 **일부러 망가뜨린 사본**(인용 삭제 · 고쳐 씀 · 시각 틀림 · 반만 인용 · 원문 없는 항목)으로 다섯 개 다 잡는지 확인합니다 — 2026-11-13 첫 실행 때 그렇게 확인했습니다.

## 6. 하지 않는 것

- 화자를 말투로 짐작해 이름을 넣지 않습니다. `발화자 N` 그대로 두고 한 번 묻습니다.
- 녹취에 없는 사양을 화면 짐작으로 채우지 않습니다. "여기 · 이거" 가 무엇인지 모르면 `❓`.
- 오인식을 원문 불릿에서 고치지 않습니다.
- 회의록의 사람 칸(`✅ 정한 것` · `자료` · `⏭`)을 채우지 않습니다. 속기에는 녹취를 **그대로** 붙이기만 합니다.
- 산출물을 프로젝트 · 인박스로 옮기지 않습니다 — 사람이 `A5.outputs` 로 고른 뒤 사람이 올립니다.
- 아웃라인을 `processFrontMatter` 류로 고치지 않습니다 — JSON 이고, 사람이 아웃라이너에서 고친 뒤면 **그 파일을 그대로** 크로스체크합니다 (다시 빌드하면 사람 손질이 날아갑니다).
