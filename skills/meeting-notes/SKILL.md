### 작업 공간 (회의 하나에 하나)

```
99.🥸(Agent) 작업 공간/<회의록 파일 이름>/
  A1.collection/검토 중/   ← 🤖 안건 카드 후보
               paused/     ← 🧑 보류 (사람이 옮김)
               history/    ← 🤖 튜닝 전 옛 카드 · 끝내 안 고른 카드
  A2.scratch(ideation)/    ← 🤖 <회의록 이름> — 지난 회의 점검
  A3.working memory/       ← 🤖 <회의록 이름> — 작업 기억 (TL;DR · 카드 목록 · 분류표 · 튜닝 기록)
  A4.meta/pre_meeting_agenda_preparer/  ← 🤖 이 회의용 스킬 사본. 튜닝은 여기서만
  A4.meta/스킬 수정 제안.md              ← 🤖 정본에 올릴 제안 (사람 승인 전)
  A5.outputs/              ← 🧑 사람이 고른 카드. 에이전트는 여기에 만들지도 옮기지도 않음
```

**작업 공간은 두 곳에 삽니다** (2026-09-28 민규 서):

| 언제 | 어디 |
| --- | --- |
| 한 바퀴 도는 중 | `99.🥸(Agent) 작업 공간/<회의록 파일 이름>/` |
| 끝나고 보관 | `4.🗄️(Archive) 보관/에이전트 작업 공간/<회의록 파일 이름>/` — 회의록 이름과 **1:1**. 사람이 "보관해줘" 할 때 폴더째 옮깁니다 |

- 둘 다 옵시디언 **제외된 파일**이고 플러그인 제외 목록에도 있습니다 (`.obsidian/app.json` · `plugins/claude/data.json`). 에이전트 카드의 `분류: 회의록` · `유형: 할일` 이 보드에 새지 않게 하려는 것입니다.
- **회의록 노트는 작업 공간을 따라가지 않습니다** — `4.🗄️(Archive) 보관/회의록/<YYYY.MM>/` 로 갑니다. 제외 폴더에 들어가면 `📝 회의록` 보드와 점검에서 사라집니다.
- 에이전트가 지난 회의의 작업 공간을 찾을 때는 **두 곳 다** 봅니다. "볼트 전체에서 찾는다" 는 말은 늘 **두 곳을 뺀** 볼트입니다.

### 회의록 칸 (제목 이름이 곧 약속)

| 칸 | 누가 쓰나 | 에이전트는 |
| --- | --- | --- |
| `참석:` `안건:` | 사람 | 읽기만 |
| `## ⏮ 지난 회의 점검` | 에이전트 한 줄 + 베이스 표 | 칸이 `- ` 뿐이면 `![[<회의록 이름> — 지난 회의 점검]]` 으로 바꿈. 베이스는 안 건드림 |

| `## 이 회의에서 나온 할 일` | 베이스가 저절로 | 안 건드림 |

**옛 모양의 회의록**(`## 🤖 AI 정리` 체크리스트 — `2026.09.22 주간 회의록`)은 이렇게 읽습니다:
AI 정리의 `→ [[…|만듦]]` 줄 = 인박스로 올린 할 일, 체크 안 된 줄 = 안 고른 후보, `⏮ 지난 회의에서 넘어온 것` = `⏮ 지난 회의 점검`.
**옛 회의록의 모양은 고치지 않습니다** — 고쳐 달라고 할 때만.

### 2.1 P. 회의판 — "판 정리해줘" (2026-09-28)

사람이 순서를 외우지 않게, **포스트잇을 어느 구역에 놓았는지 · 무엇을 적었는지가 곧 지시**입니다. 회의 하나에 판 하나.
Miro · FigJam 처럼 포스트잇을 붙이며 토론합니다. 실시간 공동 편집은 안 되므로 회의 중엔 한 사람이 화면을 공유하며 판을 움직입니다.
모양은 플러그인 `.obsidian/plugins/meeting-board` 가 입힙니다 (이름이 `회의판.canvas` 로 끝나는 캔버스만). 꺼져 있어도 규칙은 같고 모양만 평범한 캔버스입니다.

| 무엇 | 어디 |
| --- | --- |
| 판 | `<작업 공간>/<회의록 이름> 🗺️ 회의판.canvas` (작업 공간 = 99 또는 보관, 1절). **이름 끝 `회의판.canvas` 를 바꾸지 않습니다** — 플러그인이 이걸로 알아봅니다 |
| 판 양식 | `99.🥸(Agent) 작업 공간/!(Template) 회의 작업 공간/🗺️ 회의판.canvas` — 복사하면 이름 앞에 회의록 이름을, 제목 노드(`id: title`)의 `<회의록 이름>` 을 실제 이름으로 |
| 회의록의 입구 | `## 🥸 작업 공간` 칸 첫 줄 `- 🗺️ [[<회의록 이름> 🗺️ 회의판.canvas\|회의판 열기]]` (확장자 꼭) |

**색 = 누가 · 무엇** (캔버스 색 번호. 플러그인이 파스텔로 칠함)

| 색 | 번호 | 뜻 |
| --- | --- | --- |
| 보라 | `"6"` | Rin 이 붙임 |
| 파랑 | `"5"` | 민규 서가 붙임 |
| 노랑 | `"3"` | 🤖 에이전트가 붙임 |
| 초록 | `"4"` | 끝남 · 반영됨 |
| 주황 | `"2"` | 진행 중 · 밀림 |
| 분홍 | `"1"` | ❓ 확인 필요 |
| 없음 | — | 누구든 (크림색 포스트잇) |

**구역은 그룹 `id` 로 찾습니다** (라벨은 사람이 바꿀 수 있음). 노드가 어느 구역인지 = **노드 가운데 점**이 든 그룹.
구역 밖 노드 · `id` 가 `hint-` 로 시작하는 노드 · `title` 은 읽지 않습니다.

| 구역 `id` | 사람이 하는 것 | "판 정리해줘" 때 |
| --- | --- | --- |
| `zone-prev` ⏮ 지난번에 하기로 한 것 | 포스트잇 글 앞에 `✅`(또는 `끝`) · `❌`(또는 `버림`). 그냥 두면 계속 | 비었으면 5절 점검을 돌려 채움 — 한 장에 한 줄: 무엇 · 판정 · 담당 · 🔁 · `[[할일\|열기]]`. 색: ✅ 됨 초록 · 🔄 · ⏳ 주황 · ❓ 분홍 · 🚨 는 글 앞에. 표시 반영: 할일 `✅` → `상태: 완료`, `❌` → `상태: 히스토리` (사람 지시). ❓ `✅` · `❌` → 점검표 그 줄 `[x]`. 에이전트가 ⏮ 에 놓는 포스트잇은 `id` 를 `prev-` 로 시작 (데모 판은 `n-prev-`). **⏮ 포스트잇을 다른 구역으로 끌었으면**: ✅ 정했다 = `✅` 끝과 같음 (회의록 정한 것에 안 적음) · ⏭ 다음에 · 📤 할 일 = 계속 (이번 회의에서 다룸 · 새 할일 안 만듦) |
| `zone-talk` 💬 오늘 나온 이야기 | 말하면서 포스트잇 (자기 색). 🤖 노란 포스트잇에 `♥` · `👍` 투표, 버릴 건 `❌ 이유` | ① 사람 포스트잇 중 속기로 안 옮긴 것을 **위→아래 · 왼→오 순서로** 회의록 `## 속기` 끝에 `- <글> — <색의 사람>` 로 덧붙임 (옮긴 노드 id 는 작업 기억 `## 판에서 옮긴 속기` 에 적어 다시 안 옮김) ② 속기가 새로 늘었고 아직 카드를 안 뽑았으면 3절 정리. **이미 뽑힌 카드(작업 공간 `검토 중` · `A5` · `paused`)가 판에 없으면 그것부터 올림** — "정리해줘" 로 먼저 뽑고 나중에 판을 부른 경우. `검토 중` 카드는 💬 에, `A5` 카드는 ✅ 에, `paused` 카드는 ⏭ 에 (이미 고른 것이라 초록 · ✔). 작업 기억 `카드 아님` 줄도 같게. 올릴 때 → 안건 카드마다 노란 포스트잇 `🤖 <번호> <한 줄 질문>` + `[[카드\|자세히]]`, 카드 아님마다 작은 노란 포스트잇 `🤖 할 일? …` · `🤖 정함? …` ③ `❌` 붙은 🤖 카드 포스트잇 → 4절 튜닝 (이유 = ❌ 뒤 글. 없으면 묻고 멈춤) — 옛 포스트잇은 판에서 빼고 새 카드 포스트잇을 그 자리에 ④ 투표 수를 세어 보고에 (많은 순) |
| `zone-decided` ✅ 정했다 | 정한 것 포스트잇을 끌어오거나 새로 | 회의록 `## ✅ 정한 것` 에 한 줄. 🤖 카드 포스트잇이면 카드 파일을 `A5.outputs/` 로 (고름) |
| `zone-todo` 📤 할 일 — 인박스로 | 할 일 포스트잇 — **한 장 = 할 일 하나**. 사람 말로, `@Rin 금요일까지` 처럼 | 할일 노트를 만듦 (아래). 🤖 카드 포스트잇이면 카드를 A5 로 옮기고 카드의 `할 일 후보` 줄마다 하나 |
| `zone-next` ⏭ 다음에 | 다음에 얘기할 것 | 회의록 `## ⏭ 다음 회의로` 에 한 줄. 🤖 카드 포스트잇이면 카드를 `A1.collection/paused/` 로 |

**📤 할일 노트 만들기**
- 이름 · `## 뭘 해야 하나` = 포스트잇 첫 줄 (사람 말 그대로). `🤖 할 일?` · `〔…〕` · `@…` · 날짜 말은 이름에서 뺌
- `@이름` → `담당` (사람 명단에 있는 이름만. `@화자A` 는 비움). 포스트잇 색이 사람 색이고 `@` 가 없으면 담당도 비움 — 붙인 사람 ≠ 맡은 사람
- 날짜 말 → `마감` · `일정` (7절, 기준일 = 회의록 작성일)
- `상위: "[[<회의록>]]"` · `주제: 회의 할 일` · `상태: 미처리` · `구역: 0.inbox` · `작성일` 오늘 · `작성자` 자기 이름 · 자리 `0.📥 인박스/📝 회의록 인박스/`
- `링크` = 포스트잇 안의 `[[카드]]`, 또는 포스트잇과 화살표로 이은 카드 포스트잇의 카드
- 같은 이름 · 같은 `상위` 할일이 있으면 만들지 않음
- 본문 맨 위 `> 회의판에서 올림 — [[<회의록>]]`

**반영 표시** — 처리한 포스트잇은 **초록(`"4"`)** 으로 바꾸고 글 끝에 ` ✔` (할일을 만들었으면 ` ✔ [[<노트>]]`). **끝에 ✔ 가 있는 노드는 다시 처리하지 않습니다.**
사람 색(보라 · 파랑)을 초록으로 바꾸면 누가 붙였는지가 사라지므로, 초록으로 바꾸기 전에 글 끝에 `— Rin` · `— 민규 서` 가 없으면 붙입니다.
`zone-talk` 의 사람 포스트잇은 속기로 옮겨도 색을 바꾸지 않습니다 (계속 토론 중인 것).

**순서** — 불릴 때마다 위에서 아래로 한 번씩:
0. 회의록 정하기 (2절). 작업 공간 · 판이 없으면 만들고 (3절 2 · 3 + 판 양식 복사 · 제목 바꾸기) 회의록 `🥸` 칸에 판 · 작업 기억 링크
1. 끈 맞추기 (5.1) → 2. `zone-prev` → 3. `zone-talk` ①②③ → 4. `zone-decided` · `zone-todo` · `zone-next`
5. 작업 기억 진행 표 갱신
6. `zone-talk` 에 처리 안 한 🤖 카드 포스트잇이 없고 새로 처리한 것도 없으면 **"스킬 올리고 보관할까요?"** — 예면 6절 → 보관. 이때 `zone-talk` 에 남은 🤖 카드 = 안 고름 (채택 기록에 적음)
7. 보고: `판 — <회의록>  ⏮ ✅a ❌b · 속기 +c줄 · 🤖 카드 d · 투표 (♥ 많은 순 3개) · ✅ e · 📤 할 일 f · ⏭ g · 튜닝 h · 구역 밖 i`

## 3. A. 세팅 · 카드 — "정리해줘"

1. 회의록을 읽습니다. **기준일** = `작성일` (비었으면 파일 이름 앞의 날짜, 그것도 없으면 기준일 없음).
2. **작업 공간** — `99.🥸(Agent) 작업 공간/<회의록 파일 이름>/` 이 없으면 `!(Template) 회의 작업 공간/` 을 통째로 복사해 만듭니다.
   있으면 그대로 씁니다 (점검 때 먼저 만들어졌을 수 있음).
3. **스킬 사본** — `A4.meta/pre_meeting_agenda_preparer/` 가 없으면 정본 `skills/pre_meeting_agenda_preparer/` 를 복사합니다.
   **이미 있으면 덮지 않습니다** — 튜닝 중인 사본입니다.
4. **작업 기억** — `./templates/!(Template) 작업 기억.md` 로 A3 에 `<회의록 이름> — 작업 기억.md`.
   - TL;DR 세 줄 — 속기에 있는 것만. 없는 결론을 만들지 않습니다
   - 분류표 — 속기를 **한 줄도 빼지 않고** 번호를 매깁니다. `### 1.` 제목이 있으면 그 번호를 앞자리로. 빈 줄도 "빈 줄" 로.
     속기가 글머리 목록이 아니라 빈 줄로 나뉜 대화 문단이면 **발화 하나를 한 줄**로 세고, 사이의 빈 줄은 세지 않습니다
   - 화자 — 속기 줄에 이름이 없으면 발화 순서로 `화자 A` · `화자 B` … 로 나눕니다. `참석:` 이 두 사람이면(양식 기본값 `Rin · 민규 서`)
     보고할 때 **"화자 A 가 누구인가요?" 한 번만** 묻고, 답을 받으면 작업 기억 · 카드의 할 일 후보 · 카드 아님의 담당을 이름으로 바꿉니다.
     답이 오기 전엔 화자 A/B 로 둡니다. 말투로 누가 누군지 **추측하지 않습니다**
   - 추천 — `주제` 는 **볼트에 이미 있는 값에서만** (`grep -rh '^  - ' --include='*.md'` 로 모은 주제 목록),
     링크 후보는 속기에 나온 말이 볼트 노트 이름 · 사람 명단과 같을 때만. 둘 다 사람이 보고 씁니다
5. **안건 카드** — **A4 사본이 기준입니다.** 무엇을 카드로 만들지, 몇 장인지, 카드 안을 어떻게 채우는지 전부 사본의 `SKILL.md` 를 따릅니다
   (정본 규칙: "논의가 필요한 핵심 안건 단위로 분리" · 기존엔 왜 3칸 · 모범 사례 2~3개 · 쟁점 2개 이상 · 해결 방향은 비움).
   이 스킬은 순서만 정하고 카드의 모양을 정하지 않습니다 — **두 스킬이 부딪히면 사본을 따릅니다** (2026-09-28 민규 서).
   - `상위: "[[<회의록 이름>]]"` (이름이 볼트에서 하나뿐이 아니면 경로로)
   - 할 일이 드러난 카드는 속기 인용 아래 `**할 일 후보**` — 한 줄에 하나, `무엇 — 담당 <이름> · 마감 <날짜>`. 모르는 건 안 적습니다. 날짜는 7절
6. **카드 아님** — 논의할 게 없어서 카드로 만들지 않은 속기(단순 할 일 · 연락 · 일정 · 이미 정한 것)는 버리지 않고
   작업 기억 `## 카드 아님` 에 한 줄씩 적습니다 — `〔할 일〕` `〔정한 것〕` `〔다음 회의로〕` 꼬리표 · 담당 · 날짜 · 속기 번호.
   사람이 여기서 바로 인박스 · `✅ 정한 것` · `⏭ 다음 회의로` 로 옮깁니다. 분류표의 모든 줄은 카드나 이 목록 둘 중 하나에 닿아야 합니다 (공유 · 인사말은 "공유" 로 표시).
7. 작업 기억의 `안건 카드` 표를 채웁니다 (카드 링크 · 속기 번호 · 할 일 후보).
8. 회의록 `## 🥸 작업 공간` 이 `- ` 뿐이면 한 줄로 바꿉니다. `작성자` 목록 **맨 뒤에** 자기 이름 (이미 있으면 그대로).
9. **쓰기 직전에 회의록을 다시 읽습니다.** 달라졌으면 1번부터.
10. 보고하고 멈춥니다 (10절). 다음은 사람의 pick 입니다.

## 4. B. 튜닝 — "다시 뽑아줘"

사람은 고른 카드를 `A5.outputs/` 로 옮겨 둡니다. **`검토 중` 에 남은 것이 안 고른 것**입니다.

1. 남은 카드와 A5 카드를 견줍니다. 사람이 이유를 말했으면 그대로 적고, 말하지 않았으면 **추측을 `추측:` 으로 적고 물어봅니다.**
   추측을 확정처럼 적어 스킬을 고치지 않습니다.
2. 작업 기억 `## 튜닝 기록` 에 한 덩이를 더합니다 (양식의 주석 모양). 진행 표의 튜닝 횟수도.
3. **A4 사본**의 `SKILL.md` · `templates/` 를 고칩니다. 정본은 건드리지 않습니다.
4. 남은 카드를 `A1.collection/history/` 로 옮깁니다 — 이름 끝에 ` (v<회차>)`. 지우지 않습니다.
5. 고친 사본으로 **남은 것의 자리만** 다시 뽑아 `검토 중` 에 냅니다. A5 에 있는 카드는 다시 뽑지 않습니다.
6. 보고하고 멈춥니다. 사람이 다시 고르고, 원하면 반복합니다.

- 사람이 "이제 됐어" · "그만" 하면 `검토 중` 에 남은 카드를 `history/` 로 옮기고 끝냅니다.
- **이유가 "지금은 안 다룸"(카드는 맞게 뽑혔음)이면 규칙 문제가 아닙니다.** 사본을 고치지 않고, 그 카드를 `paused/` 로 옮기고,
  튜닝 기록에 `고친 규칙: 없음` 으로 한 덩이 남깁니다 (1회차로 셈). 카드 안의 `할 일 후보` 를 올릴지는 사람이 정합니다 (2026-09-28 테스트에서 정함).
- 한 회의에서 튜닝을 세 번 넘게 하면 보고에 "카드로 뽑을 속기가 아닐 수 있음" 을 한 줄 덧붙입니다.

## 5. C. 점검 — "지난 회의 점검해줘" · "다음 회의 준비해줘"

**이번 회의록**이 있어야 합니다. 없으면 이름을 묻고, `📝 회의록` 보드의 `+ 새 항목` 으로 만들어 달라고 합니다.
에이전트가 회의록을 만들지 않습니다.

0. **끈 맞추기**부터 합니다 (5.1). 끈이 틀린 할 일은 점검에서 빠지기 때문입니다.
1. **앞 회의 P** = 이번 회의록보다 `작성일` 이 앞선 회의록 중 가장 가까운 것.
   **작성일이 같은 회의록이 있으면** 파일을 만든 시각(생성 시각)이 이번 회의록보다 앞선 것 중 가장 늦은 것이 P 입니다 — 하루에 회의를 두 번 하면 생깁니다 (2026-09-28 테스트).
   그래도 가려지지 않으면 이름을 말하고 물어봅니다.
   **시작선 (2026-09-28 민규 서 — "제로에서 시작")**: 아래 네 회의록은 시험 · 옛 방식이라 **P 로 고르지 않습니다.**
   `2026.09.22 회의 안건` · `2026.09.22 주간 회의록` · `한 사이클 돌려보기 테스트` · `한 사이클 돌러보기 테스트_후속편`.
   남은 회의록 중에 P 가 없으면 첫 회의로 봅니다 — 재료 a · c · d · e · f 는 없고, **b(아직 안 끝난 회의 할 일)만** 점검표에 올립니다 (처음 = 그 할 일의 `상위` 회의, 🔁 는 시작선 뒤 회의만 셈).
2. **하기로 한 것**을 모읍니다 (작업 공간 두 곳을 뺀 볼트 전체에서. P 의 작업 공간은 99 · 보관 두 곳 다 찾음).

   | 재료 | 어디서 | 처음 나온 회의 |
   | --- | --- | --- |
   | a. 회의 할 일 | `유형: 할일` · `주제` 에 `회의 할 일` · `상위` 가 P | P |
   | b. 오래된 회의 할 일 | 같은 조건인데 `상위` 가 P 보다 앞선 회의 · 상태가 `완료` · `히스토리` 아님 | 그 `상위` |
   | c. 다음 회의로 | P 의 `## ⏭ 다음 회의로` 줄 | P |
   | d. 고른 카드 | P 작업 공간 `A5.outputs/` 의 카드 | P |
   | e. 이월 | P 의 점검표에서 **체크 안 된** ❓ 줄 | 그 줄의 `처음` 그대로 |
   | f. 카드 아님 할 일 | P 작업 기억 `## 카드 아님` 의 `〔할 일〕` 줄 | P |

   - d 는 a·b 의 할일 중 `링크` 가 그 카드를 가리키는 것이 있으면 **그 할일로 셉니다** (두 번 안 셈).
   - f 도 a·b 에 같은 일(이름이 같거나 줄 본문을 담은 것)이 있으면 그 할일로 셉니다. 없으면 ❓ — 올리지도 적지도 않은 할 일이 조용히 사라지지 않게 한 번 더 보여 줍니다 (2026-09-28 채택).
     ❓ 에서 체크 안 하면 e 로 계속 따라옵니다. 너무 시끄러우면 이 줄을 끕니다.
   - c 도 같은 내용의 할일(`상위` = P 이고 이름이 같거나 줄 본문을 담은 것)이 있으면 그 할일로 셉니다. 헷갈리면 따로 두고 `혹시: [[…]]` 를 붙입니다.
   - 옛 모양 P 면 AI 정리의 `→ [[…|만듦]]` 줄이 a 입니다.
3. **판정** — 할일 노트의 `상태` 가 정본입니다. 에이전트가 상태를 바꾸지 않습니다.

   | 판정 | 조건 |
   | --- | --- |
   | ✅ 됨 | `완료` · `히스토리` |
   | 🔄 진행 중 | `진행중` · `확인 필요` |
   | ⏳ 안 됨 | `미처리` · `to do` · `퍼즈` — `마감` 이 기준일보다 앞이면 🔴 |
   | ❓ 끈 없음 | c · d · e · f 중 가리키는 할일 노트가 없는 것 |

   ❓ 는 됐는지 **추측하지 않습니다.** 볼트에서 이름이 비슷한 노트를 찾았으면 `혹시: [[…]]` 만 덧붙입니다.
4. **🔁 이월** = `처음` 회의 뒤로 열린 회의의 수 (처음 회의는 빼고 이번 회의는 셈).
   예: 처음 09.22, 그 뒤 09.29 · 10.06 이 열렸고 이번이 10.06 → 🔁 2. **3 이상이면 줄 앞에 🚨** — 버릴까 · 쪼갤까.
   ✅ 됨 줄에는 🔁 를 적지 않습니다.
5. **점검표** — `./templates/!(Template) 지난 회의 점검.md` 로 **이번 회의** 작업 공간(없으면 3절 2번처럼 뼈대만) A2 에 `<이번 회의록 이름> — 지난 회의 점검.md`.

   ```
   ❓ 칸   - [ ] 🚨 <무엇> — <⏭ 다음 회의로 | A5 카드 [[…]] | 카드 아님> · 처음 <MM.DD> · 🔁 3
   나머지   - [[<할일 노트>]] — <상태> · 담당 <이름> · 마감 <날짜> 🔴 · 처음 <MM.DD> · 🔁 1
   ```

   - **체크박스는 ❓ 줄에만.** 할일 줄은 노트의 상태가 정본이라 체크가 없습니다.
   - 맨 위 표의 숫자를 셉니다. 🚨 는 칸과 상관없이 셉니다.
   - 한 칸이 비면 `- 없음`.
6. 이번 회의록 `## ⏮ 지난 회의 점검` 이 `- ` 뿐이면 끼워 넣기 한 줄로. `작성자` 맨 뒤에 자기 이름. **쓰기 직전에 다시 읽습니다.**
7. 보고하고 멈춥니다.

- 점검은 **여러 번 불러도 됩니다.** 다시 부르면 같은 파일을 새로 씁니다 — 단, 사람이 넣은 ❓ 체크는 같은 줄에 그대로 옮깁니다.
- 첫 회의라 P 가 없고 b 도 없으면 점검표 대신 `- 첫 회의 — 점검할 것 없음` 한 줄만 씁니다. b 가 있으면 1번의 시작선 규칙대로 b 만 올립니다.

### 5.1 끈 맞추기 — 점검 · 학습 전에 먼저

사람이 올린 회의 할 일의 `상위` 는 자주 틀립니다. 첫 테스트(2026-09-28)에서 두 번 연속 — 한 번은 비었고, 한 번은 **카드 이름이 글자로** 들어갔습니다.
할 일이 카드에서 나왔으니 카드를 `상위` 로 넣는 게 사람에겐 자연스럽습니다. 사람에게 맞추라고 하지 않고 **에이전트가 맞춥니다** (2026-09-28 채택).

1. **찾기** — `유형: 할일` · `주제` 에 `회의 할 일` 인 노트 전부(작업 공간 두 곳 제외) 중, `상위` 가 회의록(`4.🗄️(Archive) 보관/회의록/` 아래의 노트)을 **따옴표 친 위키링크**로 가리키지 않는 것.
2. **회의 찾기** — 이 순서로. 추측하지 않습니다.
   - `상위` · `링크` · 본문 중 어디에든 99 작업 공간 A5 의 **카드**가 있으면(링크든 글자든) → 그 카드의 `상위` 가 회의록
   - `상위` 에 회의록 이름이 글자로만(따옴표 · `[[ ]]` 없이) 있으면 → 그 회의록
   - 둘 다 없으면 → 고치지 않고 "어느 회의에서 나왔나요?" 로 묻기만
3. **확인받고 고치기** — 고칠 목록(노트 · 지금 값 → 바꿀 값)을 보여 주고, 사람이 된다고 하면
   `상위: "[[<회의록>]]"` 와 (카드가 있었으면) `링크: "[[<카드>]]"` **두 줄만** 바꿉니다 (9절 — 그 줄만). 다른 속성 · 본문은 안 건드립니다.
4. 보고에 `끈 맞춤 N (물어본 것 M)` 을 적습니다.

## 6. D. 학습 — "스킬 올려줘"

한 바퀴(pick 과 튜닝)가 끝났을 때 사람이 부릅니다.

0. **끈 맞추기**부터 합니다 (5.1). 인박스로 간 수를 세려면 끈이 맞아야 합니다.
1. **채택 기록** — `./채택 기록.md` 맨 아래에 한 덩이.

   ```
   ## <회의록 이름> (<날짜>)
   카드 뽑음 N · 고름 N · 튜닝 N회 · 끝내 안 고름 N
   끝내 안 고른 카드:
   - <카드 이름> (속기 1.2) — <이유 · 추측이면 "추측:">
   눈에 띈 것:
   - <같은 종류가 계속 안 골라짐 / 사람이 속기에 없던 걸 A5 에 직접 썼음 …>
   ```

   인박스로 간 수는 다음 회의 점검 때 뒤늦게 압니다 — 그때 이 덩이 끝에 `인박스로 N (점검 <날짜>)` 를 덧붙입니다.
2. **제안** — A4 사본과 정본 `skills/pre_meeting_agenda_preparer/` 를 줄 단위로 견줘, 다른 곳마다
   `A4.meta/스킬 수정 제안.md` 에 "이 줄을 이렇게 바꾸자 — 왜 (튜닝 기록 N회차)" 를 적고 보고합니다.
   - 앞 회의들의 채택 기록에 **같은 모양이 또 있으면** 제안에 `반복됨` 을 붙입니다 — 먼저 올릴 것.
3. 사람이 승인한 줄만 정본에 반영하고, 채택 기록에 `→ 정본 반영 (날짜)` 를 답니다. 이 스킬(`meeting-notes`) 자체를 고칠 때도 같습니다.

## 7. 날짜 — 카드의 할 일 후보 · 점검의 🔴

기준일 D 로 절대 날짜를 만듭니다. 주는 **월요일 시작**입니다.

| 속기 | 값 |
| --- | --- |
| 오늘 · 내일 · 모레 | D · D+1 · D+2 |
| 이번 주 X요일 | D 가 든 주의 X요일 |
| 다음 주 X요일 | 그다음 주의 X요일 |
| 이번 주까지 · 이번 주 안 | 이번 주 금요일 |
| 다음 주까지 · 다음 주 안 | 다음 주 금요일 |
| 이번 달까지 · 월말 | 그 달 마지막 날 |
| N일까지 (월 없이) | D 이후 가장 가까운 N일 |
| "곧" "빨리" "나중에" · 날짜 없음 · 기준일 없음 | **비움** |

"~까지" "마감" 은 `마감`, "~에 전화" "~시에" 처럼 그날 하는 일은 `일정`.
예: D = `2026-09-17`(목) → "다음 주까지" = `2026-09-25`, "이번 주 금요일" = `2026-09-18`. "~주까지 = 금요일" 은 이 볼트의 약속입니다.

## 8. 하지 않는 것

- 인박스 · 프로젝트에 노트 만들기 — 회의 할 일은 사람이 양식으로 올립니다. **예외: 회의판 `zone-todo` 의 포스트잇 (2.1)**
- `A5.outputs` 에 쓰기 · 옮기기 · 체크 넣기 · 지우기 — **예외: 회의판에서 사람이 `zone-decided` · `zone-todo` 로 끈 🤖 카드를 A5 로 옮기기 · `zone-prev` 의 ❓ 에 ✅ · ❌ 를 적은 것을 점검표에 체크하기 (2.1)**
- `## 속기` `## 자료` `참석:` `안건:` `## ✅ 정한 것` `## ⏭ 다음 회의로` 고치기
- 파일 · 폴더 **지우기** (볼트 규칙: 삭제는 사람이 합니다). 옮기는 건 됩니다 — `검토 중` → `history/`
- 사람 승인 없이 **정본** 스킬 고치기. 사본(A4.meta)은 튜닝 때 고칩니다
- 할일의 `상태` · `담당` · `마감` 바꾸기 — 점검은 읽기만. **예외는 끈 맞추기(5.1)의 `상위` · `링크` 두 줄 — 사람이 확인한 뒤에만 · 회의판 `zone-prev` 에서 사람이 ✅ · ❌ 를 적은 할일의 `상태: 완료` · `히스토리` (2.1)**
- 속기에 없는 담당 · 날짜 · 결론을 **추측해서** 채우기 · 에이전트 이름을 `담당` 에
- `.base` 파일 · `.obsidian` 고치기

## 9. 파일을 쓸 때 — 틀리면 조용히 깨집니다

- **줄끝은 LF.** 파이썬이면 `open(..., "w", encoding="utf-8", newline="")`. UTF-8, BOM 없이.
- 프론트매터의 위키링크는 **따옴표로**: `- "[[Rin]]"`.
- `분류` `주제` `담당` `작성자` 는 **블록 목록**.
- 이미 있는 노트의 속성을 고칠 때는 **그 줄만** 바꿉니다.
- `요약` 이 `'` 로 시작하면 큰따옴표로 감쌉니다.
- `제목` 속성을 만들지 않습니다.
- 샌드박스 노트도 속성 13종을 씁니다 (`유형: 메모` · `구역: 4.archive` · `상위` = 회의록 · `작성자` = 자기 이름 · 끝에 `PARA정리: 끔`). 제외 설정이 풀려도 새지 않게 하는 이중 안전장치입니다.

## 11. 이 스킬을 고칠 때

- 회의 규칙의 **정본은 이 파일 하나**입니다. `docs/meetings-and-skills.md` 는 여기를 가리키기만 합니다.
- 회의록 양식의 칸 이름을 바꾸면 1절의 표도 같이 고칩니다. 회의 할 일 양식의 `주제: 회의 할 일` 을 바꾸면
  5절 · 회의록 양식의 `⏮` 베이스 · `📊 회의 할 일.base` 를 같이 고칩니다 — 한 곳만 고치면 점검이 조용히 빕니다.
- 이 스킬은 볼트 맨 위 `skills/meeting-notes/` 에 삽니다. `skills/` 는 옵시디언 **제외된 파일**이고, 플러그인도 `SKILL.md` 가 있는 폴더를 노트로 보지 않습니다.
