# 회의 한 바퀴 — 정리 · 반영 · 학습

이 파일은 **에이전트가 읽는 설명서**입니다. 이 볼트에서 일하는 에이전트는 매번 다를 수 있고
(Claude · Codex · Gemini …), 누가 받든 이 순서와 규칙을 똑같이 따릅니다.
사람용 안내는 회의록 양식의 `%%` 블록에 따로 있습니다.

볼트 전체 규칙은 볼트 루트의 `CLAUDE.md` 입니다 (이 파일 기준 `../../CLAUDE.md`). 둘이 부딪히면 알리고 멈추세요.

---

## 0. 한 바퀴

**AI 가 쓴 것은 그대로 볼트에 반영할 수 없습니다.** 그래서 에이전트는 샌드박스(`99.🥸(Agent) 작업 공간/`)에 쓰고,
사람이 체크한 것만 밖으로 나갑니다. Notion AI Meeting Notes 와 Mem 의 방식을 빌렸습니다 (2026-09-23 조사).

```
Pre    회의록 맨 위 "⏮ 지난 회의에서 넘어온 것" — 회의 할 일이 됐나 안 됐나 (자동)      ← Mem Heads Up
       + "다음 회의 준비해줘" → 지난 회의의 ⏭ 다음 회의로 · 한 번 더 볼 후보
Live   사람: 속기만
Post   "정리해줘" → 99 에 AI 정리 — 안건 후보 전부, 체크리스트                          ← Notion Summary 탭
       사람: 체크
       "반영해줘" → 체크한 할 일 = 할일 노트 · 결정 = ✅ 정한 것 · 다음 안건 = ⏭ 다음 회의로
                   안 고른 줄 = 채택 기록 → 스킬 학습
Action 사람: 인박스 → 📤 PARA로 보내기 → 프로젝트에서 처리
       └──→ 다음 회의 Pre 에 "된 것 / 안 된 것" 으로 돌아옴
```

| Notion / Mem | 이 볼트 |
| --- | --- |
| Notes · Transcript 탭 (사람) | 회의록 `## 속기` · `## 자료` |
| Summary 탭 (AI, 따로 둠) | 99 의 AI 정리 — 회의록 `## 🤖 AI 정리` 에 **끼워 보여 주기만** |
| 요약 줄마다 녹취 인용 | 줄 끝 `(1.2)` — 속기 번호 |
| action item 은 사람이 태스크로 | 체크 → "반영해줘" |
| custom instructions · Retry summary | 이 스킬 · "다시 정리해줘" |
| Heads Up · Agent 의 후속 챙기기 | `⏮ 지난 회의에서 넘어온 것` · "다음 회의 준비해줘" |

### 샌드박스 폴더 (회의 하나에 하나)

```
99.🥸(Agent) 작업 공간/<회의록 파일 이름>/
  A1.collection/        ← 깊게 볼 안건 카드 (필요할 때만) · history/ 옛 버전
  A2.scratch(ideation)/ ← 다음 회의 사전 준비
  A3.working memory/    ← 작업 기억 — 분류표 (속기 줄마다 번호)
  A4.meta/              ← 스킬 수정 제안 (사람 승인 전)
  A5.outputs/           ← <회의록 파일 이름> — AI 정리.md
```

### 회의록 칸 (제목 이름이 곧 약속)

| 칸 | 누가 쓰나 | 에이전트는 |
| --- | --- | --- |
| `참석:` `안건:` | 사람 | 읽기만 |
| `## ⏮ 지난 회의에서 넘어온 것` | 베이스가 저절로 | 안 건드림 |
| `## 속기` · `## 자료` | 사람 | **읽기만. 한 글자도 안 고칩니다** |
| `## 🤖 AI 정리` | 에이전트 | "정리해줘" 때 **끼워 넣기 한 줄만** (`![[<회의록 이름> — AI 정리]]`) |
| `## ✅ 정한 것` · `## ⏭ 다음 회의로` | 사람 · "반영해줘" | 체크한 줄만 덧붙임. 사람이 쓴 줄은 안 지움 |
| `## 이 회의에서 나온 할 일` | 베이스가 저절로 | 안 건드림 |

옛 모양의 회의록(`## 결정` · `## 다음 안건` · `## 할 일 후보` 표)은 `✅ 정한 것` · `⏭ 다음 회의로` · `🤖 AI 정리` 로 읽습니다. 고쳐 달라고 하면 새 모양으로 바꿉니다.

## 2. 요청 → 일

| 요청 | 일 | 99 밖에 쓰나 |
| --- | --- | --- |
| "정리해줘" | **A. 정리** (3절) | 회의록에 끼워 넣기 한 줄 · `작성자` |
| "반영해줘" · "만들어줘" | **B. 반영** (4절) — 체크한 줄만 | 예. 할일 노트 · 회의록 두 칸 |
| "다음 회의 준비해줘" | **C. 사전 준비** (6절) | 아니오 |
| "다시 정리해줘" | A 를 다시. 사람이 넣은 체크는 같은 뜻의 줄로 옮김 | 아니오 |

- "정리하고 반영까지 해줘" 여도 **A 를 끝내고 멈춥니다.** 체크는 사람이 넣습니다.
  **왜** — 담당이나 날짜를 잘못 뽑으면 그 할 일은 엉뚱한 사람의 칸반에 조용히 앉아 있습니다. 사람이 한 번 보는 것이 유일한 확인입니다.
- 어느 회의록인지 요청에 없으면: 열려 있는 노트 → 없으면 `작성일` 이 가장 최근인 회의록을 **이름을 말하고 확인받은 뒤** 진행합니다.

## 3. A. 정리 — 속기 → AI 정리

1. 회의록을 읽습니다. **기준일** = `작성일` (비었으면 파일 이름 앞의 날짜, 그것도 없으면 기준일 없음).
2. 샌드박스 폴더를 만듭니다 (없으면). 빈 폴더에는 `.gitkeep`.
3. **분류표** — `./templates/!(Template) 작업 기억.md` 로 A3 에. 속기를 **한 줄도 빼지 않고** 번호를 매깁니다. `### 1.` 같은 제목이 있으면 그 번호를 앞자리로. 빈 줄도 "빈 줄" 로.
4. **AI 정리** — `./templates/!(Template) AI 정리.md` 로 A5 에. 아래 규칙.
5. **지난 회의 이어 보기** — 바로 앞 회의(작성일이 가장 가까운 앞 회의록)의 AI 정리에서 **안 고른 줄**과 `⏭ 다음 회의로` 를 `한 번 더` 칸에 올립니다. 한 번 더에서도 안 고르면 다음엔 안 올립니다.
6. 회의록 `## 🤖 AI 정리` 칸이 비었으면(`- ` 뿐) 끼워 넣기 한 줄로 바꿉니다. `작성자` 목록 **맨 뒤에** 자기 이름 (이미 있으면 그대로).
7. **쓰기 직전에 회의록을 다시 읽습니다.** 달라졌으면 1번부터.
8. 보고하고 멈춥니다 (10절).

### 안건 후보 — **거르지 않고 전부**

속기에서 나올 수 있는 후보를 모두 체크리스트로 냅니다. 무엇이 쓸모 있는지는 사람이 고릅니다.
처음엔 많이 뽑고, 안 골라지는 것은 채택 기록(5절)으로 배워서 줄입니다.

```
- [ ] 〔꼬리표〕 한 줄 — 덧붙임 (속기 번호)
```

| 꼬리표 | 무엇 | 체크하면 ("반영해줘") |
| --- | --- | --- |
| `〔할 일〕` | 누군가 손을 움직일 일. `→` 줄은 **반드시** | 할일 노트 |
| `〔결정〕` | "~하기로" 처럼 합의가 드러난 것 | `## ✅ 정한 것` |
| `〔확인 필요〕` | 한 사람이 답을 냈지만 합의는 안 보임 ("~할 거임", "~하셈", 자기 질문에 자기 답) · 답 없는 결정 질문 | `## ✅ 정한 것` (사람이 확인한 것으로) |
| `〔다음 안건〕` | "다음에", "갔다 와서", "못 할 듯", 당장 안 급한 아이디어 | `## ⏭ 다음 회의로` |

- **답이 곧 실행이면 두 줄로 냅니다** — `〔확인 필요〕` 하나, `〔할 일〕` 하나. ("인박스 만들어서", "Area 로 보낼거임")
- **회의의 큰 안건(속기 제목)이 지금 누가 하고 있는 일이면 그것도 `〔할 일〕`** 입니다.
- `〔할 일〕` 의 덧붙임: `— 담당 <이름> · 마감 <날짜> · 프로젝트 <폴더>`. 모르는 것은 적지 않습니다. 날짜는 7절.
- 볼트 규칙과 부딪히거나 결정이 무거우면 `〔확인 필요〕` 줄 끝에 **안건 카드** 링크를 답니다 (`./templates/!(Template) 안건 카드.md` 로 A1 에, 7단 구조). 모든 줄을 카드로 만들지 않습니다.
- 공유·설명만 있는 줄은 후보가 아니라 `## 요약` 에 씁니다.
- **체크는 비워 둡니다.** 줄 순서: 할 일 → 확인 필요 → 결정 → 다음 안건.

## 4. B. 반영 — 체크한 줄만

AI 정리를 읽고 **체크된 줄 중 아직 `→` 표시가 없는 것**만 처리합니다. 처리한 줄 끝에 `→ …` 을 붙입니다 — 다시 불려도 두 번 안 합니다.

| 꼬리표 | 어떻게 | 줄 끝 표시 |
| --- | --- | --- |
| `〔할 일〕` | 할일 노트 (아래) | `→ [[<만든 노트 경로>\|만듦]]` |
| `〔결정〕` · `〔확인 필요〕` | 회의록 `## ✅ 정한 것` 에 `- <줄 본문>` 덧붙임 (꼬리표 · 속기 번호 · 링크 뺌) | `→ 정한 것` |
| `〔다음 안건〕` | 회의록 `## ⏭ 다음 회의로` 에 덧붙임 | `→ 다음 회의로` |

그리고 **체크 안 된 줄 전부**를 채택 기록에 적습니다 (5절). 회의록 `작성자` 맨 뒤에 자기 이름.
회의록 칸이 `- ` 한 줄뿐이면 그 줄을 바꾸고, 사람이 쓴 줄이 있으면 뒤에 붙입니다. **쓰기 직전에 다시 읽습니다.**

### 할일 노트

**① 가는 곳**

| 덧붙임의 `프로젝트` | 폴더 | `구역` | `상태` | `분류` |
| --- | --- | --- | --- | --- |
| 프로젝트 폴더 이름과 **같다** | `1.🎯(Project) 프로젝트/<그 폴더>/` | `1.project` | `to do` | `- <그 폴더 이름>` |
| 없다 · 같은 게 없다 · 여럿과 맞는다 | `0.📥 인박스/📝 회의록 인박스/` | `0.inbox` | `미처리` | 비움 |

- "같다" 는 정확히 같거나, 앞의 이모지·공백을 떼고 비교했을 때 **딱 하나**와 같은 것.
- **프로젝트 폴더를 새로 만들지 않습니다.** 인박스로 보내면 사람이 `📤 PARA로 보내기` 로 정합니다.
- 인박스에 떨어지면 플러그인이 `분류` 를 칸 이름(`📝 회의록 인박스`)으로 채웁니다. 정상입니다.

**② 파일 이름** = 줄 본문 (꼬리표 · 덧붙임 · 속기 번호 뺌). `\ / : * ? " < > | # ^ [ ]` 를 빼고, 공백을 하나로, 80자 안. `.md`.

**③ 같은 게 있나** — 두 번 불려도 한 벌만.

- 가는 곳에 같은 이름의 파일이 있고 그 `상위` 가 **이 회의록**이면: 이미 만든 것. 줄 끝 표시만.
- 볼트의 다른 곳(99 제외)에 같은 이름이면서 `상위` 가 이 회의록인 할일이 있으면 (사람이 옮긴 것): 같음. 줄 끝 표시만.
- 같은 이름인데 다른 노트면: 이름 끝에 ` (<기준일>)` 을 붙여 새로 만듭니다.

**④ 쓰기** — 할일 양식의 속성 이름·순서 그대로.

상위: "[[2026.09.22 주간 회의록]]"

# ── 이외 속성 (유형별 고유값 · 통일 대상 아님) ──

> **속기 원문** (1.2)
> - *<그 줄의 속기 그대로>*

| 속성 | 값 |
| --- | --- |
| `주제` | **`회의 할 일`** 하나 — 다음 회의록의 `⏮ 지난 회의에서 넘어온 것` 이 이걸로 찾습니다. 빠뜨리면 그 할 일은 다음 회의에 안 돌아옵니다 |
| `작성일` | **오늘**. 회의 날짜가 아닙니다 |
| `마감` · `일정` | 덧붙임의 `마감 YYYY-MM-DD` 는 `마감`, `일정 YYYY-MM-DD` 는 `일정`. 나머지는 비움 |
| `상위` | 이 회의록. 이름이 볼트에서 하나뿐이 아니면 경로로 |
| `담당` | 이름마다 `- "[[이름]]"`. 없으면 `담당:` 만 — 칸반의 `👤 미할당` 탭에 뜹니다 |
| `작성자` | 자기 이름 하나 |
| `요약` `커버` `링크` | 비움. 지어내지 않습니다 |

`상위` 로 회의록을 가리키면 회의록의 `이 회의에서 나온 할 일` 에 저절로 모입니다. 회의별 폴더를 볼트에 만들지 않습니다 —
폴더는 *어느 프로젝트인지*, `상위` 는 *어느 회의에서 나왔는지*.

## 5. 학습 — 채택 기록과 스킬 수정

**반영할 때마다** `./채택 기록.md` 맨 아래에 그 회의 한 덩이를 덧붙입니다.

```
## <회의록 이름> (<반영한 날>)
뽑음 N · 고름 N (할 일 a/b · 확인 필요 c/d · 결정 e/f · 다음 안건 g/h)
안 고른 줄:
- 〔할 일〕 … (1.2)
눈에 띈 것:
- <같은 종류가 계속 안 골라짐 / 사람이 직접 써 넣은 줄이 AI 정리에 없었음 …>
```

- **스킬을 바로 고치지 않습니다.** 같은 모양이 **두 번 이상** 보이면 샌드박스 `A4.meta/스킬 수정 제안.md` 에 "이 줄을 이렇게 바꾸자" 를 쓰고 보고합니다.
  사람이 승인하면 이 파일에 한 줄로 반영하고, 채택 기록에 `→ 반영 (날짜)` 를 답니다.
- 사람이 AI 정리에 없던 줄을 회의록에 직접 써 넣었으면 그것도 적습니다 — **못 뽑은 것**이 더 중요한 학습입니다.

## 7. 날짜

기준일 D 로 절대 날짜를 만듭니다. 주는 **월요일 시작**입니다.

| 속기 | 값 |
| --- | --- |
| 오늘 · 내일 · 모레 | D · D+1 · D+2 |
| 이번 주 X요일 | D 가 든 주의 X요일 |
| 다음 주 X요일 | 그다음 주의 X요일 |
| 이번 주까지 · 이번 주 안 | 이번 주 금요일 |
| 다음 주까지 · 다음 주 안 | 다음 주 금요일 |
| 이번 달까지 · 월말 | 그 달 마지막 날 |
| N일까지 (월 없이) | D 이후 가장 가까운 N일 |
| "곧" "빨리" "나중에" · 날짜 없음 · 기준일 없음 | **비움** |

"~까지" "마감" 은 `마감`, "~에 전화" "~시에" 처럼 그날 하는 일은 `일정`.
예: D = `2026-09-17`(목) → "다음 주까지" = `2026-09-25`, "이번 주 금요일" = `2026-09-18`. "~주까지 = 금요일" 은 이 볼트의 약속입니다.

## 9. 파일을 쓸 때 — 틀리면 조용히 깨집니다

- **줄끝은 LF.** 파이썬이면 `open(..., "w", encoding="utf-8", newline="")`. UTF-8, BOM 없이.
- 프론트매터의 위키링크는 **따옴표로**: `- "[[Rin]]"`.
- `분류` `주제` `담당` `작성자` 는 **블록 목록**.
- 이미 있는 노트의 속성을 고칠 때는 **그 줄만** 바꿉니다.
- `요약` 이 `'` 로 시작하면 큰따옴표로 감쌉니다.
- `제목` 속성을 만들지 않습니다.
- 샌드박스 노트도 속성 13종을 씁니다 (`유형: 메모` · `구역: 4.archive` · `상위` = 회의록 · `작성자` = 자기 이름 · 끝에 `PARA정리: 끔`). 제외 설정이 풀려도 새지 않게 하는 이중 안전장치입니다.
