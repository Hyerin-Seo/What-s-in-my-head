# 회의록 — 정리와 배포

이 파일은 **에이전트가 읽는 설명서**입니다. 이 볼트에서 일하는 에이전트는 매번 다를 수 있고
(Claude · Codex · Gemini …), 누가 받든 이 순서와 규칙을 똑같이 따릅니다.
사람용 안내는 양식의 `%%` 블록에 따로 있습니다.

볼트 전체 규칙은 볼트 루트의 `CLAUDE.md` 입니다 (이 파일 기준 `../../CLAUDE.md`). 둘이 부딪히면 알리고 멈추세요.

---

## 0. 세계

| 무엇 | 어디 · 무엇 |
| --- | --- |
| 볼트 루트 | 이 파일 기준 `../../` (`CLAUDE.md` · `AGENTS.md` 가 있는 곳). 아래 경로는 전부 볼트 루트 기준 |
| 회의록 노트 | `4.🗄️(Archive) 보관/회의록/*.md` 중 `!(Template)` 로 시작하지 않는 것. 속성 `유형: 메모` · `분류: 회의록` |
| 회의록 양식 | `4.🗄️(Archive) 보관/회의록/!(Template) 회의록.md` |
| 할일 양식 | `1.🎯(Project) 프로젝트/!(Template) 새 할 일.md` — 속성 이름과 **순서**의 정본 |
| 프로젝트 | `1.🎯(Project) 프로젝트/` **바로 아래 폴더**. 이름에 `이미지` `image` `attachment` `첨부` 가 있거나 `.` `!` 로 시작하는 폴더는 빼고. **매번 디스크에서 목록을 읽습니다** — 여기 적어 두지 않습니다 |
| 사람 명단 | `.obsidian/plugins/claude/data.json` 의 `para.people`. 없으면 `Rin` · `민규 서` |
| 인박스 | `.obsidian/plugins/claude/data.json` 의 `inbox.newFolder`. 없으면 `0.📥 인박스/🥭 망고 인박스` |
| 자기 이름 | 제품 이름 — `Claude` `Codex` `Gemini` `ChatGPT` … |

### 회의록 본문의 칸 (제목 이름이 곧 약속)

| 칸 | 누가 쓰나 | 에이전트는 |
| --- | --- | --- |
| `참석:` `안건:` (맨 위 두 줄) | 사람 | 읽기만 |
| `## 속기` | 사람 | **읽기만. 한 글자도 안 고칩니다** |
| `## 자료` | 사람 | 읽기만 |
| `## 결정` | 에이전트 (정리) | 채움 |
| `## 다음 안건` | 에이전트 (정리) | 채움 |
| `## 할 일 후보` | 에이전트가 줄을 넣고, **사람이 `✅` 를 넣음** | 줄 추가 · 배포 뒤 `할 일` 칸을 링크로 |
| `## 이 회의에서 나온 할 일` | 보드가 저절로 | 안 건드림 |

할 일 후보 표의 열은 이 다섯이고, **머리글 이름으로** 찾습니다 (순서로 찾지 않습니다).

```
| ✅ | 할 일 | 담당 | 마감 | 프로젝트 |
```

## 1. 무슨 일을 하나 — 요청을 보고 하나만

| 요청 | 일 | 새 노트를 만드나 |
| --- | --- | --- |
| "정리해줘" · "할 일 뽑아줘" | **A. 정리** | 아니오. 회의록 한 장만 고칩니다 |
| "배포해줘" · "할 일 만들어줘" | **B. 배포** | 예. `✅` 가 들어간 줄만 |

- "정리하고 배포까지 해줘" 여도 **A 를 끝내고 멈춥니다.** 사람에게 후보 표를 보고 `✅` 를 넣어 달라고
  말합니다. `✅` 없이 B 를 하지 않습니다.
  **왜** — 담당이나 날짜를 잘못 뽑으면 그 할 일은 엉뚱한 사람의 칸반 탭에 조용히 앉아 있습니다.
  아무도 틀린 줄 모릅니다. 사람이 한 번 보는 것이 유일한 확인입니다.
- 어느 회의록인지 요청에 없으면: 열려 있는 노트 → 없으면 `작성일` 이 가장 최근인 회의록을
  **이름을 말하고 확인받은 뒤** 진행합니다.

## 2. A. 정리

### 순서

1. 회의록을 읽습니다. **기준일** = 속성 `작성일`. 비었으면 파일 이름 앞의 `YYYY-MM-DD`. 그것도 없으면 기준일 없음.
2. `## 속기` · `## 자료` · `참석:` · `안건:` 만 근거로 씁니다. 볼트의 다른 노트나 기억으로 채우지 않습니다.
3. 아래 규칙대로 `결정` · `다음 안건` · `할 일 후보` 를 만듭니다.
4. **쓰기 직전에 파일을 다시 읽습니다.** 처음 읽은 것과 다르면 (사람이 아직 쓰는 중) 1번부터 다시 합니다.
5. 칸을 씁니다 (아래 **쓰는 법**). 속성은 `작성자` 한 줄만 건드립니다.
6. 보고합니다 (6절).

### 결정

- **확정된 것만.** "~하기로 함" "확정" "결정" "그걸로 가자" 처럼 합의가 드러난 것.
- 논의만 하고 끝난 것, 의견만 나온 것은 넣지 않습니다.
- 한 줄에 하나, `- ` 로 시작.

### 다음 안건

- "다음에 다시" "다음 회의에서" "보류" "더 알아보고" "결론 못 냄" 처럼 **다음으로 넘어간 것.**
- 한 줄에 하나, `- ` 로 시작.

### 할 일 후보

누군가 **행동해야 하는 것**을 한 줄씩. 줄 앞에 `→` 가 붙은 속기 줄은 사람이 "이건 할 일" 이라고
표시한 것이니 **반드시** 후보로 넣습니다.

| 열 | 채우는 법 |
| --- | --- |
| `✅` | **비웁니다.** 에이전트는 절대 넣지 않습니다 |
| `할 일` | **동사로 끝나는 한 줄**, 결과물이 드러나게. `디자인 검토` ✗ → `로그인 화면 시안 3종 만들어 공유` ✓. 60자 안. 시각이 있으면 문장 끝에 `(15:00)` |
| `담당` | 명단의 이름 **그대로** (`Rin`, `민규 서`). 속기의 호칭이 명단의 **딱 한 사람**을 가리킬 때만 (`민규` → `민규 서`). 여럿이면 `, ` 로. 애매하면 **비움**. 에이전트 이름은 넣지 않습니다 — 담당은 책임지는 사람입니다 |
| `마감` | 아래 **날짜** 규칙. 모르면 **비움** |
| `프로젝트` | 프로젝트 폴더 이름 **그대로** (이모지까지). 속기에 드러나지 않으면 **비움** — 비우면 배포 때 인박스로 갑니다 |

### 날짜

`마감` 칸에는 둘 중 하나를 씁니다.

| 칸의 모양 | 뜻 | 속기에서 |
| --- | --- | --- |
| `YYYY-MM-DD` | **마감** — 그날까지 | "~까지" "~전까지" "마감" |
| `일정 YYYY-MM-DD` | **일정** — 그날 한다 | "~에 전화" "~에 만남" "~시에", 특정 날에 하는 일 |

기준일 D 로 절대 날짜를 만듭니다. 주는 **월요일 시작**입니다.

| 속기 | 값 |
| --- | --- |
| 오늘 · 내일 · 모레 | D · D+1 · D+2 |
| 이번 주 X요일 | D 가 든 주의 X요일 |
| 다음 주 X요일 | 그다음 주의 X요일 |
| 이번 주까지 · 이번 주 안 | 이번 주 금요일 |
| 다음 주까지 · 다음 주 안 | 다음 주 금요일 |
| 이번 달까지 · 월말 | 그 달 마지막 날 |
| N일까지 (월 없이) | D 이후 가장 가까운 N일 |
| "곧" "빨리" "나중에" · 날짜 없음 · 기준일 없음 | **비움** |

예: D = `2026-09-17`(목) → "다음 주까지" = `2026-09-25`, "이번 주 금요일" = `2026-09-18`.

"~주까지 = 금요일" 은 이 볼트의 약속입니다. 바꾸려면 이 표만 고칩니다.

### 쓰는 법

- 칸이 **비어 있으면** (`- ` 한 줄뿐이거나 아무것도 없으면) 채웁니다.
- **이미 사람이 쓴 게 있으면 지우지 않습니다.** 없는 항목만 뒤에 덧붙입니다.
- 후보 표: 내용 없는 줄(`|  |  |  |  |  |`)은 새 줄로 바꿉니다. 내용 있는 줄은 그대로 두고, **이미 있는 할 일과
  같은 뜻의 후보는 넣지 않습니다.** 새 후보는 표 아래에 붙입니다.
- 셀 안에 `|` 가 들어가면 `\|` 로 씁니다.
- 찾은 게 없으면 칸을 빈 채로 둡니다. "없음" 같은 글을 지어 넣지 않습니다.
- 본문을 써 넣었으므로 회의록 `작성자` 목록 **맨 뒤에** 자기 이름을 `- "[[Claude]]"` 모양으로 더합니다.
  이미 있으면 그대로. 앞의 이름은 절대 지우지 않습니다.

## 3. B. 배포

### 어느 줄을

`## 할 일 후보` 표의 줄마다:

| `✅` 칸 | `할 일` 칸 | 어떻게 |
| --- | --- | --- |
| `✅` `✔` `☑` `O` `o` `ㅇ` `V` `v` 중 하나 | 글자 | **배포합니다** |
| 위와 같음 | 이미 `[[…]]` 링크 | 이미 배포된 줄. 건너뜁니다 |
| 비었음 · `X` `x` · 그 밖 | — | 건너뜁니다. **`X` 는 "안 함" 입니다** (O/X 관습) |

### 줄마다

**① 가는 곳**

| `프로젝트` 칸 | 폴더 | `구역` | `상태` | `분류` |
| --- | --- | --- | --- | --- |
| 프로젝트 폴더 이름과 **같다** | `1.🎯(Project) 프로젝트/<그 폴더>/` | `1.project` | `to do` | `- <그 폴더 이름>` |
| 비었다 · 같은 게 없다 · 여럿과 맞는다 | 인박스 | `0.inbox` | `미처리` | 비움 |

- "같다" 는 정확히 같거나, 앞의 이모지·공백을 떼고 비교했을 때 **딱 하나**와 같은 것.
- **프로젝트 폴더를 새로 만들지 않습니다.** 새 프로젝트인지 정하는 건 사람입니다 — 인박스로 보내면
  사람이 `📤 PARA로 보내기` 로 정합니다.
- `분류` 를 폴더 이름과 똑같이 두는 이유: 플러그인이 `분류` 와 같은 이름의 폴더를 도착지로 씁니다.
  다르면 나중에 파일이 엉뚱한 곳으로 옮겨질 수 있습니다.

**② 파일 이름** = `할 일` 칸의 글.
`\ / : * ? " < > | # ^ [ ]` 를 빼고, 공백을 하나로, 80자 안. `.md` 를 붙입니다.

**③ 같은 게 있나** — 두 번 불려도 한 벌만 있어야 합니다.

- 가는 곳에 같은 이름의 파일이 있고 그 `상위` 가 **이 회의록**이면: 이미 배포된 것. 새로 만들지 않고 ⑤로.
- 볼트의 다른 곳에 같은 이름이면서 `상위` 가 이 회의록인 할일이 있으면 (사람이 옮긴 것): 같음. ⑤로.
- 같은 이름인데 다른 노트면: 이름 끝에 ` (<기준일>)` 을 붙여 새로 만듭니다.

**④ 쓰기** — 할일 양식의 속성 이름·순서 그대로. 아래는 프로젝트로 가는 예입니다.

```markdown
---
유형: 할일
구역: 1.project
분류:
  - 🚚 PARA 구축 — 자료 이식
주제:
상태: to do
요약:
작성일: 2026-09-17
마감: 2026-09-25
커버:
상위: "[[2026-09-17 주간 회의]]"
링크:
담당:
  - "[[민규 서]]"
작성자:
  - "[[Claude]]"
# ── 이외 속성 (유형별 고유값 · 통일 대상 아님) ──
일정:
---

## 뭘 해야 하나

견적 3곳 받아 표로 정리

## 다음 행동

- [ ] 
```

| 속성 | 값 |
| --- | --- |
| `작성일` | **오늘** (노트를 만든 날). 회의 날짜가 아닙니다 |
| `마감` · `일정` | `마감` 칸이 `YYYY-MM-DD` 면 `마감`, `일정 YYYY-MM-DD` 면 `일정`. 나머지는 비움 |
| `상위` | 이 회의록. 회의록 파일 이름이 볼트에서 **하나뿐이 아니면** 경로로 (`"[[4.🗄️(Archive) 보관/회의록/2026-09-17 주간 회의]]"`) |
| `담당` | 칸의 이름마다 `- "[[이름]]"`. 칸이 비면 `담당:` 만 — 칸반의 `👤 미할당` 탭에 뜹니다 |
| `작성자` | 자기 이름 하나 |
| `요약` `주제` `커버` `링크` | 비움. 지어내지 않습니다 |
| 인박스로 갈 때 | `구역: 0.inbox` · `상태: 미처리` · `분류:` 비움. 나머지는 같음 |

`상위` 로 회의록을 가리키면 회의록의 `## 이 회의에서 나온 할 일` 보드(`file.hasLink(this.file)`)에
저절로 모입니다. 그래서 **회의별 폴더를 만들지 않습니다** — 폴더는 *어느 프로젝트인지*,
`상위` 는 *어느 회의에서 나왔는지*. 한 정보를 두 곳에 두면 어긋납니다.

**⑤ 표에 표시** — 그 줄의 `할 일` 칸을 `[[<만든 파일 이름>]]` 으로 바꿉니다 (`.md` 없이, 별칭 없이).
다음에 배포가 또 불려도 이 링크를 보고 건너뜁니다. `✅` 칸은 그대로 둡니다.

**⑥ 쓰기 직전에 회의록을 다시 읽습니다.** 달라졌으면 그 줄부터 다시 봅니다.

---

## 4. 하지 않는 것

- `✅` 넣기 · 지우기
- `## 속기` `## 자료` `참석:` `안건:` 고치기
- 파일·폴더 **지우기** (볼트 규칙: 삭제는 사람이 합니다)
- 회의별 폴더 · 새 프로젝트 폴더 만들기
- 이미 있는 할일의 `상태` · `담당` · `마감` 바꾸기
- 회의록 노트를 옮기거나 이름 바꾸기
- 속기에 없는 담당 · 날짜 · 프로젝트를 **추측해서** 채우기
- `.base` 파일 · `.obsidian` 고치기
- 에이전트 이름을 `담당` 에 넣기

## 5. 파일을 쓸 때 — 틀리면 조용히 깨집니다

- **줄끝은 LF.** 프론트매터는 `---\n` 으로 시작해야 플러그인이 읽습니다. CRLF 면 오류 없이 값만 안 먹습니다.
  파이썬이면 `open(..., "w", encoding="utf-8", newline="")`.
- UTF-8, BOM 없이.
- 프론트매터의 위키링크는 **따옴표로**: `- "[[Rin]]"`. 따옴표가 없으면 YAML 이 중첩 목록으로 읽어 깨집니다.
- `분류` `주제` `담당` `작성자` 는 **블록 목록** (`키:` 다음 줄에 `  - 값`). `키: 값` 한 줄로 쓰지 않습니다.
- 이미 있는 노트의 속성을 고칠 때는 **그 줄만** 바꿉니다. 프론트매터를 파싱해 통째로 다시 쓰지 않습니다
  (`# ── 이외 속성 ──` 주석줄이 사라집니다).
- `제목` 속성을 만들지 않습니다. 파일 이름이 제목입니다.

## 6. 끝나면 사람에게 이렇게 알립니다

```
정리 — <회의록 이름>
  결정 N · 다음 안건 N · 할 일 후보 N
  사람이 정할 것: 담당 빈 줄 N · 마감 빈 줄 N · 프로젝트 빈 줄 N (→ 배포하면 인박스)
  다음: 후보 표에 ✅ 를 넣고 "배포해줘"

배포 — <회의록 이름>
  만듦 N
    - <경로>  (담당 · 마감)
  이미 있음 N — <이름>
  인박스로 N — <이름>: 프로젝트 칸이 비었음 / "<칸 값>" 과 같은 폴더 없음
  건너뜀 N — <줄>: ✅ 없음 / X
```
