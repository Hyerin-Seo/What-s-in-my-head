# 옵시디언 커스텀 파일 뷰(Custom File View) 개발 가이드

본 문서는 옵시디언(Obsidian) 공식 프레임워크가 지원하는 **커스텀 파일 뷰(Custom File View / TextFileView)** 및 **확장자 바인딩(`registerExtensions`)** API를 바탕으로, `.outline`이나 `.canvas`와 같은 독자적인 파일 형식을 옵시디언의 정식 에디터로 연동하는 표준 개발 아키텍처를 정리한 실전 가이드입니다.

---

## 1. 아키텍처 개념 및 상속 계층도

옵시디언의 UI 뷰는 목적에 따라 상속 계층이 엄격히 나뉘어 있습니다.

```text
Component
   └── View
        └── ItemView            (일반 도구 뷰: 사이드바 위젯, 그래프 뷰, 검색 패널 등)
             └── FileView       (단일 파일 결합 뷰: 파일 메타데이터 및 포인터 연동)
                  └── TextFileView  ★ (텍스트 기반 커스텀 파일 에디터)
```

* **`ItemView`**: 파일과 무관하게 독립적으로 존재하는 패널 (예: 백링크 탭, 아웃라인 패널).
* **`TextFileView`**: **로컬 파일(`TFile`)과 1:1로 결합**되어 파일 읽기, 쓰기, 자동 저장 디바운싱, 충돌 감지 수명주기를 코어 엔진이 직접 보장하는 **정식 에디터 추상 클래스**.
* **표준 용어 매핑**: VS Code의 **Custom Editor Provider**(`vscode.window.registerCustomEditorProvider`)와 100% 동일한 개념입니다.

---

## 2. 공식 API 명세 및 출처 (Fact-Check)

> 🔗 **공식 출처**:
> * 튜토리얼: [Obsidian Docs - Custom views](https://docs.obsidian.md/Plugins/User+interface/Custom+views)
> * API 명세: [TextFileView Reference](https://docs.obsidian.md/Reference/TypeScript+API/TextFileView)
> * API 명세: [Plugin.registerExtensions](https://docs.obsidian.md/Reference/TypeScript+API/Plugin/registerExtensions)
> * API 명세: [Plugin.registerView](https://docs.obsidian.md/Reference/TypeScript+API/Plugin/registerView)

### ① `Plugin.registerView(viewType, viewCreator)`
```ts
registerView(type: string, viewCreator: (leaf: WorkspaceLeaf) => View): void
```
* 고유한 뷰 식별자(`viewType`)와 해당 뷰의 인스턴스를 생성하는 팩토리 함수를 옵시디언 엔진에 등록합니다.

### ② `Plugin.registerExtensions(extensions, viewType)`
```ts
registerExtensions(extensions: string[], viewType: string): void
```
* 특정 파일 확장자(예: `['outline', 'spine']`)를 지정한 `viewType`으로 자동 라우팅합니다.
* 사용자가 파일 탐색기에서 해당 확장자 파일을 열면 기본 텍스트 뷰 대신 커스텀 뷰가 실행됩니다. (Obsidian v0.9.7 도입)

## 3. `TextFileView` 필수 수명주기 구현 사양

`TextFileView`를 상속받는 에디터는 아래 4대 핵심 추상 메서드를 반드시 구현해야 합니다.

| 메서드 시그니처 | 호출 시점 | 역할 및 구현 내용 |
| :--- | :--- | :--- |
| `getViewType(): string` | 뷰 식별 시 | 등록 시 사용한 고유 `viewType` 문자열 반환 |
| `getDisplayText(): string` | 탭 헤더 렌더링 시 | 탭 제목 표시 (`this.file ? this.file.basename : "Outline"`) |
| `setViewData(data: string, clear: boolean): void` | 파일 로드/외부 변경 시 | 디스크에서 읽은 원본 텍스트를 파싱하여 UI 상태로 로드 |
| `getViewData(): string` | 자동 저장(Save) 시 | 현재 에디터 상태를 디스크에 기록할 평문(JSON 등) 문자열로 직렬화하여 반환 |
| `clear(): void` | 뷰 닫힘/파일 전환 시 | 에디터 내부 상태 메모리 및 자원 해제 |

## 4. 실전 표준 보일러플레이트 코드 (React 마운트 연동)

아래 코드는 `.outline` 파일을 열어 외부 React 컴포넌트(`OutlineCanvas`)를 렌더링하고, 변경 시 옵시디언 디스크로 자동 저장하는 정석 구현체입니다.

```ts
import { Plugin, TextFileView, WorkspaceLeaf } from "obsidian";
import { Root, createRoot } from "react-dom/client";
import React from "react";

export const VIEW_TYPE_OUTLINE = "vibe-outline-view";

// ==========================================
// 1. TextFileView 에디터 구현 클래스
// ==========================================
export class OutlineTextFileView extends TextFileView {
  private reactRoot: Root | null = null;
  private currentData: any = {};

  constructor(leaf: WorkspaceLeaf) {
    super(leaf);
  }

  getViewType(): string {
    return VIEW_TYPE_OUTLINE;
  }

  getDisplayText(): string {
    return this.file ? this.file.basename : "Outline Editor";
  }

  // 뷰가 열릴 때 컨테이너 DOM 준비
  async onOpen(): Promise<void> {
    await super.onOpen();
    this.contentEl.empty();
    this.contentEl.addClass("vibe-outline-container");
    this.reactRoot = createRoot(this.contentEl);
  }

  // 디스크에서 데이터가 로드되었을 때 (역직렬화)
  setViewData(data: string, clear: boolean): void {
    try {
      this.currentData = data ? JSON.parse(data) : {};
    } catch (e) {
      this.currentData = {};
    }
    this.render();
  }

  // 옵시디언이 자동 저장 트리거할 때 (직렬화)
  getViewData(): string {
    return JSON.stringify(this.currentData, null, 2);
  }

  // React 화면 렌더링
  private render(): void {
    if (!this.reactRoot) return;

    this.reactRoot.render(
      <OutlineCanvas
        initialData={this.currentData}
        onChange={(newData) => {
          this.currentData = newData;
          // ★ 옵시디언 코어에 디스크 저장 요청 (디바운싱 자동 적용)
          this.requestSave();
        }}
      />
    );
  }

  // 뷰 닫힐 때 자원 해제
  async onClose(): Promise<void> {
    if (this.reactRoot) {
      this.reactRoot.unmount();
      this.reactRoot = null;
    }
    await super.onClose();
  }

  clear(): void {
    this.currentData = {};
  }
}

// ==========================================
// 2. 메인 플러그인 진입점 (main.ts)
// ==========================================
export default class OutlinePlugin extends Plugin {
  async onload() {
    // 1) 뷰 등록
    this.registerView(
      VIEW_TYPE_OUTLINE,
      (leaf) => new OutlineTextFileView(leaf)
    );

    // 2) 확장자 바인딩 (이 한 줄로 탐색기 더블클릭 연동 완결)
    this.registerExtensions(["outline"], VIEW_TYPE_OUTLINE);

    // 3) 새 파일 생성 커맨드 등록
    this.addCommand({
      id: "create-new-outline",
      name: "새 아웃라인 파일 생성 (.outline)",
      callback: async () => {
        const fileName = `Untitled-${Date.now()}.outline`;
        const initialContent = JSON.stringify({ version: "1.0", nodes: [] }, null, 2);
        const newFile = await this.app.vault.create(fileName, initialContent);
        const leaf = this.app.workspace.getLeaf(true);
        await leaf.openFile(newFile);
      }
    });
  }
}
```

## 5. 실제 옵시디언 코어 및 대표 플러그인의 적용 사례

1. **옵시디언 코어 캔버스 (`.canvas`)**:
   * 옵시디언 자체 내장 화이트보드 캔버스 또한 `registerView("canvas", ...)`와 `registerExtensions(["canvas"], "canvas")` 메커니즘을 동일하게 사용하여 작동합니다.
2. **커뮤니티 대표 플러그인**:
   * **Obsidian Kanban**: 마크다운을 칸반 보드로 띄우는 대표적인 `TextFileView` 변형 사례.
   * **CSV / JSON Editor**: 스프레드시트나 JSON 트리를 네이티브 탭 에디터로 띄우는 전형적인 `registerExtensions` 구현체.

---

### 💡 정리 및 핵심 시사점

1. `.outline` 커스텀 확장자 방식은 비공식 해킹이 아니라, **옵시디언 프레임워크가 공식적으로 제공하는 정식 확장 경로(`TextFileView` + `registerExtensions`)**입니다.
2. 개발자는 파일 탐색기 파일 오픈, 탭 분할, 자동 저장 타이머(`requestSave`)를 직접 만들 필요 없이 **`setViewData`와 `getViewData` 2개의 직렬화 인터페이스만 채우면 옵시디언 파일 수명주기와 완벽히 통합**됩니다.
