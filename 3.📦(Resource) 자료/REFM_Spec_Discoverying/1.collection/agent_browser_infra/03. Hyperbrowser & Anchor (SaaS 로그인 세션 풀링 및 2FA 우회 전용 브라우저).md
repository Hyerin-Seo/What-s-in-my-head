# 🔐 Hyperbrowser & Anchor (SaaS 로그인 세션 풀링 및 2FA 우회 전용 브라우저)

> [!abstract] 💡 핵심 명제
> **"진짜 알짜배기 UI 레퍼런스는 로그인 창 뒤에 숨어 있다. Hyperbrowser와 Anchor는 사용자의 인증 세션을 암호화된 풀(Pool)로 위임받아, 에이전트가 2FA 장벽을 뚫고 닫힌 SaaS 내부 화면을 캡처할 수 있게 해주는 열쇠다."**

---

### 1. 개요 및 탄생 배경
* **공식 웹사이트**: [hyperbrowser.ai](https://hyperbrowser.ai/) / [anchorbrowser.io](https://anchorbrowser.io/)
* **등장 배경**:
  * 대부분의 웹 크롤러나 AI 에이전트는 공개된 랜딩 페이지만 긁을 수 있을 뿐, **구글 닥스 본문, 노션 대시보드, 깃북 관리자 패널 같은 '진짜 핵심 UI'에는 진입조차 못 하고 로그인 창에서 멈춥니다.**
  * 매번 에이전트가 들어갈 때마다 스마트폰 2FA(2단계 인증)를 누르는 것은 자동화가 아닙니다.
  * Hyperbrowser와 Anchor는 **"인증된 세션(Authenticated Session)을 에이전트에게 안전하게 지속 공급"**하기 위해 고안되었습니다.

---

### 2. 핵심 아키텍처 및 킬러 기능

#### ① 세션 지속성 및 쿠키 풀링 (Session Persistence)
* 인간 사용자가 평소 사용하는 브라우저의 로그인 상태(쿠키, 로컬스토리지, 인증 토큰)를 안전하게 암호화된 세션 프로필로 스냅샷 저장합니다.
* 에이전트가 브라우저를 가동할 때 이 **세션 스냅샷을 즉시 주입**하여, **로그인 과정 없이 곧바로 타깃 작업 화면으로 직행**합니다.

#### ② 2단계 인증(2FA) 장벽의 영구 우회
* 브라우저 디바이스 지문(Device Fingerprint)을 세션과 일체화하여 보관하므로, 구글이나 SaaS 서비스가 "새로운 기기에서의 로그인"으로 의심하지 않아 추가 본인 인증을 요구하지 않습니다.

#### ③ 멀티 유저 세션 격리
* 서로 다른 여러 계정(예: 구글 계정 A, 깃북 계정 B, 피그마 계정 C)의 인증 프로필을 각각 격리된 컨테이너로 관리하여, 에이전트가 목적에 따라 적절한 인증 프로필을 갈아 끼우며 탐색할 수 있습니다.

---

### 3. REFM (Reference Manager) 프로덕트 적용점

1. **닫힌 SaaS 내부 핵심 인터랙션 캡처의 유일한 해법**:
   - 공개 웹사이트가 아닌, **구글 닥스의 '버전 기록' 팝업, 깃북의 'Change Request Diff 창'**처럼 로그인 장벽 뒤에 존재하는 진짜 UI/UX 화면을 에이전트가 자유자재로 드나들며 캡처할 수 있는 기반 제공.
2. **사내 프로덕트 보안 벤치마킹**:
   - 외부에 공개되지 않은 우리 팀 내부 프로젝트 화면이나 테스트 서버의 UI도 안전한 세션 위임을 통해 레퍼런스로 아카이빙 가능.
