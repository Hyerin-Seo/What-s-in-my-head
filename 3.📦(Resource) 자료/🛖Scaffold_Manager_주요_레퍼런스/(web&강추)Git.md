Git은 단순한 프로그래밍 형상 관리 도구가 아니라, **"파괴적 편집에 대한 공포(Fear of Breaking)를 완전히 없애주는 인지적 면책 장치"**입니다.

## 1. 노드 단위 로컬 커밋 & 체크포인트 (Local Commit & Checkpoint)

> **린(Rin)의 설계 피드백**: *"이런 스테이징을 모든 단계별로 자잘하게 제공해주고 싶진 않고, 차라리 개발자가 커밋을 하듯이 사용자가 명시적으로 '커밋(체크포인트)'을 찍은 경우에만 안전망으로 남아있는 방식이 훨씬 깔끔하다."*

* **Git 원형 사상**: `git commit` — 의미 있는 작업 단위를 개발자가 주도적으로 확정하여 히스토리 그래프에 영구 보존.
* **아웃라이너 적용점**:
  - 매 타이핑마다 자동 저장되는 '더러운 Undo 히스토리'와 엄격히 분리.
  - 마음에 드는 목차나 문장 상태가 되었을 때 단축키(`Ctrl+S` 또는 `Ctrl+Shift+C`)로 **`[노드 체크포인트(커밋)]`**를 생성.
  - 이후 AI에게 과감하게 수정을 맡기거나 파괴적 편집을 시도하다가 마음에 안 들면, 자잘한 실행취소를 연타할 필요 없이 **"방금 커밋 시점으로 롤백"** 버튼 하나로 즉각 복구.

---

## 2. 초록/빨강 인라인 Diff 가시화 (Visual Diff Overlay)

* **Git 원형 사상**: GitHub Pull Request & VS Code 인라인 Diff (`+` 녹색 추가 / `-` 붉은색 삭제).
* **아웃라이너 적용점**:
  - AI가 아웃라인을 다듬거나 문장을 바꿨을 때, 전체를 다시 정독하며 "어디가 바뀌었지?" 찾는 피로도 제로화.
  - 기존 노드 텍스트 위에 삭제된 부분은 **붉은색 취소선**, 추가된 부분은 **녹색 하이라이트**로 겹쳐서 표시.
  - 변경 전후의 맥락 차이를 1초 만에 직관적으로 비교·판단.

```diff
- 기존: 비즈니스 문서 작성 시 사용자가 겪는 목차 작성의 어려움 해결
+ 변경: 비전형적 글쓰기에서 뇌정지를 유발하는 백지 공포를 4단 슬롯으로 해소
```

## 3. 노드 단위 부분 승인 및 체리픽 (Cherry-pick & Accept/Reject)

* **Git 원형 사상**: `git cherry-pick` (원하는 커밋만 골라 적용) & PR 코드 리뷰 인라인 코멘트/승인.
* **아웃라이너 적용점**:
  - AI가 10개 노드를 한 번에 수정 제안했을 때, "전부 수락" 또는 "전부 거절"의 양자택일 강요 탈피.
  - 노드 옆에 붙는 `[✓ Accept]` / `[✗ Reject]` 버튼 또는 키보드 단축키(`Tab` / `Esc`)로 **마음에 드는 노드만 골라서 부분 채택**.
  - 채택되지 않은 노드는 즉시 이전 상태로 복구되고, 채택된 노드만 메인 트리에 영구 반영.

---

## 4. 2차원 캔버스 브랜칭 & 안전 병합 (Branching & Safe Merging)

* **Git 원형 사상**: GitKraken, SourceTree의 브랜치 그래프 시각화.
* **아웃라이너 적용점**:
  - 기획서나 칼럼을 쓸 때 "A안으로 전개할까? B안으로 전개할까?" 고민될 때 본문을 덮어쓰지 않음.
  - 버튼 하나로 **`[대안 브랜치 생성]`** ➔ 2차원 캔버스 위에 v1, v2, v3 갈래가 나란히 시각적 브랜치로 분기.
  - 팀원 또는 AI와 브랜치별 장단점을 비교한 뒤, 최종 채택된 브랜치를 메인 아웃라인으로 **`Merge(체크아웃)`**.

---

## 5. 노드 픽스 & 인용 잠금 (Node Lock & Pinning)

* **Git 원형 사상**: Read-only Tag, Protected Branch (보호된 브랜치).
* **아웃라이너 적용점**:
  - 이미 사람의 뇌에서 확정된 핵심 대전제 노드는 `Ctrl+L`로 **`[노드 픽스(Pin)]`** 잠금.
  - 잠긴 노드는 인용문 블록 스타일로 시각화되며, 이후 AI에게 "이 섹션 전체 다시 써줘"라고 명령해도 잠긴 노드는 손대지 않고 빈칸/미확정 노드만 재생성.
