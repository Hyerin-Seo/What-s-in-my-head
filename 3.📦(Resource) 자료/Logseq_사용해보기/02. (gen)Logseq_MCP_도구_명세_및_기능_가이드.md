# 02. Logseq MCP 도구 명세 및 기능 가이드

Logseq MCP(Model Context Protocol) 서버는 Logseq의 로컬 그래프 데이터베이스(Datascript/Datalog 기반) 엔진과 AI Agent를 직접 연결해 주는 프로토콜 인터페이스입니다.

Workflowy MCP가 세분화된 개별 조작 도구(13종)와 락(Lease) 시스템을 사용하는 것과 달리, Logseq MCP는 **그래프 조회 및 검색 도구 5종**과 **원자적 일괄 트랜잭션 도구(`upsertNodes`) 1종**으로 구성된 고밀도 아키텍처를 취하고 있습니다.

---

## 1. 아키텍처 및 데이터 모델

* **기반 아키텍처**: Clojure / Datascript 그래프 데이터베이스 연동
* **노드 엔티티 모델**:
  * `page` (페이지): 일반 문서 페이지, 저널 페이지
  * `block` (블록): 페이지에 속한 개별 불릿 단위 본문 노드
  * `tag` (태그): 계층 및 상속 관계(`extends`)를 가질 수 있는 분류 노드 (Logseq에서는 페이지와 동일 취급)
  * `property` (프로퍼티): 데이터 타입 및 카디널리티(`:one`, `:many`)를 갖는 속성 스키마 노드
* **식별자 체계**: 표준 UUID 문자열을 기본 식별자로 사용하며, 페이지는 고유 이름(Title)으로도 지정 가능합니다.

---

## 2. 제공 도구(Tool) 6종 상세 명세

### A. 그래프 탐색 및 조회 도구 (5종)

#### 1. `listPages` (전체 페이지 목록 조회)
* **역할**: 그래프에 존재하는 모든 페이지 목록을 가져옵니다.
* **파라미터**:
  * `expand` *(boolean, 선택)*: `true` 설정 시 페이지별 상세 메타데이터(수정일자, 속성 등)를 함께 반환합니다.
* **용도**: 그래프의 전체 지식 구조를 조감하거나 특정 페이지의 존재 유무를 확인할 때 사용합니다.

#### 2. `getPage` (페이지 본문 및 블록 트리 조회)
* **역할**: 지정된 페이지의 본문 텍스트와 하위 블록 구조 전체를 조회합니다.
* **파라미터**:
  * `pageName` *(string, 필수)*: 조회할 페이지의 이름(Title) 또는 고유 UUID
* **특징**: Logseq에서는 태그와 프로퍼티 역시 내부적으로 페이지 엔티티이므로, 이 도구로 태그 및 프로퍼티의 상세 정보를 동일하게 조회할 수 있습니다.

#### 3. `searchBlocks` (키워드 블록 전문 검색)
* **역할**: 그래프 전체를 대상으로 특정 검색어가 포함된 블록들을 찾아냅니다.
* **파라미터**:
  * `searchTerm` *(string, 필수)*: 검색할 키워드 문자열
* **용도**: 페이지 위치를 알지 못하더라도 특정 개념이나 작업 항목이 포함된 블록의 위치와 UUID를 신속하게 추적할 때 활용합니다.

#### 4. `listTags` (전체 태그 목록 조회)
* **역할**: 그래프 내에 정의된 모든 태그 목록을 조회합니다.
* **파라미터**:
  * `expand` *(boolean, 선택)*: `true` 설정 시 태그의 부모 상속 구조(`class-extends`) 및 태그 전용 속성(`class-properties`) 상세를 포함합니다.

#### 5. `listProperties` (전체 프로퍼티 스키마 조회)
* **역할**: 그래프에 등록된 모든 속성(Property) 목록과 해당 스키마를 조회합니다.
* **파라미터**:
  * `expand` *(boolean, 선택)*: `true` 설정 시 프로퍼티 타입(`property-type`), 카디널리티(`property-cardinality`: `:one` 또는 `:many`), 허용 태그 목록(`property-classes`) 등의 상세 스펙을 반환합니다.

---

### B. 일괄 트랜잭션 및 편집 도구 (1종)

#### 6. `upsertNodes` (원자적 노드 일괄 생성 및 수정)
* **역할**: 페이지, 블록, 태그, 프로퍼티의 신규 생성(`add`)과 기존 수정(`edit`)을 **단일 트랜잭션 배치(Batch)**로 실행하는 핵심 뮤테이션 도구입니다.
* **호출 원칙**: 토큰 효율성과 데이터 무결성을 위해 사용자 요청 1회당 **최대 1번만 호출**하는 것을 원칙으로 합니다.

##### 주요 파라미터
* `dry-run` *(boolean, 선택)*: 실제 데이터베이스에 변경 사항을 커밋하지 않고 유효성 검증만 시뮬레이션합니다.
* `operations` *(array, 필수)*: 일괄 실행할 연산 객체들의 배열

##### 개별 연산 객체 필드
| 필드명 | 타입 | 설명 |
| :--- | :--- | :--- |
| `operation` | string (`"add"` \| `"edit"`) | 연산 종류 |
| `entityType` | string (`"page"` \| `"block"` \| `"tag"` \| `"property"`) | 대상 노드 엔티티 타입 |
| `id` | string \| null | • `edit` 시: 수정 대상의 실제 UUID<br>• `add` 시: 동일 배치 내 후속 연산에서 참조할 임시 ID (예: `"temp-Inbox"`) |
| `data` | object | 노드 세부 속성 맵 (아래 상세 참조) |

##### `data` 필드 상세 키
* `:title` *(string)*: 페이지/태그/프로퍼티의 이름 또는 블록의 본문 텍스트
* `:page-id` *(string)*: 블록을 추가할 때 **소속될 페이지의 UUID** (또는 배치 내 선행 생성된 페이지의 임시 ID)
* `:tags` *(array)*: 적용할 태그들의 UUID 목록
* `:property-type`: 프로퍼티의 데이터 타입
* `:property-cardinality`: 카디널리티 (`:one` 또는 `:many`)
* `:property-classes`: 프로퍼티가 허용하는 태그/클래스 목록
* `:class-extends`: 부모 상위 태그 목록
* `:class-properties`: 해당 태그가 갖는 프로퍼티 정의 목록

## 3. `upsertNodes` 입력 예시 (Clojure EDN / JSON)

### 예시 1: 기존 페이지에 새 블록 추가 및 페이지 제목 수정
```json
{
  "operations": [
    {
      "operation": "add",
      "entityType": "block",
      "id": null,
      "data": {
        "page-id": "119268a6-704f-4e9e-8c34-36dfc6133729",
        "title": "새로 추가된 스캐폴딩 뼈대 블록"
      }
    },
    {
      "operation": "edit",
      "entityType": "page",
      "id": "119268a6-704f-4e9e-8c34-36dfc6133729",
      "data": {
        "title": "수정된 페이지 제목"
      }
    }
  ]
}
```

### 예시 2: 신규 페이지 생성과 동시에 하위 블록 및 태그 연결 (임시 ID 참조)
```json
{
  "operations": [
    {
      "operation": "add",
      "entityType": "page",
      "id": "temp-Inbox",
      "data": {
        "title": "Inbox"
      }
    },
    {
      "operation": "add",
      "entityType": "block",
      "id": null,
      "data": {
        "page-id": "temp-Inbox",
        "title": "새 작업 항목",
        "tags": ["00000002-1282-1814-5700-000000000000"]
      }
    }
  ]
}
```

## 4. Workflowy MCP vs Logseq MCP 비교

| 항목 | **Workflowy MCP** | **Logseq MCP** |
| :--- | :--- | :--- |
| **도구 수** | 13종 (세분화 도구군) | 6종 (고밀도 압축 도구군) |
| **수정 방식** | `tree_patch` 기반 트리 이동/삭제/수정 | `upsertNodes` 기반 일괄 트랜잭션 배치 |
| **동시성 제어** | Lease 락 획득/갱신/반환 (`lease_acquire` 등 4종) | 단일 일괄 호출 및 `dry-run` 검증 |
| **UI 피드백** | 전용 토스트 알림(`message_success`) 및 줌 이동 | Logseq 백엔드 데이터베이스 직결 |
| **스키마 메타데이터** | 텍스트 서식 태그 중심 | 정식 `property`, `tag` 메타데이터 조회 지원 |

## 5. AI Agent 권장 작업 프로토콜

1. **스키마 및 태그 파악 (Schema Discovery)**:
   * `listProperties` 및 `listTags`를 먼저 조회하여 대상 그래프의 기존 분류 규칙 및 허용된 프로퍼티 스키마를 확인합니다.
2. **대상 중복 확인 (Idempotency Check)**:
   * 페이지를 새로 만들거나 블록을 추가하기 전, `getPage` 또는 `searchBlocks`를 호출하여 이미 존재하는 페이지/블록인지 검사합니다.
3. **안전성 검증 (Dry-run Simulation - 대규모 변경 시)**:
   * 복합 연산 시 `upsertNodes`에 `dry-run: true`를 지정하여 데이터베이스 반영 전 유효성 검증을 사전 수행합니다.
4. **원자적 일괄 커밋 (Atomic Execution)**:
   * 페이지 생성과 하위 블록 배치, 태그 연결을 단 한 번의 `upsertNodes` 호출에 묶어 전송함으로써 트랜잭션 무결성을 확보합니다.
