## 📝 중앙 에디터 본문

### 🔴 [필수] 2-1. 단 하나의 발상 전환 명제
우리는 가장 먼저 굳어진 상식을 뒤집었습니다.  
**"코드를 사람이 짜지 않게 만들자."**  
사람이 화면 요소를 하나하나 찾아 코딩하는 방식을 완전히 버리고, 사람은 '무엇을 검사할지' 의도만 일상 언어로 말하면 실제 실행 코드는 도구가 스스로 짜게 했습니다.

### 🔴 [필수] 2-2. BEFORE vs AFTER 극적 대조

| 구분 | 예전 방식 (Before) | 새로운 방식 (After: 토스닥터 V2) |
| :--- | :--- | :--- |
| **사람의 역할** | 화면을 열어 버튼 위치를 찾고 절차적으로 코드 타이핑 | **"송금 화면에서 1만 원을 보낸다" 일상 시나리오만 작성** |
| **도구의 역할** | 사람이 짠 코드대로 맹목적인 클릭만 수행 | **시나리오를 읽고 실제 화면을 보며 코드를 스스로 생성** |
| **작업 시간** | 테스트 1개당 수십 분의 코딩 소요 | **3줄짜리 시나리오 작성으로 1분 만에 완료** |

---

### ⚪ [선택] 2-3. 실제 입력 시나리오 예시
```gherkin
시나리오: 송금 정보 입력하기
  Given: 송금 퍼널에 진입한다
  When: 받는 계좌와 보낼 금액을 입력한다
  Then: 송금 확인 화면이 노출된다
```

### ⚪ [선택] 2-4. 팀의 역할 분담 원칙
> *"사람은 '무엇을 검증할지(의도)'만 고민하고, '어떻게 구현할지(코드)'는 도구에게 온전히 맡긴다."*
