# Vibe Writing의 진정한 지향점 — 문장 생성을 넘어 시각 뼈대(Visual-First)와 Angling 큐레이션으로

> **핵심 테제**:  
> **"글쓰기 AI 도구의 승패는 '얼마나 문장을 청산유수로 써주는가'에 있지 않다."**  
> **"피로한 독자가 글을 굳이 읽지 않고도 1초 만에 납득할 '시각 뼈대(Visual Spine)'를 세워주고, 레퍼런스를 바탕으로 어떤 승부수(Angling)로 독자의 결핍을 찌를지 우선순위를 큐레이션해 주는가에 있다."**

---

## 🚫 1. 현행 Vibe Writing 도구들의 맹점: "텍스트 편향의 늪"

최근 급부상한 Vibe Writing 도구들(AudioPen, Type.ai, Lex.page, Oasis 등)은 타이핑의 고통을 줄이고 생각을 덤프하는 데 집중하고 있습니다. 하지만 이 도구들은 치명적인 **'텍스트 편향(Text-Centric Trap)'**에 갇혀 있습니다.

| 기존 Vibe Writing 도구들의 한계 | 결과적으로 발생하는 문제 |
| :--- | :--- |
| **줄글 텍스트만 청산유수로 생성** | 독자는 긴 텍스트를 읽을 여유가 없음 ➔ 3초 만에 이탈 |
| **'어조(Tone)'나 '길이' 조절에만 집착** | 글의 문체는 그럴듯하지만, 독자의 결핍을 찌르는 승부수가 없음 |
| **레퍼런스를 '문체 복제용'으로만 소모** | 레퍼런스가 왜 성공했는지 '물리적 우선순위'를 추출하지 못함 |

결국 기존 툴들은 아무리 Vibe를 살려봤자, 독자 입장에서는 **"읽기 피로한 AI 텍스트 덩어리"**를 배출하는 데 머물러 있습니다.

---

## 📸 2. 지향점 ①: Text-First가 아닌 `Visual-First (이미지 뼈대 우선주의)`

> **"잘 쓴 블로그는 '글을 읽을 필요가 없도록' 만드는 블로그다. 책이나 보고서가 아니니까."**

블로그의 독자는 글을 정독(Reading)하지 않고 스크롤을 내리며 훑어봅니다(Scanning).  
따라서 우리의 스캐폴더는 텍스트를 채우는 서랍장이 아니라, **스크롤을 내릴 때 시선을 꽂아주는 '비주얼 앵커(Visual Anchor)의 징검다리'**를 먼저 놓아주어야 합니다.

```text
[ 우리가 추구하는 Visual-First 스캐폴딩 흐름 ]

1. [시각적 킬러 앵커 먼저 배치]
   ├── [앵커 1] ⚖️ Before vs After 극적 대조 표 (과거 고통 vs 현재 해결)
   ├── [앵커 2] 📸 실제 문제 화면 스크린샷 (계좌창 가린 툴팁 캡처)
   └── [앵커 3] 📉 실패 및 복구 다이어그램 (순서도 및 금지선)
         │
         ▼
2. [텍스트는 시각 장치 사이를 잇는 2~3줄 캡션으로 가볍게 완성]
   └─▶ 작성자는 긴 글을 쓸 필요 없이, 사진 밑에 코멘트만 달아 10분 만에 글 완성!
```

## 🎯 3. 지향점 ②: 모호한 컨설팅 용어가 아닌 `Angling 우선순위 큐레이션`

> **"피로한 독자의 시선과 결핍을 어떤 각도로 관통할 것인가(Angling)."**

'실무 병목형', '기술 돌파구형' 같은 모호한 마케팅 외계어는 작성자에게 불필요한 인지 부하만 가중시킵니다.  
우리가 지향하는 Angling은 레퍼런스를 분석하여 **"무엇을 1순위로 대문짝만하게 보여주고, 독자의 피로를 덜기 위해 무엇을 과감히 버렸는가(Pruning)"**를 물리적으로 큐레이션해 주는 조준경입니다.

```text
[ 레퍼런스 분석 기반 Angling 큐레이션 화면 ]
• 타깃 독자와 결핍 : "매주 반복되는 배포 점검으로 지친 실무자 (손동작 반복에서 해방)"
• 레퍼런스의 1순위  : [Before vs After 대조표] ➔ 30분 코딩 vs 1분 시나리오
• 레퍼런스의 2순위  : [실제 툴팁 닫힘 캡처 화면] ➔ 현장 증거
• 레퍼런스가 버린 것: [장황한 서버 아키텍처 다이어그램] ➔ 과감히 생략 (피로 방지)
👉 "당신의 글도 [Before-After 표]와 [실제 알림 캡처] 2개 중심으로 뼈대를 잡으시겠습니까?"
```

## 💡 4. 최종 제품 비전: 문장 생성기가 아닌 '와꾸 시뮬레이터'

우리의 도구는 단어를 대신 써주는 '대필 작가'가 아닙니다.  
도면에 선언된 `[[Decision 01 — 우리 도구는 시뮬레이터다]]` 사상 그대로, **"와꾸(구조)가 안 잡힌 상태에서, 피로한 독자를 관통할 앵글과 시각 뼈대를 같이 시뮬레이션해 주는 전략적 파트너"**가 되는 것이 본 제품의 유일한 지향점입니다.

1. **레퍼런스를 넣으면**: 독자를 관통한 핵심 킬러 앵커와 우선순위를 1초 만에 큐레이션하고,
2. **원샷 덤프를 던지면**: 좌측 빌더에 [이미지 앵커 + 대조 박스]가 이미 꽂힌 상태로 세팅되며,
3. **사용자는**: 복잡한 이론 공부 없이 사진 한 장 던지고 캡션 두 줄 달아 최고 품질의 글을 낚아챕니다.
