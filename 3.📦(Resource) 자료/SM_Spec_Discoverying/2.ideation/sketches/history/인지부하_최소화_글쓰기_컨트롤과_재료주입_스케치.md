# 인지부하 최소화 글쓰기 컨트롤과 재료 주입 스케치

> **핵심 테제**:  
> **"사용자는 글쓰기 공학자가 아니다. 복잡한 메타 체크리스트를 읽고 공부하게 만들면 창을 닫아버린다."**  
> 레퍼런스에서 추출한 정교한 규칙(DoD)은 시스템의 엔진 룸 안으로 숨기고, 사용자에게는 **오직 3가지 초경량 조작 장치(스위치, 대조박스, 드롭존)**만 제공하여 인지 부하를 제로(0)로 만듭니다.

---

## 🚫 1. 무엇을 버렸는가? (안티패턴 제거)

| 과거의 피로한 방식 (인지 과부하)                 | 새롭게 정의한 방식 (인지 부하 제로)                     |
| :---------------------------------- | :---------------------------------------- |
| • 10여 개의 세부 체크리스트를 나열하고 일일이 읽게 함    | • **스마트 디폴트**: 이미 최적의 5개 카드가 켜진 채로 시작     |
| • "이 항목을 픽(pick)하시겠습니까?"라며 메타 선택 강요 | • **원클릭 토글**: 필요 없으면 `[ON/OFF]` 스위치로 딸깍 끔 |
| • 각 항목이 왜 필요한지 심오한 글쓰기 이론을 설명       | • **직관적 빈칸**: 에디터에 놓인 상자에 단어 2개 툭 넣고 끝    |

---

## 🎛️ 2. 사용자가 쥐게 되는 3대 직관적 Control (조작 장치)

사용자는 글을 쓸 때 깊은 이론을 고민하지 않고, 눈앞에 보이는 다음 **3가지 UI 조작**만 수행합니다.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [사용자가 실제로 조작하는 3대 초경량 Control]                          │
│                                                                        │
│ 1. 🎚️ ON / OFF 토글       ➔ "실패담 쓸 거 없네? 스위치 딸깍 끄기"     │
│ 2. ⚖️ 대조 박스 빈칸 채우기 ➔ "[ 과거 고통 ] vs [ 현재 해결 ] 단어 입력"│
│ 3. 📥 사진 툭 던지기 (Drop) ➔ "점선 상자에 슬랙 캡처 이미지 툭 드롭"   │
└────────────────────────────────────────────────────────────────────────┘
```

### ① Control 1: [ON / OFF 토글 스위치] — 생각 없이 켜고 끄기
- 좌측 탐색기 카드의 우측에 단순한 토글 스위치 `[ON]`이 기본으로 켜져 있습니다.
- 사용자 생각: *"어? 난 이번 프로젝트에서 딱히 실패한 거 없는데?"*
- **사용자 행동**: `[04. 시행착오]` 카드의 스위치를 `[OFF]`로 딸깍 누름.
- **결과**: 복잡한 이론이나 체크리스트 검토 없이 4번 카드가 스르륵 숨겨지고, 글은 4개 블록으로 깔끔하게 재정렬됩니다.

### ② Control 2: [대조 박스] — 질문 없이 빈칸에 단어 넣기
- 2번 카드(`핵심아이디어`)를 열면 복잡한 서술형 질문 대신 **직관적인 2단 상자**만 놓여 있습니다:
  ```text
  ┌─────────────────────────────┐   ┌─────────────────────────────┐
  │ [ 예전의 고통 / 과거 방식 ] │   │ [ 지금의 해결 / 새로운 방식 ]│
  │ 회의 1시간에 정리 2시간 야근│ ➔ │ 3줄 핵심 요약 슬랙 발송 1분 │
  └─────────────────────────────┘   └─────────────────────────────┘
  ```
- **사용자 행동**: 과거와 현재의 단어 2개만 상자에 적어 넣으면, 시스템이 자동으로 유려한 Before-After 대조 문장으로 엮어냅니다.

### ③ Control 3: [사진 드롭존] — 규격 설명 없이 이미지 툭 던지기
- 3번 카드(`해결방안`)에는 긴 설명문 대신 점선 드롭존이 껌뻑입니다:
  ```text
  ┌ - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - ┐
  │  📷 여기에 슬랙 알림 캡처나 화면 스크린샷을 끌어다 놓으세요   │
  └ - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - ┘
  ```
- **사용자 행동**: 슬랙에서 캡처한 이미지 파일을 마우스로 툭 던져 넣으면 끝입니다.

## ⚡ 3. 재료가 주입되는 실전 워크플로우 (1초 완성)

사용자가 자리에 앉아 글을 완성하기까지 겪는 실제 경험입니다:

```text
1. 사용자의 원샷 덤프 (One-Shot Dump)
   👤 "회의 에이전트 도입기 쓸 거야. 1시간 회의하고 2시간 정리하던 걸
       잡담 필터링 넣어서 1분 만에 3줄 요약하게 바꿨거든."
            │
            ▼ (시스템이 토스닥터 V2 규격으로 1초 만에 자동 분배)
2. 좌측 빌더 스캐폴더 완성 (Default ON)
   [●] 01. 도입배경    ➔ (1시간 회의 2시간 야근 채워짐)
   [●] 02. 핵심아이디어 ➔ (Before-After 대조 박스 채워짐)
   [●] 03. 해결방안    ➔ (잡담 필터링 채워짐 / [📷 사진 자리] 점선 깜빡임)
   [○] 04. 시행착오    ➔ (말씀 안 하셔서 비어있음 / [ON/OFF] 스위치 대기)
   [●] 05. 도입결과    ➔ (1분 만에 공유 채워짐)
            │
            ▼ (사용자의 초경량 마감 조작)
3. 사용자의 30초 컨트롤
   - 3번에 슬랙 캡처 이미지 툭 드롭 (사진 채움)
   - 4번 시행착오 스위치 [OFF] 딸깍 누름 (제외 완료)
   - [발행하기] 클릭 ➔ 고품질 아티클 완성!
```

## 💡 결론: 엔진의 고도화, 인터페이스의 단순화

- **시스템(엔진)**: 토스닥터 레퍼런스의 5대 뼈대, 필수/선택 세부 항목, Before-After 문법, 증거 우선주의 등 심오한 지식을 100% 품고 백그라운드에서 동작합니다.
- **사용자(인터페이스)**: 심오한 지식을 단 1줄도 공부하지 않고, 오직 **`[스위치 딸깍]`, `[단어 2개 입력]`, `[사진 툭 던지기]`**만으로 최상급 기술 블로그를 완성합니다.
