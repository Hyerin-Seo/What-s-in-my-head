# 레퍼런스 기반 기술 아티클 집필 — 사전 필수 재료와 TODO 체크리스트

> **핵심 테제**:  
> **"요리를 시작하기 전 도마 위에 식재료를 먼저 꺼내놓듯, 글을 쓰기 전 '내 프로젝트에서 긁어와야 할 재료 바구니'가 미리 정의되어야 백지 공포 없이 5분 만에 글이 조립된다."**  
> 토스닥터 레퍼런스를 분해하여 도출한 **5대 섹터별 필수 재료(Fact) 및 사전 TODO 규격**입니다.

---

## 🧺 기술 아티클 5대 섹터별 사전 재료 바구니 (Ingredients Checklist)

글을 쓰기 위해 자리에 앉았을 때, 모니터 메모장에 다음 **5가지 재료 묶음**이 준비되어 있으면 글쓰기는 '창작의 고통'이 아니라 '블록 조립'이 됩니다.

```text
[ 5대 필수 재료 바구니 ]
├── 1. [도입배경 재료] ➔ 과거에 낭비되던 구체적 숫자(시간/횟수) + 기존 도구의 실패 사건
├── 2. [아이디어 재료] ➔ 상식을 뒤집은 우리 팀의 1원칙 문장 + Before/After 대비표 데이터
├── 3. [해결방안 재료] ➔ 실제 작동/에러 증거 스크린샷 1장 + 비용을 아낀 3단계 처리 흐름
├── 4. [시행착오 재료] ➔ 가장 뼈아팠던 실수 1건의 사건 기록 + 다시는 안 할 절대 금지선(규칙)
└── 5. [도입결과 재료] ➔ 팀원이 얻게 된 심리적 여유(인용구) + 다음 버전(로드맵)의 가칭
```

## 📋 세부 섹터별 사전 TODO 체크리스트

### 1️⃣ 01. 도입배경을 쓰기 위한 재료 TODO
- [ ] **[수치 재료] 과거의 반복 피로를 증명할 숫자 1개 확보**  
  *(토스 예시: 매주 5~7개 RC 빌드, 수백 번 화면 클릭 / 회의록 예시: 1시간 회의에 2시간 타이핑)*
- [ ] **[사건 재료] 기존 방식이나 도구가 무용지물이 되었던 구체적 에피소드 1개**  
  *(토스 예시: 버튼명이 '확인'에서 '확인하기'로 바뀌어 테스트 와르르 깨짐 / 회의록 예시: 10페이지 줄글 녹취록 나와 아무도 안 읽음)*
- [ ] **[용어 재료] 글에 등장할 사내 약어 1~2개에 대한 쉬운 일상 비유 정리**  
  *(토스 예시: RC 빌드 = 최종 점검용 앱, 스모크 테스트 = 불 땠을 때 연기 나는지 보는 기초 점검)*

---

### 2️⃣ 02. 핵심아이디어를 쓰기 위한 재료 TODO
- [ ] **[명제 재료] 팀이 세운 '단 하나의 발상 전환' 선언문 1줄**  
  *(토스 예시: "사람은 코드를 한 줄도 짜지 않는다" / 회의록 예시: "완벽한 전체 녹취록을 포기한다")*
- [ ] **[대조 재료] 과거(Before)와 현재(After)의 차이를 보여줄 3가지 대조 항목**  
  - 사람의 역할 변화: 과거 vs 현재
  - 도구의 역할 변화: 과거 vs 현재
  - 소요 시간의 변화: 과거 vs 현재
- [ ] **[예시 재료] 사람이 실제로 입력하는 직관적인 시나리오 3줄 샘플**  
  *(토스 예시: "송금 화면 진입 ➔ 금액 입력 ➔ 확인 노출" 3줄)*

---

### 3️⃣ 03. 해결방안을 쓰기 위한 재료 TODO
- [ ] **[증거 캡처] 실제 작동 장면이나 에러를 뚫고 지나간 스크린샷 1장 확보**  
  *(토스 예시: 계좌 입력창을 가린 공유 툴팁을 스마트파인더가 감지해 닫아내는 실제 로그 화면 / 회의록 예시: 슬랙에 1분 만에 도착한 3줄 요약 알림 캡처)*
- [ ] **[돌파구 재료] 가장 골치 아팠던 돌발 장애물을 우회한 기술적 장치 1개**  
  *(토스 예시: 화면 덮은 팝업을 치우는 심폐소생 / 회의록 예시: 잡담과 스몰토크를 걷어내는 노이즈 필터링)*
- [ ] **[전략 재료] 리소스(비용/시간) 낭비를 막기 위한 2~3단계 처리 흐름도**  
  *(토스 예시: 1단계 겉면 탐색 ➔ 2단계 심층 탐색 ➔ 3단계 사람에게 질문)*

---

### 4️⃣ 04. 시행착오를 쓰기 위한 재료 TODO
- [ ] **[실패 사건] 개발/도입 과정에서 겪었던 가장 아찔했던 낭패 사건 1건**  
  *(토스 예시: AI에게 전체 UI 넘기다 토큰 비용 폭탄, 비슷한 요소 누르다 5스텝 연쇄 거짓 성공 / 회의록 예시: 농담을 중요 안건으로 오인해 서버 포맷 소동)*
- [ ] **[방지선 재료] 그 실패를 겪고 나서 팀이 세운 절대 금지선(안티패턴) 1개**  
  *(토스 예시: "검증 단계에서는 절대 similar-match 눈속임 통과를 금지한다" / 회의록 예시: "모호한 발언은 억지로 지어내지 않고 [확인 필요]로 넘긴다")*

---

### 5️⃣ 05. 도입결과를 쓰기 위한 재료 TODO
- [ ] **[가치 재료] 업무 시간 단축 외에 팀원들이 얻게 된 심리적 여유(정성적 변화)**  
  *(토스 예시: 충혈되던 눈 ➔ 깊은 사용성 고민, '불안 대신 확신' / 회의록 예시: 타이피스트 ➔ 진짜 회의 발언자로 참여)*
- [ ] **[인터뷰 재료] 동료의 안도감이 묻어나는 실제 한마디 인용구 1개**  
  *(토스 예시: "배포 빌드 나올 때마다 긴장하던 과거로 절대 못 돌아간다")*
- [ ] **[로드맵 재료] 이 성공을 발판 삼아 나아갈 차세대 도구/프로젝트의 이름**  
  *(토스 예시: 전체 앱 건강을 돌보는 '토스체커' / 회의록 예시: Jira 티켓 자동 생성 연동)*

## 🔄 워크스페이스 내 작동 메커니즘

1. **글쓰기 시작 전 (재료 수집 단계)**:  
   - 사용자는 이 체크리스트를 보며, 슬랙 대화록이나 개인 메모장에서 위 항목들을 복사해 옵니다.
2. **좌측 빌더 생성 단계 (스캐폴딩)**:  
   - 준비된 재료를 툭 던지면, 시스템이 좌측 카드 스택의 빈칸에 1초 만에 배치합니다.
3. **완성도 검증 단계 (DoD)**:  
   - 글을 다 쓴 뒤 우측 인스펙터에서 이 TODO 체크리스트에 초록 불이 다 들어왔는지 확인하고 발행합니다.
