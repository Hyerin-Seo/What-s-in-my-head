기획(Why & What)과 설계(How & Detail)의 적정 깊이를 결정하는 문제는 단순한 감각이 아니라, 지난 50년간 시스템 공학, 소프트웨어 공학, 복잡계 의사결정론의 **세계적 거장들과 국제 표준(ISO/IEEE)이 수학적·경험적으로 공식화해 온 핵심 과제**입니다.

이 분야의 저명한 연구진과 표준 기구들이 정립한 **5대 핵심 이론과 판별 공식**을 정리합니다.

---

### 1. 콕번의 크리스탈 매트릭스 (Alistair Cockburn's Crystal Grid)
> **국제 애자일 선언문 공동 작성자 / 소프트웨어 방법론의 거장**

알리스테어 콕번은 설계와 방법론의 무게를 결정하는 **단 2개의 절대 축**을 공식화했습니다:

```text
치명도 (Criticality)
  ▲
L │  생명 위험 (Life)             ➔ [극단적 정밀 선행 설계 (ISO/의료/항공)]
E │  치명적 손실 (Essential Money)
D │  재정적 손실 (Discretionary)
C │  단순 불편 (Comfort)          ➔ [가벼운 대화와 즉시 실행 (Crystal Clear)]
  └────────────────────────────► 팀 규모 (Team Size)
       1~6명    7~20명   21~40명 ...
```

* **축 1: 팀 규모 (Team Size)**:
  * 인원이 늘어날수록 의사소통 채널은 $\frac{N(N-1)}{2}$로 폭증합니다. 6명을 넘어가면 암묵적 교감이 불가능해지므로 문서를 통한 규격화가 강제됩니다.
* **축 2: 잠재적 결함의 치명도 (Criticality)**:
  * **C (Comfort)** : 버그가 나도 사용자가 약간 불편하고 끝남 ➔ **설계 최소화 (대화 중심)**
  * **L (Life) / E (Essential Money)** : 결함 발생 시 회사가 파산하거나 생명이 위태로움 ➔ **방어적 정밀 설계 100% 필수**
* **결론**: 팀의 규모와 실패 시 잃는 대가의 곱에 따라 설계의 무게(투명 ➔ 노랑 ➔ 주황 ➔ 빨강)가 결정됩니다.

### 2. 스노든의 키네핀 프레임워크 (Dave Snowden's Cynefin Framework)
> **IBM 인지비즈니스 연구소 디렉터 / 복잡계 의사결정 이론의 표준**

데이브 스노든은 작업이 속한 **'인과관계의 공간(Problem Space)'**에 따라 기획과 설계의 형식이 완전히 달라진다고 규정했습니다.

| 영역 (Domain) | 인과관계의 성격 | 작업 방식 | 기획·설계의 형태 |
| :--- | :--- | :--- | :--- |
| **명확 (Clear)** | 원인과 결과가 자명함 | 감지 ➔ 분류 ➔ 대응 | **표준운영절차 (SOP / 매뉴얼)** |
| **복잡 (Complicated)** | 전문가의 정밀 분석이 필요함 | 감지 ➔ **분석** ➔ 대응 | **선행 정밀 분석 및 아키텍처 도면** |
| **복합 (Complex)** | 예측 불가, 사후에만 이해됨 | **실험** ➔ 감지 ➔ 대응 | **가설 기반 스캐폴딩 / 프로토타입** |
| **혼돈 (Chaotic)** | 인과관계 붕괴, 불타는 중 | **즉각 행동** ➔ 감지 | **설계 생략, 즉각적 위기 진압** |

* **거장의 시각**:  
  분석으로 풀 수 있는 문제(Complicated: 다리 건설, DB 마이그레이션)는 **선행 설계**가 답이지만, 해보기 전에는 알 수 없는 문제(Complex: 신제품 론칭, 사용자 반응)에서 선행 설계를 길게 잡는 것은 **인지적 오만(Cognitive Arrogance)**입니다.

### 3. 라이너트센의 제품 개발 흐름 원리 (Donald Reinertsen)
> **MIT/Caltech 출신 / 린 제품 개발(Lean Product Development)의 최고 권위자**

제조업의 린(Lean)을 지식 작업으로 전환한 도널드 라이너트센은 경제학적 모델로 설계의 경제성을 증명했습니다.

* **지연 비용 (Cost of Delay, CoD)**:
  * "이 기능/산출물이 하루 늦게 배포될 때 타버리는 경제적 가치는 얼마인가?"
  * 지연 비용이 극도로 높은 환경에서는 완벽한 설계를 하느라 낭비하는 시간 비용이 설계 부실로 인한 재작업 비용을 압도합니다.
* **배치 사이즈 (Batch Size)와 대기 행렬**:
  * 한 번에 기획하고 설계하는 덩어리(Batch)가 클수록 리드타임이 기하급수적으로 늘어납니다.
  * **거장의 시각**: "설계를 없애라는 것이 아니라, **설계와 검증의 덩어리(배치)를 극단적으로 잘게 쪼개서(Micro-outline / Slicing) 피드백 루프를 10배 빠르게 회전시켜라.**"

### 4. 프레더릭 브룩스의 복잡성 이론 (Fred Brooks)
> **튜링상 수상자 / 『맨먼스 미신』, 『은탄환은 없다』 저자**

컴퓨터 과학의 거장 브룩스는 모든 작업의 복잡성을 두 가지로 쪼갰습니다:

1. **본질적 복잡성 (Essential Complexity)**:
   * 사용자의 실제 고통, 해결하려는 비즈니스 도메인의 논리, 데이터 간의 필연적 관계.
   * 기획과 설계가 온전히 싸워야 할 유일한 대상입니다.
2. **우발적 복잡성 (Accidental Complexity)**:
   * 다루기 불편한 도구, 타이핑 오타, 복잡한 프레임워크 설정, 서투른 조작감.
* **개념적 무결성 (Conceptual Integrity)**:
  * 브룩스는 **"시스템 설계에서 가장 중요한 것은 단 하나의 일관된 개념적 무결성이다"**라고 선언했습니다. 여러 사람의 잡다한 아이디어를 타협해서 섞은 설계보다, 주 아키텍트가 일관되게 밀어붙인 도면이 시스템을 살립니다.

### 5. 배리 뵘의 위험 주도 모델 (Barry Boehm's Risk-Driven Principle)
> **소프트웨어 공학의 선구자 / COCOMO 및 나선형(Spiral) 모델 창시자**

배리 뵘 교수는 방법론 전쟁(워터폴 vs 애자일)을 종식시키며 다음과 같은 공식 판별식을 제시했습니다:

$$\text{필요한 설계의 양} \propto \text{프로젝트가 직면한 리스크(Risk)의 크기}$$

* **아키텍처/구조 리스크가 크다** ➔ 선행 아키텍처 설계를 깊게 판다.
* **요구사항/사용자 선호 리스크가 크다** ➔ 기획 도면을 줄이고 즉시 프로토타입을 배포한다.
* **일정 리스크가 크다** ➔ 스코프를 쪼개고 슬라이싱 설계를 한다.
* **거장의 시각**: "설계의 목적은 '완벽한 서류'를 남기는 것이 아니라, **'가장 치명적인 리스크를 사전에 소각(Burn down)하는 것'**이다."

### 🏛️ 거장들의 시각과 4대 차원의 1:1 매핑

우리가 정립한 4대 차원 진단 프레임워크는 학계 거장들의 핵심 이론과 다음과 같이 완벽히 일치합니다:

| 4대 차원 | 학계 및 표준의 공식 개념 | 핵심 거장 / 표준 |
| :--- | :--- | :--- |
| **1. 결과물 (What)** | 잠재적 결함의 치명도 (Criticality) & 매체 물성 | Alistair Cockburn (Crystal) |
| **2. 프로세스 (How)** | 문제 공간의 인과관계 (Complicated vs Complex) | Dave Snowden (Cynefin) |
| **3. 작업 팀 (Who)** | 개념적 무결성 (Conceptual Integrity) & 의사소통 비용 | Fred Brooks (Turing Award) |
| **4. 환경 압력 (When)** | 지연 비용 (Cost of Delay) & 위험 주도 공학 | Donald Reinertsen & Barry Boehm |
