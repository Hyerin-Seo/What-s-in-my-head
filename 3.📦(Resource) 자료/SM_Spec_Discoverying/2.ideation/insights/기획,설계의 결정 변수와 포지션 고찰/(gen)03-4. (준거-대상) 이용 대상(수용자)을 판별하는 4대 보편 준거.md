기획(Planning)의 제1 정의는 **"누구의 어떤 결핍을 채울 것인가?"**이며, 설계(Design)의 모든 인터페이스는 **"그 대상의 뇌(혹은 시스템)에 어떻게 꽂힐 것인가?"**를 기준으로 결정됩니다.

결과물을 이용할 **'대상(수용자 / Consumer)'이 기획과 설계를 강제하는 4대 보편적 준거**는 다음과 같습니다.

---

### 1. 수용자의 거리: 나 자신(Self)인가, 타자(Others)인가?
> **"내가 쓰고 치울 것인가, 남의 손에 쥐여줄 것인가?"**

기획과 설계에서 **'친절함(설명, UI, 에러 핸들링)의 비용'**을 결정하는 1차 분기점입니다.

* **나 자신 (Self-use)**:
  * 나 혼자 볼 옵시디언 메모, 나 혼자 돌릴 스크립트.
  * 친절한 안내 문구, 예외 처리 팝업, 세련된 비주얼 디자인 ➔ **0% 필요**.
  * 내 뇌 속에 모든 컨텍스트가 있으므로 껍데기 설계를 과감히 건너뛰고 코어 로직으로 직행합니다.
* **타자 (External Users / Public)**:
  * 동료, 외부 고객, 기술 블로그를 읽을 불특정 다수의 독자.
  * 제작자가 옆에 없어도 상대방 혼자서 온전히 이해하고 쓸 수 있어야 합니다. ➔ **온보딩 설계, 직관적인 UI, 친절한 에러 문구, 가독성 엔지니어링 100% 필수**.

---

### 2. 수용자의 숙련도: 도메인 전문가(Expert)인가, 낯선 초심자(Novice)인가?
> **"전문 용어를 쏟아내도 되는가, 중학생도 이해하게 풀어야 하는가?"**

인터페이스의 정보 밀도와 **'실수 방지(Poka-Yoke) 설계의 두께'**를 결정합니다.

* **숙련자 / 파워 유저 (Expert)**:
  * 개발자, 데이터 엔지니어, 숙련된 아키텍트.
  * 친절한 설명보다 **"단축키, 높은 정보 밀도, 정밀한 제어권(Control)"**을 원합니다. ➔ **고밀도 인터페이스, CLI, 전문 용어 기반의 정밀 설계**.
* **초심자 / 일반 대중 (Novice / Layman)**:
  * 기술 블로그 글을 읽을 주니어 개발자, 혹은 일반 앱 사용자.
  * 조금만 어려워도 즉시 이탈하거나 조작 실수를 저지릅니다. ➔ **실수를 원천 차단하는 가드레일, 제로 러닝커브, 쉬운 비유와 서사적 스캐폴딩 필수**.

---

### 3. 수용자의 본성: 감성의 인간(Human Brain)인가, 무감정의 기계(Machine/System)인가?
> **"마음을 움직여야 하는가, 데이터 규격만 맞추면 되는가?"**

산출물이 통과해야 할 **'수용 인터페이스의 본질적 규격'**입니다.

* **기계 / 외부 시스템 (Machine / API / Database)**:
  * 감정, 스토리텔링, 디자인의 여백 ➔ 0% 필요.
  * 오직 **엄격한 스키마, 타입 안정성, 멱등성, 응답 속도**만이 전부입니다. ➔ **수학적·논리적 프로토콜 설계**.
* **인간의 뇌 (Human Attention & Emotion)**:
  * 아무리 완벽하고 옳은 내용이라도 지루하면 3초 만에 뒤로 가기를 누릅니다.
  * 독자의 주의력을 쥐고 흔들어야 합니다. ➔ **주의력(Attention) 배분, 완급 조절, 고통과 카타르시스의 서사 슬롯 설계**.

---

### 4. 수용자의 관여도: 스쳐 지나가는 관객(Casual)인가, 생존이 걸린 당사자(Mission-Critical)인가?
> **"심심해서 훑어보는가, 인생이나 돈이 걸려 있는가?"**

결과물이 견뎌내야 할 **'신뢰와 내구성의 수위'**입니다.

* **낮은 관여도 (Casual Consumer)**:
  * 타임라인을 슥슥 넘기며 보는 SNS 독자, 무료 콘텐츠 소비자.
  * 깊은 설명은 읽지 않습니다. ➔ **첫 3초 안에 시선을 낚아채는 훅(Hook)과 비주얼 설계**.
* **극단적 관여도 (Mission-Critical User)**:
  * 이 소프트웨어로 정산을 처리하는 재무팀, 이 아키텍처로 서비스를 올려야 하는 스타트업 창업자.
  * 단 1회의 다운타임이나 데이터 유실도 용납하지 않습니다. ➔ **신뢰성, 롤백 가능성, 감사 추적성을 입증하는 극단의 방어 설계**.

### ⚖️ 이용 대상(수용자) 판별 매트릭스

| 판별 축 | ⚡ A극 (직관·실행형 우세 / 가벼운 설계) | 🛡️ B극 (수용자 중심 정밀 설계 강제) |
| :--- | :--- | :--- |
| **1. 수용자 거리** | 나 혼자 쓰고 버린다 (**Self**) | 불특정 다수의 남이 쓴다 (**Others**) |
| **2. 수용자 숙련도** | 척하면 아는 전문가 (**Expert**) | 낯설고 이탈하기 쉬운 초심자 (**Novice**) |
| **3. 수용자 본성** | 스키마만 맞으면 되는 기계 (**Machine**) | 공감과 재미가 필요한 사람 (**Human Brain**) |
| **4. 수용자 관여도** | 심심풀이로 훑어본다 (**Casual**) | 생존과 돈이 걸려 있다 (**Mission-Critical**) |

### 💡 SM(스펙 매니저 / 시스템 매니저)의 수용자 교훈

> **"모든 설계의 궁극적 종착지는 수용자의 인터페이스다."**

* 수용자가 **기계나 나 자신(A극)**일 때는 온보딩이나 가독성 설계를 과감히 걷어내고 코어 로직에 집중해야 엔지니어링 낭비가 없습니다.
* 수용자가 **초심자이거나 미션 크리티컬한 타자(B극)**일 때는 코어 로직이 아무리 훌륭해도 수용자 가드레일 설계가 부실하면 100% 실패작으로 판정납니다.

진정한 SM의 역량은, **"내가 빚어내는 결과물이 닿을 수용자의 문턱 높이를 정확히 측정하고, 그 문턱을 넘을 수 있는 최적의 친절함과 방어막을 설계하는 것"**에 있습니다.
