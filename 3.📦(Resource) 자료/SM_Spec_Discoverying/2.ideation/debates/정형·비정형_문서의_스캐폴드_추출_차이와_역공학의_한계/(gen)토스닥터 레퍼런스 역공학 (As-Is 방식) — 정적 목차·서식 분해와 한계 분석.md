# 토스닥터 레퍼런스 역공학 (As-Is 방식) — 정적 목차·서식 분해와 한계 분석

> [토스 테크 — "쉼 없이 도는 테스트, 사람이 어디까지 돌봐야 할까요? - 토스닥터(Toss Doctor)"](https://toss.tech/article/toss-doctor)

## 1. 기존 As-Is 방식의 추출 관점

기존 규격 문서 중심의 프레임워크(Outline = 정적 목차 트리, Segment = 단락 빈칸, Recipe = 전역 스타일 가이드)로 토스닥터 아티클을 역공학했을 때 추출되는 결과물이다.

### 1.1. As-Is Recipe (전역 스타일 가이드)
* **어조 (Tone & Voice)**: 
  * "전문적이면서도 친절한 해요체 어조를 유지할 것."
  * "독자에게 말을 건네는 듯한 대화체 문장 사용."
* **작성 지침 (General Guidelines)**:
  * "과거 버전의 한계를 언급하고 새 버전의 개선점을 설명할 것."
  * "실제 코드나 시나리오 예시를 포함할 것."
  * "도입부에서 문제 상황을 제시하고, 본론에서 4가지 해결책을 기술한 뒤, 결론에서 향후 확장 계획을 언급할 것."
* **제약 조건 (Constraints)**:
  * 총 분량: 공백 포함 4,000~5,000자 내외.
  * 기술 용어(RC, BDD, MCP, Locator 등) 사용 시 약어 표기 병기.

---

### 1.2. As-Is Scaffold (Outline & Segment & Wireframe)

```text
[Outline 1] 서론: 스모크 테스트와 토스닥터 소개
  ├── [Segment 1-1] 배경: 토스 앱의 잦은 배포와 수동 스모크 테스트의 피로도
  └── [Segment 1-2] 토스닥터 V1의 성과와 한계 (손이 많이 가고 유지보수 어려움)

[Outline 2] 본론: 토스닥터 V2의 4대 개선점
  ├── [Segment 2-1] 개선점 1: 코드 생성 자동화 (Gherkin 시나리오 ➔ Appium MCP 코드젠)
  ├── [Segment 2-2] 개선점 2: 화면 요소 자동 탐색 (스마트파인더 심폐소생)
  ├── [Segment 2-3] 개선점 3: 실패 원인 자동 분석 (/diagnosis와 recoverable 판정)
  └── [Segment 2-4] 개선점 4: 자동 복구 실행 (멈추고 확인 후 locator 수정)

[Outline 3] 시스템 아키텍처: 토스닥터 서버
  └── [Segment 3-1] 실시간 양방향 통신을 통한 오케스트레이션

[Outline 4] 결론 및 확장: 토스닥터에서 토스체커로
  ├── [Segment 4-1] 리그레션 테스트(1,375개 TC)로의 확장
  └── [Segment 4-2] 맺음말: 사람이 집중해야 할 가치 (설계에 집중)
```

* **Wireframe**: 일반 1단 세로 블로그 뷰포트 (문단 ➔ 코드 블록 ➔ 이미지 ➔ 문단 순차 배치).

## 2. As-Is 추출 방식이 초래하는 치명적 한계

이 스키마를 가지고 다른 개발자가 "우리 회사의 캐시 시스템 리팩토링 글"이나 "데이터 파이프라인 자동화 글"을 쓰려고 투입하면, 다음과 같은 **3대 무력화(Nullification)**가 발생한다.

### 2.1. 맹탕 요약(Over-abstraction)의 덫
* 아웃라인이 `[1. 배경] ➔ [2. 문제점] ➔ [3. 해결책 4가지] ➔ [4. 결론]`이라는 너무나 뻔한 교과서적 목차로 환원된다.
* 결과적으로 작성자는 **"이 목차를 모르는 사람이 어디 있나? 빈 화면에서 문장을 어떻게 시작해야 할지 여전히 막막하다"**는 백지 공포를 전혀 해결받지 못한다.

### 2.2. 토스 글 특유의 '쫄깃한 텐션과 호흡(Beat)' 증발
* 토스 아티클이 잘 읽히는 진짜 이유는 목차가 아니라 다음과 같은 **미세 호흡 장치**들이다:
  * *"약은 약사에게, 테스트는 토스닥터에게 세션을 기억하시나요?"* (독자와의 내적 친밀감 형성)
  * *"여기서 한 번 부딪힌 게 있는데요"* (솔직한 실패 고백을 통한 긴장감 조성)
  * *"말하자면, 쓰러진 그 자리에서 곧바로 하는 심폐소생이에요"* (극적인 비유)
  * E-1부터 E-5까지 순차적으로 복구되는 슬라이드형 리듬감.
* As-Is 목차 분해 방식은 이런 **인지적 텐션과 전개 타이밍**을 전부 텍스트 내용물로 취급하여 버려버리고, 뼈대에는 무미건조한 '개선점 1, 2, 3, 4'만 남겨둔다.

### 2.3. Recipe와 Segment의 단절
* Recipe는 구름 위의 말("친절한 해요체")만 하고 있고, 실제 Segment("개선점 2를 쓰시오")는 아무런 가이드 없이 방치된다.
* 결국 AI에게 이 As-Is 스펙으로 초안을 쓰게 하면, 토스 특유의 생동감은 온데간데없고 **교과서 톤의 딱딱한 보고서 문장(ChatGPT Glaze)**이 튀어나온다.
