# Spec-Driven Resource Extractor (기준 스펙 · 절차적 사유 기반 리소스 추출 스킬)

## 1. 목적 및 철학

기준 문서 기반 리소스 추출에서 가장 흔한 실패는 두 가지다:
1. **기계적 평면 추출 (Schema Blindness)**: 기준 문서의 슬롯 이름만 보고 대상 소재의 물리적·운영적 제약(예: 지역 이동 제약 vs 시설 완결성)을 생각하지 않은 채 모든 슬롯을 똑같은 추상 키워드 나열로 우겨넣어 실무 판단에 쓸 수 없는 일반화 문구를 양산하는 오류.
2. **성급한 도메인 칼질 (Premature Taxonomy)**: 아직 조사하지도 않은 소재까지 몇 개의 고정 유형(`A형 / B형`)으로 미리 재단해 두고 억지로 끼워 맞춰, 새로운 소재나 타 도메인이 들어올 때 구조를 왜곡하는 오류.

이 스킬은 **미리 박아둔 분류표를 쓰지 않고, 작업 시점마다 원문과 기준 문서의 구조적 제약·종속성·귀속성을 절차적으로 사유(Procedural Reasoning)하여 가장 정확한 추출·적재 형태를 결정**하는 데 목적이 있다.

---

## 2. 절대 가드레일

1. **하위 참고 문서 및 기준 문서 필수 선행 열람 (`Spec Lock`)**
   * 작업 시작 직후 반드시 [`structural_reasoning_guide.md`](./references/structural_reasoning_guide.md)와 [`resource_detail_template.md`](./templates/resource_detail_template.md), 그리고 작업 폴더의 기준 문서(`*조사_기준*`·`*spec*`)를 읽어 `Phase`·`적용/제외 필터`·`리소스 수집 항목`·`세부 기준`을 잠근다. 기준 문서가 없으면 임의 분류하지 말고 사용자와 합의한다.
2. **제외 필터 존중**
   * 기준 문서가 꺼 둔 조건(예: 거리 제한·예산 컷오프)을 에이전트가 임의로 되살려 유효한 부품이나 사례를 탈락시키지 않는다.
3. **1차 공식 출처 승격 (`Official Lookup`)**
   * 발견된 장소·업체·서비스 스펙은 블로그 후기 문장을 복붙하지 말고 **공식 홈페이지**를 조회해 주소·정원·요금·패키지·규정 등 1차 팩트로 보강한다 *(미확인 시 추정 금지, 미확인 표기)*.
4. **이미지 무제한 1:1 매칭 & 시각 검수 필수**
   * 개수 상한을 두지 않는다. 빈 시설 사진에 한정하지 않고 `컨텐츠·식사 세팅·활동 현장·분위기·주의/실패 실물 근거` 등 **구체 실체가 있는 모든 항목**에 원문/공식 이미지를 확보한다.
   * 브라우저를 띄우지 않고 HTTP 정적 추출로 로컬 `이미지/` 폴더에 저장한 뒤, **반드시 이미지 뷰어(`read_file`)로 직접 열어 내용을 눈으로 확인**한다 *(포스팅 글·사진 순서 오차로 인한 오매칭, 저해상도·스톡·광고 이미지 차단)*.
5. **절차적 사유 없는 혼합·고정 칼질 금지**
   * 어떤 소재에 대한 고정 분류표도 전제하지 않고, 매 작업 시 `Step 1`의 사유 4축으로 **`앵커 종속 계층(A > B)` vs `독립 평면 풀`**과 **`대상 고유 자산` vs `주체 수행 행사`**를 판별한다.
6. **상세(`.md`) vs 메타(`.outline`) 역할 분리 & 원자화**
   * 사설 상호·상세 스펙·이미지는 상세 리소스 `.md`에 집중하고, `.outline`의 컨셉 아래에는 판단·조합 가능한 단위만 **`1불릿 = 1단위 모듈`**로 작성한다 *(`/`·`→` 시간순 줄글 묶음 및 `입실·체크아웃·퇴소` 같은 당연한 절차 금지)*.

---

## 3. 6단계 실행 프로토콜

```text
[Step 0: 기준 문서 + 기존 아웃라인 로드]
  ➔ [Step 1: 소재 구조 · 슬롯 성격 절차적 사유 (4축 잠금)]
  ➔ [Step 2: 원문 + 공식 1차 출처 + 전 슬롯 이미지 확보·시각 검수]
  ➔ [Step 3: 2-Track 상세 리소스 .md 생성]
  ➔ [Step 4: 사유 결과 기반 상위 .outline 동기화]
  ➔ [Step 5: JSON · 이미지 1:1 정합성 무결성 검증]
```

### Step 0. 기준 스펙 및 리빙 아웃라인 로드
* 기준 문서(`*조사_기준*` 등)에서 ① `Phase` 및 `적용/제외 필터`, ② `리소스 수집 항목`, ③ `세부 기준`, ④ 대상 `.outline` 및 출력 경로 *(디폴트 `{기준문서_폴더}/리소스/{컨셉}_{대상명}.md`)* 를 읽는다.
* 대상 `.outline`이 존재하면 해당 컨셉(예: `관광`, `글램핑` 등)의 현재 노드 구조와 사용자 편집·완료(`isCompleted`) 상태를 먼저 읽는다.

### Step 1. 소재 구조 및 슬롯 성격 절차적 사유 (`Contextual Reasoning`)
[`structural_reasoning_guide.md`](./references/structural_reasoning_guide.md)에 따라 아래 4가지를 사유해 이번 대상의 구조 전략을 잠근다:
1. **`Primary Anchor`:** 이 소재에서 의사결정과 동선을 현실적으로 끌고 다니는 1차 결정 단위는 무엇인가? *(원문·기준에서 귀납 도출)*
2. **`Slot Dependency`:** 상위 축이 바뀌면 하위 슬롯 내용이 무의미해지거나 달라지는가? 종속적이면 추상 키워드 대신 `상위 앵커 > 하위 고유 실체` 계층 트리로 묶는다.
3. **`Asset vs. Execution`:** 해당 장소/대상에 가면 본래 있는 **고유 자산**인가, 주체가 어디서든 수행하는 **자체 행사·프로그램·식사** 또는 **타 지역 경유**인가? 고유 자산만 거점·컨텐츠에 남기고 자체 수행 일정/행사는 `일정 및 행사`·`레크레이션`·`식사` 등 본래 슬롯으로 보낸다.
4. **`Living Outline Alignment`:** 기존 `.outline`에 사용자가 직접 잡은 트리 계층이나 완료 처리가 있으면 이를 최우선 구조 정답으로 따른다.

### Step 2. 원문 + 공식 1차 출처 + 전 슬롯 이미지 확보
* 대상 URL 본문을 읽고, 핵심 거점/엔티티는 `search_web` + HTTP fetch로 **공식 홈페이지 URL과 세부 시설·프로그램·요금·제약 스펙**을 직접 확인한다.
* 블로그 원문 및 공식 사이트에서 각 항목에 해당하는 `<img>` URL을 추출해 `{출력폴더}/이미지/{대상명}/`에 저장한다. *(너무 큰 고해상도 원본은 뷰어/볼트 관리를 위해 적정 해상도로 리사이즈 가능)*
* 저장된 이미지를 `read_file`로 직접 열어 확인하고 **실제 내용과 일치하는 파일명으로 정리**하며 스톡·저해상도·오매칭 파일을 삭제한다.

### Step 3. 2-Track 상세 리소스 파일 생성 (`templates/resource_detail_template.md`)
* 디폴트 경로 `{기준문서_폴더}/리소스/{컨셉}_{대상명}.md` *(지정 경로가 있으면 오버라이드)* 에 작성한다.
* **`1. 레퍼런스` *(설계 · 판단 기준)*:** 진행 리듬, 선택 기준선, 비호응·주의 안티패턴 + 현장 분위기/실패 근거 이미지.
* **`2. 리소스` *(수집 항목 1:1 매핑)*:** 기준 문서의 `리소스 수집 항목` 순서 그대로 슬롯을 세우고, 확인된 팩트·공식 스펙·부품 리스트 + 검수 완료된 로컬 이미지(`![[파일명]]`)를 항목별로 임베드한다.

### Step 4. 사유 결과 기반 상위 `.outline` 동기화 *(대상 `.outline` 존재 시)*
* `.outline` 내 해당 컨셉 불릿 아래를 2갈래로 유지·갱신한다:
  1. **`참고 사례 · 상세 리소스`:** `[[{컨셉}_{대상명}.md]]` 링크 추가 *(기존 링크 보존, 중복 금지)*
  2. **`특징`:** `Step 1`에서 도출한 구조 전략에 맞춰 기준 문서의 슬롯 하위에 적재한다.
     * **종속 슬롯**은 `앵커 > 고유 실체` 계층 트리로 적재한다 *(예: 지역 > 해당 지역 고유 스팟/체험)*.
     * **독립 슬롯** 및 **자체 수행 일정·행사·레크레이션·식사·비용·주의사항**은 각 본래 슬롯 하위에 중복 없이 **`1불릿 = 1단위 모듈`**로 적재한다 *(기존 `isCompleted: true` 상태는 보존)*.

### Step 5. 무결성 검증
* `.outline` 수정 시 JSON 파싱(`json.load`)으로 문법 오류 없음을 확인한다.
* 상세 `.md`에 임베드된 모든 `![[...]]` 이미지가 `이미지/{대상명}/` 폴더의 실제 파일명과 100% 일치하고 미사용 고아 파일이 없음을 확인한다.
