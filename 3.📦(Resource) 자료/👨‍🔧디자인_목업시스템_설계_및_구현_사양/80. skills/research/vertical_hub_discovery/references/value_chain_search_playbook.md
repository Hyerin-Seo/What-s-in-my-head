# 가치사슬 4축 탐색 & 루트 도메인 역등반 플레이북 (Value-Chain Search & Root-Domain Ascent Playbook)

이 가이드는 `vertical_hub_discovery` 스킬이 임의의 도메인에 대해 **"검색되지 않는 메타 표현"**이나 **"거대 범용 포탈 기억 회상"**에 빠지지 않고, 실제 전문 포탈·버티컬 마켓·공급자 아카이브·실무자 커뮤니티를 끝까지 발굴하고 검증하기 위한 절차적 추론 지침입니다.

---

## Step 1. 검색어 생성: 메타 키워드 금지 및 가치사슬 4축(4-Axis) 전개

에이전트가 `"OO 후기 모음 사이트"`, `"OO 레퍼런스 포탈 리스트"` 같은 메타 검색어만 던지면, 실제 버티컬 사이트들은 제목에 그런 표현을 쓰지 않기 때문에 검색에서 누락됩니다.
반드시 아래 **4개의 가치사슬(Value-Chain) 축**에 맞춰 도메인 용어를 동적으로 치환해 최소 4갈래 이상 교차 탐색하십시오.

| 가치사슬 축 (Axis) | 찾는 대상의 정체 | 쿼리 치환 공식 (도메인 변수 `{D}`, 행위/산출물 `{A}`) | 기대 발굴 출처 유형 |
| :--- | :--- | :--- | :--- |
| **Axis 1. 버티컬 마켓·패키지·비교견적 허브** | 다수의 상품·업체·패키지·프로그램을 카탈로그화해 견적/매칭/예약을 중개하는 B2B·B2C 마켓 | `"{D} 패키지 비교"`, `"{D} 견적 플랫폼"`, `"{D} 프로그램 모음"`, `"{D} 전문 업체 비교"`, `"{D} 큐레이션 마켓"` | 카테고리·단가·스펙·사례 DB를 보유한 버티컬 포탈 |
| **Axis 2. 공급자·실행사 포트폴리오/사례 아카이브** | 자체적으로 수십~수백 건의 고객 수행 사례(Case Study / Review 게시판)를 누적 공개하는 전문 에이전시·벤더 | `"{D} 진행 사례"`, `"{D} 레퍼런스 포트폴리오"`, `"{D} 프로젝트 후기 게시판"`, `"{D} 도입 사례"`, `"{D} 현장 스케치"` | 실무 진행 사진·일정·인원·결과가 담긴 1차 아카이브 |
| **Axis 3. 실무자·수요자 커뮤니티 & Q&A 채널** | 실제 담당자나 구매자가 고민, 실패 경험, 업체 평판, 예산 팁을 주고받는 커뮤니티·영상·포럼 | `"{D} 담당자 추천"`, `"{D} 실무 후기"`, `"{D} 어디서 하나요"`, `"{D} 커뮤니티"`, `"{D} 실패 후기"` | 현장 페인포인트, 암묵지, 비공식 평판 데이터 |
| **Axis 4. 협회·공공·전문 미디어·디렉토리** | 관련 협회, 공공기관 지원사업 DB, 전문 매거진, 벤치마크 리포트, 디렉토리 사이트 | `"{D} 협회"`, `"{D} 가이드라인"`, `"{D} 통계 리포트"`, `"{D} 우수 사례집"`, `"{D} 전문 매거진"` | 공신력 있는 수치, 제도·안전 기준, 산업 디렉토리 |

### 쿼리 변형 규칙 (Zero-Assumption Query Expansion)
1. **동의어·영문·약어 병행**: 한국어 키워드만으로 버티컬 허브가 부족하면 영문 핵심 용어(`marketplace`, `directory`, `case studies`, `aggregator`, `vendor list`)나 업계 약어/B2B 용어로 즉시 확장합니다.
2. **하위 카테고리 드릴다운**: 1차 검색에서 상위 도메인이 너무 넓어 거대 플랫폼만 뜨면, **하위 세부 영역 2~3개**(예: 특정 지역/규모/장비/방식/목적)를 지정해 전문 롱테일 허브를 끌어냅니다.

## Step 2. 단일 페이지 함정 탈출: 루트 도메인 역등반 (Root-Domain Ascent)

검색 결과에 개별 상세 페이지(예: `/shop/item.php?id=123`, `/post/456`, `/board/view?no=78`)나 블로그형 아티클 URL이 하나라도 걸리면, **그 URL 하나만 읽고 닫지 마십시오.** 해당 사이트가 "1회성 글"인지 "수백 건의 DB를 품은 버티컬 허브"인지는 루트로 올라가 봐야 알 수 있습니다.

### 역등반 5단계 체크리스트 (HTTP 기반)
임의의 후보 URL `https://example.com/a/b/c?x=1`을 발견하면 다음 순서로 구조를 역추적합니다.

1. **루트(Root) 및 내비게이션 해부**:
   - `https://example.com/` 메인 페이지를 HTTP로 조회하여 상단 GNB(Global Navigation Bar), 푸터 메뉴, 전체 카테고리 트리, 사이트 설명을 추출합니다.
2. **사이트맵·로봇 규정 확인 (가능 시)**:
   - `/robots.txt` 및 `/sitemap.xml`을 가볍게 확인해 숨겨진 대규모 디렉토리(`/review/`, `/case/`, `/portfolio/`, `/directory/`, `/bbs/`, `/shop/`, `/archive/` 등)가 있는지 파악합니다.
3. **고밀도 게시판/아카이브 경로 탐색**:
   - 메인 메뉴나 링크 중 `후기`, `사례`, `포트폴리오`, `레퍼런스`, `매거진`, `연구소(Lab)`, `견적`, `전체보기`에 해당하는 경로를 직접 열어 게시물 목록과 누적 건수(페이지네이션 끝번호, 총 게시물 수 표기 등)를 확인합니다.
4. **내부 검색(Internal Search) 엔드포인트 탐지**:
   - 사이트 내 검색창(`<form action="...">`, `/search`, `/shop/search.php`, `/bbs/search.php` 등)이 공개 GET 요청으로 동작한다면, **현재 타겟 키워드 1~2개로 내부 검색을 시험 호출**해 해당 허브 안에 타겟 데이터가 실제로 몇 건이나 존재하는지 실증합니다.
5. **허브 vs 단일 출처 판정**:
   - **허브 승격 조건**: 동일 도메인 내 관련 레코드·사례·상품이 다수(최소 10건 이상 또는 체계적 카테고리)로 구조화되어 있고, 2단계 후속 리서치(`real_review_blog_research` 또는 `spec_driven_resource_extractor`)의 공급원(Source Pool)으로 재사용 가능한 경우에만 `버티컬 허브`로 분류합니다.

## Step 3. HTTP 라이브 실사 & 접근성 3등급 분류 (Honest Access Audit)

검색 엔진 스니펫이나 기억에 의존해 "여기에 후기가 많다"고 추측하지 말고, 표준 HTTP 요청(`urllib` 등; 브라우저 실행 금지)으로 직접 응답을 확인해 아래 3등급으로 정직하게 분리 보고합니다.

| 접근성 등급 | 판정 기준 (HTTP 실사 결과) | 보고서 표기 및 후속 조치 |
| :--- | :--- | :--- |
| **1. Open HTTP DB (직접 검증됨)** | HTTP 200으로 정적 HTML/JSON 본문, 카테고리 목록, 게시물 리스트/상세 본문이 정상 조회되며 건수·날짜·포맷을 직접 확인 가능 | 확인된 실제 건수, 메뉴 구조, 검색 URL 패턴, 대표 샘플(1~3건)을 그대로 보고하고, Stage 1/2 스킬의 최우선 소스로 연결 |
| **2. Partial / SPA (부분 확인·렌더링 제한)** | 메타태그, 일부 API, RSS, 스니펫이나 루트 구조만 보이고 핵심 리스트가 JS 동적 렌더링으로 비어 있거나 일부 차단됨 | 확인 가능한 범위와 차단된 지점(예: "카테고리 프레임은 확인되나 후기 목록은 클라이언트 렌더링")을 명시하고 추정 금지 |
| **3. Login-Gated / Index-Blocked (폐쇄·검색 제한)** | 401/403, 로그인 리다이렉트, 혹은 검색엔진 `site:`/`domain:` 인덱싱이 막혀 에이전트 도구가 내부 개별 글 URL에 접근 불가 (예: 로그인 필수 폐쇄형 커뮤니티, 검색 인덱싱이 제한된 일부 포탈 카페/블로그) | **"에이전트 직접 조회 불가 — 사용자 수동 확인 채널"**로 명확히 분리. 존재 이유와 예상 데이터 가치, 사용자가 직접 입력할 추천 검색어만 안내하고 마치 본 것처럼 허위 링크/요약 생성 절대 금지 |

## Step 4. 편향(Bias) 및 품질 한계 주석 의무화

버티컬 허브는 구조적으로 특정 편향을 가집니다. 출처 지도를 넘길 때 각 허브마다 최소 1개의 현실적 주의점을 명시하십시오.
- **공급자 자사 사례 편향**: 실행사/벤더의 성공 사례 보드는 실패·클레임 사례가 누락되고 예산을 낙관적으로 보여줄 수 있음.
- **마켓 수수료/제휴 편향**: 중개 플랫폼은 제휴 업체 중심으로 상위 노출되거나, 표준 패키지 외 커스텀 요구의 실제 난이도가 가려질 수 있음.
- **데이터 노후화(Stale Archive)**: 최근 게시물 연도 확인을 통해 몇 년 전 종료된 프로그램이나 구버전 가격표가 섞여 있는지 체크.
