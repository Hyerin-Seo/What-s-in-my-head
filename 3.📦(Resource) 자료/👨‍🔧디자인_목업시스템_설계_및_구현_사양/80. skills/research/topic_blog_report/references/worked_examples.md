# 같은 절차, 다른 구성 — 예시 두 개

> **틀이 아니다.** 같은 사고 단계를 성격이 다른 두 주제에 적용하면 구성이 얼마나 달라지는지 보여 주려는 예시다.
> 질문 · 관찰은 2026-11-19 에 실제로 열어 본 화면 기준이고, 숫자 · 규정은 여기 옮기지 않았다 (실행할 때마다 다시 확인한다).

---

## 예시 A. "회사 단체 용품 · 선물 살 곳 조사해서 블로그처럼"

**1. 독자와 결정** — 팀 예산 담당자가 어디서 살지 정한다. 요청자의 관점(피드백으로 확인): *가격표보다 "그 사이트에 들어가면 어떤 곳인지" — 쇼핑몰인지, 업체 비교 플랫폼인지 — 가 감각적으로 전달될 것.*

**2. 질문 지도 (발췌)** — "소량(10~20명)도 주문돼?" · "인당 2~3만 원에 맞출 수 있어?" · "팀원 주소 다 모아야 해?" · "세금계산서 · 법인카드 돼?" · "들어가면 바로 사는 곳이야, 견적 받는 곳이야?"

**3. 조건** — 인원(소규모 / 50명 이상), 로고 인쇄 여부, 마감까지 남은 기간.

**4. 증거 지도의 핵심** — "들어가면 어떤 곳이냐"는 **봐야** 아는 질문 → 사이트마다 첫 화면 캡처가 주인공. 수량 · 가격은 판매 페이지 인용.

**5. 관찰 (실제)**
* 세모단: 첫 화면에 "여러 업체의 견적을 한눈에!" + 진행 3단계 + 품목 고르는 칸 + 업체 수 · 누적 요청 수. 1.6화면 길이. → *물건을 고르는 곳이 아니라, 품목을 알려 주면 업체들이 견적을 보내는 곳.*
* 비더굿즈: 첫 화면이 굿즈 사진 모자이크와 브랜드 문구. 13화면 넘게 길다. → *분위기를 보며 고르는 브랜드형 쇼핑몰.*
* 오피스디포: 들어가자마자 가운데 팝업이 화면을 덮고, 닫으면 회원 혜택 띠 · 카테고리 메뉴 · 기업 상담 신청 칸. → *회원 · 기업 구매 중심의 대형 쇼핑몰.*

**6. 도출된 구성** — 한눈 비교표(사이트 · 한 줄 정체 · 첫 화면 · 가격 보이는 곳 · 이런 상황에) → 사이트별 섹션(첫 화면 캡처 크게 → 정체 · 느낌 → 사양 몇 줄) → 상황별 고르기.

## 예시 B. "단체로 스키장 이용할 때 고려할 사항 조사해서 블로그로"

**1. 독자와 결정** — 회사 · 동호회의 단체 스키 일정을 꾸리는 사람이 무엇을 미리 정하고 확인할지 안다. 관점은 요청문에 없음 → 한 문장으로 묻거나, 묻기 어려우면 "비용 · 안전 · 진행 동선"을 기본으로 두고 노트에 `관점 미확인`.

**2. 질문 지도 (모아야 할 방향)** — 몇 명부터 단체 혜택이 되나 · 리프트 · 장비 · 의류를 어떻게 맞추나 · 초보가 많으면 강습은 · 이동은 셔틀 · 전세버스 중 무엇이 · 날씨 · 개장 상황이 바뀌면 · 다치면 · 숙박이면 집합 · 식사는. (실행 때는 커뮤니티 질문 · 후기의 후회 · 리조트 FAQ 에서 원래 표현으로 모은다.)

**3. 조건** — 인원, 초보 비율, 당일 / 1박, 출발지, 시즌 시점(개장 직후 · 성수기).

**4. 증거 지도의 핵심** — 대부분 **읽어서** 아는 질문 → 리조트 공식 안내의 **원문 규정 · 요금**이 주인공. 이동 · 대기 · 동선처럼 공식에 없는 것은 **경험담**. 화면은 신청 절차를 보여 줄 때만.

**5. 수집하며 바뀐 생각 (실제)**
* 리조트 홈에서 "단체"가 든 링크를 따라가니 하이원 · 용평 · 엘리시안 모두 **연회 · 세미나 · 단체행사 문의** 페이지로 갔다. 인용을 뽑아 보니 시설 소개와 문의 연락처가 대부분이었다.
* → "단체 리프트 혜택" 질문의 증거는 이 페이지에 없다. 증거 지도를 고쳐 **요금 · 할인 안내 페이지**와 **문의로만 확인되는 항목**을 나눴다. 문의로만 확인되는 것은 리포트에 "직접 물어볼 것" 목록으로 남긴다.

**6. 도출된 구성** — 한눈 체크표(항목 · 왜 중요한가 · 어디서 확인 · 놓치면) → 조건 분기표(당일/1박 × 초보 비율) → 결정 순서대로 항목별 섹션(규정 원문 인용 + 경험담 구분) → 리조트 몇 곳의 단체 조건 비교(확인된 것만) → 문의할 것 · 준비 체크리스트.

## 두 예시에서 볼 것

| | 예시 A (구매처) | 예시 B (고려사항) |
|---|---|---|
| 섹션의 단위 | 대상(사이트) | 질문 묶음(고려 항목) |
| 주인공 증거 | 첫 화면 캡처 (봐야 앎) | 원문 규정 · 요금 (읽으면 됨) + 경험담 |
| 조건이 드러나는 곳 | 상황별 고르기 | 분기표 · "~라면" 문단 |
| 구성을 바꾼 것 | 요청자의 관점 | 수집 중 발견 (단체 페이지 ≠ 리프트 규정) |

구성은 주제 이름이 아니라 **독자 질문 · 조건 · 증거의 형태**가 정했다. 그리고 두 번 모두 처음 생각한 구성이 그대로 가지 않았다 — 관점을 듣고, 자료를 보고 고쳤다. 그것이 정상이고, 그래서 1국면(뼈대 대화)이 기본이다.

* 예시 A 에서 관점("첫 화면 느낌")은 완성본을 받은 뒤에야 나왔다. 첫 뼈대에서 "사이트별로 무엇을 먼저 보여 줄까요 — 들어갔을 때의 느낌인가요, 가격 · 수량인가요?" 를 물었다면 한 바퀴 만에 잡혔을 것이다.
* 예시 B 에서 "단체 페이지 ≠ 리프트 규정"은 첫 뼈대의 "조사하며 발견한 것"으로 보여 줄 거리다. 요청자가 "리프트보다 연회 · 숙박이 더 궁금하다"고 하면 구성이 통째로 바뀐다 — 깊게 파기 전에 확인하는 이유다.
