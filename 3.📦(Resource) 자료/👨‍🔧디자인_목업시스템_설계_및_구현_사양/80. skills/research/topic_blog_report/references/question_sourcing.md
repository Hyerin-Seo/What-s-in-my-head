# 독자 질문 모으기 (Step 2 요령)

목차의 재료는 독자가 실제로 품는 질문이다. 에이전트가 떠올린 "있을 법한 항목"은 빠뜨리는 것과 쓸모없는 것이 섞인다. 질문은 **모아서** 만든다.

---

## 1. 어디서 모으나

| 출처 | 무엇이 나오나 | 찾는 법 (주제어 = X) |
|---|---|---|
| 공개 커뮤니티 · Q&A 제목 | 결정 직전의 진짜 고민, 표현 그대로 | `X 질문`, `X 고민`, `X 어떻게 해요`, `X 처음` + 지식인 · 공개 카페 글 · 레딧류 |
| 연관 검색어 · 자동완성 | 많이 묻는 하위 주제 | 검색 결과의 연관 검색 · "함께 찾은" 항목 |
| 후기 속 후회와 팁 | 미리 알았으면 좋았을 것 → 가장 값진 질문 | `X 후기 아쉬운`, `X 실패`, `X 꿀팁`, `X 주의`, `X 다음엔` |
| 공식 FAQ · 이용 안내 목차 | 공급자가 반복해서 받는 질문 | 공식 사이트의 FAQ · 이용 안내 · 단체/기업 안내 페이지 |
| 비교 · 정리 글의 공통 항목 | 여러 사람이 중요하다고 본 축 | 정리 글 3~5개의 소제목을 나란히 놓고 겹치는 것 |
| 요청자의 말 | 요청자 고유의 관점 | 요청문 · 이전 피드백 · 같은 폴더의 기준 문서 |

* 한 출처에서만 모으지 않는다. 최소 세 종류의 출처에서 모은다.
* 질문은 **원래 표현에 가깝게** 적고 출처를 붙인다: `몇 명부터 단체 할인돼요? (지식인 제목)`.
* 에이전트가 덧붙인 질문은 `추정` 표시를 단다. 추정이 절반을 넘으면 더 모은다.

---

## 2. 묶기

* 같은 정보로 답할 수 있는 질문끼리 묶는다. 묶음 이름은 독자의 말로: "할인은 몇 명부터, 얼마나?" — "요금 체계" 같은 공급자 말보다 낫다.
* 보통 4~9묶음. 10개가 넘으면 결정에 덜 중요한 것을 `부록` 으로 내린다. 3개 이하이면 질문을 더 모은다.
* 한 질문이 여러 묶음에 걸치면 답이 확정되는 쪽에 둔다.

## 3. 순서 정하기

1. **중요도**: 이 묶음을 잘못 알면 독자가 무엇을 잃나? (돈 · 시간 · 안전 · 체면 · 되돌릴 수 없는 선택) 큰 손해 순.
2. **결정 흐름**: 독자가 실제로 정해 나가는 순서 (먼저 정해야 다음을 고를 수 있는 것이 앞).
3. 둘이 충돌하면 결정 흐름을 따르되, 가장 큰 손해가 걸린 묶음은 한눈 요약에서 먼저 짚는다.

## 4. 요청자의 관점 확인

질문 지도는 "보통 사람들"의 질문이다. 요청자는 그중 일부를 특히 보고 싶거나, 지도에 없는 관점을 가질 수 있다 (예: "사이트에 들어가면 어떤 느낌인지").
* 요청문에 관점이 드러나면 그 묶음을 앞에 두고 증거를 두껍게 한다.
* 드러나지 않으면 Step 1 에서 한 문장으로 묻는다. 묻기 어려우면 질문 지도 상위 3묶음을 기본으로 하되 노트에 "관점 미확인"을 남긴다.
