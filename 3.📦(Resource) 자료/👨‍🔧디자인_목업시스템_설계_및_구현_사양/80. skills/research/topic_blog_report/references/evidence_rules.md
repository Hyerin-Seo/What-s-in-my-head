# 증거 다루기 (Step 4 · 5 · 7 요령)

리포트의 문장은 증거 위에 선다. 증거마다 **무엇을 확정하는가**와 **어디서 왔는가**가 있어야 한다.

---

## 1. 증거의 형태와 쓰는 법

| 형태 | 확정하는 것 | 모으는 도구 | 본문에서 |
|---|---|---|---|
| **원문 문구** (규정 · 조건 · 공지) | 정해진 규칙 · 기준 | `extract_quotes.py` | 인용 상자에 원문 그대로 + 출처 링크 + 확인일 |
| **숫자** (가격 · 인원 · 기간 · 거리) | 비교 · 예산 | `extract_quotes.py` (표 행 포함) | 표. 기준(부가세 · 1인/단체 · 시즌 · 날짜)을 함께 |
| **화면** (사이트 · 신청 절차 · 요금표 이미지) | 정체 · 분위기 · 절차 · 이미지로만 있는 정보 | `page_capture.py` | 크게 보여 주고 해석. 캡션 = 무엇의 화면 + 출처 + 캡처일 |
| **실물 · 현장 사진** | 생김새 · 규모 · 분위기 | `collect_images.py` | 해당 대상 섹션에만. 캡션 = 무엇 + 출처 |
| **경험담** (후기 · 커뮤니티) | 실제로 겪는 일 · 공식에 안 나오는 것 | 검색 + `extract_quotes.py` (공개 글) · `real_review_blog_research` | "경험담" 표시 + 출처. 공식과 섞지 않는다 |
| **직접 비교** (여러 곳을 같은 기준으로) | 차이 | 위 도구들의 결과를 표로 | 비교 기준을 표 위에 밝힌다 |

## 2. 출처의 무게

* **공식 1차** (운영자 · 공급자 페이지 · 약관 · 요금표) > **경험담** (후기 · 커뮤니티) > **정리 글** (블로그 요약 · 큐레이션).
* 정리 글의 숫자는 그대로 쓰지 않는다. 그 숫자가 나온 공식 페이지를 찾아 확인하거나 `[확인 필요]`.
* 공식과 경험담이 다르면 둘 다 쓰고 차이를 말한다 ("안내에는 ~, 실제 후기에는 ~").
* 날짜가 중요한 정보(요금 · 시즌 · 정책)는 확인일을 붙인다. 지난 시즌 자료면 그렇다고 쓴다.

## 3. 사진 · 캡처 귀속 (가장 자주 틀리는 곳)

1. 섹션이 다루는 대상의 사진 · 캡처만 그 섹션에 붙인다. 파일 이름 접두와 `images.json` 의 `sourcePage` 로 대조한다.
2. 맞는 사진이 없으면 **사진 없이** 쓴다. 비슷한 다른 대상 · 스톡 · 다른 판매처 사진으로 채우지 않는다.
3. 한 사진은 한 대상에만 쓴다 (요약 · 표지 묶음 제외).
4. 캡션에서 출처를 지우지 않는다.
5. 홍보 배너는 "그곳이 내세우는 것"을 보여 줄 때만, 그렇게 캡션을 달아 쓴다.

## 4. 눈 검수

* 캡처는 원본을 연다 (글자가 읽혀야 한다). 사진은 `--sheet` 검수판을 연다.
* 쓸 사진은 `images.json` 에 `"checked": true`, `"note": "무엇 · 어느 섹션"` 으로 적는다.
* 인용은 `extract_quotes.py` 결과에서 **문장 단위로** 옮긴다. 줄이거나 바꿔 쓸 거면 인용 표시를 하지 않고 "안내에 따르면 ~" 으로 풀어 쓴다.

## 5. 막힌 곳 · 못 본 것

* 로그인 · 차단 · 열리지 않음: 그 화면이 있으면 그대로 기록하고 "회원 전용 — 첫 화면이 로그인 창"처럼 사실만 쓴다. 안의 내용을 추정하지 않는다.
* 본문이 이미지라 인용이 안 뽑히면 캡처 · 사진으로 눈으로 읽고, 옮긴 값에 "이미지 요금표에서 확인" 을 붙인다.
* 못 본 것은 조사 노트의 `못 본 곳` 에 이유와 함께.

## 6. 공개 발행할 때만

기본 독자는 요청자 본인이다. 외부 공개라면 캡처 · 사진의 사용 허락을 확인해야 한다고 요청자에게 알린다.
