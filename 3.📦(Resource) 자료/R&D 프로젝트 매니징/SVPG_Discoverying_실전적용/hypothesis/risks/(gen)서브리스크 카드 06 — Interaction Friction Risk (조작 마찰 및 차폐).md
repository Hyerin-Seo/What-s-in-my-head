# 서브리스크 카드 06 — Interaction Friction Risk (새 탭 점핑을 없애는 '인라인 증거 엿보기'와 무차폐 3-Tap 완결)

> **SVPG 정본 헌법**:  
> **"사용성 리스크의 마지막 관문은 조작 마찰(Interaction Friction)이다. 출처를 확인하겠다고 사용자를 다른 웹사이트로 튕겨 보내는 순간, 팝업 광고와 쿠키 동의 창이 화면을 가리고 사용자의 집중 흐름(Flow)은 산산조각 난다. 진정한 마찰 없는 인터랙션은 사용자가 자신이 보던 원래 화면을 1픽셀도 벗어나지 않고, 그 자리에서 원천 증거를 0.1초 만에 엿보고(Peek) 3번의 탭 이내에 행동을 끝내게 만드는 극단적 차폐의 미학에 있다."**  
> *(출처: [`C-2017-12-04 The Four Big Risks`](file:///c:/AI_Projects/WebNovelAssistant/VibePatchNote/workbench/96.data_pipeline/svpg-product-discovery/C-2017-12-04_the_four_big_risks.md) E2, [`C-2018-09-28 Product Discovery at Apple`](file:///c:/AI_Projects/WebNovelAssistant/VibePatchNote/workbench/96.data_pipeline/svpg-product-discovery/C-2018-09-28_product_discovery_at_apple.md) E3)*

## 1. 서브 리스크 정의 및 검증 전제 (Premise)

*(토론 카드 01-E/F 및 가설 2.0/3.0과의 1:1 결속: [`가설 카드 2.0`](file:///c:/망고독%20관련%20자료/프로젝트_매니지먼트/What-s-in-my-head/3.📦(Resource)%20자료/R&D%20프로젝트%20매니징/SVPG_Discoverying_실전적용/hypothesis/(gen)가설%20카드%202.0%20—%20클레임%20단위%20증거%20스냅샷%20및%20제로%20서치%20어트리뷰션%20뷰.md), [`가설 카드 3.0`](file:///c:/망고독%20관련%20자료/프로젝트_매니지먼트/What-s-in-my-head/3.📦(Resource)%20자료/R&D%20프로젝트%20매니징/SVPG_Discoverying_실전적용/hypothesis/(gen)가설%20카드%203.0%20—%20상황%20제약%20매칭%20엔진%20및%20관심사%20렌즈%20기반%2010초%20정답%20런타임.md))*

* **서브 리스크 명칭**: Interaction Friction Risk (외부 링크 점핑 피로 및 화면 차폐를 극복하는 인라인 엿보기 리스크)
* **책임 주체 (R&R)**: **Product Designer (제품 디자이너)**
* **핵심 질문**:  
  > *"사용자는 출처를 확인하기 위해 새 브라우저 탭으로 튕겨 나가 팝업 광고를 끄고 긴 글에서 본문을 찾아 헤매는 **'문맥 전환 피로(Context Switching Fatigue)'** 없이,  
  > 원래 보던 화면에서 마우스 호버나 가벼운 탭 한 번으로 원천 증거 문장을 **'인라인 엿보기(Inline Peek Popover)'**로 즉시 대조하고, **3클릭 / 3초 이내에 인지 부하 없이 최종 의사결정을 완결**할 수 있는가?"*
* **핵심 검증 전제**:  
  출처 확인 과정에서 사용자를 외부 웹사이트로 보내거나 화면 전체를 가리는 모달 팝업을 띄우는 순간 인터랙션은 실패한다. 오직 **[인라인 제약 칩 1회 탭] ➔ [호버 즉시 0.1초 원천 증거 엿보기] ➔ [확정 1회 탭]**이라는 극단적으로 차폐된 3단계 미니멀 동선만이 사용자의 인지 흐름(Cognitive Flow)을 깨지 않고 과업을 완결시킬 것이다.

## 2. 💥 극단적 실패 시나리오 (Concrete Failure Scenario)

우리 제품이 '외부 링크 이동의 마찰'로 인해 사용자를 피로하게 만들어 이탈시키는 시나리오:

1. **상황**:  
   사용자가 "23시 체크인 방음 호텔" 또는 "Python 3.12 지원 라이브러리"를 검색하여 결과 카드 1개를 받음.
2. **실패 현상**:  
   결과 카드 아래에 출처 확인 버튼이 있어서 눌렀더니, **외부 블로그나 공식 사이트 새 탭이 열리며 브라우저 화면이 완전히 전환됨(Context Lost)**.  
   * 스마트폰 화면에 "쿠키 수집에 동의하세요", "앱을 설치하면 50% 할인"이라는 전면 팝업 배너가 뜸.
   * 사용자는 짜증을 내며 팝업 'X' 버튼을 찾느라 애를 먹고, 정작 내가 찾던 23시 체크인 문장이 블로그 어디에 적혀있는지 몰라 손가락으로 30초 동안 스크롤을 내리다 포기함.
   * 원래 우리 앱으로 돌아가려고 뒤로가기를 3번 눌렀더니 앱 세션이 만료되어 초기 화면으로 튕김.
3. **참사의 본질**:  
   출처 확인의 책임을 외부 사이트로 외주 주어버림으로써, **극심한 화면 차폐(Screen Occlusion)와 문맥 이탈(Link Jumping)**을 유발해 사용자 경험을 완전히 박살 냄.

## 3. 🔍 기존 사용자가 매일 겪는 '링크 점핑 고역' (The Tab Jumping Hell)

기존 검색과 RAG를 쓸 때 사용자들이 겪는 현실의 물리적 마찰:

* **새 탭 증식과 메모리 폭발**:  
  출처 확인하겠다고 링크 5개 눌렀더니 크롬에 탭이 15개 열려 스마트폰이 버벅거리고 원래 찾던 탭을 잃어버리는 현상.
* **페이지 내 2차 수동 검색 고역 (Ctrl+F Fatigue)**:  
  외부 사이트로 이동한 후, 본문이 너무 길어서 다시 브라우저 메뉴를 열고 `페이지 내 검색`을 켜서 키워드를 타이핑해야 하는 이중 노동.
* **화면 가림 팝업의 스트레스**:  
  언론사나 블로그 사이트에 덕지덕지 붙은 배너 광고와 플로팅 동영상이 화면의 70%를 가려 시야를 차폐하는 고통.

## 4. 🏢 글로벌/국내 레퍼런스 기업 3종 심층 분석

### ① Arc Browser 'Little Arc' & Peek (아크 브라우저의 엿보기 혁신)
* **접근 방식**: 링크를 클릭했을 때 전체 화면 새 탭을 열지 않고, 현재 화면 위에 작고 가벼운 임시 창(Peek)을 띄워 0.5초 만에 내용을 훑어보게 함.
* **마찰 소멸 메커니즘**: `ESC`를 누르거나 손을 떼는 순간 임시 창이 사라지며 원래 내가 하던 작업 맥락으로 즉시 복귀(Zero Context Lost).
* **적용 전략**: 우리 시스템도 팩트 뱃지를 탭하면 새 창으로 튕겨 나가지 않고, **원천 문장 하이라이트가 미니 팝오버로 슬림하게 떴다 사라지는 인라인 엿보기(Inline Peek)**를 구현해야 함.

### ② Notion Page Mention Hover (노션 멘션 엿보기)
* **접근 방식**: 본문 내 링크나 페이지 멘션에 마우스를 올리면, 페이지로 이동하지 않고도 해당 페이지의 핵심 요약과 미리보기가 0.1초 만에 플로팅 카드로 렌더링.
* **마찰 소멸 메커니즘**: 클릭 없이 마우스 호버만으로 정보를 검증할 수 있어 문서 탐색 마찰을 90% 제거.
* **적용 전략**: 팩트 어트리뷰션 뱃지에 마우스를 올리는 즉시 **형광펜 스냅샷 문장이 카드 옆에 즉각 바인딩**되어야 함.

### ③ Apple Quick Look (애플 퀵룩 스페이스바)
* **접근 방식**: 파일을 열기 위해 무거운 프로그램을 실행할 필요 없이, 파일 선택 후 `스페이스바` 단 한 번으로 0.1초 만에 내용 전체를 미리보기.
* **마찰 소멸 메커니즘**: 프로그램 로딩 지연과 창 전환의 마찰을 0으로 소멸시킴.
* **적용 전략**: 팩트의 진위를 확인하는 과정을 **'원터치 퀵룩' 수준으로 극한 압축**해야 함.

## 5. ⚠️ 치명적 실패 반례 (Counterexamples) 2종

### 반례 1: 네이버 지식백과의 '외부 출처 무단 이동' 참사
* **실패 사건**: 백과사전 단어를 읽다가 각주 링크를 누르면, 백과사전 화면이 완전히 닫히고 외부 학술지나 언론사 사이트 메인 페이지로 튕겨 나가 원래 읽던 문맥을 완전히 상실함.
* **치명적 패인**: 사용자의 읽기 흐름을 깨뜨리는 난폭한 화면 전환으로 인해 각주 클릭률이 1% 미만으로 추락함.

### 반례 2: 레거시 관공서/금융 앱의 '전면 모달 팝업 남발'
* **실패 사건**: 약관 한 줄 확인하겠다고 누르면 화면 전체를 가리는 회색 딤(Dim) 처리 모달이 뜨고, 스크롤을 끝까지 내려야만 '확인' 버튼이 활성화되는 인터페이스.
* **치명적 패인**: 사용자를 가두어두는 강제적 화면 차폐(Screen Occlusion)로 인해 극심한 인지 저항과 반발을 초래함.

## 7. ⚖️ 기계적 🟢 Pass / 🔴 Fail 수치 판정선 (Quantitative Thresholds)

본 카드는 타깃 사용자의 **새 탭 이동 없는 인라인 증거 확인 속도와 화면 차폐율**을 기계적으로 측정한다.

| 평가 지표 | 측정 단위 | 🟢 Pass (검증 성공) | 🔴 Fail (즉각 중단/피벗) |
| :--- | :--- | :--- | :--- |
| **인라인 증거 엿보기 반응 속도** | ms (Peek Latency) | **< 100ms (호버/탭 즉시 0.1초 내 원천 증거 스냅샷 노출)** | >= 500ms (스피너가 돌며 로딩 지연 발생) |
| **외부 링크 점핑(새 탭) 발생률** | % (Context Loss) | **0.0% (팩트 검증 과정에서 외부 웹사이트로의 화면 전환 0건)** | >= 20.0% (출처를 보려면 무조건 외부 새 창으로 이동해야 함) |
| **총 인터랙션 완결 탭 수** | 횟수 (Tap Count) | **<= 3회 (질문 입력 ➔ 제약 칩 1회 ➔ 증거 엿보기 ➔ 확정)** | >= 6회 (새 탭 닫기, 팝업 끄기 등 불필요한 탭 누적) |
| **전체 화면 차폐 모달 수** | 개수 (Screen Occlusion) | **0개 (메인 뷰를 가리는 전체 화면 팝업 0건, 인라인 팝오버만 허용)** | >= 1개 (화면 전체를 덮는 모달 팝업 출현) |
