# 토론 카드 01-E — 시맨틱 서치(Vector RAG)의 구조적 결함과 조건부 제약 검증 한계

> **SVPG 정본 헌법**:  
> **"기술의 외형적 트렌드(LLM, Vector DB)에 도취되어 기술의 근본적 한계를 직시하지 못하면, 고객에게 그럴듯한 거짓말을 파는 사기 제품을 만들게 된다. 엔지니어링 리드는 알고리즘이 '무엇을 할 수 없는가(Failure Mode)'를 가장 잔인하게 파헤쳐야 한다."**

## 1. 쟁점 개요 (Background)

* **PM의 질문**:  
  > *"NotebookLM의 한계는 '시맨틱 서치' 기반이기 때문이야. 보험 약관처럼 사용자가 가입한 보장 항목은 일부인데, '심장 수술'을 치면 관련 없는 온갖 보장 내역이 다 튀어나와. 공공 및 오픈 사이언스로 제한한다고 딱 맞는 걸 가져올까? 도메인이 문제가 아니라 시맨틱 서치 자체가 문제야."*
* **토론 목적**: 
  * 왜 도메인을 B2C에서 학술/전문 데이터로 바꾼다 해도 '시맨틱 서치(Vector RAG)' 방식으로는 팩트 어트리뷰션이 100% 실패할 수밖에 없는지, 그 **기술적 파산 원인(Root Failure Cause)**을 정밀 해체함.

---

## 2. 보험 약관 사례로 본 시맨틱 서치의 3대 구조적 결함

```
[사용자의 실제 계약] : 암 특약만 가입됨 (심장 특약 미가입)
[사용자의 실제 질문] : "내가 이번에 심장 수술을 받는데 보장받을 수 있어?"
[시맨틱 임베딩 연산] : '심장 수술', '보장', '수술비' 벡터 코사인 유사도 98% 매칭!
[NotebookLM의 출력] : "네! 심장 수술 시 5,000만 원이 보장됩니다 [출처: 약관 42페이지]" ➔ (치명적 오답)
```

이 치명적 오류는 모델의 환각(Hallucination) 때문이 아니라, **시맨틱 서치(Vector RAG)라는 아키텍처 자체의 3대 구조적 결함**에서 기인함:

### ① 제약 조건(Constraints) 평가의 원천 부재
* 시맨틱 임베딩은 오직 **"단어와 문맥의 의미적 유사도(Similarity)"**만 측정할 뿐, **"이 조항이 참(True)이 되기 위한 전제 조건(가입 여부, 유효 기간, 고객 등급)"**을 검증할 수 없음.
* 텍스트 덩어리 자체에 '심장 수술 보장'이라는 단어가 들어있기만 하면, 사용자의 가입 스코프(Scope)와 일치하는지 여부와 상관없이 무조건 상위 랭킹으로 추출함.
* ➔ **결과: "의미는 100% 유사하지만, 논리적으로는 100% 거짓인 정보(Semantically Similar, Logically False)"** 출력.

### ② 논리적 부정(Negation / Exception)의 붕괴
* 임베딩 벡터 공간에서 *"보장한다"*와 *"다음 각 호의 사유는 보장하지 아니한다(면책 조항)"*는 거의 동일한 벡터 위치를 공유함.
* 시맨틱 서치는 '예외', '제외', '단서 조항'의 논리적 Boolean 인과를 분별하지 못하여, 엉뚱한 면책 문구를 보장 문구의 근거로 둔갑시킴.

### ③ 엔터티 간 관계(Relational Binding) 상실
* 문서를 무지성 청크(Chunk)로 잘라 벡터화하는 순간, **[피보험자 ➔ 가입 특약 ➔ 보장 항목 ➔ 지급 기준]**이라는 엄격한 관계형 스키마(Relational Schema)가 파괴되고 단순 텍스트 파편으로 전락함.

## 3. 학술 및 공공 도메인에서의 동일한 실패

도메인을 오픈 사이언스(arXiv, 논문)나 법령으로 옮겨도 이 실패는 100% 동일하게 반복됨:

* **논문 인용 참사**:
  * 연구자가 *"A 알고리즘이 B 문제 해결에 효과적인가?"*라고 물었을 때,
  * 시맨틱 서치는 두 단어가 많이 등장한 논문을 긁어옴.
  * 하지만 해당 논문이 **"A 알고리즘은 B 문제에 아무런 효과가 없음을 입증했다(Negative Result)"**는 결론이어도, 유사도가 높다는 이유로 *"효과가 있다"*며 인용하는 대참사가 발생함.
* **결론**: **도메인의 문제가 아니라, "유사도 매칭"에만 의존하는 기술 패러다임 자체가 문제의 진원지임.**

---

## 4. 토론 결론: 패러다임 시프트의 요구

우리가 달성해야 할 진짜 기술적 쐐기(Wedge)는 '더 큰 벡터 DB'나 '더 큰 임베딩 모델'이 아님:

| 비교 축 | 기존 시맨틱 서치 (NotebookLM / RAG) | 우리가 정의해야 할 차세대 어트리뷰션 |
| :--- | :--- | :--- |
| **판정 기준** | **유사도 매칭 (Similarity Matching)** | **제약 조건 충족 (Constraint Satisfaction)** |
| **데이터 형태** | 평문 텍스트 청크 (Flat Text Chunks) | **조건·관계·규칙이 결속된 구조화 그래프/스키마** |
| **검증 메커니즘** | "비슷한 단어가 있으니 이게 출처다" | **"사용자의 전제 조건 A, B를 만족하므로 이것이 참이다"** |
| **결과 신뢰성** | 그럴듯한 오답 (확률적) | **결정론적 팩트 (Deterministic)** |

> **💡 핵심 합의**:  
> **"팩트 어트리뷰션의 성패는 '글자를 얼마나 잘 찾아오는가'가 아니라, '조건과 제약(Constraints)을 얼마나 엄격하게 걸러내는가'에 달려 있다."**
