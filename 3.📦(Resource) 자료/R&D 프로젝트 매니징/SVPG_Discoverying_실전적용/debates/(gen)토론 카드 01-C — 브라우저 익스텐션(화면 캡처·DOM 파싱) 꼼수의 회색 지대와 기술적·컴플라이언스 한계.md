## 1. 쟁점 개요 (Background)

* **PM의 질문**: *"요즘 익스텐션처럼 GPT, Claude, Gemini가 사용자가 보는 화면을 '꼼수'를 활용해 제한도 뚫고 다 가져가고 쳐다보는 식으로 쓰던데, 여기서도 출처 표기를 못 하는 것을 보면 역시나 법적 문제 아닌가?"*
* **조사 및 토론 목적**: 브라우저 익스텐션 기반의 화면 캡처/DOM 스크래핑 방식이 가진 **회색 지대(Gray Area)의 실체**와, 그럼에도 불구하고 **왜 정확한 팩트 출처 앵커링을 구현하지 못하는지**에 대한 기술적·법적 원인을 규명함.

---

## 2. 익스텐션 '화면 훔쳐보기'의 작동 원리와 회색 지대

### ① 클라이언트 사이드 우회 꼼수 (The Client-side Workaround)
* 서비스 서버가 타사 웹사이트를 크롤링하면 IP 차단(Robots.txt)과 부정경쟁방지법 고소를 당하지만, **사용자의 브라우저 익스텐션(Chrome Extension 등)을 통해 사용자가 보고 있는 현재 탭의 DOM이나 스크린샷을 가져오는 것**은 형식상 "사용자 본인의 대리 행위"가 되므로 법적 단속을 교묘히 피해 왔음.

### ② 하지만 왜 '출처 표기'는 여전히 불가능한가?
화면을 다 들여다보면서도 AI가 *"이 문장은 저 웹페이지의 몇 번째 레코드에서 나온 것입니다"*라고 1:1 출처 뱃지를 달아주지 못하는 이유는 크게 **2가지 절벽** 때문임:

## 3. 화면 캡처 방식의 2대 치명적 절벽

### 🛑 1. 기술적 절벽: 극심한 시맨틱 유실 (Semantic Loss)
* **DOM의 일회성과 난독화**:
  * 최신 웹 플랫폼(네이버, 카카오, 구글, 학술 포털)은 React, Vue 기반의 SPA(Single Page Application)로 구동되며, 클래스명은 `class="_2kL8x"`처럼 무작위 해시로 난독화되어 있고, 화면 스크롤 시 DOM이 가상화(Virtual DOM)되어 사라짐.
* **불변 식별자(Canonical Anchor)의 부재**:
  * 익스텐션이 긁어가는 것은 렌더링된 겉껍데기 텍스트나 픽셀 이미지뿐임.
  * 따라서 원본 데이터의 **[고유 식별자(ID), 공식 API 엔드포인트 URL, 데이터 수집 시점 타임스탬프, 데이터베이스 원본 행(Row)]**이라는 핵심 메타데이터가 100% 증발함.
* **결과**: LLM은 "화면에서 본 텍스트"만 알 뿐, 그것이 언제 갱신된 것인지, 어떤 링크로 증명해야 하는지 알 길이 없어 출처를 연결할 수 없음.

### 🛑 2. 컴플라이언스 절벽: 개인정보 침해 및 UI 변조 분쟁
* **개인정보보호법(PII) 위반 리스크**:
  * 사용자가 보고 있는 화면에는 로그인된 계정 정보, 사적인 대화, 결제 정보 등 극도로 민감한 개인정보가 함께 노출됨. 이를 무차별 스크래핑하여 외부 LLM 서버로 전송하는 행위는 GDPR 및 개인정보보호법상 최고 수준의 과징금 대상임.
* **UI 무단 변조(In-page Overlay) 영업방해 시비**:
  * 익스텐션이 타사 웹사이트 위에 강제로 자체 팝오버를 띄우거나 출처 버튼을 주입(DOM Injection)하는 행위는 플랫폼 사업자로부터 **"악성 애드웨어/영업방해"**로 간주되어 브라우저 스토어(Chrome Web Store)에서 강제 퇴출당함.

## 4. 토론 결론 및 가설 2.0에 주는 교훈

| 구분 | 익스텐션 화면 캡처 꼼수 | 가설 2.0의 정공법 어트리뷰션 |
| :--- | :--- | :--- |
| **데이터 수집** | 불안정한 DOM/스크린샷 긁기 | **공인 Open API의 구조화된 JSON 데이터** |
| **출처 보증** | 불가능 (시맨틱 메타데이터 소실) | **[공식 원천 URL + 타임스탬프 + 발췌문] 1:1 보증** |
| **안정성** | 웹사이트 UI 변경 시 즉시 고장 | **표준화된 API 계약으로 영구적 불변성 유지** |
| **법적 리스크** | 개인정보 유출 및 스토어 퇴출 리스크 | **100% 합법 라이선스 기반 클린 파이프라인** |

### 💡 핵심 교훈
* 브라우저 화면을 훔쳐보는 꼼수는 **"신뢰할 수 있는 팩트 증명"**을 절대로 만들어낼 수 없음.
* 우리가 가설 2.0에서 취해야 할 길은 얄팍한 익스텐션 스크래핑이 아니라, **공인 API 기반으로 [주장-증거]를 100% 결속하는 '무결점 정공법 인스펙터'**여야만 함.
