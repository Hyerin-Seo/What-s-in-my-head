# (gen)프로토타입 00 — 가치(Value) 검증 총괄 로드맵 (신호 위계 및 3대 실측 프로토콜 허브)

> **SVPG 정본 헌법 (Marty Cagan)**:  
> *"The primary purpose of prototyping is to help discover a successful solution... before you proceed to building the actual product."*  
> *(프로토타입의 제1 목적은 실제 제품을 개발(코딩)하기 전에, 성공적인 솔루션을 발견하고 리스크를 검증하는 것이다.)*

## 1. 개요: 코딩 착수 전 가치(Value) 실측 헌법

본 문서는 `(gen)토론 카드 03`의 결론을 기반으로, **풀스택 상용 소프트웨어(React + FastAPI + DB) 코딩에 착수하기 전 2~3일 만에 시장의 실질적 화폐 지불(WTP)과 비가역적 전환 행동(WTS)을 실측하는 3대 가치(Value) 검증 프로토콜 및 종합 실행 로드맵**을 규정하는 총괄 허브 카드이다.

### 1.1 가치 검증 신호의 3대 위계 사다리 (Hierarchy of Evidence)

| 위계 레벨 | 신호 명칭 | 고객 행동 양식 | 유효성 판정 |
| :--- | :--- | :--- | :--- |
| **Level 3** | **비가역적 전환 (WTS)** | 기존 Word·ChatGPT 창을 영구히 닫고, 실제 마감 과제를 이 도구로만 작성 | **[궁극적 정본] 100% 통과** |
| **Level 2** | **실질적 화폐 결속 (WTP)** | 신용카드 번호 등록, 사전 예약금 결제, 공식 LOI 협약 서명 | **[최소 유효] 가치 검증 통과** |
| **Level 1** | **구두 칭찬 / 설문 의견** | "정말 좋네요", "출시되면 꼭 살게요", "디자인 멋집니다" | **[쓰레기 신호] 100% 무효 기각** |

## 2. 3대 가치(Value) 검증 프로토콜 세부 카드 맵 (1카드 1주제)

가치(Value) 검증은 리스크 성격과 대상 고객에 따라 아래 3개 전용 실행 카드로 분리하여 병렬 실측한다:

```text
prototypes/value/
├── 🎨 [[ (gen)프로토타입 01 — Figma 사용자 인터랙티브 프로토타입 (정성적 WTS·WTP 실측 프로토콜) ]]
│   • 주관: Product Designer + PM
│   • 형태: 코딩 0줄, 2일 제작 초고해상도 3단 클릭 목업
│   • 타깃: 2주 내 실제 마감 과제를 쥔 창업가·연구원 3명
│   • 판정: 다음 주 Word 창 끄기(WTS) & 50% 할인가 카드 번호 등록(WTP)
│
├── 📊 [[ (gen)프로토타입 02 — 페이크 도어 랜딩페이지 (정량적 클릭 수요 및 CVR 실측 스모크 테스트) ]]
│   • 주관: PM + Growth
│   • 형태: 1페이지 티저 (헤드카피 + 30초 데모 영상 + [월 39,000원 결제] 버튼)
│   • 타깃: 스타트업/창업 커뮤니티 대중 콜드 트래픽
│   • 판정: 고유 방문자 대비 결제 버튼 클릭 전환율 CVR ≥ 5% (Pass)
│
└── 🏢 [[ (gen)프로토타입 03 — B2B 사전 구매 의향서 (LOI 체결 기반 엔터프라이즈 WTP 실측) ]]
    • 주관: Founder + PM
    • 형태: Figma 시연 + A4 1장 B2B 사전 도입 협약서(LOI)
    • 타깃: 제안서/과제 작성이 빈번한 중소기업·스타트업 대표이사
    • 판정: 연 60만 원 전사 도입 조건의 공식 직인/서명 1건 이상 회수
```

## 3. 1주일 디스커버리 스프린트 실행 타임라인

```text
[Day 1~2: Figma User Prototype 직조]
- 2D 캔버스 없는 3단 레이아웃 (Reference - Document - Composer)
- 클릭 시 반응하는 초고해상도 인터랙티브 프로토타입 완성 (소요 2일)

[Day 3~4: 병렬 스파이크 가동]
├─ Track 1 (Value 실측)       : 마감 과제 보유자 3명 대면 Figma 테스트 & 선결제 카드 등록 유도
└─ Track 2 (Feasibility 스파이크) : 터미널 파이썬 스크립트(scratch/)로 1:1 팩트 앵커링 기술 실현성 계측

[Day 5: 사망 판정 회의 (Kill Criteria Evaluation)]
- Value 검증 통과 (WTP 카드 등록 1건 이상 OR Fake Door CVR ≥ 5% OR B2B LOI 1건) AND Feasibility 통과?
  ├─ YES ➔ 비로소 본격적인 상용 소프트웨어(Build to Earn) 코딩 착수
  └─ NO  ➔ 상용 코드를 1줄도 작성하지 않았으므로 매몰비용 0원 상태에서 즉각 기획 피봇
```

## 4. 팀 준수 절대 원칙 (Non-Negotiable)

1. **상용 코드 작성 금지**: 위 3대 프로토타입 중 최소 1개 이상에서 Level 2(화폐 결속) 이상의 실측 신호가 검증되기 전까지 상용 엔지니어링 본 코딩을 일체 금지한다.
2. **구두 호평 전량 폐기**: 설문이나 인터뷰에서 나온 모든 의견과 칭찬(Level 1)은 성과 지표로 채택하지 않는다.
3. **신속한 실패와 피봇**: 프로토타입 제작과 실험에 2~3일 이상을 쓰지 않으며, 판정선 미달 시 미련 없이 가설을 폐기한다.
