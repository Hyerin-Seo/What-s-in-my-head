# 현황 조사 04 — 시각·비선형 작업 공간 3종

## 판정: 2D Canvas를 제품 전제로 두지 않는다

세 제품의 공식 원문만으로도 2D/화이트보드형 지식 작업 공간, 공유 권한, 보안, 백업·내보내기 기능이 이미 존재함을 확인했다. 따라서 “2D Canvas가 있어야 자료를 정리할 수 있다”는 것은 발견된 문제가 아니라 아직 검증되지 않은 해법 가설이다.

| 서비스 | 공식 원문으로 확인한 범위 | 중요한 제약 |
| --- | --- | --- |
| Obsidian Canvas | 노트·미디어·웹 링크를 무한 2D 공간에 놓고 연결하며, 파일 형식이 공개되어 있다. | 캔버스의 데이터 위치·동기화·협업 방식은 별도로 구분해야 한다. Canvas 존재만으로 공동 검토·형식 준수는 보장되지 않는다. |
| Heptabase | 카드와 화이트보드를 분리된 데이터 모델로 다루고, 공유 범위·권한·백업·버전 복원을 명시한다. | 시각 배치와 카드 본문·속성·버전은 서로 다른 복구 범위를 가진다. 근거 앵커 보존도 따로 검증해야 한다. |
| Miro | AI가 가시 캔버스 문맥을 처리하고, 관리자가 AI 사용을 제한할 수 있으며, 권한/플랜별 내보내기와 Enterprise 감사 목적 내보내기를 제공한다. | 보드 PDF/CSV/SVG 반출은 구조·관계·댓글·링크를 완전 보존하지 않을 수 있다. 특히 일반 CSV는 보드 구조·관계를 유지하지 않는다. |

## 망고독이 답해야 할 질문

| 질문 | 나쁜 판정 방식 | 필요한 관찰 |
| --- | --- | --- |
| 2D Canvas가 필요한가? | “예뻐 보인다”, “생각 정리에 좋다” | 같은 실제 문서를 편집기·분할 화면·Canvas로 수행해 완료 시간, 누락, 원문 재확인, 되돌리기 횟수를 비교 |
| Canvas가 문서 결과물로 이어지는가? | 보드가 완성됐다는 인상 | Word/PDF/한글 등 요구 형식으로 반출해 제목 체계·표·인용·링크·댓글/검토 흔적이 보존되는지 검사 |
| 팀에서 안전한가? | 링크 공유가 가능함 | 초대·역할 변경·외부 공유 차단·복구·감사 필요성을 실제 조직 정책과 대조 |

## 사전 중단 기준

아래 중 하나라도 관찰되면 2D Canvas 중심 개발을 중단하거나 보조 기능으로 낮춘다.

1. 참가자 다수가 Canvas보다 편집기/분할 화면에서 같은 과업을 더 빨리, 더 적은 오류로 마친다.
2. Canvas 사용 후에도 원문 근거를 찾는 시간 또는 최종 형식 수정 시간이 줄지 않는다.
3. 도입 후보가 보안·권한·반출 요건 때문에 Canvas형 공간을 업무에 쓸 수 없다고 밝힌다.

## 증거 상태 갱신

- 서비스 현황: 18/18 서비스 확인. 공식 원문 53/54건; Gemini의 독립적인 가격/플랜 원문 1건은 보완 대상이다.
- 공개 행동 증거: 0/60건.
- 실제 문서 과업 팩: 0/12건.
- 실제 참여자 인터뷰·관찰: 0/12명.

이제 서비스 현황 조사의 최소 범위는 거의 찼다. 다음 작업은 벤더 기능이 아닌, 실제 공개 문서 과업과 사용자의 관찰 가능한 행동을 수집하는 것이다.
