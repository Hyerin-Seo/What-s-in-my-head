# 소스 범위·필수 서비스·수집 기준

> **목적**: 검색 결과 몇 개나 익명의 커뮤니티 발화만으로 시장·제품 결론을 만들지 않는다. 이 문서는 조사 전에 정한 최소 표본틀이며, 서비스 기능 변화는 수집일과 원문 URL을 기준으로 다시 확인한다.

## 1. 최소 수집량과 분포

| 소스 묶음 | 최소량 | 분포 규칙 | 쓸 수 있는 결론 |
| --- | ---: | --- | --- |
| 서비스 1차 출처 | 54개 페이지 | 필수 서비스 18종 × 서비스당 3개 | 기능·제약·가격·보안·내보내기 비교 |
| 공개 행동 증거 | 60건 | 12개 이상 도메인, 도메인당 최대 10건, 작성자 30명 이상 | 반복되는 불만·우회·전환 신호의 후보 |
| 실제 참가자 원자료 | 12명 내외 | 3코호트, 각 3명 이상. 최근 실제 사례 필수 | Job, 비용, 실제 Tool Stack |
| 공개 문서 과업 팩 | 12팩 | 아래 5개 문서 유형을 최소 2팩씩 포함 | 대안·프로토타입·기술 시험 |
| 전문·공공 작성 기준 | 20건 | 국내·해외 공공 출처를 모두 포함 | 형식 제약과 제출 맥락 |

공개 행동 증거의 수는 유병률이나 시장 규모를 뜻하지 않는다. 한 서비스·한 커뮤니티의 불만이 과대 대표되지 않도록 하는 **탐색 범위 하한**이다.

## 2. 반드시 확인할 서비스 18종

서비스별로 아래 세 종류를 각각 최소 1건씩 수집한다: **(a) 제품 기능 페이지, (b) 도움말·API·관리 문서, (c) 가격·보안·개인정보·파일 내보내기 중 관련 문서**. 기능 비교는 수집일과 플랜을 기록한다.

| 축 | 필수 서비스 | 이번 조사에서 확인할 질문 |
| --- | --- | --- |
| 기존 문서 편집 | Microsoft Word + Microsoft 365 Copilot, Google Docs + Gemini for Workspace, Notion + Notion AI, Coda + Coda AI, Confluence + Rovo, ClickUp Docs + ClickUp Brain | 기존 문서 안에서 형식 유지·근거 접근·협업·내보내기가 어디까지 되는가 |
| 리서치·근거 기반 작성 | NotebookLM, Perplexity, Genspark, Elicit, SciSpace | 출처 제시, 소스 제한, 장문 산출물, 재검증 흐름은 무엇인가 |
| 범용·자율 에이전트 | ChatGPT, Claude, Gemini, Manus | 파일·도구·장문 작성·재시도·감사 가능성은 제품별로 어떻게 다른가 |
| 시각·비선형 작업 공간 | Obsidian Canvas, Heptabase, Miro | 공간 배치가 단지 정리 경험인지, 실제 문서 과업의 시간·정확도를 개선하는지 |

**제외 금지**: 위 서비스 중 하나가 기능을 이미 제공한다고 확인되면, “시장 공백” 주장을 수정하거나 철회한다. 경쟁 서비스의 약점만 기록하는 방식은 금지한다.

실제 원문 수집 현황과 플랜·버전은 [[(chatgpt)필수 서비스 Source Register]]에서 관리한다.

## 3. 공개 행동 증거의 출처 사이트

아래는 검색 시작점이다. 특정 서비스의 홍보성 페이지·단일 밈·재인용 글은 원자료로 세지 않는다.

| 출처 유형 | 필수 도메인 또는 기관 | 수집할 것 | 주의점 |
| --- | --- | --- |
| 기술 커뮤니티 | Hacker News, Reddit, GeekNews, Product Hunt | 실제 사용 맥락, 실패·우회, 대체 도구 | 불만 게시물은 대표성 증거가 아니다 |
| 검증 가능한 제품 리뷰 | G2, Capterra, TrustRadius | 역할·조직 규모·플랜이 드러난 장단점 | 리뷰 인센티브·별점만으로 결론 내리지 않는다 |
| 한국형 문서·지원 맥락 | K-Startup, IRIS, NTIS, 나라장터, KOTRA | 사업계획서·과제·입찰의 제출 형식과 자료 요구 | 공고문은 사용자 행동 증거가 아니라 과업 제약 증거다 |
| 공공·전문 보고서 맥락 | NIA, NIPA, KDI, STEPI, KIET, 국회입법조사처 | 정책·연구·전략 보고서의 공개 형식·근거 관행 | 특정 기관의 양식을 일반화하지 않는다 |
| 해외 공공 보고서 맥락 | SEC EDGAR, OECD, World Bank, EU Funding & Tenders | 영어권 공시·정책·제안서의 형식과 검증 요구 | 국내 사용자의 실제 문제와 분리해 해석한다 |

각 공개 항목에는 permalink, 작성자 또는 기관, 게시일, 수집일, 검색어, 서비스·플랜, 문서 작업 맥락, 포함·제외 이유를 기록한다.

## 4. 문서 과업 팩 12종

각 과업 팩은 저작권·기밀 문제가 없는 공개 자료만 사용한다. **형식/레퍼런스 1건 + 근거 자료 3건 이상 + 성공 조건 1건**을 하나의 팩으로 묶는다. 실제 프로토타입 테스트에는 참여자의 동의를 얻은 비식별 자료를 우선한다.

| 과업 유형 | 최소 팩 수 | 필수 요소 |
| --- | ---: | --- |
| 정부지원·R&D 제안서 | 3 | 공고/양식, 과거 공개 예시 또는 평가 기준, 시장·기술 근거 |
| 입찰·RFP 대응 문서 | 2 | RFP, 요구사항 체크리스트, 제안 구조·근거 |
| 전략·시장 분석 보고서 | 3 | 보고서 목차, 데이터·시장 자료, 의사결정 요약 |
| 정책·연구 브리프 | 2 | 공개 보고서 형식, 통계·논문·정책 근거 |
| 기술·품질·실사 보고서 | 2 | 규격 또는 체크리스트, 증거 자료, 오류 판정 기준 |

각 팩의 성공 조건은 “그럴듯한 글”이 아니라 다음처럼 검증 가능하게 쓴다: 필수 섹션 완성, 형식 누락 수, 근거 없는 주장 수, 근거 재확인 시간, 검토자가 되돌린 항목 수.

## 5. 출처 등급과 교차 검증

| 등급 | 예시 | 사용 방식 |
| --- | --- | --- |
| A — 1차 | 실제 참가자 관찰, 원문 문서, 공식 제품 문서, 공개 공고 원문 | 기능·행동·형식 주장에 우선 사용 |
| B — 독립 2차 | 전문 리뷰, 연구기관 보고서, 신뢰할 수 있는 분석 | A 출처와 교차 확인 |
| C — 공개 신호 | 포럼, 커뮤니티, 사용자 리뷰 | 인터뷰 질문과 후보 문제를 찾는 데 사용 |
| D — 재인용·AI 요약 | 출처 없는 블로그 요약, AI 생성 문장 | Evidence Matrix의 증거로 사용 금지 |

핵심 주장 하나는 최소한 **서로 독립적인 A 출처 2개** 또는 **A 출처 1개 + B 출처 1개**와 연결한다. 단, 제품의 공식 기능은 해당 서비스의 A 출처만으로 확인할 수 있지만, 고객의 실제 문제를 공식 제품 페이지로 증명할 수는 없다.

## 6. 수집 중단·보완 규칙

- 필수 18종 중 미확인 서비스가 있으면 경쟁 지형 결론을 쓰지 않는다.
- 60건을 채웠어도 한 코호트·한 도메인·한 서비스에 쏠렸으면 해당 표본을 보완한다.
- 서비스 기능이 최근 90일보다 오래된 원문에만 근거하면 최신 도움말·변경 로그를 다시 확인한다.
- 인용문은 25단어 이내의 필요한 발췌와 permalink를 함께 남긴다. 맥락을 알 수 없는 익명 인용은 폐기한다.
- 수집량을 채우는 것이 목적이 아니다. 새로운 정보가 더 이상 나오지 않을 때도 상충 사례를 최소 5건 찾을 때까지 종합을 보류한다.
