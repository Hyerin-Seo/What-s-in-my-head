# (gen)Purpose & Overview — 온보딩 2단계: 실전 하네스(Harness) 및 Co-working 노하우 적용과 상한선 체감

> **온보딩 2단계 정본 헌법 (`usablility_사용성 담당 첫 실전 테스트 문서 및 백데이터 요건` 연계)**:  
> *"1단계가 아무런 고급 도구 없이 날것(raw) 상태에서 일반 챗창으로 작업하며 겪는 복붙 노가다와 사용성 피로를 체감하는 과정이었다면,  
> **2단계는 유튜브 등에서 회자되는 파워 유저들의 워크플로우 중 진짜 쓸 만한 하네스 세팅과 에이전트 협업(co-working) 꿀팁을 민규 서가 압축 선별하여 Rin에게 전수하고, 이를 적용해 보며 '에이전트를 제대로 썼을 때의 진짜 잠재력과 상한선'을 체감하는 단계**이다."*

---

## 1. 2단계의 명확한 목적 및 배경 (The Core Purpose)

1단계(`docs-agent-building`)에서 날것의 챗창에 부딪혀본 작업자는 "단순 대화창으로는 긴 문서 작업을 하기가 너무 불편하고 지친다"는 한계를 몸으로 알게 되었습니다.

그렇다면 다음 질문이 자연스럽게 이어집니다.
> *"세상에 에이전트를 잘 쓴다는 파워 유저들은 대체 어떤 하네스(프롬프트 틀, 템플릿, 컨텍스트 세팅)를 채워서 일하길래 10배 빠르다고 말하는 걸까?"*

이 2단계(`docs-agent-harness`)의 유일한 목적은 **그 상한선(Ceiling)을 직접 확인하는 것**입니다:
* 작업자가 유튜브 수백 편을 찾아보며 시간을 낭비할 필요가 없습니다.
* **민규 서가 평소 검증해둔 '문서 작업 개꿀팁' 중 허수를 걷어내고 실무에 유효한 알짜 하네스/협업 요령 3~4가지를 선별하여 압축 전수**합니다.
* Rin은 이 전수받은 하네스를 장착하고 Candidate 과제에 다시 적용해 봄으로써, **"에이전트가 제대로 통제되었을 때 발휘하는 진짜 생산성의 맛과 상한선"**을 맛보게 됩니다.

## 2. 이 공간(`docs-agent-harness`)에서 진행될 핵심 내용

민규 서의 실전 To-Do 과제(`empowered_유튜브·하네스 기반 에이전트 협업 노하우 선별 및 전수`)와 1:1로 맞물려 다음 작업들이 전개됩니다:

```text
┌────────────────────────────────────────────────────────┐
│  [1. 레퍼런스 선별] 유튜브 파워 유저의 실전 팁 2~3편 발췌│
│  → 영상 속 장황한 설명을 쳐내고 실무에 유효한 핵심만 압축 │
├────────────────────────────────────────────────────────┤
│  [2. 하네스 툴킷화] 프롬프트 템플릿 + 문맥 유지 팁 3선   │
│  → Rin이 복사해서 바로 쓸 수 있는 형태의 하네스로 정제    │
├────────────────────────────────────────────────────────┤
│  [3. 1:1 노하우 전수 및 실전 적용]                      │
│  → 선별된 하네스를 장착하고 Candidate 문서에 실전 적용   │
├────────────────────────────────────────────────────────┤
│  [4. 상한선 확인 및 한계 포착]                          │
│  → "와, 여기까지는 진짜 편해지네!" + "그래도 이건 안 되네" │
└────────────────────────────────────────────────────────┘
```

## 3. 2단계가 남겨야 할 진짜 소득 (What We Gain)

작업자는 하네스를 장착하고 작업해 보며 두 가지 중요한 기준선을 얻게 됩니다:

1. **에이전트 코워킹의 진짜 잠재력 체감**:
   * "1단계에서는 표 하나 제대로 못 뽑아서 화가 났는데, 민규 서가 알려준 하네스 세팅을 쓰니까 1분 만에 뼈대가 잡히네?"라는 극적인 생산성 도약(Aha-moment)을 경험합니다.
2. **파워 유저 하네스의 '남은 한계' 포착 (망고독의 무대)**:
   * 아무리 유튜브 꿀팁과 프롬프트 하네스를 총동원해도, **"여전히 텍스트 기반 인터페이스로는 마우스 드래그나 캔버스 앵커링 같은 직접 조작(Direct Manipulation)의 직관성을 따라올 수 없다"**는 마지막 병목을 발견하게 됩니다.
   * 이 결핍을 스스로 인지했을 때, 비로소 **망고독 프로토타입의 캔버스/에디터를 조작할 수 있는 가장 예리한 '사용성 감각'**이 완성됩니다.

## 5. 최종 연결: 망고독 프로토타입 Usability 검증으로의 도약

이 2단계를 마친 Rin은 더 이상 낯선 개념에 막히는 초심자가 아닙니다.  
**에이전트의 밑바닥(1단계)과 상한선(2단계)을 모두 경험한 정예 테스터**로서, 비로소 망고독 프로토타입을 손에 쥐고 손가락이 멈추거나 헷갈리는 지점(Confusion Point)을 즉시 Usability 개선 과제로 추출할 수 있게 됩니다.
