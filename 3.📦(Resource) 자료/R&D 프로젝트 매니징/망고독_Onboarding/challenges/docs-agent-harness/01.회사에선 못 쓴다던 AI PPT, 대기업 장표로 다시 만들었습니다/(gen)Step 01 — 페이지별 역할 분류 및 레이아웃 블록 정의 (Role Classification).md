# (gen)Step 01 — 페이지별 역할 분류 및 레이아웃 블록 정의 (Role Classification)

> **Step 01 헌법**:  
> *"AI에게 '한 페이지 멋지게 써줘'라고 하면 줄글로 흘러내린다.  
> 텍스트를 채우기 전에 **이 페이지가 [실적 비교표]인지 [로드맵]인지 역할을 먼저 못 박고, 정보 블록(Box)의 개수와 비율을 먼저 고정**하라."*

---

## 1. 왜 '페이지별 역할 분류'가 첫 번째 하네스인가?

일반 채팅창에서 AI에게 내용을 요청하면, AI는 텍스트를 얼마나 길게 써야 할지, 어디에 배치해야 할지 전혀 모른 채 화면 가득 줄글을 쏟아냅니다.

대기업 장표(삼성, 현대, LG)의 공통점은 **슬라이드 한 장의 '역할'이 극도로 명확히 분절되어 있다는 점**입니다:
* "이 장표는 3개 사업부의 실적을 비교하는 장표다" ➔ **3열 균등 분할 블록**
* "이 장표는 상반기 핵심 문제 1가지를 고발하는 장표다" ➔ **상단 1줄 헤드라인 + 중앙 대형 1개 블록**
* "이 장표는 향후 3개년 추진 계획이다" ➔ **가로 3단계 타임라인 화살표 블록**

역할이 분류되면 **정보가 들어갈 '그릇(블록)'의 형태가 자동으로 결정**됩니다.

---

## 2. 대기업 실무 장표의 5대 핵심 역할 유형

| 장표 역할 유형 | 목적 및 성격 | 정보 블록(Box) 추천 구조 | 배치 비율 (Grid) |
| :--- | :--- | :--- | :--- |
| **A. 키 메시지형 (Headline)** | 경영진 의사결정용 1줄 결론 제시 | 상단 결론 카드 + 하단 2열 근거 블록 | 상하 3:7 분할 |
| **B. 3자 비교형 (Comparison)** | 대안 A vs B vs C 장단점 비교 | 가로 3열 균등 카드 매트릭스 | 1:1:1 좌우 대칭 |
| **C. 데이터 실적형 (Data Table)** | 분기별 실적 및 KPI 달성률 | 상단 지표 요약(3칸) + 하단 상세 격자 표 | 상하 2:8 분할 |
| **D. 프로세스/로드맵 (Timeline)** | 단계별 실행 계획 및 마일스톤 | 가로 3~4단계 화살표/스텝 블록 | 가로 선형 플로우 |
| **E. 매트릭스형 (2x2 Matrix)** | 우선순위 및 시장 포지셔닝 | 4분면 격자 블록 | 2x2 정사각 격자 |

---

## 3. 실전 하네스 프롬프트 템플릿 (AI에게 족쇄 채우기)

AI에게 내용을 채우라고 지시하기 전에, 반드시 아래와 같이 **블록 구조 하네스**를 먼저 선언합니다.

```text
[Step 01 하네스 지시문]
"이번 페이지의 역할은 [B. 3자 대안 비교형]입니다.
화면 전체를 임의로 줄글로 채우지 마십시오.
반드시 아래의 블록 구조 규격을 엄격히 지켜서 출력하십시오:

- 상단 헤더: 전체를 관통하는 1줄 결론 (최대 40자)
- 본문 레이아웃: 가로 3열(Column) 균등 분할 카드 구조
  * 1열 카드: [기존 대안] (특징 3개 불릿 + 단점 1개)
  * 2열 카드: [경쟁사 모델] (특징 3개 불릿 + 한계 1개)
  * 3열 카드: [우리 솔루션] (차별점 3개 불릿 + 기대효과)
- 하단 풋터: 핵심 시사점 1줄 (각주 크기)"
```

## 4. 효과 및 망고독(Scaffolding) 연결점

* **효과**: AI가 줄글로 주절거리거나 사족을 붙이지 못하고, **정확히 지정된 3개 열의 카드 블록 안에만 팩트를 쏙쏙 채워 넣게 됨**.
* **망고독 연결**: 망고독의 **캔버스 컴포넌트(Container, Grid Node)**가 바로 이 역할을 마우스 클릭 한 번으로 수행하는 물리적 하네스입니다.
