# (gen)Step 04 — 교차 출처 앵커링 및 액션 인사이트 큐레이션 (Cross-Source Synthesis)

> **Step 04 헌법**:  
> *"요약(Summary)은 과거를 말하지만, 보고서(Report)는 미래를 말한다.  
> 복수의 소스 문서를 교차 대조(Cross-Source)하여 숨겨진 리스크를 발굴하고, **'그래서 우리가 내일 당장 무엇을 실행해야 하는가(Next Action)'**를 도출하라."*

---

## 1. 왜 '교차 분석(Synthesis)'이 보고서의 완성인가?

단순한 요약 도구와 실무 보고서의 결정적 차이는 **'통합적 인사이트(Synthesis)'**에 있습니다:
* 소스 A(시장 보고서)만 보면 기회가 보이고,
* 소스 B(사내 시스템 규칙)만 보면 제약이 보입니다.
* 진정한 실무 보고서는 **"소스 A의 기회와 소스 B의 제약을 교차 대조하여 현실적인 돌파구를 제시하는 것"**입니다.

노트북LM은 여러 문서를 동시에 올려두었을 때, **복수 출처의 팩트를 엮어내는 교차 앵커링(Cross-Source Grounding)**에 가장 강력한 힘을 발휘합니다.

---

## 2. 교차 인사이트 도출 3단계 프레임워크

```text
┌────────────────────────────────────────────────────────┐
│ [1단계: 소스 간 대립점 포착] (Friction Discovery)      │
│   → 소스 1(목표)과 소스 2(현실) 간의 격차와 충돌 식별   │
├────────────────────────────────────────────────────────┤
│ [2단계: 숨겨진 리스크 분석] (Risk Identification)       │
│   → 단순 지표 뒤에 숨겨진 구조적 병목 및 비용 리스크   │
├────────────────────────────────────────────────────────┤
│ [3단계: 액션 플랜 큐레이션] (Actionable Next Steps)     │
│   → 당장 1주일 내 착수할 수 있는 R&R 및 마일스톤 제언   │
└────────────────────────────────────────────────────────┘
```

## 3. 실전 하네스 프롬프트 템플릿 (교차 인사이트 및 액션 도출)

```text
[Step 04 교차 합성 프롬프트]
"현재 업로드된 [소스 A]와 [소스 B]를 상호 교차 대조하여 최종 시사점을 도출하십시오:

1. [소스 간 상호 대조 분석]:
   - [소스 A]에서 제시하는 기회/목표와 [소스 B]에 명시된 현실적 제약/원칙이 충돌하는 핵심 지점 2가지를 짚어낼 것.
2. [잠재 리스크 식별]:
   - 이대로 실행했을 때 발생할 수 있는 운영상/기술상 리스크 3선 (각 리스크별 완화 대책 병기).
3. [결론: 3대 Action Items]:
   - 경영진과 실무팀이 당장 다음 주부터 실행해야 할 3가지 구체적 과제 (우선순위, 담당 주체 명시).
* 모든 제언은 반드시 관련 소스 번호([1], [2])를 정확히 링크할 것."
```

## 4. 효과 및 망고독(Scaffolding) 연결점

* **효과**: AI가 단순한 정보 복사기를 넘어, **복수의 문서를 꿰뚫어 보고 전략적 방향을 제시하는 '스마트한 기획 보조관'으로 진화**.
* **망고독 연결**: 망고독의 **멀티 소스 앵커링(다중 참조 링크)** 아키텍처가 바로 복수의 백데이터를 하나의 슬롯에 교차 주입하여 시너지를 내는 핵심 메커니즘입니다.
