# (gen)Step 01 — 원천 소스 데이터 바인딩 및 그라운딩 기준선 고정 (Source Grounding)

> **Step 01 헌법**:  
> *"AI에게 넓은 인터넷 바다를 헤엄치게 두지 마라.  
> **내가 제공한 소스(PDF, 문서, 링크) 안에 AI를 가두어두고, 오직 그 안에서만 지식을 인용(Grounding)하게 만들 때 환각은 0%**가 된다."*

---

## 1. 왜 '소스 바인딩(Source Grounding)'이 최우선인가?

일반 ChatGPT나 Claude 창에 프롬프트를 입력하면, AI는 자신이 학습한 방대한 외부 지식에서 그럴싸한 단어들을 엮어냅니다. 그 결과 실무 보고서에서 가장 위험한 **"없는 통계 지어내기", "규칙 위조"**가 발생합니다.

구글 노트북LM(NotebookLM)의 핵심 하네스는 **'RAG(검색 증강 생성) 기반 소스 바인딩'**입니다:
* 사용자가 좌측 패널에 업로드한 문서(최대 50개 소스)만을 **'절대적 진실의 유일한 원천(Ground Truth)'**으로 선언합니다.
* AI가 작성하는 모든 문장은 **소스 원문의 실제 문단 번호([1], [2])와 1:1로 묶여 앵커링**됩니다.

---

## 2. 실전 소스 업로드 및 컨텍스트 정제 전략

노트북LM에 원천 데이터를 장착할 때 지켜야 할 3대 원칙:

```text
┌────────────────────────────────────────────────────────┐
│ [원칙 1] 단일 파일 몰빵 금지 ➔ '성격별 분절 소스' 등록  │
│   → 소스 1: 사내 시스템 규칙 (CLAUDE.md)               │
│   → 소스 2: 최신 통계 및 시장 데이터 (PDF / URL)       │
│   → 소스 3: 과거 사내 모범 보고서 양식 (텍스트 덤프)    │
├────────────────────────────────────────────────────────┤
│ [원칙 2] 소스 체크박스 필터링 (Surgical Focusing)      │
│   → 특정 파트를 작성할 때는 관련 없는 소스의 체크를 해제│
│   → AI의 컨텍스트 혼선과 불필요한 간섭을 원천 차단      │
└────────────────────────────────────────────────────────┘
```

---

## 3. 실전 하네스 프롬프트 템플릿 (외부 지식 차단 선언)

노트북LM 챗창에 질문하기 전, 첫 번째 프롬프트에 **지식 경계 하네스**를 명시합니다.

```text
[Step 01 소스 고정 프롬프트]
"당신은 오직 현재 업로드된 [소스 문서들]에 기재된 사실만을 바탕으로 보고서를 작성하는 분석관입니다.

지침:
1. 소스에 명시되지 않은 외부 지식, 일반적인 상식, 추정치는 일체 답변에 포함하지 마십시오.
2. 소스에서 근거를 찾을 수 없는 항목은 지어내지 말고 반드시 '해당 내용은 제공된 소스에 명시되어 있지 않음'으로 표기하십시오.
3. 모든 핵심 주장과 데이터 뒤에는 반드시 소스 인용 번호([1], [2])를 정확히 병기하십시오."
```

## 4. 효과 및 망고독(Scaffolding) 연결점

* **효과**: AI가 쓴 문장을 인간이 일일이 의심하고 구글링하며 검수할 필요 없이, **각주 번호를 클릭해 원문을 1초 만에 확인하는 완벽한 팩트 신뢰 확보**.
* **망고독 연결**: 망고독의 **Reference 드래그 앤 드롭 앵커링**이 바로 이 원천 소스 바인딩을 리치 텍스트 에디터와 캔버스 위에서 시각화한 형태입니다.
