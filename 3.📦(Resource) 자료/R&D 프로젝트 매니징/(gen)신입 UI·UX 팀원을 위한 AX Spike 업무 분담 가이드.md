# 신입 UI·UX 팀원을 위한 AX Spike 업무 분담 가이드

> **핵심 요약**: R&D 및 AX 경험이 없는 신입 디자이너에게 자율성을 주면 100% 완벽주의의 늪에 빠집니다. 매니저가 **가설·DoD·Kill 기준을 4종 세트로 좁혀주고, Low-Fi(와이어프레임)를 강제하는 가드레일**을 제공해야 팀원도 보호하고 R&D 검증 속도를 확보할 수 있습니다.

---

## 1. 배경: 왜 신입 UI/UX에게 Spike를 그대로 주면 안 되는가?

* **전통적인 UI/UX 디자이너의 사고방식 (양산형 / SI)**:
  * *"요구사항이 명확하게 주어지면, 디자인 시스템 규격에 맞춰 가장 예쁘고 완성도 높은 고해상도(Hi-Fi) 화면을 산출한다."*
* **R&D 디자이너의 사고방식 (탐색적 AX)**:
  * *"이 인터랙션이 인간에게 진짜 편한지(손맛) 확인하기 위해, 3일 안에 가장 거칠고 빠른 버리는 목업(Throwaway Prototype)을 만들어 검증한다."*

접근 패러다임 자체가 정반대이기 때문에, 가이드 없이 Spike를 맡기면 3일 내내 피그마 오토레이아웃과 폰트 크기만 맞추다가 정작 가설 검증은 하나도 못 한 채 시간이 만료됩니다.

---

## 2. 신입 UI/UX가 R&D/AX에서 빠지기 쉬운 3대 치명적 함정

### 🚨 함정 1. '피그마 장인'의 늪 (완벽주의에 의한 시간 낭비)
* **현상**: 3일 안에 결론을 내고 버릴 수도 있는 프로토타입인데, 여백 8px, 컬러 팔레트, 디자인 컴포넌트 라이브러리를 구축하느라 시간을 다 씁니다.
* **결과**: 결과물은 화려하고 예쁜데, 사용자가 조작했을 때의 인지 부하 감소 여부는 전혀 측정되지 않습니다.

### 🚨 함정 2. AI의 '비결정론적 특성(Non-deterministic)' 무지
* **현상**: 일반 앱처럼 버튼을 누르면 즉시 성공하는 **'이상적인 단 하나의 해피 패스(Happy Path)'**만 디자인해 옵니다.
* **결과**: AI가 헛소리를 하거나(Hallucination), 응답 지연으로 멈칫거리거나, 스트리밍 토큰이 끊기는 동적인 예외 상태 디자인이 완전히 누락됩니다.

### 🚨 함정 3. '실패(Kill)에 대한 공포'
* **현상**: 일반 디자인 업무에서 "시안 기각"은 무능이나 인사고과 탈락을 의미하므로, 자신이 만든 인터랙션이 불편하다는 데이터가 나와도 억지로 변명하며 지키려 합니다.
* **결과**: R&D의 핵심인 빠른 실패(Fail-Fast)가 작동하지 않고 매몰 비용이 발생합니다.

## 3. 신입 UI/UX를 위한 4대 업무 분담 가드레일 (Scaffolding)

```
[매니저(Lead)의 역할]                           [신입 UI/UX의 역할]
- 가설(Why) 명확화                               - 피그마 인터랙션 컴포넌트 구현
- DoD & Kill 기준 사전 확정       ──▶            - 팀원 3명 대상 조작 시뮬레이션
- 해상도(Low-Fi) 강제 제한                       - 1페이지 조작성 결과 리포트 제출
- 레퍼런스(Cursor, Miro) 제공
```

### 🛡️ 가드레일 1. 해상도를 강제로 낮춰라 (Low-Fi 강제)
* 업무 지시 시 명확한 제약을 겁니다:
  > *"절대 디자인 시스템을 만들지 마세요. 회색 네모 박스와 기본 고딕체로만 그리세요. 예쁘게 그려오면 반려할 겁니다. 중요한 것은 **마우스로 드래그할 때의 조작감(손맛)**입니다."*

### 🛡️ 가드레일 2. 가설(Hypothesis)과 Kill 기준은 매니저가 세팅해서 전달하라
* 신입에게 *"오버레이 프롬프팅 가설 세워봐"*라고 하면 일주일 동안 고민합니다.
* 매니저가 **가설, 타임박스, DoD, Kill 기준 4종 세트**를 채운 상태로 업무를 발주해야 합니다.

### 🛡️ 가드레일 3. 반드시 "외부 레퍼런스(벤치마크)"를 쥐어줘라
* 아무것도 없는 상태에서 AX를 상상하게 하면 비현실적인 기획이 나옵니다.
* **"미로(Miro)의 캔버스 영역 선택 인터랙션", "Cursor의 `Cmd+K` 인라인 편집창"** 등 실제 존재하는 동작 영상/스크린샷 2~3개를 주고 *"이 둘을 조합해서 우리 문서 오버레이로 변형해 보세요"*라고 범위를 좁혀줍니다.

### 🛡️ 가드레일 4. "Kill을 증명해 오면 최고의 성과"라고 심리적 안전감을 주어라
* 디자이너에게 사전에 선언합니다:
  > *"이 3일짜리 스파이크는 네 디자인을 채택하기 위한 게 아니라, **오버레이 방식이 글쓰기 흐름을 방해한다는 걸 3일 만에 밝혀내서 우리 팀이 3개월간 헛고생하는 걸 막아주는 게 목표**야. 불편하다는 데이터를 가져오면 최고의 칭찬을 해줄게."*

## 4. 실전 템플릿: [신입 UI/UX 전용 AX Spike 위임 카드]

신입 팀원에게 업무를 티켓으로 배분할 때 사용하는 표준 양식입니다.

```markdown
■ 과업명: [AX Spike 01] 문서 오버레이 기반 맥락 지정 인터랙션 손맛 검증
- 담당자: 신입 UI/UX 디자이너
- 타임박스: 2일 (16시간)

1. 검증 가설 (Why):
   문서 특정 영역을 마우스로 드래그해 반투명 오버레이를 씌우면, 
   채팅창에 타이핑하는 것보다 맥락 지정 피로가 줄어들 것이다.

2. 레퍼런스 (참고):
   - 미로(Miro) 영역 다중 선택 박스 동작
   - Cursor 에디터 코드 블록 하이라이트 인터랙션

3. 산출물 제한 (제약):
   - ⚠️ 절대 최종 그래픽 디자인 금지 (회색 박스와 와이어프레임으로만 작업)
   - 피그마 '스마트 애니메이션'으로 드래그 동작이 구현된 클릭 가능한 프로토타입 1개

4. 완료 정의 (DoD):
   - 팀원 3명에게 직접 마우스로 오버레이를 씌워보게 한 뒤, 
     "본문 글자가 가려져서 답답한가?"에 대한 1페이지 인터뷰 리포트 제출

5. 킬 기준 (Kill Criteria):
   - 3명 중 2명 이상이 "오버레이 씌우는 행위 자체가 글쓰기 흐름을 방해한다"고 응답 시 
     ➔ 즉시 오버레이 폐기(Kill)하고 우측 패널 고정 핀 방식으로 피벗
```

## 5. 결론: 매니저의 마인드셋

신입 UI/UX 팀원에게 R&D Spike를 맡길 때 가장 중요한 것은 **자유를 주는 것이 아니라, 날카롭고 좁은 가드레일(가설 + Kill 기준 + Low-Fi 제한)을 쳐서 안전하게 뛰어놀게 해주는 것**입니다.

가드레일이 견고할 때 신입 팀원은 실패의 두려움 없이 과감한 인터랙션을 실험할 수 있고, 우리 프로젝트는 헛개발 없이 빠른 R&D 속도를 유지할 수 있습니다.
