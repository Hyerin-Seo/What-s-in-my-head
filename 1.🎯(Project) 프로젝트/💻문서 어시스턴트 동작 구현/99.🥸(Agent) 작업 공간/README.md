# 🥸 에이전트 작업 공간 (Agent Workspace)

## 1. 공간 개요 및 목적 (Overview & Sandbox Policy)

- **정체성:** 정규 PARA 구역(`0.inbox` ~ `4.archive`)과 분리된 **에이전트 전용 격리 작업 공간(Sandbox)**.
- **존재 이유:** 에이전트가 리서치, 아이데이션, 멀티스텝 작업 기억, 원본 수집 등을 수행할 때 볼트 본문이나 정규 보드(`.base`)를 오염시키지 않도록 임시 데이터를 안전하게 격리.
- **핵심 원칙:** "임시 작업과 스크래치는 99번 내부에서 자유롭게 다루되, 검증 완료된 최종 산출물만 정규 볼트로 승격한다."

---

## 2. 하위 폴더별 역할 및 세부 기준 (Directory Architecture)

사업 기획, 디자인, 기술 아키텍처 등 프로젝트 전반의 다양한 활동을 균형 있게 지원하도록 3개 하위 공간의 역할을 규정합니다.

| 폴더 | 주요 역할 및 업무 범위 | 세부 상태/기준 |
| :--- | :--- | :--- |
| **`A1.Collection`** | 기술 사양·아키텍처 레퍼런스, 디자인·UI/UX 자료, 시장 조사 및 사업 계획 기초 데이터 등 프로젝트 전반의 원천 자료 수집소 | - **검토 중**: 기술 타당성 또는 사업/기획 적합성을 분석·검토 중인 자료<br>- **paused**: 우선순위나 리소스에 따라 잠시 보류해 둔 참고 자료<br>- **history**: 기획 또는 개발에 반영 완료되어 이력으로 보존하는 자료 |
| **`A2.Scratch(Ideation)`** | 신규 아이템 발굴, 비즈니스 모델 구상부터 시스템 구조 설계, 기술 프로토타입 가설, UI 콘셉트 스케치까지 자유로운 발상 공간 | 형식에 구애받지 않고 기술·비즈니스 가설 검증, 러프한 초안, 마인드맵을 실험하는 다목적 작업대(Scratchpad) |
| **`A3.Working Memory`** | 사업 계획서 작성, 시스템 아키텍처 설계, 복합 기능 구현 등 호흡이 긴 다단계 태스크의 진행 상태 및 맥락 보존 공간 | 복잡한 프로젝트 수행 중 맥락 손실을 방지하고, 에이전트 간 또는 사람-에이전트 간 끊김 없는 인수인계를 위한 작업 기억 |
