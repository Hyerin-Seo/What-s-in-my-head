# (gen)Risk 02 — Usability Risk (Composer 인터랙션 및 조작성 검증)

> **SVPG 정본 헌법 (Marty Cagan)**:  
> *"고객이 이 제품을 사용하는 방법을 쉽게 알아내고 조작할 수 있는가? (Can users figure out how to use it?)"*  
> 기능이 아무리 훌륭해도, 30장짜리 거대한 문서를 조작하는 멘탈 모델이 복잡하거나 피로감을 유발하면 사용자는 도구를 집어던진다.

---

## 1. 리스크 정의 및 치명도 (The Fatal Risk)

* **핵심 질문**: 복잡한 2D 캔버스 없이, **좌측 `@Reference` 백데이터 뷰어, 우측 `Composer` 프롬프트/지휘창, 중앙 `Document` 실시간 프리뷰의 3단 화면 구성만으로 사용자가 30~50장 대형 문서를 길을 잃지 않고 직관적으로 통제할 수 있는가?**
* **치명도**: **상 (High / 인지 부하 리스크)**
  * 30~50장 분량의 문서는 책 한 권에 준하는 구조적 깊이(H1~H4 다단 목차, 수십 개의 표와 캡션)를 지닌다.
  * 개발자들은 IDE와 파일 트리, Git Diff 인터랙션에 익숙하지만, 일반 지식 노동자(기획자, 연구원, 창업가)에게 다단 문서의 인라인 Diff(Accept/Reject)와 Composer 지휘 인터랙션은 생소할 수 있다.
  * "내가 지금 어디를 수정하고 있는지", "Composer가 문서를 제멋대로 망가뜨리지 않는지"에 대한 **장악감(Sense of Control)을 주지 못하면 사용자는 불안감 때문에 조작을 포기한다.**

---

## 2. 핵심 검증 가설 (Core Hypotheses)

| 번호 | 검증 가설 (Hypothesis) | 가설 지탱 근거 |
| :--- | :--- | :--- |
| **H1** | **3단 분할 멘탈 모델**: 사용자는 2D 무한 캔버스가 없어도, **[목차 트리 + 섹션 집중 뷰 + Composer]의 3단 분할 구조**를 통해 30장 전체의 거시적 맥락과 미시적 문장을 동시에 장악할 수 있다. | 노션/옵시디언의 목차 패널과 워드의 내비게이션 바가 이미 입증한 인지적 친숙함 |
| **H2** | **Composer 러닝커브**: Cursor를 써본 적 없는 비개발자 직군도 **`@파일명` 멘션과 "이 표의 2026년 수치를 백데이터 p.12 기준으로 채워줘" 수준의 자연어 지시를 3분 이내에 학습**하여 능숙히 조작한다. | 메신저 기반 멘션(@) 및 생성형 AI 채팅에 대한 전국민적 UX 학습 완료 |
| **H3** | **부분 수용/거절 (Diff)**: Composer가 제안한 수정본에 대해 **섹션 단위로 [Accept] / [Reject]를 선택하는 인터랙션이, 사용자로 하여금 "내가 문서를 완벽히 통제하고 있다"는 안도감**을 제공한다. | Cursor의 Cmd+K 인라인 diff 수용 경험을 문서 직조로 이식 |

## 3. 사망 판정 기준 (Kill Criteria / Fail Fast)

다음 조건 중 하나라도 충족될 경우, **현재 인터랙션 설계를 즉각 기각하고 UI 구조를 전면 재설계**한다:

1. **조작 미로 (Navigation Lost)**: 첫 사용자 UT 중, 30장 문서 내에서 특정 섹션을 찾거나 수정 지점으로 이동하는 데 **2분 이상 방황하거나 길을 잃는 비율이 40% 이상**일 때.
2. **Accept 피로도 폭발**: Composer의 수정 제안을 검토하는 과정에서 Diff 단위가 너무 파편화되어, **사용자가 [Accept/Reject] 버튼을 누르는 행위 자체에 극심한 피로를 호소하며 "그냥 내가 워드에서 타이핑할래"라고 포기**할 때.
3. **참조 결속 가시성 부재**: 본문의 특정 문장을 클릭했을 때 좌측 `@Reference` 뷰어의 해당 원본 페이지가 즉각 하이라이트되지 않아, **사용자가 "이 수치가 어디서 나왔는지 확인하기 번거롭다"고 불평**할 때.

## 4. 검증 프로토타입 형태 (Prototype & Experiment)

* **검증 형태**: **Figma 고충실도 인터랙티브 프로토타입 + 경량 프론트엔드 스파이크**
  * 실제 백엔드 LLM 연동 없이, 정적 데이터로 동작하는 3단 인터랙션 화면 구축.
  * 피험자에게 실제 30장 규모의 공공 사업계획서 템플릿과 5개의 가상 백데이터 PDF 제공.
  * 피험자에게 다음 3대 필수 과업(Task) 부여:
    1. *과업 1*: 좌측 `@Reference`에서 특정 기술 규격 문서를 열어 팩트 확인하기.
    2. *과업 2*: Composer 입력창에 `@기술명세서 p.4 바탕으로 3.2절 성능 지표 표 생성해줘` 지시하기.
    3. *과업 3*: 생성된 표의 Diff를 확인하고 [Accept]하여 문서에 영구 반영하기.
