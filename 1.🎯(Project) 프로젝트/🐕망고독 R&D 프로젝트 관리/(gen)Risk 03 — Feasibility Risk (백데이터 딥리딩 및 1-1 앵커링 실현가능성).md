# (gen)Risk 03 — Feasibility Risk (백데이터 딥리딩 및 1-1 앵커링 실현가능성)

> **SVPG 정본 헌법 (Marty Cagan)**:  
> *"우리 엔지니어들이 현재의 기술, 역량, 시간 제약 내에서 이것을 실제로 구축할 수 있는가? (Can our engineers build it?)"*  
> 백엔드 아키텍처와 LLM 파이프라인이 약속된 속도, 정합성, 100% 팩트 결속을 물리적으로 지탱하지 못하면 제품은 사상누각이다.

---

## 1. 리스크 정의 및 치명도 (The Fatal Risk)

* **핵심 질문**: 100~300페이지 분량의 이기종 백데이터(PDF, HWP, 복잡한 표, 도표)를 실시간으로 인덱싱하고, **본문의 모든 문장과 수치를 원본 백데이터의 정확한 위치(페이지, 단락, 바운딩 박스)와 100% 오차 없이 일대일로 앵커링(`1:1 Fact-Anchored`)하는 엔진(`scaffold-engine`)을 현실적인 응답 속도 내에 구현할 수 있는가?**
* **치명도**: **최상 (Extreme / 기술 붕괴 리스크)**
  * 전문 규격 문서(정부과제, 제안서)에서 **수치 하나, 날짜 하나의 환각(Hallucination)이나 오표기는 사업 탈락 및 감사 고발로 직결**된다.
  * 기존 나이브 RAG(텍스트 청킹 후 유사도 검색) 방식은 표(Table) 구조가 깨지고 문맥이 파편화되어 30장짜리 유기적 대형 문서를 결속할 수 없다.
  * 문서 생성 속도가 30분을 넘어가거나, PDF 파싱에 에러가 빈번하면 제품은 상용화될 수 없다.

---

## 2. 핵심 검증 가설 (Core Hypotheses)

| 번호 | 검증 가설 (Hypothesis) | 가설 지탱 근거 |
| :--- | :--- | :--- |
| **H1** | **복합 서식 무손실 파싱**: 공공/기업 백데이터의 대다수를 차지하는 **다단 텍스트 및 복잡한 병합 표(Nested Table)를 Markdown/JSON AST 구조로 95% 이상 정확하게 추출**할 수 있다. | 최신 고성능 도큐먼트 파서 엔진 및 멀티모달 비전 인덱싱 기술 활용 |
| **H2** | **1:1 양방향 팩트 앵커링**: 생성된 문서의 모든 슬롯(수치, 일정, 단가 등)에 대해 **원본 백데이터의 [DocID, Page, Paragraph_Hash, BoundingBox]를 메타데이터로 100% 영속화**할 수 있다. | `packages/scaffold-engine`의 Slot-Anchor 데이터 계약 및 AST 링킹 메커니즘 |
| **H3** | **대형 문서 무결성 컴파일**: 30~50장(2만 자 이상)의 방대한 문서 직조 시, 앞뒤 섹션 간의 **논리적 모순이나 용어 불일치 없이 단일 완제품으로 일관되게 컴파일**할 수 있다. | 계층형 아웃라인 트리 기반 하향식(Top-down) 스테이지 직조 파이프라인 |

---

## 3. 사망 판정 기준 (Kill Criteria / Fail Fast)

다음 조건 중 하나라도 발생할 경우, **현재 파이프라인 아키텍처는 기술적으로 실현 불가능한 것으로 판정하고 엔진 설계를 근본적으로 변경**한다:

1. **치명적 환각 발생**: 실제 사업계획서 생성 벤치마크 10건 중, 백데이터에 없는 거짓 수치나 왜곡된 사실이 **단 1건이라도 사실인 양 앵커링되어 통과할 때** (환각 허용치 0%).
2. **표 파싱 붕괴**: 예산 편성표, 사업화 일정표 등 복잡한 병합 표 파싱 시 셀 데이터가 밀리거나 유실되는 비율이 **5%를 초과할 때**.
3. **인덱싱 지연 시간 초과**: 50페이지 분량의 백데이터 PDF 3건을 투입했을 때, 딥리딩 인덱싱 및 지식 그래프 슬롯 구축 시간이 **60초를 초과하여 대화형 직조 흐름이 완전히 끊길 때**.

---

## 4. 검증 스파이크 형태 (Engineering Spike & Proof of Concept)

* **검증 형태**: **백엔드 고립 기술 스파이크 (Headless PoC Pipeline)**
  * UI나 프론트엔드 작업 없이 순수 Python 백엔드 환경에서 실행.
  * **실제 데이터셋 확보**: 실제 중기부/과기정통부 R&D 지원사업 공고문(PDF 80p) + 모의 사업계획서 템플릿(HWP/Docx 40p) + 백데이터 연구노트/실적자료(PDF 30p).
  * 파이프라인 구성:
    ```text
    [원천 백데이터 3건]
            ↓
    [1. Multi-modal Parser] → 표/다단/텍스트 완전 보존
            ↓
    [2. Scaffold Slot Extractor] → 핵심 슬롯 및 사실관계 추출
            ↓
    [3. Fact-Anchor Graph] → 각 팩트와 원본 [Page, Box] 1:1 매핑
            ↓
    [4. 30장 완제품 컴파일러] → Tiptap 호환 JSON AST 생성
    ```
  * 생성된 JSON 결과물의 팩트 앵커 추적 정합성을 자동 검증 스크립트로 전수 계측.

## 5. 정량적 기술 통과 기준 (Feasibility Benchmarks)

| 검증 항목 | 최소 통과 기준 (Must-have) | 측정 방식 |
| :--- | :--- | :--- |
| **표/양식 복원율** | **95% 이상** (셀 병합 및 수치 정렬 보존) | 원본 PDF 표 대비 추출 JSON 셀 일치율 전수 대조 |
| **팩트 앵커 정밀도** | **100% 결속** (오참조율 0.0%) | 생성된 수치 100개 무작위 추출 후 원본 위치 1:1 역추적 검증 |
| **초기 인덱싱 속도** | **100페이지당 30초 이내** | 파일 업로드 완료 시점부터 슬롯 인덱스 생성 완료까지 시간 실측 |
| **30장 직조 속도** | **전체 파이프라인 3분 이내** | 아웃라인 확정 후 최종 30장 Tiptap AST 컴파일 완료 시간 |
