### 1. 핵심 고민 배경 — "선행 탐색의 미스매칭과 레퍼런스 지옥" vs "3-노드 앵커 후 역주입과 스타일 DNA"

- **글쓰기 전 선행 탐색의 구조적 함정과 탐색 지옥**:
  - 주제가 구체화되기 전 레퍼런스를 먼저 찾으면, 정작 글을 쓸 때 내용과 핀트가 빗나간 자료를 쥐게 됨 (속기: "레퍼런스는 주제(Immer)가 정해지기 전에 골랐고 결국 적절한 레퍼런스가 아니었어")
  - 또한 더 완벽한 자료를 찾으려다 본문은 한 줄도 못 쓰는 *"레퍼런스 찾기 지옥"*에 빠지며, 작업자가 결단을 내리지 못하고 에너지를 소진함 (발화자 3: "또 이렇게 써 놓고 다른 레퍼런스 찾아 지옥에 빠져 가지고")
- **중간 단계(3-노드) 역방향 투입의 필요성**:
  - 발화자 1은 도그푸딩 회고에서 *"3번까지 썼을 때라도 역으로 레퍼런스를 찾는 과정을 워크플로우에 포함했어야 했다"*고 고백함 (속기: 01:01:45 · 01:02:58)
  - 내 핵심 뼈대(1~3번)가 잡힌 시점에 레퍼런스를 꽂아야 내 생각의 주도권을 지키면서 레퍼런스를 도구로 부릴 수 있음
- **"느낌(밀도·호흡)"을 시스템 사양으로 정의하는 기술적 도전**:
  - 레퍼런스의 텍스트를 베끼는 것이 아니라, *"문단당 정보 밀도, 설명 대 예시의 3:7 비율, 도입부 훅 호흡"*이라는 무형의 감각(느낌)을 AI에게 전달할 규격화된 파라미터가 절실함 (발화자 3: "그럼 그 느낌은 어떻게 전달해?")

### 2. 선택지 비교 및 쟁점 (A vs B vs C)

| 구분 | 선택지 A (권장: 선 앵커 후 역주입 + 메타 스타일 DNA / EXP13) | 선택지 B (사전 뼈대 통째 역공학 / 10.14 EXP05) | 선택지 C (사람 눈으로만 보고 수동 참고) |
| :--- | :--- | :--- | :--- |
| **방식** | 2~3개 노드 작성 후 레퍼런스 URL 투입 시, 텍스트는 버리고 `[밀도 / 사례 비율 / 훅 호흡]` 3대 메타 규격만 추출해 아웃라인 프롬프트에 주입 | 글을 쓰기 전 레퍼런스 목차 전체를 파싱해 템플릿 슬롯으로 깔아두고 빈칸 채우기 | 레퍼런스를 화면 한쪽에 띄워두고 작업자가 눈으로 훑으며 영감만 얻어 손으로 집필 |
| **장점** | - 선행 탐색 지옥 원천 차단 (내 생각 먼저 고정)<br>- 표절 시비 없는 100% 합법적 뉘앙스/호흡 복제<br>- 비정형 기술 문서에 최적화 | - 백지 상태 없이 즉시 완성형 골격 획득<br>- 정형화된 보고서/문서 작성에 유리 | - 신규 파서 개발 공수 0<br>- 도구의 제약 없이 가장 유연함 |
| **단점/부담** | - 텍스트에서 메타 밀도·비율을 판별하는 경량 프로파일러 프롬프트 설계 필요 | - 남의 틀에 내 생각을 억지로 구겨 넣게 됨<br>- 비정형 글쓰기에서 생각의 발산 저해 | - 그 느낌을 AI에게 전달할 수 없어 AI 결과물 품질 저하<br>- 작업자의 주관적 역량에만 전적으로 의존 |

### 3. 검증 실행 방향 및 집중 과제

- **스타일 DNA 프로파일러 및 제약 바인딩 축 (민규 서)**:
  - `EXP13`에 따라 입력된 웹문서/텍스트에서 [평균 단락 길이, 개념 대 코드/예시 비율, 질문형 훅 여부]를 판별하는 경량 메타 분석기 구현
  - 추출된 프로필을 아웃라인 하위 노드 생성 시 시스템 프롬프트 제약(System Constraint)으로 주입하는 파이프라인 검증
- **인플라이트 주입 팝오버 및 밀도 게이지 UX 축 (Rin)**:
  - 아웃라인 2~3개 노드 작성 시 우측에 활성화되는 `[ 📎 영감 레퍼런스 주입 ]` 스텝 게이트 인터랙션 설계
  - 사용자가 선택한 레퍼런스 스타일(예: 코드 중심 70%)에 맞춰 현재 작성 노드가 적정 밀도를 달성했는지 보여주는 '밀도 달성 게이지' UI 검증
