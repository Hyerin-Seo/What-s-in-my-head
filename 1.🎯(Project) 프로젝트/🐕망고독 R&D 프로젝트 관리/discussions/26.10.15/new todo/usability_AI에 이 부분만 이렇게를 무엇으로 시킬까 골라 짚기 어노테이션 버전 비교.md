### 1. 핵심 고민 배경 — "숨은그림찾기식 비교 독해와 선택 불가" vs "개발자 도구 수준의 정밀 셀렉션 및 인라인 Diff"

- **재작성 결과 대조 시 발생하는 극심한 인지 독해 비용**:
  - AI에게 수정을 시키면 매번 전체 문장을 새로 쏟아내어, 이전 판과 무엇이 달라졌는지 확인하기 위해 작업자가 앞뒤 텍스트를 정독해야 함 (속기: "다시 뽑아 봐라 하면 또 막 뱉어. 그럼 앞과 뒤 차이를 내가 읽으면서 또 생각해야 되잖아. 뭐가 나아졌지? 그럼 또 위 채팅 읽고... AI 도움 받아서 좋다는 생각을 못 해")
  - 또한 "여기서 요만큼만 마음에 들고, 또 요거 요거 요렇게 마음에 드는" 비연속 다중 영역을 동시에 골라 지시하고 싶으나 현재는 동시 선택이 불가능함 (속기: "아니 이거랑 이거랑 같이 선택 안 되잖아 지금?")
- **확정 노드까지 흔들리는 불안감과 작업자의 임시 대응**:
  - 이미 95점으로 잘 짜인 핵심 문장이 AI 수정 과정에서 멋대로 변형되는 것을 막기 위해, 작업자(발화자 1)는 실제 작업 시 노드 타입을 '인용(Quote)'으로 강제 변경하여 기준점을 방어하는 편법을 써야 했음
- **Antigravity/Cursor 등 검증된 코드 에디터 인터랙션의 이식 필요성**:
  - 발화자 1은 이 문제의 해법으로 *"안티그래피에 있는 코드 관련 UI를 따면 된다"*고 명쾌하게 제시함 (속기: "셀렉션 기능 넣어 주면 되고, 바뀐 곳 보여주고 받는 거... 여기 다 있는 기능들이거든")

### 2. 선택지 비교 및 쟁점 (A vs B vs C)

| 구분 | 선택지 A (권장: 멀티 셀렉션 + 노드 픽스 + 인라인 Diff / EXP08·10·11) | 선택지 B (단일 노드 순차 드래그 팝오버) | 선택지 C (채팅창 프롬프트 수동 복사-붙여넣기) |
| :--- | :--- | :--- | :--- |
| **방식** | `Ctrl`+클릭으로 비연속 노드를 다중 선택해 일괄 지시하고, 확정 노드는 핀(`📌`/인용 스타일)으로 잠그며, 변경 결과는 초록/빨강 인라인 Diff로 노드별 Accept/Reject | 텍스트 드래그 시 뜨는 미니 툴바로 한 번에 한 문장씩만 개별 지시 및 덮어쓰기 | 수정할 노드를 복사해 옆 채팅창에 붙여넣고 "이 부분 고쳐줘" 타이핑 후 결과 복사 |
| **장점** | - 개발자 도구 수준의 정밀한 통제감 획득<br>- 이전 버전 손실 없는 체리피킹(Cherry-pick) 가능<br>- 변경점 파악 독해 시간 80% 이상 단축 | - 직관적이고 친숙한 워드프로세서 경험<br>- 구현 난이도 낮음 | - 신규 UI 개발 공수 0<br>- 복잡한 에디터 상태 관리 불필요 |
| **단점/부담** | - 에디터 내 인라인 Diff 렌더링 및 락킹 상태 관리 난이도 높음<br>- 단축키 및 멀티셀렉션 학습 비용 | - 여러 군데 유기적 연결 지시 불가<br>- 노드마다 반복 클릭하는 극심한 피로 | - 대화 내역 누적으로 컨텍스트 유실<br>- 문서 위계와 지시 내용의 매핑 붕괴 |

### 3. 검증 실행 방향 및 집중 과제

- **정밀 에디터 인터랙션 및 셀렉션 UX 축 (Rin)**:
  - `EXP10` 멀티 셀렉션 플로팅 바 및 `EXP08` 노드 픽스(인용문 잠금) 시각적 스타일링 프로토타입 설계
  - 인라인 Diff 오버레이 시 가독성을 해치지 않으면서 `Tab(수락)` / `Esc(거절)` 단축키로 신속하게 처리하는 마이크로 인터랙션 검증
- **트리 Diff 엔진 및 불변 앵커 하네스 축 (민규 서)**:
  - AI 생성 전후의 아웃라인 트리를 노드 ID 기반으로 비교하여 변경된 청크만 추출하는 경량 Diff 알고리즘 구현 (`EXP11`)
  - 핀 꽂힌 노드를 시스템 프롬프트의 `[Immutable Anchor]` 슬롯에 바인딩하여 AI의 임의 변형을 원천 방어하는 하네스 로직 설계
