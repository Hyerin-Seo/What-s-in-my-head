### 1. 핵심 고민 배경 — "캔버스 노드 과부하와 AI의 시각 오염" vs "인간 클린 캔버스와 AI 고스트 드로어의 레이어 분리"

- **혼자 쓸 때는 완벽했던 캔버스가 AI 개입으로 붕괴됨**:
  - 발화자 3은 사람이 글을 읽으며 캔버스에 카드를 배치하고 선을 이을 때는 사고의 확산이 완벽하게 정리되었다고 평가함 (속기: "처음에 그냥 글을 읽으면서 써 나갈 때는 완벽했거든")
  - 그러나 AI가 개입하여 카드를 대량으로 쏟아내고 관계선을 어지럽히는 순간, 판이 극도로 지저분해져 정작 내 원래 생각이 어디 있었는지 눈에 전혀 안 들어오는 마비 상태가 됨 (속기: "캔버스가 무한정 편하냐? 아니야. 노드가 많아지니까 일단 안 보여. AI가 개입을 해서 내 캔버스를 더럽히는 순간에 아예 눈에서 안 보이거든")
  - 발화자 1 역시 이에 대해 *"맞아 맞아"*로 깊이 공감하며 화면 공간 제어의 필요성을 인정함
- **작업자 중심 와꾸와 독자 관점 최종 서식의 간극**:
  - 발화자 1은 블로그 출판 단계로 넘어가지 않고 아웃라이너로만 작업을 마쳤는데, 이로 인해 작성자 본인만 알아보는 거친 와꾸가 되어 처음 읽는 상대방(발화자 3)이 내용을 직관적으로 따라가지 못함
  - 따라서 캔버스든 아웃라인이든, 우측에 독자가 볼 최종 완성형 서식을 스캔 뜨듯 실시간으로 보여주는 미리보기(Preview) 장치가 반드시 병행되어야 함 (발화자 3: "비정형적인 거라고 해서 서식 보여주는 걸 제공 안 할 이유는 없어")

### 2. 선택지 비교 및 쟁점 (A vs B vs C)

| 구분 | 선택지 A (권장: 인간 캔버스 + AI 고스트 드로어 2중 레이어 / EXP14) | 선택지 B (단일 캔버스 바닥에 직접 노드 동시 렌더링) | 선택지 C (캔버스를 배제하고 오직 텍스트 아웃라이너만 사용) |
| :--- | :--- | :--- | :--- |
| **방식** | 메인 캔버스는 오직 인간이 승인한 노드만 유지하고, AI 생성물은 우측 접이식 서랍(Ghost Shelf)에 격리 대기시키며 드래그로만 반입 | AI가 생성한 카드와 연결선을 메인 캔버스 빈자리에 실시간으로 자동 배치 | 2차원 캔버스를 완전히 걷어내고 1차원 수직 아웃라인 트리 에디터만 유지 |
| **장점** | - 인간의 사고 공간 청정도 100% 보존<br>- 시각적 노이즈 없이 원하는 카드만 선별 반입<br>- 반투명 고스트 노드 호버로 배치 위치 사전 예측 | - 모든 정보가 한 평면에 시각화됨<br>- 신규 레이어 분리 UI 개발 공수 불필요 | - 구조가 단순하여 시각 피로도가 가장 낮음<br>- 위계 관리와 텍스트 집필에 집중 |
| **단점/부담** | - 캔버스 레이어 분리 및 드래그 앤 드롭 반입 사양 개발 필요<br>- 고스트 렌더링 성능 최적화 | - 노드 수십 개 증가 시 판 전체가 마비됨<br>- 내가 쓴 것과 AI가 쓴 것이 섞여 통제감 상실 | - 복잡한 아이디어 발산이나 비선형적 갈래 조망 불가<br>- 관계선 가지치기 손맛 부재 |

### 3. 검증 실행 방향 및 집중 과제 (Decision 03 연계)

- **캔버스 2중 레이어 아키텍처 및 고스트 렌더러 축 (민규 서)**:
  - React Flow 기반 캔버스에 '인간 작업 레이어'와 'AI 임시 제안 레이어(Ghost Layer)'를 분리하는 상태 관리 아키텍처 설계
  - AI 생성 카드를 우측 미니 서랍에 담아두고, 호버 시 캔버스에 반투명 점선 노드로 띄워주는 고스트 프리뷰 렌더러 구현 (`EXP14`)
- **드래그 앤 반입(Drag to Adopt) 및 우측 서식 스캔 UX 축 (Rin)**:
  - 드로어 내 카드를 마우스로 끌어 메인 캔버스로 편입시키는 드래그 앤 드롭 UX 플로우 설계
  - `Decision 03`에 따라 아웃라인/캔버스 작업 중에도 우측 스플릿 패널에서 최종 마크다운/블로그 서식을 스캔하듯 실시간 렌더링해주는 미리보기 연동성 검증
