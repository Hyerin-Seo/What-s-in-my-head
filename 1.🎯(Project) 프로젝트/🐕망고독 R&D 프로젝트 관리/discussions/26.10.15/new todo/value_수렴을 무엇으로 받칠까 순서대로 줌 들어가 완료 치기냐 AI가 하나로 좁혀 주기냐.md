### 1. 핵심 고민 배경 — "AI의 무한 확산과 선택 피로" vs "순차적 줌 인 체크완료와 인지 부하 절감"

- **선택지가 늘어날수록 결정이 지연되는 수렴의 병목**:
  - AI와 협업할 때 가장 큰 고통은 대안이 부족한 것이 아니라, AI가 사용자의 모든 말에 *"다 굿굿, 네 말도 맞아"* 하며 무한 확산만 시키는 현상임 (속기: "선택 장애가 있는데 이 선택 장애를 더 극대화만 시키지 뭔가 수렴이 안 되는 느낌... 하루 종일 결국 얘랑 이거 가지고 대화만 하고 결론을 도출하지 못해")
  - 발화자 3의 지적처럼 날카로운 비판과 가지치기를 통해 *"하나로 딱 원 포인트로 수렴하고 매듭을 지어야"* 다음 스텝으로 나아갈 수 있는데, 오히려 AI가 결정을 방해하여 작업 부스팅을 받지 못함
- **순서대로 끊어가며 줌 인하는 작업 방식의 유효성 입증**:
  - 반면 발화자 1은 1-1, 1-2, 1-3 순서로 항목을 하나씩 체크하고, 깊은 작업이 필요할 때만 줌을 당겨 포커스하는 방식으로 *"인지 부하가 그냥 확 줄었다"*고 회고함 (속기: "1번이 정리되고 나면 2번 흐름은 또 확 잡혀. 한 방에 클리어하려 하면 훨씬 많이 걸려")
  - 또한 발화자 3은 줌 인 상태에서도 1번, 2번 등 다른 섹션으로 즉시 점프할 수 있도록 PPT 슬라이드 목록 형태의 상위 목차 레일이 필요하다고 역제안함

### 2. 선택지 비교 및 쟁점 (A vs B vs C)

| 구분 | 선택지 A (권장: 순차 줌 체크완료 + 목차 레일 / EXP15) | 선택지 B (AI 단일 수렴 권고 프롬프트 강제 / EXP09) | 선택지 C (자유 대화형 무제한 선택지 제공) |
| :--- | :--- | :--- | :--- |
| **방식** | 줌 인 상태에서도 좌측에 PPT형 1·2·3·4 상위 목차 레일을 유지하고, 섹션 정리 후 인라인 체크완료(`Ctrl+Enter`)로 다음 노드로 이동 | AI에게 여러 대안 나열을 금지하고, `[단일 권장안 1개 + 기각 사유 + 날카로운 자가 비판]` 3단 구조로 응답 강제 | 현재처럼 AI가 4~5개 후보안을 열거하고 사용자가 채팅창에서 대화하며 수동 선별 |
| **장점** | - 전체 문서 맥락을 잃지 않는 고몰입 순차 집필<br>- 섹션 완료 시마다 매듭(Done) 감각 부여<br>- 인지 부하 급감 및 작성 속도 2배 향상 | - 고민 시간 없이 즉시 1개안으로 수렴<br>- AI의 맹목적 동조 차단 및 비판적 검증력 획득<br>- 프롬프트 튜닝만으로 즉시 적용 가능 | - 아이디어 발산 단계에서 사고 확장 극대화<br>- 사용자의 선택 자율성 100% 보장 |
| **단점/부담** | - 줌 인 전용 사이드 레일 컴포넌트 개발 필요<br>- 뼈대가 없는 백지 상태에서는 적용 불가 | - AI의 단일 추천안이 마음에 들지 않을 경우 재생성 필요<br>- 사용자가 통제감을 잃었다고 느낄 위험 | - 선택 피로 극대화로 하루 종일 대화만 맴돔<br>- 문서 작성 완료율(Completion Rate) 급락 |

### 3. 검증 실행 방향 및 집중 과제

- **내비게이션 및 수렴 인터랙션 축 (Rin)**:
  - `EXP15`에 정의된 대로 줌 인 화면 좌측에 180~220px 폭의 초슬림 목차 레일을 배치하여, 줌 아웃 없이 1번과 3번을 자유롭게 오가는 원클릭 줌 홉(Instant Zoom Hop) UX 사용성 검증
  - 섹션 완료 시 시각적 체크 배지를 달아주고 다음 순번으로 시선을 자연스럽게 이끄는 마이크로 인터랙션 흐름 설계
- **단일 수렴 에이전트 하네스 축 (민규 서)**:
  - `EXP09` 수렴 모드 트리거 시, 다수 나열을 차단하고 채택안 1개와 탈락 대안의 기각 사유를 명시하는 Decision Agent 프롬프트 파이프라인 프로토타입 구현 및 응답 품질 검증
