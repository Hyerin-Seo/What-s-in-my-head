### 1. 핵심 고민 배경 — "폴더가 곧 맥락" vs "데이터 중복과 관리 부채"

- **동일 레퍼런스의 양쪽 공존 문제**:
  - 아카이브(`UI + 디자인 + 기술 레퍼런스`)와 리소스(`🛖Scaffold_Manager_주요_레퍼런스`)에 동일 레퍼런스(LivingWriter, Dabble, 스크리브너 등)가 중복으로 존재함
  - 아카이브 쪽은 과거 노션 이관 후 '불필요'하다고 판단해 내렸던 것이고, 리소스 쪽은 이번 Scaffold Manager 조사를 위해 다시 꺼내 올린 것임
- **두 사람의 시각 차이**:
  - **민규 서 (맥락 우선 & 실용주의)**: PARA 체계에서 폴더 위치는 곧 '지금 어떤 맥락에서 쓰이는가'를 의미함. 이번 과제에 맞게 새로 모으는 것이 빠르며, 볼트는 정밀한 DB 테이블이 아니므로 실무적 중복(비정규화)을 허용해도 무방함
  - **Rin (일관성 & 관리 부채 경계)**: 한쪽에선 버렸고 한쪽에선 살렸는데, 시간이 지나면 어디에 뭐가 있는지 모르는 '비버의 나뭇가지 긁어오기' 상태가 됨. 인원이 늘어났을 때 기준이 없으면 데이터 관리가 완전히 깨짐

### 2. 선택지 비교 및 쟁점 (A vs B vs C)

| 구분 | 선택지 A (권장: 비정규화 + 링크) | 선택지 B (단일 정본 정책) | 선택지 C (에이전트 인입 검증) |
| :--- | :--- | :--- | :--- |
| **방식** | 맥락별 사본을 허용하되, 사본 프론트매터 `링크:`에 원본 노트를 필수 바인딩 | 노트를 복사하지 않고 기존 노트를 이동시키거나 `주제` 태그로만 맥락 부여 | 에이전트가 새 레퍼런스 수집 시 볼트 내 기존 존재 여부를 조회해 중복 알림 |
| **장점** | - 현재 폴더 맥락 유지<br>- 원본과 사본의 계통(Lineage) 추적 가능 | - 데이터 중복 제로<br>- 최신 판단 상태가 한 곳에 집중 | - 작업자의 수동 탐색 피로 제거<br>- 자연스러운 레퍼런스 재활용 유도 |
| **단점/부담** | - 사본 생성 시 링크 연결 규칙 준수 필요 | - 레퍼런스 작업 때마다 과거 폴더 정리 선행 부담 | - 에이전트 수집 스크립트/하네스 추가 구현 필요 |
