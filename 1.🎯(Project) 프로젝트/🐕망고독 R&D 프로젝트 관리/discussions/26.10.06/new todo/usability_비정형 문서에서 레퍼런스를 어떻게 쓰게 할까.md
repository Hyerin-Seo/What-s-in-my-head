### 1. 핵심 고민 배경 — "토스닥터 블로그 실험 실패"와 "정형 vs 비정형의 경계"

- **토스닥터 블로그 v1·v2 실험 실패 교훈**:
  - 기술 블로그 레퍼런스를 정형 문서처럼 잘게 쪼개어 필수·선택 항목의 빈칸(Form Filler)으로 만들어봤으나, 글 하나 쓰는데 검토해야 할 칸이 과도하게 많아져 작성 피로도가 급증함 (민규 서 v1·v2 폐기)
  - 반면 ML 블로그 레퍼런스를 백그라운드로 먹이고 에이전트와 대화형으로 풀었을 때는 10분 만에 아웃라인이 도출됨
- **Rin의 핵심 반론 — "대화만으로 풀면 우리 도구의 존재 이유가 무엇인가?"**:
  - 기술 블로그, 회사소개서, 자기소개서, 사업계획서도 결국 **"문제 정의 → 한 일/해결책 → 성과/결과 → 향후 계획"**이라는 4마디 논리 문법(Move)이 존재함
  - 단순히 배경에 깔고 챗봇과 대화하는 식이라면 기존 ChatGPT/Claude 웹 인터페이스와 다를 바 없으며, 콕핏(감독형) 제품 정체성이 사라짐

### 2. 선택지 비교 및 쟁점 (A vs B vs C)

| 구분 | 선택지 A (권장: 거시 뼈대 UI + 미시 대화) | 선택지 B (전면 백그라운드화) | 선택지 C (비정형도 빈칸 와이어프레임) |
| :--- | :--- | :--- | :--- |
| **방식** | 4마디 큰 뼈대만 화면에 느슨한 콕핏 블록으로 노출하고 세부는 대화로 채움 | 화면에는 일체 구조를 노출하지 않고 순수 백그라운드 메타데이터/설정값으로만 처리 | 정형 규격 문서처럼 모든 세부 요소를 화면상 빈칸으로 강제 바인딩 |
| **장점** | - 콕핏 조작감과 유연성의 균형<br>- 비정형 글쓰기의 인지 부하 대폭 감소 | - 가장 가벼운 인터페이스<br>- 10분 만에 초안 뽑는 신속성 | - 정형/비정형 문서 간 UI 일관성 유지 |
| **단점/부담** | - '어디까지를 거시 뼈대로 볼 것인가'에 대한 스키마 정의 필요 | - 기존 챗봇과의 차별성 실종<br>- 사용자가 전체 구조를 조망(감독) 불가 | - 봐야 할 항목 폭증으로 피로도 극대화 (실패 검증 완료) |

### 3. 검증 실행 방향 및 이번 주 집중 과제 (Decision 02 연계)

- **사용성 축 (Rin)**:
  - 비정형 글을 쓸 때 화면 좌측/상단에 어떤 시각적 컴포넌트(마디 네비게이션, 인디케이터, 상태 태그 등)가 있어야 작업자가 길을 잃지 않고 콕핏 조작감을 느끼는지 UI 컴포넌트 정의
- **실현성 및 스키마 축 (민규 서)**:
  - LLM이 비정형 레퍼런스에서 뽑아내야 할 핵심 데이터 스키마(거시 논리 블록, 필수 슬롯, 어조/스타일 파라미터)를 정의하고 백단 파싱 로직 구체화
