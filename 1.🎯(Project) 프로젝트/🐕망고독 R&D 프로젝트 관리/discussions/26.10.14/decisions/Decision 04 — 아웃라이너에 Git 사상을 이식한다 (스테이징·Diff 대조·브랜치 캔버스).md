# 🎯 Decision 04 — 아웃라이너에 Git 사상을 이식한다 (스테이징·Diff 대조·브랜치 캔버스)

## 1. 결정 내용 (What)

> [!check]
> - **Git 핵심 사상의 전면 수용**: 버전 관리 실패의 불안 없이 과감히 문서를 갈아엎을 수 있도록, 비파괴 스냅숏·로컬 스테이징·인라인 Diff 대조·브랜치 시각화라는 Git 사상을 아웃라이너의 핵심 엔진/UI로 공식 채택
> - **국소 노드 단위 로컬 스테이징**: 과거 시스템 복잡도를 가중시켰던 "전체 문서 단위의 무거운 Git 롤백"을 지양하고, 작업자가 집중하는 줌 인 노드 단위의 경량 스테이징 메커니즘 구축
> - **초록/빨강 인라인 Diff 및 캔버스 브랜칭 결합**: 무엇이 추가되고 빠졌는지를 시각적으로 즉각 대조(초록/빨강 하이라이트)하고, 복수 대안을 캔버스 2차원 공간 상에서 브랜치 트리로 조망

---

## 2. 결정 사유 (Why)

1. **아웃라이너 본연의 작업 고통(변경점 실종) 해소**: 문서 구조를 세 번 이상 갈아엎는 동안 무엇이 어떻게 바뀌었는지 대조되지 않아 작업자가 극심한 피로도와 불안감을 겪음 → 시각적 Diff 대조가 필수적임
2. **사양 실패의 본질 재정의**: 과거 Git 연동이 꼬였던 것은 "Git이라는 거대한 도구를 통째로 얹으려 했기 때문"이며, 사용자가 진짜 원했던 것은 "내가 고친 부분의 안전한 스테이징과 초록/빨강 diff 확인"이라는 본질을 간파함
3. **캔버스 공간과의 시너지**: 1차원 수직 트리에서는 여러 갈래(브랜치)를 비교하기 어렵지만, 이를 2차원 캔버스에 뿌려줄 때 비로소 직관적인 구조 비교와 가지치기의 "맛"이 살아남

---

## 3. 실행 가이드라인 (Boundary & Criteria)

- **집중 대상 (Do)**:
  - 작업 중인 노드 단위의 초경량 로컬 체크포인트(스테이징) 인터랙션 구현
  - 노드 및 텍스트 수정 전후를 한눈에 식별할 수 있는 초록(`+` 추가) / 빨강(`-` 삭제) 인라인 Diff 렌더링
  - 버전 갈래를 캔버스 보드 뷰에서 브랜치 연결선 형태로 시각화
  - 언제든 직전 상태로 안심하고 돌아갈 수 있는 비파괴 롤백 기능
- **제외 대상 (Don't)**:
  - 전체 파일시스템이나 원격 레포지토리를 묶는 무거운 Git 바이너리 직결 배제
  - 3-way merge나 복잡한 충돌 해결(Conflict resolution) 같은 과도한 엔지니어링 스펙 배제
  - 단순 텍스트 백업 로그 수준의 조잡한 히스토리 나열 지양
- **완료 판단 기준 (DoD)**:
  - 아웃라인 수정 중 단축키로 이전 판과의 초록/빨강 Diff를 즉각 확인하고, 안전하게 롤백하거나 캔버스 브랜치로 분기할 수 있는지 실측 검증 (10월 30일 마일스톤)
