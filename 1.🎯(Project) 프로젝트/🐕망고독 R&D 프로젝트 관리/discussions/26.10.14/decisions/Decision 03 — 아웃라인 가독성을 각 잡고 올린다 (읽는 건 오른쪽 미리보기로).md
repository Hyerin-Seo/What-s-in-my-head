# 🎯 Decision 03 — 아웃라인 가독성을 각 잡고 올린다 (읽는 건 오른쪽 미리보기로)

## 1. 결정 내용 (What)

> [!check]
> - **가독성 개선 최우선 과제화**: 단순 볼드 처리를 넘어, 읽지 않고 스캔만 해도 제목·부제목·문단 위계가 드러나도록 시각 처리 전면 개편
> - **편집과 열람의 관심사 분리**: 빽빽한 아웃라인 에디터 자체에 서식을 우겨넣지 않고, 좌측은 경량 구조 조작, 우측은 실시간 완성본 미리보기(5:5 분할 뷰)로 배치
> - **실시간 동기화 및 오토 스크롤**: 좌측 아웃라인에서 편집 중인 노드의 위치를 우측 미리보기 패널에서 부드럽게 추적 하이라이트

---

## 2. 결정 사유 (Why)

1. **사람 눈의 인지적 한계 직면**: AI는 텍스트 트리만으로도 맥락을 잘 파악하지만, 사람은 불릿 텍스트가 조금만 길어져도 머리에 쥐가 나고 처음부터 끝까지 다 읽어야 하는 극심한 피로도 발생
2. **에디터 조작감 훼손 방지**: 아웃라이너에 과도한 리치 서식을 직접 넣으려 하면 고유의 날렵한 키보드 이동과 구조 편집 속도가 무너짐
3. **위키독스·Overleaf 등 성공 모델 입증**: 좌측 구조 소스 조작 + 우측 실시간 조판·렌더링 듀얼 뷰 모델이 조작감과 열람 가독성을 동시에 만족시키는 최적의 해법임

---

## 3. 실행 가이드라인 (Boundary & Criteria)

- **집중 대상 (Do)**:
  - 좌측 아웃라인과 우측 완성본 실시간 렌더링 뷰어의 5:5 분할 레이아웃 구축
  - 아웃라인 인덴트 레벨에 따른 우측 마크다운 문서 계층(H1, H2, 단락, 인용구) 실시간 매핑
  - 아웃라인 자체의 서식 템플릿 규칙 정립 (불필요한 인라인 수식어 배제 등)
- **제외 대상 (Don't)**:
  - 아웃라이너 불릿 노드 자체에 복잡한 리치 텍스트 서식 툴바를 덕지덕지 붙이는 시도 배제
  - 단순 Workflowy 메모 앱 스타일의 텍스트 트리를 여과 없이 화면에 방치하는 행위 지양
  - 우측 뷰어를 단순 텍스트 덤프로 구성하는 것 지양 (사람 눈이 편안한 조판 레이아웃 필수)
- **완료 판단 기준 (DoD)**:
  - 글을 꼼꼼히 읽지 않고 화면을 훑어보는 것(Scanning)만으로도 전체 문서의 흐름과 경중이 3초 안에 파악되는지 정성 검증 (10월 30일 마일스톤)
