### 1. 핵심 고민 배경 — "채팅창의 휘발성 대화" vs "화면에서 의도를 꽂는 콕핏 인터랙션"

- **100% 일치하는 레퍼런스는 세상에 존재하지 않음**:
  - 아무리 훌륭한 레퍼런스를 찾아도 내 목적과 100% 딱 맞아떨어지는 글은 없으며, 결국 작업자의 에고와 관점이 투영되는 10~20%의 미세 튜닝이 전체 작업의 60% 이상 에너지를 소모함 (속기: "업무가 어렵다도 어렵다지만 클로드도 이거는 잘 못 하는 영역이다")
  - 발화자 2의 지적처럼 *"얘가 왜 70점이고 왜 95점인지에 대해 AI와 싱크를 맞추는 과정"*이 필수적인데, 현재는 이를 1번부터 9번까지 끝없이 갈아엎으며 맞추고 있음
- **채팅창 의존의 한계와 인터페이스 부재**:
  - 발화자 1은 당장 이를 *"채팅창에서 버무린다"*고 표현했으나, 채팅으로 나눈 디렉션은 문서 뼈대와 분리되어 쉽게 휘발되고 맥락이 단절됨
  - 반면 피그마나 슬라이드를 만들 때는 특정 위치에 포스트잇이나 캡처를 꽂아두듯 작업하므로, **"화면의 바로 그 노드 자리에 간편하게 의도(인텐트)와 뉘앙스를 넘기는 수단"**이 절실함 (발화자 2: "그걸 주는 걸 어떻게 주는지가 간편해야 된다는 거야")

### 2. 선택지 비교 및 쟁점 (A vs B vs C)

| 구분 | 선택지 A (권장: 화면 인라인 어노테이션 / EXP04) | 선택지 B (채팅창 프롬프트 버무리기) | 선택지 C (정적 스타일 가이드 / 규칙 사전 정의) |
| :--- | :--- | :--- | :--- |
| **방식** | 아웃라인 노드 우측 호버 핀(`💬`)으로 팝오버를 열고, 캡처·핵심 인용·이유를 뱃지(`[1]`) 형태로 부착하여 AI에게 인텐트 전달 | 사이드 패널 채팅창에서 대화하며 "2번 섹션은 이런 톤으로, 3번은 저런 레퍼런스 구도로 써줘"라고 자연어로 지시 | `rules`나 프롬프트 템플릿에 "95점 기준: 문체는 단호하게, 코드는 3줄 이내" 등 정적 규칙 사전 주입 |
| **장점** | - 작업 위치와 디렉션의 맥락 완전 일치<br>- 디자이너의 직관적 무드보드/코멘트 손맛<br>- 아웃라인에 영구적으로 근거가 남음 | - 신규 개발 공수 0 (지금 즉시 가능)<br>- 비정형적인 발산 아이데이션에 유연함 | - 시스템적으로 일관된 톤앤매너 유지<br>- 매번 지시할 필요 없는 자동화 |

### 3. 검증 실행 방향 및 집중 과제 (Decision 02 연계)

- **디렉터 콕핏 인터랙션 설계 축 (Rin)**:
  - 노드 옆에 레퍼런스 조각(캡처 썸네일, 1줄 인용, "이 구도가 좋다"는 메모)을 누더기처럼 가볍게 부착하는 팝오버 화면 와꾸 설계
  - `Decision 02`에 의결된 대로, 레퍼런스 분석 보고서 작성을 전면 폐기하고 인라인 어노테이션 핀으로 전환했을 때 실제 집필 속도가 빨라지는지 정성 체감 검증
- **LLM 컨텍스트 주입 엔진 축 (민규 서)**:
  - 아웃라인 노드에 부착된 어노테이션 메타데이터(`intent`, `reference_snippet`)를 추출하여, 해당 섹션 초안 생성 시 시스템 프롬프트에 슬롯 주입하는 경량 하네스 구조 설계
