### 1. 핵심 고민 배경 — "백지 상태의 구조화 공포" vs "레퍼런스 내용 불일치와 역설계 파싱"

- **빈 화면(Blank Canvas) 공포와 70~80%의 시각적 뼈대**:
  - 맨땅에서 처음부터 글의 위계와 목차를 잡으려 하면 시행착오가 극심하지만, 웹상에는 이미 검증된 짜임새와 시각적 리듬감을 갖춘 훌륭한 글들이 넘쳐남
  - 기술 블로그나 전문 글도 내용의 차이일 뿐, 전체 구성의 70~80%는 헤딩 위계, 코드/캡처 블록 배치, 단락 호흡 등 시각적 구조의 힘임 (속기: "네 말이 맞아. 거의 한 70에서 80%는 시각적 정보야")
- **내용 복제가 아닌 피그마식 '와꾸(Frame) 파싱' 필요성**:
  - 발화자 1은 처음에 레퍼런스를 그대로 쓰려다 내용이 맞지 않아 좌절했으나(속기: "내용적으로는 그렇게 딱 매칭은 안 되더라고"),
  - 발화자 2는 디자이너가 피그마에서 사이트 UI를 원클릭으로 따와 레이아웃만 남기고 자기 색으로 바꾸듯(속기: "피그마를 클릭하면 다 따는 거야. 피그마가"), **"내용은 싹 비우고(Slot 처리) 섹션 틀과 배치만 아웃라인 템플릿으로 따오는 역공학 인터랙션"**을 역제안함

### 2. 선택지 비교 및 쟁점 (A vs B vs C)

| 구분 | 선택지 A (권장: 피그마식 골격 역공학 / EXP05) | 선택지 B (사람이 손으로 직접 구조 베끼기) | 선택지 C (사전 정의된 정적 카테고리 템플릿만 사용) |
| :--- | :--- | :--- | :--- |
| **방식** | 레퍼런스 URL/마크다운 입력 시 본문 텍스트는 버리고 헤딩(`H1~H3`), 리스트, 코드/이미지 슬롯만 아웃라인 트리로 자동 파싱 | 작업자가 레퍼런스를 좌측에 띄워두고 우측 아웃라이너에 헤딩과 목차를 하나하나 수동으로 타이핑 복제 | 정해진 고정 템플릿 3종(블로그, 뉴스레터, SNS) 외에 외부 레퍼런스 파싱은 일체 배제 |
| **장점** | - 백지 상태 없이 즉시 완성도 높은 골격 획득<br>- 불필요한 섹션은 `[X]`로 즉시 가지치기 가능<br>- 다양한 장르의 글에 범용 대응 | - 추가 파서 개발 공수 불필요<br>- 손으로 치면서 자연스럽게 구조 학습 | - 시스템 복잡도 최소화<br>- 검증된 틀 안에서만 작성이 일어나 품질 균일 |
| **단점/부담** | - 웹페이지 DOM 파싱 및 노이즈(광고, 네비게이션) 제거 로직 필요<br>- 원본 글마다 구조 완성도 편차 존재 | - 단순 노가다로 인한 극심한 작업 피로도<br>- 글을 쓰기도 전에 구조 잡다 지침 | - 사용자 맞춤형 다양성 수용 불가<br>- 새로운 유형의 문서 작성 시 한계 봉착 |

### 3. 검증 실행 방향 및 집중 과제 (Decision 01 연계)

- **스캐폴드 파싱 및 슬롯 엔진 축 (민규 서)**:
  - 대표적인 기술 블로그 및 전문 문서 URL에서 헤딩 위계와 코드/이미지 블록 위치를 추출하여 아웃라인 트리(JSON/Markdown)로 변환하는 경량 파서 파이프라인 프로토타입 개발
  - 추출된 노드에 `[도입부 문제 정의]`, `[해결 코드 예시]` 등 가이드 플레이스홀더를 자동 삽입하는 슬롯 템플릿화 엔진 검증
- **템플릿 가지치기 인터랙션 축 (Rin)**:
  - 역공학으로 생성된 아웃라인 뼈대에서 불필요한 섹션을 원클릭으로 쳐내고(`[X]`), 내 핵심 알맹이(30~40%)만 채워 넣는 편집 UX 프로토타입 사용성 평가
