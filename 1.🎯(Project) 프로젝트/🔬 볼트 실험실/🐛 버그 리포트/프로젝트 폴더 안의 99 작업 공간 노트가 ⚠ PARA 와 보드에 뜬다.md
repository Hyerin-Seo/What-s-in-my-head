## 무슨 일이 났나

- `1.🎯(Project) 프로젝트/🍟에이전트와 기술 블로그를 써보즈아/99.🥸(Agent) 작업 공간/` 안의 후보 노트 여섯 장(`유형: 메모`)이
  상태바 ⚠ PARA 목록과 `python .obsidian/scripts/route.py --repair` 에 "유형 메모 인데 1.project 에 있음" 으로 떴다.
- 보드와 검색에도 그대로 떴다 — `유형 == "메모"` 로 거르는 보드에 후보가 줄줄이 나온다.
- 볼트 맨 위의 `99.🥸(Agent) 작업 공간/` 은 멀쩡히 빠져 있었다. **안쪽에 둔 것만** 샜다.

## 이렇게 하면 다시 난다

1. 프로젝트 폴더 안에 `99.🥸(Agent) 작업 공간/` 을 만들고 `유형: 메모` 노트를 넣는다
2. 상태바의 ⚠ PARA 를 누른다 → 그 노트가 "1.project 에 없는 유형" 으로 잡혀 있다
3. `python .obsidian/scripts/route.py --repair` → 같은 노트가 "유형 메모 인데 1.project 에 있음"

## 이래야 맞다

- 폴더 이름이 `99.🥸(Agent) 작업 공간` 이면 **어느 깊이에 있든** 보드 · 검색 · PARA 구역 정리 · 커버 · 어긋남 검사 · `route.py` 에서 빠진다.

## 알아낸 것

- 제외가 세 곳 다 **볼트 맨 위 기준**이었다.
  - `.obsidian/app.json` 의 `userIgnoreFilters` — `"99.🥸(Agent) 작업 공간/"` 은 정규식이 아니라서
    옵시디언이 `^` 를 붙인다 (obsidian.asar `updateUserIgnoreFilters` : `new RegExp("^"+escape(o),"i")`).
  - 플러그인 `isExcluded` (PARA 구역 정리 · 커버) — `path === ex || path.startsWith(ex + "/")`.
  - `route.py` — 99 를 아예 안 뺐다. 맨 위 99 도 훑고 있었다.
- 고침
  - `app.json` — `"/(^|\\/)99\\.🥸\\(Agent\\) 작업 공간\\//"`. `/…/` 로 감싸면 정규식으로 읽는다 (`!(Template)` 항목과 같은 모양).
  - `plugins/claude/main.js` — `inAgentWorkspace(path)` : 경로의 어느 조각이든 그 이름이면 제외. `isExcluded` 두 곳과
    담당자 뷰를 모으는 `assignees` 에 넣었다. `data.json` 의 제외 목록은 **안 건드렸다** (설정을 늘리지 않고 이름으로 가린다).
  - `route.py` — `walk_md()` 가 `99.🥸(Agent) 작업 공간` 과 `4.🗄️(Archive) 보관/에이전트 작업 공간` 을 건너뛴다.
    첨부를 누가 쓰는지 볼 때(`other_users`)만 그 안까지 읽는다 — 99 의 노트가 쓰는 그림을 "혼자 쓰는 첨부" 로 보고 끌고 가면 안 되니까.
- 확인 — 진짜 볼트는 안 건드리고, 두 프로젝트 폴더를 복사한 작은 볼트를 **따로 띄운 옵시디언**(1.13.7)에서 옛 코드 · 새 코드로 한 번씩 돌렸다.

  | | 옛 코드 | 새 코드 |
  | --- | --- | --- |
  | 상태바 | ⚠ PARA 7 (후보 여섯 + 대조군) | ⚠ PARA 1 (대조군만) |
  | `유형 == "메모"` 보드 | 7줄 | 1줄 (대조군) |
  | 검색 `목차 후보` | 후보 여섯 장이 나옴 | 안 나옴 |
  | 안쪽 99 노트의 `isUserIgnored` · `isExcluded` | false | true |

  대조군은 99 **밖**, 프로젝트 폴더 바로 아래에 둔 `유형: 메모` 한 장이다. 이건 계속 잡혀야 검사가 살아 있는 것이다.
  `route.py --repair` 는 새 코드를 진짜 볼트에 미리보기(쓰기 없음)로 돌려 **0개**를 확인했다.
- **사람이 볼 것** — 진짜 볼트에 들어온 뒤 Claude 플러그인을 껐다 켜고(플러그인은 다시 켜야 바뀐다), 상태바 ⚠ PARA 에서 후보 여섯 장이 빠졌는지.

## 같은 자리에서 하나 더 — route.py 가 `.claude/worktrees` 의 볼트 사본을 통째로 잡았다

- `--repair` 미리보기가 **1,074개**를 냈다. 천여 장은 프로젝트 폴더 안 `.claude/worktrees/…` 에 있는 볼트 사본(git 워크트리)이었다.
  사본의 `2.🌱(Area) 관리 영역/…` 노트가 전부 "2.area → 1.project" 로 잡힌다. `--write` 를 붙였으면 사본 천여 장의 `구역` 을 고쳐 썼을 것이다.
- `route.py` 는 `.obsidian` · `.trash` 두 이름만 건너뛰었다. 옵시디언은 **점으로 시작하는 폴더를 전부** 안 읽는다.
- 고침 — `keep_dir()` : 점으로 시작하는 폴더는 안 들어간다 (노트 훑기 · 첨부 색인 둘 다).
  같은 이름의 노트가 사본에도 있어서 이동이 "노트 특정 실패 (2개)" 로 막히던 것도 같이 풀린다.
- 1,074개 → 사본을 빼면 21개 → 그 21개는 `4.🗄️(Archive) 보관/에이전트 작업 공간/` 의 `구역` 없는 에이전트 노트라 위에서 같이 뺐다 → **0개**.
