### [회의록 자동 사냥]
	- 해야 하는게 : to do 관리, 일정표 관리, 회의 전 자료 정리, 회의 후 자료 정리, 각각의 일 gtd 형식으로 해야하는 업무 분배
	- 이런 업무를 하는 직군 : 보통은 막내가 서기 역학, 팀장이 지시 / pm이 취합 요약 액션 아이템 티켓을 발행하여 분배 / ceo면 비서가 다함

1. 회의록 구조화 및 추출 스키마 (LLM Parsing)

회의록을 입력받는 LLM 에이전트에게 단순 요약이 아닌, 엄격한 필드 구조로 출력하도록 프롬프트를 고정합니다.

- **공통 결정 사항 (`decisions`):** 회의에서 확정된 정책, 방향성, 합의 내용 정리.
    
- **공통 및 차기 안건 (`next_agenda`):** 다음 회의에서 다룰 주제, 팔로업 필요 이슈, 준비물.
    
- **개인별 액션 아이템 (`action_items`):**
    
    - 담당자 (`assignee`)
        
    - 마감 기한 (`due_date`)
        
    - 구체적 행동 지침 (`task_description` - GTD 기반 동사형 명시)
        
    - 우선순위 (`priority`) 및 산출물 형태 (`deliverable`)
        

2. GTD 기반 태스크 정제 로직

추출된 할 일은 모호한 문장이 아니라 즉각 실행 가능한 형태(Next Action)로 변환되어야 누락되지 않습니다.

- **동사형 전환:** '디자인 시안 검토' 대신 '김대리: 로그인 화면 피그마 시안 3종 제작 후 슬랙 공유' 형태로 액션 구체화.
    
- **기한 엄격화:** '다음 주까지' 같은 모호한 표현을 회의 날짜 기준으로 정확한 날짜(`2026-08-26 18:00`)로 변환.
    
- **컨텍스트 태깅:** 업무 성격에 맞게 `@개발`, `@기획`, `@외부미팅` 등의 GTD 태그 자동 부여.

3. 담당자별 자동 배포 및 트래킹 파이프라인

파싱된 데이터를 기반으로 실무자의 개인 환경에 자동으로 침투시키는 워크플로우입니다.

Plaintext

```
[회의록 입력] (음성 녹음 / 텍스트)
       ↓
[LLM 파싱 에이전트] (구조화 JSON 생성)
       ↓
 ┌─────┴──────────────────────────────┐
 │                                    │
[공통 안건 및 회의 요약]       [개인별 액션 아이템]
       ↓                              ↓
공용 노션/위키 자동 문서화     담당자 개인 슬랙 DM / 캘린더 / Todo 등록
                               (김대리: 기한 D-1 자동 리마인드)
```

- **개인 DM 알림:** 회의 종료 즉시 김대리에게 "김대리님, 오늘 회의에서 할당된 To-do는 [X]건이며 마감은 [날짜]입니다" 형태로 개인화된 슬랙 메시지 발송.
    
- **캘린더/투두 자동 등록:** 구글 캘린더 마감 일정 등록 또는 Todoist/노션 개인 데이터베이스로 티켓 자동 생성.
    
- **리더용 통합 대시보드:** 관리자 화면에는 인원별 할당 작업과 마감 현황이 칸반 형태로 일괄 정렬되어 한눈에 진행 상황 모니터링.

### ✍️ 3단계: 인사이트 추출 및 보고서 재조립 (Synthesis)

'비서실장'이 사장님을 위해 핵심만 1장으로 요약하는 단계입니다.

- 현업에서 가장 가치 있는 정보는 "그래서 이게 왜 중요한데?"입니다. LLM에게 아래 구조의 JSON으로 출력하도록 강제합니다.
    
    - `"Headline"`: 시선을 끄는 요약 제목
        
    - `"Context"`: 이 트렌드가 발생한 배경 (3줄 요약)
        
    - `"Business_Impact"`: 우리 프로젝트나 비즈니스에 적용할 수 있는 아이디어 혹은 위협 요소
        
    - `"Source_Links"`: 더 깊이 보고 싶을 때 누를 원본 링크들
        

### 🎨 4단계: 시각적 대시보드 렌더링 (Output)

빽빽한 텍스트 기반의 문서 툴(노션, 엑셀 등)로 결과를 받으면 피로감이 큽니다.

- 가장 추천하는 방식은 백엔드에서 생성된 JSON 결과물을 가져와, **React 기반의 커스텀 웹보드**에 렌더링하는 것입니다.
    
- Cosmos나 Are.na, Milanote처럼 텍스트는 최소화하고, 관련 이미지나 썸네일을 시각적인 카드 형태로 띄워놓는 미니멀한 대시보드를 구축합니다.
    
- 아침에 커피를 마시며 이 대시보드를 스크롤하다가, 눈에 띄는 카드를 클릭하면 그제야 상세한 'Business Impact'와 원문 링크가 펼쳐지도록 설계하면 정보 습득의 효율이 극대화됩니다.

### 1. 의도 파악 및 검색어 분기 (Query Expansion)

- **핵심:** 사용자가 던진 대충 쓴 한 줄의 질문을 AI가 다각도의 전문적인 검색어로 스스로 쪼개는 단계입니다.
    
- **작동:** "최근 PPT 잘 만드는 AI 사이트"라고 입력하면, 에이전트는 내부적으로 `2026 AI 프레젠테이션 툴 장단점 비교`, `Gamma vs Tome vs Canva Docs 요금제`, `AI PPT maker Reddit 실사용 후기` 등 3~5개의 구체적인 쿼리를 동시다발적으로 생성합니다.
    

### 2. 자율 탐색 및 정보 수집 루프 (ReAct Loop)

- **핵심:** 구글 첫 페이지의 요약 텍스트만 보는 것이 아니라, 링크를 타고 들어가 실제 문서를 끝까지 긁어오는 단계입니다.
    
- **작동:** 검색 결과를 바탕으로 블로그, 공식 릴리즈 노트, 커뮤니티(Hacker News 등)의 본문 텍스트를 파싱하여 읽어 들입니다.
    
- **판단:** "마누스 최근 업데이트"를 찾다가 정보가 부족하거나 과거 데이터만 나오면, 스스로 "정보가 부실하므로 `Manus AI 2026 changelog`로 재검색한다"는 판단을 내리고 추가 서핑을 진행합니다.
    

### 3. 노이즈 제거 및 데이터 병합 (Synthesis)

- **핵심:** 광고성 어그로 글이나 중복된 정보를 걸러내고, 유의미한 팩트만 남기는 과정입니다.
    
- **작동:** 수집된 방대한 텍스트 덩어리에서 '광고성 스폰서 리뷰'를 배제하고, 서로 다른 출처에서 교차 검증된 팩트(예: 실제 요금, 새롭게 추가된 기능, 유저들이 공통으로 지적하는 단점)만 추출하여 하나의 깨끗한 데이터로 병합합니다.
    

### 4. 동적 보고서 렌더링 (Dynamic Reporting)

- **핵심:** 조사한 주제의 성격에 맞춰 AI가 가장 보기 좋은 형태로 알아서 문서 포맷을 결정하여 출력합니다.
    
- **작동:** '비교'가 필요한 PPT 툴 조사라면 스펙과 가격이 포함된 **비교 테이블**로, '업데이트 소식'이라면 요점만 짚어주는 **타임라인 요약**으로, '새로운 개념 학습'이라면 **마인드맵이나 스텝바이스텝 불릿 포인트** 형태로 최종 결과물을 던져줍니다.

### ⚙️ 1. '자동 퇴근 요정' 에이전트 구축 로직

기성 툴을 쓰지 않고, 깃과 직접 연동해 알아서 칸반을 옮기고 보고서까지 써주는 자동화 파이프라인을 짠다면 다음 4단계 로직이 필요합니다.

- **1단계: 이벤트 감지 (Webhook / Git Hooks)**
    
    - 퇴근 전 `git push`를 하거나 PR을 생성하는 순간을 자동화의 트리거(시작점)로 잡습니다. 로컬 터미널의 `post-commit` 훅을 이용할 수도 있습니다.
        
- **2단계: Diff 추출 및 에이전트 분석 (맥락 파악)**
    
    - 단순히 커밋 메시지만 보는 것이 아니라, `git diff`를 떠서 변경된 코드 라인 자체를 LLM에게 던집니다.
        
    - LLM은 코드를 읽고 _"사이드 패널 동적 분할 뷰의 전체화면 버그를 수정했고, 에디터 패널 에셋 구조를 원래대로 복구했음"_ 처럼 작업 내역을 정확한 언어로 번역하고 요약합니다.
        
- **3단계: 칸반 티켓 자동 매핑 (시맨틱 탐색)**
    
    - API를 통해 현재 '진행 중'인 내 칸반 티켓 목록을 불러옵니다.
        
    - 에이전트가 방금 분석한 코드 변경 내역과 가장 의미가 일치하는 티켓을 스스로 찾아낸 뒤, 해당 티켓의 상태를 '완료'로 옮겨버립니다.
        
- **4단계: 메신저 발송 (보고 자동화)**
    
    - 수정된 코드의 요약본과 이동된 칸반 티켓 링크를 묶어서, 슬랙이나 디스코드에 "오늘의 작업 내역입니다"라고 자동 발송합니다.
