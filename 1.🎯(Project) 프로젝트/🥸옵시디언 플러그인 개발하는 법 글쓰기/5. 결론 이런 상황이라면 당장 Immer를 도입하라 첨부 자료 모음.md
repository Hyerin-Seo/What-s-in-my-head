# 📦 5. 결론: 이런 상황이라면 당장 Immer를 도입하라 첨부 자료 모음

이 문서는 `글감 후보군.outline`의 **5. 결론: 이런 상황이라면 당장 Immer를 도입하라** 항목에 1:1로 임베드(`![[...#...]]`)되어, 실무 프로젝트의 상태 구조에 따른 Immer 도입 판단 기준 매트릭스와 500개 노드 환경에서도 60fps로 매끄럽게 동작하는 최종 에디터의 시연 자료를 제공하는 아카이브 노트입니다.

---

## Immer 선택 기준 종합 가이드 매트릭스 (이런 분은 추천 vs 굳이 쓸 필요 없어요잉)

| 상태 구조 및 개발 상황 | Immer 도입 추천 | 권장 아키텍처 및 이유 |
| :--- | :---: | :--- |
| **2~3단계 이상 깊은 중첩 객체 (트리, 아웃라이너, 폴더 구조)** | **적극 추천 (필수)** | 스프레드 괄호 지옥과 400줄 재귀 슬라이스를 1~2줄 네이티브 문법으로 종결 |
| **D&D, 순서 변경, 하위 편입 등 잦은 계층 재배치 에디터** | **적극 추천 (필수)** | 복잡한 인덱스 시프트 및 순환 참조 위험 없이 `splice` 2줄로 무결성 보장 |
| **Undo / Redo (실행 취소/다시 실행) 스택 구축** | **적극 추천** | 전체 트리 복사 없이 변경 델타(`patches`)만 기록하여 메모리 절약 |
| **속성(isFolded, todo, tags 등)이 계속 늘어나는 확장형 스키마** | **적극 추천** | 객체 수동 복사가 없어 필드 누락 버그 제로, 기존 함수 수정 0줄 보장 |
| **1단계 얕은 상태 (단순 입력 폼, 모달 토글, 카운터)** | **비추천 (불필요)** | 리액트 기본 `useState`로 충분하며, 굳이 라이브러리를 추가할 이유가 없음 |
| **초당 수천 번의 픽셀/좌표 연산 (3D WebGL, 캔버스 게임 루프)** | **비추천** | 고주파수 렌더 루프에서는 Proxy 생성 오버헤드가 미세 병목이 될 수 있음 |
| **이미 Redux Toolkit(RTK)을 메인 상태 관리자로 쓰고 있는 경우** | **이미 사용 중!** | RTK의 `createSlice` 내부에 이미 Immer가 내장되어 있으므로 추가 설치 불필요 |

## 수백 개 노드 환경에서 고속 타이핑과 D&D가 60fps로 매끄럽게 동작하는 실제 에디터 화면

```text
🖥️ [옵시디언 사이드바 - 최종 완성된 Gaeddong Outliner 에디터 (520개 노드 상태)]

[View: Bullets] [Active: Root] [Zoom: 100%]                      [⚡ 60 FPS]
────────────────────────────────────────────────────────────────────────────
• 1. 대규모 시스템 프로젝트 아키텍처
  • 1.1 프론트엔드 UI/UX 레이어
    • 1.1.1 React 19 기반 가상 트리 렌더러
      • [선택된 블록] ➔ 마우스로 잡아 대분류 2번으로 부드럽게 드래그 중...
        │
        └──────► [파란색 드롭 인디케이터 라인 표시: 0.01초 만에 찰떡 스냅!]
  • 1.2 백엔드 엔진 & 옵시디언 어댑터
    • [현재 커서 위치] ➔ "초당 400타 고속 타이핑 테스트 진행 중"
      "옵시디언 플러그인 개발이 이렇게 부드러울 수가 있다니!" ✨
      (한글 자모 분리 0건, 입력 지연 12ms 이내 즉각 렌더링!)

💡 [최종 동작 쾌감 요약]
- 500개 이상의 노드가 빼곡히 펼쳐진 상태에서도 메모장처럼 가볍고 즉각 반응
- 깊은 위계에서 Enter, Tab, Backspace를 마구 연타해도 커서 프리징 제로
- 복잡한 트리 D&D 이동 후 Ctrl+Z 연타 시 화면 깜빡임 없이 직전 상태로 무손실 복원
```
