## 무슨 일이 났나

- `📚 망고네 책장` · `📓 도서관 메모` 에서 `+ 추가` 를 누르면 **이미 없어진
  `3.📦(Resource) 자료/(Library) 망고네 도서관/…` 폴더가 다시 생기고** 새 노트가 그 안에 박혔다.
  도서관은 민규 서 브랜치(`fix-by-mango`)에서 4.archive 로 옮겨진 뒤였다.
- 보관의 `🪄 작가 요구사항 파악` 에서 `+ 추가` 를 누르면 **인박스**로 갔다.
- 같은 때 오른쪽 위에 "📂 (Library) 망고네 도서관 — 인박스의 새 칸으로 봅니다" 라는
  엉뚱한 알림이 떴다. 인박스와 상관없는 폴더였다.
- 경로를 고친 뒤 다시 누르니, 이번엔 새 책이 보관에 잘 생겼다가 **3.resource 최상단으로
  도로 옮겨지고** 작성일이 비었다.

## 이렇게 하면 다시 난다

1. 보드가 있는 폴더를 다른 구역으로 옮긴다 (특히 옵시디언 **밖에서** — git pull 등)
2. 그 보드에서 `+ 추가`

## 이래야 맞다

- 폴더가 어느 구역으로 옮겨지든 `+ 추가` 는 **보드가 지금 사는 자리**에 만들어야 한다.
  PARA 는 폴더가 통째로 R → A, R → P 로 옮겨 다니는 게 정상이다. 그때마다 깨지면 PARA 를 못 쓴다.

## 알아낸 것

뿌리는 하나였다 — **위치를 글자로 박아 둔 값이, 폴더가 옮겨지면서 낡았다.** 그게 네 군데서 터졌다.

| 증상 | 원인 | 고침 |
| --- | --- | --- |
| 옛 폴더가 되살아남 | 보드가 `newItemFolder`·`quickAddFolder`·`file.inFolder(…)` 를 **볼트 기준 전체 경로 글자**로 들고 있다. 베이스가 상대 경로를 안 받는다 (asar — `newItemMenu.open` 이 `폴더 + 이름` 을 그대로 씀). 옵시디언은 없는 폴더를 **만들어서** 넣는다 | 보드 속 경로가 폴더를 따라가게 했다. 옵시디언 안에서 옮기면 `rename` 을 받아 바로, 밖에서 옮기면 켤 때·폴더가 생기거나 사라질 때 **다른 구역의 같은 하위 경로**를 찾아 고친다. 보드가 사는 구역에 쌍둥이가 있으면 유령 폴더보다 그쪽을 믿는다 |
| 인박스로 감 | `작가 요구사항 파악` 등 보드 5장에 `newItemFolder` 가 **아예 없어서** 옵시디언 기본 위치(인박스)로 떨어졌다 | 구역 안에 사는 보드에 **보드가 사는 폴더**를 넣었다. 홈 보드는 인박스가 맞아서 뺐다 |
| 새 책이 도로 옮겨짐 | 양식 `📖 (책 제목)` 에 `구역: 3.resource` 가 박혀 있었고, 새 노트가 그걸 물려받자 PARA 구역 정리가 **사람이 바꾼 속성**으로 보고 옮겼다. 옮기는 바람에 작성일 채우기도 파일을 놓쳤다 | 태어난 뒤 **첫 한 번은 자리가 구역을 정한다** — 옮기지 않고 `구역` 을 폴더에 맞춘다. 채우기는 경로 대신 파일 객체를 붙잡는다 |
| 엉뚱한 인박스 알림 | 인박스 폴더 알림이 **인박스 안인지 확인을 안 했다** | 인박스 밖 폴더면 안 띄운다 |

- 실제 볼트에 쓰지 않고 돌려 확인: 끊긴 경로 7곳 + 새 항목 폴더 5장, 바뀐 건 경로 줄뿐, YAML 25장 정상.
- `🔥 오늘`·`🧠 주간 리뷰` 의 도서관 빼기 필터도 옛 경로라 유령 폴더가 있는 동안엔 못 고쳤다.
  유령 폴더를 지우자 점검이 돌아 같이 고쳐졌다.
- 유령 폴더와 테스트 노트(`무제`)는 사람이 지웠다.
