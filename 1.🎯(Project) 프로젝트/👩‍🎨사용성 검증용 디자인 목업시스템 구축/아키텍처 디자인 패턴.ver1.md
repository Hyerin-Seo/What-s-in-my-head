이 방대하고 유기적인 요구사항들을 버그 없이 매끄럽게 돌아가게 하려면, 프론트엔드 아키텍처는 **검증된 5가지 핵심 UI/소프트웨어 디자인 패턴의 결합체**로 잡아야 합니다.

지금 우리가 도출한 스펙에서 필연적으로 나타나는 **5대 아키텍처 패턴**을 정리해 드립니다.

---

### 1. [구조 패턴] 프랙탈 복합체 패턴 (Fractal Composite Pattern)
*“Project부터 Slot까지 단 하나의 단일 트리 문법으로 통일한다”*

* **원리**: 
  - `Project`, `Document`, `Page/Element`, `Slot`을 별도의 클래스나 테이블로 따로 만들면 줌(Zoom) 기능이 망가집니다.
  - 모든 단계를 **동일한 `OutlinerNode` 인터페이스**를 구현하는 하나의 **재귀적 복합체(Composite)**로 통일합니다.
* **이유**:
  - 이렇게 해야 **단 하나의 드래그 앤 드롭(DND) 엔진, 단 하나의 줌인/줌아웃 엔진, 단 하나의 Breadcrumb 계산기**로 4단계를 모두 처리할 수 있습니다.

---

### 2. [화면 전환 패턴] 레이아웃 전략 패턴 (Layout Strategy Pattern)
*“`if (phase === 1)` 조건문 지옥을 버리고, Phase별로 레이아웃 프리셋을 갈아 끼운다”*

* **원리**:
  - 화면 컴포넌트 안에 `phase === 1 ? <Storyline /> : <Tiptap />` 같은 삼항 연산자를 덕지덕지 바르면 코드가 썩습니다.
  - 상위 워크벤치는 **단지 3개의 영역(좌, 중, 우) 슬롯**만 열어두고, Phase에 따라 주입되는 **Layout Strategy(전략 객체)**만 교체합니다.

```text
[ Phase 1 전략 ] ──▶ 좌: 참조 덱         | 중앙: 내 스토리라인   | 우: 접힘
[ Phase 2 전략 ] ──▶ 좌: 내 스토리라인   | 중앙: A4 서식 레이아웃 | 우: 템플릿 갤러리
[ Phase 3 전략 ] ──▶ 좌: 목차 네비게이터 | 중앙: Tiptap 위지윅   | 우: AI Composer & Staging
```

---

### 3. [협업 패턴] 스테이지-커밋 패턴 (Stage-Commit Pattern)
*“Git의 Staging 개념을 프론트엔드 UI로 옮겨온다”*

* **원리**:
  - 참조 프로젝트에서 블록을 끌어오거나, AI가 문장을 생성했을 때 **원본 본문에 즉시 덮어쓰지 않습니다.**
  - 반드시 **`Staging Store (임시 대기실)`**에 카드로 격리해 띄워둡니다.
  - 사용자가 `[✔ 부분 수락]`을 누른 조항만 원본 트리에 원자적으로 머지(Commit)합니다.
* **효과**: 사용자가 언제든 안심하고 AI를 돌려볼 수 있고, 원본 데이터 오염이 100% 방지됩니다.

---

### 4. [성능 패턴] 윈도우 청킹 가상화 (Windowed Chunking Virtualization)
*“300페이지 문서를 15페이지 단위의 물리적 청크로 슬라이딩 렌더링한다”*

* **원리**:
  - 브라우저 DOM에는 항상 **[이전 청크] + [현재 청크] + [다음 청크]** 총 30~45페이지 분량만 마운트합니다.
  - 스크롤 위치에 따라 화면 바깥 청크는 DOM을 해제하고, 빈 `div` 높이 스페이서(Spacer)로 스크롤바 높이만 보존합니다.
* **효과**: 수백 페이지의 제안서도 10페이지짜리 문서를 다루는 것과 똑같은 60fps 초경량 메모리를 유지합니다.

---

### 5. [신경망 패턴] 커맨드 버스 & 프로젝션 (Command Bus & View Projections)
*“패널끼리는 서로의 존재를 1도 모른 채 오직 Command로만 소통한다”*

* **원리**:
  - 좌측 아웃라이너, 중앙 Tiptap, 우측 AI 창, 상단 Breadcrumb은 **서로를 `import`하지 않습니다.**
  - 오직 `JUMP_TO_NODE`, `ZOOM_IN`, `APPLY_STAGED_DIFF` 같은 **Command Bus**를 통해서만 명령을 주고받습니다.

---

### 종합 아키텍처 다이어그램 (Architecture Blueprint)

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│ [ UI Presentation Layer ]                                                        │
│   Phase Stepper : [Phase 1: 스토리라이닝] ── [Phase 2: 서식 튜닝] ── [Phase 3: 본문작성] │
│   ┌──────────────────────┬─────────────────────────────┬───────────────────────┐ │
│   │ [ Dockable Left ]    │ [ Center Viewport ]         │ [ Dockable Right ]    │ │
│   │ Project Outliner     │ Windowed Chunk Container    │ Template Gallery /    │ │
│   │ + Reference Deck     │ (Tiptap Sub-Renderers)      │ AI Composer Staging   │ │
│   └──────────────────────┴─────────────────────────────┴───────────────────────┘ │
└─────────────────────────────────────────┬────────────────────────────────────────┘
                                          │ (모든 조작은 불변 Command 발행)
                                          ▼
┌──────────────────────────────────────────────────────────────────────────────────┐
│ [ Control Layer ]                                                                │
│   • Command Bus (ZOOM, STAGE, COMMIT, DRAG_MOVE, INVERT for Undo)               │
│   • Workbench Phase State Machine (현재 Phase에 맞게 패널 슬롯 스위칭)          │
└─────────────────────────────────────────┬────────────────────────────────────────┘
                                          │ (단일 원본 갱신)
                                          ▼
┌──────────────────────────────────────────────────────────────────────────────────┐
│ [ Data Kernel Layer (In-Memory Single Source of Truth) ]                         │
│   • ProjectAggregate : Fractal OutlinerNode Map (Project ──▶ Doc ──▶ Page ──▶ Slot)│
│   • ReferenceRegistry : 참조 프로젝트 3개 (Read-Only 덱)                          │
│   • StagingQueue : AI 및 참조 복사 대기 큐                                       │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 한 줄 요약

프론트엔드는 **"프랙탈 복합체(데이터 모델) + 레이아웃 전략(Phase 전환) + 스테이징(AI 검토) + 청킹 가상화(대용량 렌더링)"**이라는 4대 축으로 설계하면, 
아무리 복잡한 Phase 전환과 참조 프로젝트 대조, AI 자동 생성이 맞물려도 코드가 절대 꼬이지 않는 완벽한 구조적 뼈대를 갖추게 됩니다.---
