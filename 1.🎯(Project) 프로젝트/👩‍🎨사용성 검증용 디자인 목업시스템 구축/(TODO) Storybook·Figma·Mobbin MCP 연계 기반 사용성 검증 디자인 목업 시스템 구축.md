## 뭘 해야 하나

### 1. 배경 및 문제 의식 (Why)
- `사용성 검증 회의 준비 자료.outline`에 도출된 핵심 검증 항목들(예: 날것의 메모 투입 ➔ AI 3대 폼 후보 추천 ➔ 1클릭 뼈대 안착, Diff 대조 및 슬롯 잠금 등)은 말이나 글(텍스트)만으로는 직관적인 효능감과 손맛을 검증하기 어려움.
- 백엔드 API와 DB 전체를 띄우지 않고도, **컴포넌트 단위로 Mock 데이터를 주입하여 브라우저에서 버튼을 누르고 폼이 꽂히는 실제 인터랙션을 즉시 확인**할 수 있는 초경량 디자인 목업 환경이 필수적임.

### 2. 3대 도구의 역할 분담 및 MCP 연계 파이프라인 (What & How)
단일 도구에 의존하지 않고, **[영감 탐색 ➔ 와꾸 시각화 ➔ 실동작 인터랙션 검증]**의 3단계 유기적 파이프라인 구축:

```text
[1단계: Mobbin MCP]         [2단계: Figma MCP]             [3단계: Storybook MCP]
글로벌 B2B SaaS 레퍼런스  ➔  전체 화면 레이아웃 와꾸 배치  ➔  살아있는 React 컴포넌트 구동
(웹 에디터·추천 패턴 수집)      (30분 컷 시각화·화면 흐름)         (더미 데이터 주입 & 실제 클릭 손맛)
```

1. **Mobbin (레퍼런스 탐색 & 벤치마킹)**:
   - 역할: Linear, Notion, Miro 등 글로벌 선도 SaaS의 에디터·모달·추천 플로우 캡처 수집.
   - 주의사항: 모바일 캡처 비중이 높으므로 반드시 `Platform: Web` 필터를 지정하여 데스크톱 웹 에디터/캔버스 패턴 위주로 선별.
   - 연동: Mobbin MCP를 통해 에이전트가 최적의 UI 패턴을 즉각 탐색·참조.

2. **Figma (와꾸 설계 & 시각적 조망)**:
   - 역할: 캔버스 좌우 분할 구조, 3대 서식 카드 팝업 등 전체 레이아웃 프레임을 30분 만에 시각화.
   - 한계점 보완: 피그마는 정적 그림이므로 무리하게 스마트 애니메이트 화살표 스파게티를 만들지 않고, 순수 레이아웃·흐름 공유용으로 한정.

3. **Storybook (실동작 인터랙션 & 상태 스위칭 검증)**:
   - 역할: `@storybook/addon-mcp`를 탑재하여 백엔드 서버 없이 브라우저 상에서 컴포넌트 단위 실동작 검증.
   - 핵심 검증 스토리:
     - `Story 1 (Raw Input)`: 날것의 메모 인입 뷰
     - `Story 2 (Preset Popup)`: 3대 서식 후보(표/조항/카드) 추천 팝업 (Mock 주입)
     - `Story 3 (Slot Binding)`: 1클릭 선택 시 뼈대 슬롯에 쏙 안착되는 뷰
     - `Story 4 (Diff & Lock)`: 슬롯 변경점 하이라이트 및 자물쇠 잠금 뷰
   - 최대 이점: 검증이 완료된 컴포넌트는 버려지지 않고 실제 프로덕션 코드(`apps/web`)로 직행.
