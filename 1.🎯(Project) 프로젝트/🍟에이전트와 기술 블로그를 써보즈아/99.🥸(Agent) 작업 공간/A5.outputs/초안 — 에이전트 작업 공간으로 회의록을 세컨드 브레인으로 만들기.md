# 에이전트 작업 공간(agent workspace)으로 회의록을 세컨드 브레인으로 만들기

## 개요

회의가 끝나면 정리가 밀렸습니다. 그래서 에이전트에게 회의록 정리를 맡겼는데, 이번에는 다른 문제가 생겼습니다. 에이전트가 쓴 노트가 사람이 쓴 노트와 같은 자리에 쌓였습니다.

에이전트에게 정리를 시킬 때마다 이런 말을 덧붙여야 했습니다.

> 회의록 본문은 건드리지 말고
> 할 일은 바로 만들지 말고 후보로만 뽑고
> 네가 쓴 건 보드에 안 뜨게 따로 둬 줘

그래도 에이전트가 쓴 카드는 회의록 보드에 섞였고, 어느 것이 사람이 정한 것이고 어느 것이 에이전트의 초안인지 가려 읽어야 했습니다.

〔삽화 1〕

그래서 이런 생각이 들었습니다. '에이전트는 마음껏 쓰게 두고, 사람이 고른 것만 볼트에 들어오게 할 수는 없을까?'

우리는 볼트 안에 에이전트만 쓰는 자리를 따로 팠습니다. 이름은 `99.🥸(Agent) 작업 공간` 입니다. 이 글은 그 안의 폴더 다섯 개가 무엇을 하는지, 회의록이 거기서 어떻게 분류되고 사람 손을 거쳐 볼트로 올라가는지, 그렇게 쌓인 기록이 어떻게 세컨드 브레인 노릇을 했는지를 다룹니다.

## 작업 공간 / 스킬

회의 하나에 작업 공간 하나가 생깁니다. 구조는 이렇습니다.

```
99.🥸(Agent) 작업 공간/<회의록 이름>/
 ├ A1.collection
 ├ A2.scratch(ideation)
 ├ A3.working memory
 ├ A4.meta
 └ A5.outputs
```

| 폴더 | 누가 쓰나 | 역할 |
| --- | --- | --- |
| A1.collection | 에이전트 | 뽑은 카드를 모으는 곳. `검토 중` · `paused` · `history` 로 나뉨 |
| A2.scratch(ideation) | 에이전트 | 지난 회의에서 하기로 한 것이 됐는지 점검표 |
| A3.working memory | 에이전트 | 작업 기억. 세 줄 요약 · 속기 분류표 · 고친 기록 |
| A4.meta | 에이전트 | 이 회의에만 쓰는 스킬 사본. 고치는 것은 여기서만 |
| A5.outputs | **사람** | 사람이 고른 카드. 에이전트는 여기에 쓰지도 옮기지도 않음 |

폴더를 채우는 순서는 스킬이 정합니다. 작업 공간이 자리라면 스킬은 순서입니다.

## 작업 공간

작업 공간은 에이전트가 쓴 것이 볼트에 섞이지 않게 가둬 두는 자리입니다. 에이전트는 여기에만 씁니다. 볼트로 올리는 것은 사람만 합니다.

회의 하나를 돌리고 나면 안은 이렇게 됩니다.

```
2026.10.01 15분 공유회/
 ├ A1.collection/
 │   ├ 검토 중/     (비어 있음 — 다 골랐거나 치웠음)
 │   ├ paused/
 │   └ history/     1.1_와꾸가_안_잡힌_사람_…   1.2_진심_펀치_테스트_…   1.3_…
 ├ A3.working memory/   2026.10.01 15분 공유회 — 작업 기억
 ├ A4.meta/         pre_meeting_agenda_preparer/   meeting_decision_recorder/
 └ A5.outputs/      D1_우리_도구는_시뮬레이터다_…
```

> Tip: 주목할 것은 **옵시디언의 "제외된 파일"** 입니다. 작업 공간 폴더를 통째로 제외해 두면 파일 탐색기에는 그대로 보이고, 보드 · 검색 · 그래프에는 안 뜹니다. 에이전트 노트에 속성을 달아 하나씩 가리는 것이 아니라 폴더째로 가립니다.

이렇게 해 두면 에이전트가 카드를 몇 장을 쓰든 사람의 보드는 그대로입니다.

## Before / After 예시

차이는 회의록 보드를 열어 보면 가장 잘 보입니다.

### Before (작업 공간을 가리기 전)

에이전트가 쓴 카드의 속성은 이렇게 생겼습니다.

```yaml
유형: 메모
분류:
  - 회의록
상태: 검토 중
작성자:
  - "[[Claude]]"
```

회의록 보드는 `분류: 회의록` 인 노트를 모읍니다. 주간 리뷰는 `상태: 검토 중` 인 노트를 모읍니다. 에이전트 카드는 둘 다에 떴습니다. 나중에 세어 보니 에이전트 노트 70장 가운데 약 30장이 `분류: 회의록` 이었습니다.

회의록을 찾으러 보드를 열면 에이전트의 초안부터 걸러 내야 했습니다.

### After (폴더째 제외한 뒤)

고친 것은 설정 한 줄입니다.

```diff
  "userIgnoreFilters": [
    "skills/",
-   "/!\\(Template\\)/"
+   "/!\\(Template\\)/",
+   "99.🥸(Agent) 작업 공간/"
  ]
```

카드의 속성은 그대로 두었습니다. 보드에는 사람이 올린 것만 남았습니다.

〔삽화 2〕

## 작업 공간을 만들 때 고려했던 기준

#### 에이전트는 작업 공간에만 쓴다

볼트의 노트를 직접 고치게 두면 무엇이 초안이고 무엇이 정한 것인지 흐려집니다. 에이전트가 볼트 쪽에 남기는 것은 회의록에 작업 공간으로 가는 링크 한두 줄뿐입니다.

#### 고르는 것은 사람이고, 고르는 자리는 하나다

- A1 `검토 중` = 에이전트가 낸 후보
- A5 `outputs` = 사람이 고른 것

사람은 마음에 드는 카드를 A5 로 옮기기만 합니다. 표에 체크하거나 칸반에서 끌게도 해 봤는데, 고르는 곳이 여럿이면 헷갈렸습니다.

#### 안 고른 것도 지우지 않는다

안 고른 카드는 `history` 로 갑니다. 지우지 않습니다. 이 기준이 나중에 뜻밖의 쓸모를 냈습니다 (아래 심화).

## 도입 후 느낀 변화

#### 보드에서 에이전트의 초안을 걸러 읽지 않아도 된다

회의록 보드와 주간 리뷰에는 사람이 올린 것만 뜹니다.

#### 에이전트에게 덧붙이던 말이 사라졌다

"따로 둬 줘", "바로 만들지 마" 를 매번 말하지 않습니다. 어디에 쓰는지가 폴더로 정해져 있습니다.

#### 에이전트가 틀려도 치울 것이 없다

카드가 마음에 안 들면 안 고르면 됩니다. 볼트에는 아무것도 안 들어왔으니 되돌릴 것도 없습니다.

## 언제 작업 공간을 쓰면 좋은가

#### 에이전트가 쓴 것과 사람이 정한 것을 가려야 하는 경우

회의록 · 결정처럼 "누가 정했나" 가 중요한 기록.

#### 에이전트가 한 번에 여러 장을 쓰는 경우

후보를 많이 내게 할수록, 그 후보가 볼트에 안 섞이는 자리가 필요합니다.

## 스킬

작업 공간이 자리라면 스킬은 회의록을 그 자리에 채워 넣는 순서입니다. 사람이 하는 말은 이 정도입니다.

| 스킬 · 요청 | 하는 일 | 예시 요청 |
| --- | --- | --- |
| 회의 정리 | 속기를 읽고 작업 공간을 만들어 카드를 뽑음 | "이 회의록 정리해줘" |
| 안건 카드 | 아직 안 정한 것을 결정 질문과 쟁점으로 구조화 | (회의 정리가 부름) |
| 결정 카드 | 이미 정한 것을 결정 · 기한 · 이유로 기록 | (회의 정리가 부름) |
| 다시 뽑기 | 안 고른 카드의 이유로 스킬 사본을 고쳐 다시 뽑음 | "다시 뽑아줘" |
| 지난 회의 점검 | 지난번에 하기로 한 것이 됐는지 점검표를 깖 | "지난 회의 점검해줘" |

회의 정리는 속기를 요약하고 끝나지 않습니다. 속기를 한 줄도 빼지 않고 번호를 매긴 뒤 세 갈래로 분류합니다.

```
속기 (한 줄도 빼지 않고 번호)
       ↓
세 갈래로 분류
  · 아직 안 정한 것      → 안건 카드
  · 이미 정한 것         → 결정 카드
  · 논의할 게 없는 것     → 카드 아님 목록 (단순 할 일 · 연락)
       ↓
A1 검토 중
       ↓
사람이 골라 A5 로
       ↓
사람 말로 다듬어 프로젝트의 회의 날짜 폴더로
```

에이전트가 다 해 주는 것은 아닙니다. 9월 29일 회의는 녹음 전사 376발화였고, 에이전트는 안건 카드 여섯 장을 뽑았습니다. 우리가 고른 것은 세 장입니다. 고른 세 장도 그대로 쓰지 않았습니다. 카드 하나를 할 일 석 장으로 쪼갰고, 카드에 없던 내용을 더했습니다.

하지만 376발화를 받아 적고 갈라 놓는 일이 "정리해줘" 한마디로 줄었습니다. 사람은 고르고 더하는 데만 시간을 씁니다.

## 언제 스킬을 쓰면 좋은가

#### 순서가 늘 같은 일인 경우

회의는 매번 같은 차례로 정리됩니다 — 읽고, 가르고, 카드로 쓰고, 고르기를 기다립니다.

#### 노트 여러 장을 한 번에 만들어야 하는 경우

회의 하나에서 카드가 여러 장 나옵니다. 한 번에 다 시키면 서로 엉킵니다. 안건 카드와 결정 카드를 다른 스킬로 나눈 까닭입니다.

## 쌓인 회의록을 세컨드 브레인으로 쓰는 패턴

회의록이 이렇게 쌓이자 생각지 못한 쓸모가 생겼습니다. 에이전트에게 **설명하는 대신 가리킬 수 있게** 됐습니다.

우리 팀에는 "와꾸" 라는 말이 있습니다. 에이전트는 이 말을 모릅니다. 풀어서 설명해도 자기 식으로 알아듣고 엉뚱한 기능 사양을 내놓았습니다.

그래서 설명을 그만두고 폴더를 가리켰습니다.

〔삽화 3〕

### 예시: 에이전트에게 "와꾸가 안 잡혔다" 가 무슨 뜻인지 물을 때

#### AS-IS: 말로 설명한다

```
질문  우리 팀에서 "와꾸가 안 잡혔다" 는 게 무슨 뜻이야?
  → 에이전트가 낱말 뜻으로 짐작
  → "양식이나 기준 문서가 없어서 틀이 안 잡힌 백지 상태를 말합니다."
```

틀렸습니다. 우리 팀에서는 기준 문서가 있어도 와꾸가 안 잡힐 수 있습니다.

#### TO-BE: 회의 폴더를 가리킨다

```
질문  discussions → 현재 이 내용을 본다면 우리 팀이 어떤 과정을 진행하는지를 알게 될거야.
  → 회의 날짜 폴더의 결정 카드
  → 링크된 안건 카드의 속기 원문
  → "80%는 양식(기준 문서)이 있어도, 20%의 모르는 칸이 나오면 와꾸가 안 잡힌 것이다." (속기 32:50)
```

실제 화면입니다. 에이전트는 1분 만에 회의에서 오간 말 셋을 시각과 함께 꺼내 왔습니다.

![[통쾌한 순간 2 — 에이전트의 답.png]]

#### 실제 전달 데이터 비교

AS-IS: 회의 전사를 통째로 읽혔다면 — 전사는 "와꾸" 를 이렇게 받아 적었습니다.

| 전사에 적힌 글자 | 횟수 |
| --- | --: |
| 와꾸 | 10 |
| 왔고 | 8 |
| 와코 | 2 |
| 와꼬 | 2 |
| 악구 | 1 |

스물세 번 가운데 "와꾸" 로 적힌 것은 열 번입니다.

TO-BE: 에이전트가 읽은 안건 카드

```markdown
# 1.1 와꾸가 안 잡힌 사람 — 첫 타겟을 어디에 그을까

> **속기 원문**
> - 발화자 2 (23:50) *… 기준 문서를 갖고 있다는 거 자체가 왔고가 잡혔다는 거 아니야?*
> - 발화자 1 (32:50) *그러니까 와꾸가 안 잡혔다라는 것은 내가 80%는 나왔는데 20%는 몰라. 그럼 왔고 안 잡힌 거야.*
```

카드는 제목에서 "와꾸" 한 가지로 묶고, 그 말이 오간 발화를 시각과 함께 옮겨 둡니다. 에이전트가 꺼내 온 말 셋은 전부 이 칸에 있던 것입니다.

이 말은 회의에서 사람 둘도 서로 다르게 알아들어, 23:50 부터 32:50 까지 9분 동안 세 번 되물은 말입니다. 에이전트가 가져온 것은 그 되물음이 끝난 자리였습니다.

**이 카드는 어디에 있었나요?**

`history` 폴더입니다. 우리가 **안 고른** 카드였습니다. 그 회의에서 고른 것은 결정 카드 한 장뿐이고, 그 결정 카드가 안 고른 안건 카드들을 링크로 가리키고 있었습니다. "안 고른 것도 지우지 않는다" 는 기준이 여기서 쓸모를 냈습니다.

**[참고] 회의 두 번의 크기**

| 회의 | 전사 전체 | 프로젝트 폴더에 올라간 것 | 줄어든 비율 |
| --- | --: | --: | --: |
| 09.29 (376발화) | 70,383 bytes | 16,394 bytes | 76.7% |
| 10.01 (175발화) | 35,913 bytes | 1,729 bytes | 95.2% |

안건 카드 한 장은 5,798 bytes 로, 그 회의 전사의 16% 입니다.

> 참고: 파일 크기이지 토큰이 아닙니다. 에이전트가 그날 실제로 얼마나 읽었는지를 잰 것도 아닙니다. 카드를 전부 합치면 줄지 않습니다 — 09.29 회의는 카드 전체가 67,390 bytes 로 전사와 거의 같습니다. 줄어드는 것은 한 번에 읽는 양입니다. 그리고 에이전트가 꺼낸 말 셋 가운데 하나는 화자가 틀렸습니다. 뜻은 잡았고 누가 말했는지는 놓쳤습니다.

## 마무리

처음에는 에이전트가 쓴 것을 볼트에서 떼어 놓으려고 폴더를 팠습니다. 그런데 그렇게 떼어 쌓은 기록이, 나중에는 에이전트에게 우리 팀을 설명해 주는 기억이 됐습니다.

에이전트에게 무엇을 시킬지보다, 에이전트가 쓴 것을 어디에 두고 누가 고를지를 먼저 정해 보시기를 권합니다.

여기서 한 걸음 더 가면, 사람이 안 고른 카드의 이유로 스킬이 회의마다 고쳐지고, 다음 회의 전에 지난 합의가 지켜졌는지 에이전트가 먼저 점검하는 데까지 넓힐 수 있습니다.

## 지은 것과 확인할 것

- **지은 것 둘**: 개요의 인용 세 줄 · 심화 AS-IS 의 답 한 줄. 새 대화에서 폴더 없이 한 번 물어보면 실물로 바꿀 수 있습니다.
- TO-BE 의 질문은 실제로 한 말이지만 "와꾸의 뜻" 을 물은 것은 아니었습니다 ("'행위' 에 집중하라" 는 요청이었고, 답 안에 와꾸의 뜻이 들어 있었습니다).
- "표에 체크하거나 칸반에서 끌게도 해 봤는데 헷갈렸다" 는 제 기억 메모에 있는 것이고 볼트 문서에는 그 말로 적혀 있지 않습니다. 맞는지 확인이 필요합니다.
