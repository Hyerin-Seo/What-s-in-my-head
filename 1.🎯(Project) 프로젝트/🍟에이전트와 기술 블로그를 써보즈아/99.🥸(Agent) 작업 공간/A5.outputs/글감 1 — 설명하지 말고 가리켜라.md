# 글감 1 — 설명하지 말고 가리켜라

| | |
| --- | --- |
| **독자** | 에이전트에게 "그게 아니라…" 를 세 번째 치고 있는 사람 |
| **가져갈 것** | 다시 설명하는 대신 가리킬 수 있는 회의 기록의 최소 모양 세 가지와, 가리키는 한 줄 |
| **한 줄 주장** | 길을 잃은 에이전트를 돌려놓는 것은 더 긴 프롬프트가 아니라 팀이 실제로 한 말이다 |

## "어쩌라고?" 에 대한 답

오늘 당신의 에이전트가 엉뚱한 사양을 늘어놓는다면, 설명을 고쳐 쓰지 말고 지난 회의 기록을 읽히라는 것. 읽힐 기록이 없다면 무엇부터 남기면 되는지.

## 가제

- 설명하지 말고 가리켜라 — 회의록 폴더 하나로 에이전트의 방향을 1분 만에 돌린 이야기
- "아니야 아니야" 를 그만 치게 된 날

## 목차

```
장면            "아니야 아니야 이런 것을 제시해달라는 것이 아니야" (캡처 1)
무엇이 문제였나     먼저 읽은 참조에 끌려가 무슨 말을 해도 모듈 사양만 나왔다
한 일            설명을 더 하지 않았다. 폴더 둘을 가리켰다
1분 뒤           에이전트의 답 (캡처 2) — 회의 발화 셋을 시각과 함께 꺼내 옴
무엇을 읽었길래     회의 기록의 모양 — 발화 원문과 시각 · 안건 카드 · 결정 카드 · 날짜 폴더
인용은 정확했나     원문 대조표 — 시각은 셋 다 맞음, 문장 하나는 다듬어짐, 화자 하나는 틀림
가리킬 수 있으려면   최소 세 가지 — 원문 발화가 남아 있을 것 · 회의마다 한 폴더 · 정한 것과 안 정한 것이 따로
언제 통하고 언제 안 통하나
마무리
```

## 지금 가진 재료 · 없는 재료

- 있음: 캡처 두 장, 속기 원문 대조표, 회의 기록의 실제 폴더 구조
- 없음: **오염됐을 때의 답 원문** (Before). 이것이 없으면 "엉뚱했다" 가 말로만 남습니다

## 약점

- 한 번 있었던 일입니다. "항상 통한다" 로 쓰면 안 됩니다.
- "컨텍스트를 주면 잘한다" 는 누구나 아는 말로 읽힐 수 있습니다. 이 글만의 것은 **컨텍스트가 문서가 아니라 회의에서 오간 말**이라는 점입니다. 거기에 힘을 실어야 합니다.
