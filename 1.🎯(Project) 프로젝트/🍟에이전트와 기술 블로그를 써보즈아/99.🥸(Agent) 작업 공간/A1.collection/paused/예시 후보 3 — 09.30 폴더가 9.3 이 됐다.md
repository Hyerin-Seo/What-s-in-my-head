# 예시 후보 3 — `09.30` 폴더가 `9.3` 이 됐다

> **한 줄**: 회의 날짜 폴더 `09.30` 이 분류 칸에 숫자 `9.3` 으로 떴다. 에이전트는 따옴표를 쳐서 고쳤다고 했는데, 틀린 고침이었다.

## 실제 재료 (버그 리포트 그대로, 2026-09-30)

```yaml
분류:
  - 🐕망고독 R&D 프로젝트 관리
  - 09.30          # YAML 이 숫자 9.3 으로 읽음
  - decisions
```

속성 창에는 `["🐕망고독 R&D 프로젝트 관리",9.3,"decisions"]` 로 뜨고 ⚠️ 가 붙었다. 결정 노트 6장.

- 에이전트의 첫 고침: `"09.30"` 으로 따옴표를 쳐서 살려 둠.
- Rin 이 찾은 진짜 원인: 하위 폴더 이름은 애초에 분류에 넣는 값이 아니다. 분류는 프로젝트 폴더 하나.
- 리포트에 남은 문장: "처음엔 제가 `"09.30"` 으로 따옴표만 쳐서 살려 뒀는데, 그게 틀렸습니다."

After — 고친 노트:

```yaml
분류:
  - 🐕망고독 R&D 프로젝트 관리
```

문서 (`docs/meetings-and-skills.md`):

```markdown
폴더가 *어느 회의에서 나왔는지* 이고 `분류` 는 여전히 프로젝트 폴더 하나 — 하위 폴더 이름은 분류에 넣지 않습니다.
```

## 글에서 이렇게 보인다

> 분류 칸에 `9.3` 이 떠 있었습니다. 폴더 이름 `09.30` 을 YAML 이 숫자로 읽은 것입니다.
> 에이전트는 따옴표를 쳐서 고쳤습니다. 값은 멀쩡해졌지만 고침은 틀렸습니다. 그 칸에는 애초에 폴더 이름이 들어가면 안 됐습니다.
> 증상은 에이전트가 막았고, 원인은 사람이 찾았습니다.

## 뼈대의 어느 칸에

- **규칙 한 토막** — YAML 규칙을 보여 주는 자리에 실제로 깨진 값 하나.
- 또는 **스킬의 한계 인정** — "에이전트가 다 해 주는 것은 아닙니다" 의 실례.

## 왜 괜찮은가

- 세 줄짜리 YAML 로 보입니다. 설명이 필요 없습니다.
- 에이전트가 **틀리게 고친** 것을 그대로 적을 수 있어 "객관적으로 인정" 에 맞습니다.
