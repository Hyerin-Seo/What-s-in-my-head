# 글감 3 — 같은 요청을 세 번

| | |
| --- | --- |
| **독자** | 에이전트를 날마다 쓰는 개발자 · 기획자. 답이 이상해지면 새 대화를 여는 사람 |
| **가져갈 것** | 오염된 대화를 살리는 방법 셋의 비교와, 직접 따라 해 볼 수 있는 절차 |
| **한 줄 주장** | 오염된 에이전트에게는 설명을 더하는 것보다 회의 기록을 읽히는 편이 빠르다 — 를 나란히 놓고 보여 준다 |

## "어쩌라고?" 에 대한 답

답이 이상해졌을 때 고를 수 있는 길이 셋(그대로 밀기 · 다시 설명하기 · 기록을 가리키기)이고, 각각 무엇이 나오는지를 보고 고르라는 것.

## 가제

- 같은 요청, 세 번 — 오염된 에이전트를 회의록으로 되돌리기
- 프롬프트를 고쳐 쓰기 전에 회의록부터 읽혀 봤다

## 목차

```
개요            무슨 요청을 해도 모듈 사양만 나오던 대화
같은 요청 하나     끝까지 이 요청 하나로 간다 (요청 원문)
① 오염된 채로      다른 참조를 먼저 읽은 상태 — 답 원문
② 다시 설명하고    "행위에 집중하라" 고 말로 설명 — 답 원문
③ 회의록을 가리키고  폴더 둘을 가리킴 — 답 원문 (캡처 2)
나란히 놓기       세 답의 첫 문단 · 꺼내 온 근거 · 걸린 시간
무엇이 달랐나      ③ 만 팀의 실제 발화를 시각과 함께 꺼냈다
인용 검증        원문 대조표 — 맞은 것, 다듬어진 것, 틀린 것
따라 해 보기      회의 기록이 이런 모양이면 된다
언제 안 통하나
마무리
```

## 지금 가진 재료 · 없는 재료

- 있음: ③ 의 캡처와 대조표
- **없음: ① 과 ② 의 답 원문, 요청 원문.** 그 대화를 사람이 가져오거나, 같은 조건으로 다시 돌려야 합니다
- 없음: 걸린 시간 (③ 만 `Worked for 1m`)

## 약점

- **재료의 3분의 2 가 아직 없습니다.** 다시 돌리면 같은 오염이 재현될지 알 수 없습니다.
- 다시 돌린 것은 "실제로 겪은 일" 이 아니라 실험입니다. 글에서 그렇게 밝혀야 합니다.
