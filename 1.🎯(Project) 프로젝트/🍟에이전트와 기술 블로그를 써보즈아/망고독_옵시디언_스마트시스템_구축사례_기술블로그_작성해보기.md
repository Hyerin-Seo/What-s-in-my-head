## 🦴 레퍼런스 글의 뼈대 — 우리 글의 틀 (공통점 1)

> 레퍼런스: **「하네스 엔지니어링(harness engineering)으로 팀 맞춤형 AI 환경 구축하기」** — 이재홍 (파트너셀프서비스팀 프론트엔드). Cursor 의 `Rules` · `Skills` 로 AI 가 팀 규칙을 처음부터 알게 만든 이야기.
> **우리 볼트와 주제가 거의 같습니다** — 그 팀의 Rules = 우리 `CLAUDE.md` · `docs/`, Skills = 우리 `skills/`, 전처리 스크립트 = 우리 플러그인.
> 구성: 이론 → 구체 예시 → 수치 → 실무 적용. 1인칭 "우리 팀", 합니다체 (원문에서 한 번 더 확인).

| # | 레퍼런스 소제목 | 거기서 다루는 것 | 우리 글에 넣을 재료 (볼트 근거) |
| --- | --- | --- | --- |
| 1 | 개요 | 배경 문제 + 하네스 개념 | 노션에서 옵시디언으로 옮긴 이유 · 사람 둘 + 에이전트 여럿(Claude · Codex · Gemini)이 같은 볼트를 씀 — `CLAUDE.md` 첫머리 |
| 2 | Rules / Skills | 디렉터리 구조 · 역할 (표) | `CLAUDE.md`(입구) · `docs/`(주제별 규칙) · `AGENTS.md`(CLAUDE.md 안 읽는 에이전트용) · `skills/` — 표 하나로 |
| 3 | Rules | 컨벤션 전달 방식 (코드) | 속성 13종 · 위키링크는 따옴표로 · 줄끝 LF — `docs/properties.md` 의 YAML 규칙 한 토막 |
| 4 | Before / After | 규칙 전후 비교 (이미지) | **회의 한 바퀴**: 속기만 쓰면 → 안건 카드 + 결정 카드가 `검토 중` 에. 09.29 회의 녹음 전사 376발화 → 안건 6 · 결정 6 (`에이전트 작업 공간/2026.09.29 주간 회의록`) |
| 5 | Rules 작성 기준 | 원칙 3가지 | "틀려도 오류가 안 나고 **조용히 깨지는 것**만 입구에" · "지어내지 않는다" · "삭제는 사람이" — `CLAUDE.md` 의 `어떤 일이든 지키는 것` |
| 6 | 도입 후 변화 | 개선 3가지 | 1,404줄 `CLAUDE.md` 를 `docs/` 로 쪼갬 (2026-09-21) · 에이전트가 바뀌어도 같은 규칙 · AI 가 쓴 건 99 샌드박스 → 사람이 골라야 볼트로 |
| 7 | 언제 Rules 를 쓰나 | 2가지 | 모든 노트에 걸리는 것 (속성 · 구역 · 분류) |
| 8 | Skills | 자동화 워크플로 (표 · 파이프라인 그림) | `skills/meeting-notes` 의 Pre → Live → Post → Action → Learn · 안건/결정 카드 스킬 · 회의마다 스킬 사본을 튜닝하고 사람이 승인하면 정본으로 |
| 9 | 언제 Skills 를 쓰나 | 2가지 | 순서가 있는 일 (회의 정리 · 할 일 쪼개기 `editor_mockup_todo_manager`) |
| 10 | 전처리 스크립트 · 컨텍스트 최적화 (AS-IS/TO-BE) | 스크립트 · 수치 표 | 플러그인 `claude`: 인박스에 던진 파일을 노트로 감싸고 요약 · PARA 구역 정리 · 칸반 보드 자동 생성. 에이전트는 **폴더 대신 속성으로** 찾음 (`CLAUDE.md` 의 `자료를 찾을 때`) |
| 11 | 마무리 | 개인기 → 팀 시스템, 다음은 다중 에이전트 | 회의판(포스트잇 구역 = 지시) · 볼트 동기화 · 채택 기록으로 스킬이 배움 |

**우리 글에만 있는 것 (차별점 후보)** — 사람 손을 거친 것만 볼트로 승격 (99 샌드박스) · 스킬이 회의마다 튜닝되고 채택 기록으로 배움 · 버그를 볼트 안 🐛 버그 리포트 카드로 관리.
