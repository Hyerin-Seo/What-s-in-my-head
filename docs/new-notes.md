# 새 노트 · 양식 · 작성자

> 입구는 볼트 맨 위 `CLAUDE.md` 입니다. 노트를 새로 만들거나, 본문을 써 넣거나, `작성자`·`커버` 를 다룰 때 읽습니다.
> 2026-09-21 에 `CLAUDE.md` 에서 떼어 왔습니다. 규칙은 그대로이고 자리만 옮겼습니다.

## 새 노트를 만들 때

- 속성 13종을 **전부** 넣습니다. 값이 없으면 빈 칸으로 둡니다.
  (사람이 옵시디언에서 만들면 플러그인이 알아서 얹습니다 — 아래 **어느 폴더에서 만들든** 참고)
- **`제목` 속성은 만들지 마세요.** 파일명이 제목입니다. 보드는 `file` 을 씁니다.
- `유형` 과 `구역` 은 반드시 채웁니다. 이게 없으면 어느 보드에도 안 뜹니다.
- 어디 둘지 모르겠으면 `0.📥 인박스/` 에 넣고 `구역: 0.inbox` 로 둡니다.

### 양식의 프론트매터는 **통째로** 복사됩니다 — 자기 설명을 속성에 두지 마세요

보드의 `+` 로 만든 노트는 `newItemTemplate` 이 가리키는 양식의 프론트매터를
**한 칸도 빼지 않고** 베껴 옵니다 (obsidian.asar 확인 — 빈 파일을 만든 뒤
`processFrontMatter` 로 양식의 값을 통째로 넣습니다). **본문은 안 베낍니다.**

그래서 양식 자신을 설명하는 값이 속성에 있으면 새 노트마다 따라붙습니다.

| 양식에 이렇게 있으면 | 새 노트가 이렇게 됩니다 |
| --- | --- |
| `요약: 새 할 일 만들 때 복사하는 틀` | 버그 잡는 할일의 요약이 "복사하는 틀" |
| `주제: 양식 · 할 일` | 만드는 노트마다 `#양식` |
| `작성자: "[[Claude]]"` | **내가 쓴 카드의 작성자가 Claude** |

2026-09-16 에 셋 다 실제로 그랬습니다. 그래서 `newItemTemplate` 으로 쓰이는 양식
다섯 장에서 `요약`·`주제`·`작성자` 를 비웠습니다. 양식이 뭔지는 **본문의 `%%` 주석**에
적습니다 — 본문은 안 베끼니 거기가 안전한 자리입니다.

| 양식에 남겨도 되는 것 | 왜 |
| --- | --- |
| `유형` `구역` `상태` | 새 노트가 **가져야 하는** 값입니다. 그게 양식의 일 |
| `상위`(품의서) · `커버`(책) | 그 양식으로 만드는 노트가 실제로 물려받을 값 |
| 유형별 고유 속성 칸 (`일정` `저자` …) | 빈 칸 자체가 틀입니다 |

- **양식은 옵시디언 "제외된 파일"입니다** — `.obsidian/app.json` 의 `userIgnoreFilters` 에 `/!\(Template\)/`
  (경로 어디든 `!(Template)` 가 들어간 파일). 파일 탐색기에는 보이고 **보드·검색에는 안 뜹니다.**
  예전엔 `[조사 목적] 제목`(유형 자료) 같은 양식이 🪄 리소스 모음집에 진짜 자료 카드로 떠서, 2026-09-17 에
  양식인 줄 모르고 지워진 일이 있습니다 (되살렸습니다).
  - **`+ 새 항목` 은 그대로 됩니다.** 보드는 양식을 `vault.getFileByPath` 로 찾고 속성을
    `metadataCache.getFileCache` 로 읽는데, 둘 다 제외 여부를 안 봅니다 (obsidian.asar 확인).
  - 플러그인(PARA 구역 정리·커버)도 경로에 `!(Template)` 가 들어가면 건너뜁니다 (`isTemplatePath`).
  - **새 양식을 만들면 파일이나 폴더 이름을 `!(Template)` 로 시작하세요.** 그래야 저절로 빠집니다.
  - `[레퍼런스] 제목` 처럼 손으로 복사해 쓰는 양식도 같습니다. 탐색기에서 열어 복사하세요.
- 이미 물려받아 버린 노트는 `요약` 을 **비웠습니다.** 제목을 보고 지어내지 않습니다.
- 양식이 **비워 둔** 칸(`작성일`·`분류`)과 **본문**은 아래 **양식에서 만든 노트는 빈 칸을
  채웁니다** 가 맡습니다. 양식에서 지운 건 "새 노트가 스스로 채울 값" 이라는 뜻입니다.
- **양식 본문 맨 위의 `%%` 블록은 안 따라갑니다.** 거기 적는 것은 *양식 자신에게* 하는
  말("이건 틀이다")이라 새 노트가 물려받을 이유가 없습니다. **뒤에 붙인 `%%` 블록은
  그대로 갑니다** — 그건 *채우는 사람에게* 하는 말입니다 (인박스 양식이 그 모양).
  위치로만 가릅니다. 표시를 따로 두면 그 표시를 또 외워야 합니다.

### 양식에서 만든 노트는 빈 칸을 채웁니다 — `작성일`·`분류`

**속성 붙이기(`stamp`)는 프론트매터가 아예 없는 노트만 봅니다.** 보드의 `+` 로 만든
노트는 양식의 속성을 통째로 물려받아 `유형`·`구역`·`상태` 가 이미 차 있으니 그 그물에
안 걸립니다. 그래서 양식이 비워 둔 칸은 **영영 빈 채로** 남았습니다 — 보드에서 만든
할일마다 작성일이 없고, `🚚 PARA 구축` 폴더에서 만들었는데 분류가 비어 있었습니다.

자리와 시각은 **사실**이라 채웁니다. 그 둘뿐입니다.

| 칸 | 무엇으로 | 확실한가 |
| --- | --- | --- |
| `구역` | 태어난 폴더의 구역 | 확실 — 양식에 박힌 구역은 **양식을 만들던 때의 자리**입니다 |
| `작성일` | 오늘 | 확실 — 오늘 만든 노트입니다 |
| `분류` | 같은 폴더 이웃이 쓰는 값 → 없으면 상위 폴더 이름 중 그 구역이 쓰는 것 | 관찰. 없으면 **비워 둡니다** |
| 본문 | 그 폴더(없으면 위 폴더)의 양식 본문 | 확실 — 그 자리의 틀입니다 |

**`구역` 은 태어난 자리를 따릅니다 — 파일을 옮기지 않습니다.** 양식에 `구역: 3.resource` 가
박혀 있으면 새 노트도 그걸 달고 태어나는데, PARA 구역 정리는 원래 "구역 속성이 바뀌면 파일을
그리로 옮긴다" 입니다. 그래서 2026-09-17 에 책장이 새 책을 보관에 **제대로** 만들었는데도, 양식의
`구역: 3.resource` 를 보고 3.resource 최상단으로 **도로 옮겼습니다.** 이제 태어난 뒤 **첫 한 번**
(8초 안)은 옮기지 않고 `구역` 을 폴더에 맞춰 고쳐 씁니다. 그다음부터 사람이 `구역` 을 바꾸면
원래대로 파일이 따라갑니다. 막 태어난 노트는 **파일 객체**로 기억해서, 새 항목 창에서 제목을 바로
바꿔도 놓치지 않습니다 (예전엔 경로로 찾아서 작성일이 빈 채로 남았습니다).

**본문까지 채우는 이유**: 보드의 `+` 는 양식의 **속성만** 베끼고 본문은 빈 채로 둡니다
(obsidian.asar 확인 — `vault.create(경로, "")` 로 빈 파일을 만든 뒤 속성만 써넣습니다).
반쪽만 베끼는 것이라 나머지 반쪽을 채웁니다. 양식은 **그 폴더부터 구역 폴더까지**
거슬러 올라가며 찾고, **한 폴더에 하나뿐일 때만** 씁니다 — 둘이면 어느 쪽인지 사람만
압니다. 유형이 다른 양식도 안 씁니다. 기다리는 사이에 뭐라도 적었으면 물러납니다.

- `요약`·`주제`·`작성자` 는 **안 건드립니다.** 그건 내용을 읽어야 아는 것이라 자리가
  말해 주지 않습니다 (속성 붙이기와 같은 기준입니다).
- **만들 때 딱 한 번만** 봅니다. `vault create` 에만 붙고 `metadataCache changed` 에는
  안 붙습니다 — 사람이 나중에 분류를 지웠는데 다시 채워 넣으면 그건 고쳐 주는 게
  아니라 **되돌리는 것**입니다.
- 양식의 속성이 캐시에 들어오기를 기다렸다가(최대 3초) 봅니다. 빈 파일을 먼저 만들고
  속성은 그다음에 써넣기 때문입니다.
- **대문·대시보드·양식(`홈` `대시보드` `양식`)은 채우지 않습니다.** 휴지통이나 git 에서 **되살려도**
  옵시디언에는 "새로 생김" 으로 오기 때문에, 2026-09-17 에 실수로 지운 `3. resource` 를 되살리자
  빈 `작성일` 에 오늘이 박혔습니다. 이 노트들은 작성일·분류가 비어 있는 게 맞습니다.
- 한 장만 따로는 명령 팔레트 `이 노트 빈 칸 채우기 (작성일·분류)`.
  볼트 전체를 훑는 명령은 **일부러 없습니다** — 옛 노트의 작성일은 오늘이 아닙니다.
- 끄려면 설정 → Claude → PARA 구역 정리 → `양식에서 만든 노트의 빈 작성일·분류를 채운다`.

### 책장에서 추가한 책은 **책 폴더째로** 섭니다

책은 `(Book) 서적/<제목>/📖 <제목>.md` 와 `<제목>/이미지/` 로 삽니다 (한 권도 빠짐없이).
`커버` 가 책 폴더 기준 상대 경로라 폴더가 있어야 표지가 붙습니다. 그런데 보드의 `+ 새 항목` 은
**파일 하나만** 떨굽니다 — 폴더도, `이미지/` 도, `📖 ` 도 없이.

설정의 **폴더째 담는 보드**(기본 `📚 망고네 책장`)가 새 항목을 떨구는 폴더 **바로 아래**에 노트가
생기거나 이름이 바뀌면, **PARA 구역 정리** 가 제목으로 세웁니다.

```
(Book) 서적/달러구트 꿈 백화점.md
  → (Book) 서적/달러구트 꿈 백화점/📖 달러구트 꿈 백화점.md
    (Book) 서적/달러구트 꿈 백화점/이미지/
```

- 떨구는 폴더는 **보드의 `newItemFolder` 에서 읽습니다.** 경로를 코드에 안 적습니다 —
  도서관이 구역을 또 옮겨도 `docs/boards.md` 의 보드 경로 따라가기와 함께 따라갑니다.
- 이름이 `무제` 인 동안은 기다립니다. 새 항목 창에서 제목을 지으면 이름 바꾸기가 오고, 그때 세웁니다.
  `📖 ` 를 붙여서 지어도 됩니다.
- 본문이 비어 있으면 **그 보드의 양식 본문**을 깝니다 (`+` 는 속성만 베낍니다).
- 같은 이름의 책이 이미 있으면 안 옮기고 알립니다.
- **책장 한정입니다.** 품의서·자료 양식도 폴더 안에 살지만 그 노트들은 폴더째 살지 않습니다.
  다른 보드를 더하려면 설정 → Claude → PARA 구역 정리 → `폴더째 담는 보드` (한 줄에 보드 이름 하나).
- 한 장만 따로는 명령 팔레트 `이 책을 책 폴더로 세우기 (📖 제목 + 이미지/)`.

### 어느 폴더에서 만들든 속성이 붙습니다

**인박스만 자동이고 나머지는 손으로, 일 이유가 없습니다.** GTD 볼트라
`할머니한테 9시에 전화하기` 같은 노트가 프로젝트 폴더에서 바로 태어납니다.
속성이 없으면 그 노트는 **어느 보드에도 안 뜨고 어긋남 목록에도 안 잡힙니다** —
틀린 게 아니라 없는 것처럼 취급됩니다. 그게 제일 나쁩니다.

그래서 PARA 폴더 안에 프론트매터 없는 `.md` 가 생기거나 **옮겨 오면** 1.5초 뒤 속성 13종을 얹습니다.
(옮겨 온 것은 2026-09-17 부터 — 그 전엔 만들 때만 봐서, 탐색기로 인박스 칸에 끌어 옮긴 문서에 아무 일도 안 일어났습니다.)
채우는 것은 **자리가 말해주는 것뿐**입니다.

| 속성 | 어디서 | 확실한가 |
| --- | --- | --- |
| `구역` | 폴더 | 확실 |
| `작성일` | 오늘 | 확실 |
| `유형` | 그 구역에 쓸 수 있는 유형이 **하나뿐일 때만** | 확실 — `1.project` 는 `할일` 뿐입니다 |
| `상태` | 정해진 유형이 쓰는 첫 값 | 관례 — 할일 → `진행중`, 인박스 → `미처리` |
| `분류` | 같은 폴더 이웃 → 없으면 **상위 폴더 이름** 중 그 구역이 쓰는 값 | 관찰 (지어내지 않음) |
| 나머지 | 빈칸 | — |

**“유형은 사람이 고릅니다” 는 여전히 맞습니다 — 적용되는 자리가 다릅니다.**

| 언제 | 누가 정하나 | 왜 |
| --- | --- | --- |
| 인박스 → PARA 로 **이사**할 때 | 사람 (`📤 PARA로 보내기` 창) | 그때 정하는 것이 "이게 뭔지" 입니다. 아직 안 정해졌습니다 |
| PARA 폴더 **안에서 태어날** 때 | 자리 | 어디에 만들었는지가 이미 답입니다. `1.project` 안이면 `할일` 말고 될 것이 없습니다 |

- 고를 여지가 있는 구역(`2.area` 9종 · `3.resource` 7종 · `4.archive`)이면
  **유형을 비워 둡니다.** 대신 ① 이웃이 쓰는 유형을 **누를 수 있는 알림**으로 권하고
  ② 비어 있다는 사실이 어긋남 목록(상태바 `⚠ PARA`)에 잡힙니다. 안 보이는 일은 없습니다.
- **대문·틀 유형은 안 권합니다** — `홈` `대시보드` `양식` `바로가기`. 한 폴더에 하나뿐인
  것이라 이웃이 그거라고 새 노트도 그건 아닙니다. `(Library) 망고네 도서관` 은 이웃이
  `🏠 도서관 홈` **한 장뿐**이라 "같은 폴더는 바로가기 를 씁니다" 를 권했고, 그대로
  눌렀더니 캔버스 노트가 홈의 `🔖 바로가기` 카드에 끼어 버렸습니다 (2026-09-16).
  이 표(`NEVER_SUGGEST_KINDS`)는 **권하기에만** 씁니다 — `STRUCTURAL_KINDS` 는 구역
  검사 예외라 `route.py` 와 짝이 맞아야 하니 따로 둡니다.
- **파일 이름이나 본문으로는 여전히 추측하지 않습니다.** 자리는 사람이 고른 사실이고,
  이름은 그냥 글자입니다.
- 이미 프론트매터가 있는 노트는 **한 글자도 안 건드립니다.** 양식(`!(Template)…`)과
  제외 폴더(`!🏠 홈` · `!Template`), 볼트 최상단 파일도 건너뜁니다.
- 끄려면 설정 → Claude → PARA 구역 정리 → `만들면 속성을 바로 붙인다`.
  밀린 것은 명령 팔레트 `볼트 전체 — 속성 없는 노트 채우기`.

**PARA 폴더에서 손으로 쓴 노트의 `요약`·`주제` 는 자동으로 안 채웁니다.** 제목만 있는 상태에서
요약하면 **지어내는 것**이 됩니다. 본문을 적은 뒤 명령 팔레트의 `이 노트 요약·주제 채우기 (agy · 어느 폴더든)` 를
쓰세요. 인박스에 첨부나 **내용이 있는 문서(.md)를 던진 것**은 자동으로 채웁니다 (아래 인박스 절).

### `커버` 는 손으로 넣지 마세요 — 자동입니다

`plugins/gaeddong-claude` 의 **커버 자동 채우기** 가 이렇게 합니다.

| 상황 | 무엇을 하나 |
| --- | --- |
| `커버` 가 비었고 본문에 이미지가 있다 | **맨 위 이미지**를 `커버` 에 넣습니다 |
| `커버` 가 이미 차 있고 그 파일이 있다 | **안 건드립니다.** 사람이 고른 걸 덮어쓰지 않습니다 |
| `커버` 에 값은 있는데 **그 파일이 볼트에 없다** | 깨진 값이므로 본문 첫 이미지로 갈아 끼웁니다 |
| `커버` 가 외부 주소(`http`)나 색상(`#rrggbb`) | 그대로 둡니다 — 파일이 아니어도 베이스가 씁니다 |
| 본문에 이미지는 없고 **캔버스가 끼워져 있다** (`![[x.canvas]]` — 캔버스 노트) | 캔버스의 블록 지도를 그림으로 만들어 커버에 넣습니다 (아래) |
| 본문에 이미지도 캔버스도 없다 | 비워 둡니다 |

**캔버스 노트의 커버** (2026-10-02 Rin) — 캔버스 옆에 세운 노트는 본문에 캔버스 미리보기만 있어서 칸반 카드가 글자만 떴습니다.
옵시디언이 그려 주는 미리보기는 화면일 뿐 파일이 아니라서, 플러그인이 캔버스 파일(노드 자리 · 크기 · 색 · 연결선)을 읽어
**같은 모양의 SVG 를 직접 그립니다** (`canvasPreviewSvg`). 글자는 안 그립니다.

- 자리 · 이름: 캔버스가 있는 폴더의 `이미지/<캔버스 이름> (캔버스 미리보기).svg`
- **캔버스를 고치면 3초 뒤 그림도 새로 그립니다** (같은 파일을 덮어써서 커버 링크는 그대로).
- 본문에 사람이 이미지를 넣었으면 그 이미지가 먼저입니다. 이미 차 있는 커버는 안 건드립니다.
- 빈 캔버스는 그릴 게 없어 비워 둡니다. 끄려면 설정 → Claude → 커버 자동 채우기 → `캔버스 노트는 캔버스 미리보기를 커버로`.
- 캔버스 이름을 바꾸면 옛 그림 파일이 남습니다 (커버는 옛 그림을 계속 가리킴) — 커버를 비우면 새 이름으로 다시 만들어집니다.

**언제 도나** — 노트를 고칠 때(`metadataCache changed`) + **옵시디언을 켤 때 한 번**.
켤 때 훑는 게 없으면 이미 있던 노트는 손대기 전까지 영영 안 채워집니다. 처음에 그걸
빼놓아서 20건이 그대로 있었습니다.

- 그래서 노트를 만들 때 `커버` 는 **비워 두면 됩니다.** 본문 맨 위에 이미지를 넣으면
  1~2초 뒤에 알아서 채워집니다.
- 값 형태는 `커버: "[[파일명]]"`. 볼트에 같은 이름 파일이 31개 있어서, 이름만으로
  모호할 때는 플러그인이 `fileToLinktext` 로 **전체 경로**를 씁니다.
- **대문 5장만 예외입니다** — 커버가 링크가 아니라 경로 글자입니다. 그림을 갈아 끼울 때
  같은 이름으로 넣기만 하면 되게 하려고요. `docs/para.md` 의 `구역마다 대문 노트` 를 보세요.
- 베이스 카드는 커버가 링크면 `resolve()`, 문자열이면
  `getFirstLinkpathDest(값, 노트경로)` 로 풉니다 (obsidian.asar 확인). 그래서
  `이미지/표지.jpg` 같은 **노트 기준 상대 경로도 됩니다** — 책들이 그 형태입니다.
- **같은 이름 파일이 여럿이면 `./` 를 붙이세요.** `이미지/표지.jpg` 는 자기 폴더의 것을 **먼저** 찾지만,
  자기 폴더에 없으면 **다른 폴더의 `…/이미지/표지.jpg` 로 넘어갑니다** (asar 의 `_getLinkpathDest` —
  같은 이름이면 자기 폴더 쪽, 그다음 남의 것). 그래서 표지를 아직 안 넣은 새 책에 남의 책 표지가 떴습니다.
  `./이미지/표지.jpg` 는 **자기 폴더만** 봅니다. 책 양식 `📖 (책 제목)` 의 `커버`·본문 표지가 이 모양입니다.
- 특정 노트만 빼려면 그 노트에 `커버자동: 끔` 을 넣습니다.
- 밀린 것은 명령 팔레트 → **볼트 전체 — 빈 커버 채우기**.

### `작성자` 는 반드시 채웁니다 — 에이전트에게

**노트를 만들거나 본문을 새로 써 넣었다면 `작성자` 에 자기 이름을 넣으세요.**
민규 서가 나중에 "이건 누가 쓴 글이지" 를 알 수 있어야 합니다.

| 값 | 누구 |
| --- | --- |
| `"[[민규 서]]"` | 민규 서가 직접 씀 |
| `"[[Rin]]"` | Rin이 직접 씀 |
| `"[[Claude]]"` | Claude가 씀 |
| `"[[Gemini]]"` | Gemini · antigravity가 씀 |
| `"[[ChatGPT]]"` | ChatGPT가 씀 |
| `"[[bug]]"` | 사람이 아닙니다 — **버그 표시**. 아래를 보세요 |

- **위키링크로, 따옴표를 씌워서** 넣습니다. `- [[Claude]]` 처럼 따옴표를 빼면
  YAML이 `[[...]]` 를 중첩 리스트로 읽어 값이 깨집니다. 반드시 `- "[[Claude]]"`.
- `담당`(누가 책임지나) 과 `작성자`(누가 썼나) 는 다른 것입니다. 섞지 마세요.
- **예외가 하나 있습니다 — `bug`.** `🐛 버그 리포트` 의 노트는 `작성자` 에 `"[[bug]]"`
  가 먼저 붙습니다. 사람이 아니라 **종류 표시**입니다. 칸반 카드에서 제일 눈에 띄는
  칩이 작성자 칩이라, "이건 버그다" 를 거기에 답니다 (2026-09-16 요청).
  사람이 쓴 것을 밝히려면 `bug` 를 두고 **뒤에 이름을 더합니다** (`bug` · `Rin`) —
  그러면 둘 다 칩으로 뜹니다. 이 예외는 그 폴더에서만 씁니다.
- 모르면 **비워 둡니다.** 추측해서 사람 이름을 넣지 마세요.
  단 파일 이름 앞에 `(rin)` `(gen)` `(seo)` 가 붙어 있으면 그건 추측이 아닙니다 — 아래를 보세요.

### 파일 이름 앞머리가 작성자입니다 — 자동으로 채웁니다

이 볼트는 파일 이름 앞에 누가 썼는지를 붙여 왔습니다. 사람이 **직접 붙인 표시**라서
읽어도 되는 사실입니다. (파일 이름으로 *내용*을 추측하는 것과는 다릅니다 — 그건 안 합니다)

| 앞머리 | 작성자 |
| --- | --- |
| `(rin)` | `"[[Rin]]"` |
| `(gen)` `(GEN)` | `"[[Gemini]]"` |
| `(seo)` | `"[[민규 서]]"` |
| `(SEO&GEN)` | 둘 다 |

- 대소문자는 맞춰 봅니다. `&` `+` `,` `/` 로 이으면 여럿으로 읽습니다.
- **표에 없는 앞머리는 건너뜁니다.** `(draw)` `(Draw)` `(idea)` `(meet)` 는 사람이 아니라
  *종류* 표시입니다. 표는 설정 → Claude → PARA 구역 정리 에서 고칩니다.
- **`작성자` 가 비어 있을 때만** 채웁니다. 적혀 있으면 한 글자도 안 건드립니다.
- 속성을 붙일 때 같이 돕니다. 밀린 것은 명령 팔레트
  `볼트 전체 — 파일 이름 앞머리로 작성자 채우기` · `이 노트 작성자 채우기 (파일 이름 앞머리)`.

### 이미 있는 노트를 고칠 때

**한 번 들어간 이름은 지우지 않습니다.** 리스트 맨 앞이 최초 작성자입니다.
`작성자` 를 두는 이유가 "이 글에 AI가 쓴 문장이 섞여 있다" 를 알리는 것이라,
AI 문장이 남아 있는 동안은 그 이름이 남아 있어야 합니다.

| 상황 | 어떻게 |
| --- | --- |
| 남의 글을 **다듬음** (오타·문장 정리) | 원래 이름 그대로. 자기 이름은 넣어도 되고 안 넣어도 됩니다 |
| 남의 초안에 **살을 붙임** | 원래 이름 뒤에 자기 이름을 **추가** |
| **통째로 다시 씀** | 원래 이름을 지우고 자기 이름만 — 남의 문장이 안 남았을 때만 |
| 속성·링크만 손댐 (본문 그대로) | **건드리지 않습니다** |

에이전트는 본문을 새로 써 넣었으면 **반드시** 자기 이름을 넣습니다.
사람이 자기 이름을 추가하는 것은 선택입니다.

**속성만 채운 것은 쓴 게 아닙니다.** 인박스 감싸기가 `요약`·`주제` 를 채울 때
`작성자` 를 안 건드리는 이유입니다 — 한 줄 요약을 채웠다고 그 노트를 쓴 것이
아닙니다. 본문을 써 넣었을 때만 이름을 답니다.
