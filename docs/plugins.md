### `plugins/claude` — 직접 만든 기능 여섯이 한 플러그인

2026-09-15 에 넷을 하나로 묶었습니다. 예전에는 `para-mover` · `inbox-auto` ·
`cover-auto` · `canvas-open-right` 로 플러그인 목록에 흩어져 있었습니다.

| 기능 (모듈 id) | 무엇 |
| --- | --- |
| **PARA 구역 정리** (`para`) | `구역` ↔ 폴더 양방향 동기화 + `📤 PARA로 보내기` 창. 상태로는 안 옮김. 프로젝트별 보드와 캔버스 노트도 여기서 세웁니다 |
| **인박스 자동 감싸기** (`inbox`) | 던진 파일을 노트로 감쌈 + `✏️ 새 인박스` 로 손으로 쓰기 (서버 없음) |
| **커버 자동 채우기** (`cover`) | 본문 첫 이미지를 `커버` 에 넣음. 빈 커버만 채움 |
| **캔버스 우측에서 열기** (`canvas`) | 캔버스 카드를 우측 화면·오른쪽 사이드바에서 |
| **상태 칩** (`chip`) | 표·카드의 `상태` 칸에 값을 적어 둬서 CSS가 색 칩으로 그림 |
| **홈 버튼** (`home`) | 탭 제목줄 오른쪽에 🏠 — 누르면 그 탭이 홈으로 (Ctrl+클릭은 새 탭). 홈은 **이름**(`🏠 홈`)으로 찾습니다 |

**왜 묶었나** — 넷이 따로 노는 도구가 아니라 한 살림이라 같이 굴러야 합니다.

- **버전이 하나여야 합니다.** 넷이 같은 프론트매터를 같은 방식으로 고칩니다.
  실제로 `setProps` 가 둘에 복사돼 있었고, 한쪽에만 있던 기능(`작성자` 이어붙이기)이
  다른 쪽엔 없었습니다. 이제 **쓰기 함수는 `setProps` 하나뿐**입니다.
- 같은 표를 두 군데 안 적게 됩니다 — 이미지 확장자 목록도 둘이 따로 갖고 있었습니다.
- 설정이 한 화면에 모입니다. 무엇이 자동으로 도는 볼트인지 한눈에 보입니다.

**구조** — 기능 하나가 `Mod` 하나입니다.

| | |
| --- | --- |
| 명령 id | `claude:<모듈id>-<원래id>` (예: `claude:para-send-active`). 모듈 id 를 앞에 붙여 안 부딪히게 합니다 |
| 설정 | `data.json` 한 파일에 `{ modules, para, inbox, cover, canvas }` 로 칸을 나눠 담습니다 |
| 껐다 켜기 | 설정 화면에서 기능별로. **다음에 옵시디언을 켤 때부터** 반영됩니다 |
| 밖에서 부르기 | 핀보드가 `app.plugins.plugins["claude"]` 의 `zones` · `openSendModal()` · `openNewNoteModal()` 를 씁니다. 모듈이 꺼져 있어도 본체가 받아서 알림만 냅니다 |

- **모듈을 더할 때**: `Mod` 를 상속하고 `MODULES` 배열에 넣습니다. `DEFAULTS` 에 칸을
  만들고, 설정칸이 필요하면 `displaySettings(c)` 를 붙이면 그 화면에 저절로 끼어듭니다.
- **`_schema.json`** 은 AI 요약이 `agy` 에 넘기는 출력 형식입니다. 플러그인 폴더에서
  그때그때 새로 씁니다 (`this.plugin.manifest.dir` 기준이라 폴더 이름이 바뀌어도 따라갑니다).
- 옛 넷은 지우지 않고 `.obsidian/_옛 플러그인 (2026-09-15 claude 로 합침)/` 에 그대로
  뒀습니다. 새 것이 멀쩡히 도는 걸 확인했으면 사람이 지우면 됩니다.
  **되살리지 마세요** — 같이 켜면 명령과 이벤트가 두 벌씩 돕니다.

**CSS를 고칠 때**: 표시가 이상하면 옵시디언 기본값을 의심하기 전에 **위 스니펫을 먼저 걷어내고**
증상이 남는지 확인하세요. 그리고 한 곳의 문제에 전역 선택자를 쓰지 마세요.

## `상태` 는 표에서도 칩입니다 — 그렇다고 목록으로 바꾸지 마세요

`담당`·`작성자`·`분류` 는 칩으로 뜨는데 `상태` 만 맨 글자였습니다. 이유가 있습니다.

| 속성 | 타입 | 옵시디언이 그리는 것 |
| --- | --- | --- |
| `담당` `작성자` | multitext + 위키링크 | `<a class="internal-link" data-href="민규 서">` → 이름별로 CSS가 잡힙니다 |
| `분류` `주제` | multitext | 알약 + 고를 수 있는 목록 |
| `상태` | text | 그냥 글자. **값이 DOM 어디에도 안 남습니다** |

베이스 표는 칸에 `data-property="note.상태"` 만 답니다 (obsidian.asar 의
`i.el.dataset.property=n` 확인). 그래서 `chip` 기능이 그 칸에
`data-chip-value="진행중"` 을 적어 주고, 색은 `plugins/claude/styles.css` 가 고릅니다.

**칩은 안쪽 칸에 씌웁니다. 바깥 칸에 칠하면 칸 전체가 칠해집니다.**

```
div.bases-td[data-property="note.상태"]           ← chip 이 data-chip-value 를 적는 곳
  div.bases-table-cell                            ← 옵시디언: display:flex; width:100%
    div.metadata-input-longtext[contenteditable]  ← **글자가 여기. 여기에 .claude-chip**
```

담당·작성자도 알약 껍데기(`.multi-select-pill`)가 아니라 그 안쪽
`.multi-select-pill-content.internal-link` 에 색이 붙습니다 (`author-chips.css`).
**같은 자리입니다.** 처음에 `.bases-table-cell` 에 칠했다가 "색만 바뀐 칸" 이 나왔습니다 —
그 칸은 옵시디언이 `width:100%` 로 못박아 둡니다 (obsidian.asar 확인). 다시 그러지 마세요.

**✕ 는 일부러 안 답니다.** 그건 multitext 알약의 *값 지우기* 단추입니다. 상태를 지우면
그 카드가 칸반에서 사라지므로 표에서 한 번 눌러 지워지면 안 됩니다.

| 값 | 색 |
| --- | --- |
| `to do` | 회색 |
| `진행중` | 파랑 |
| `확인 필요` | 노랑 |
| `완료` | 초록 |
| `퍼즈` | 보라 |
| `히스토리` | 흐린 회색 |
| `미처리` · `검토 중` · `picked` | 주황 · 청록 · 분홍 |

**칩을 누르면 드롭다운이 뜹니다.** 그 노트의 `유형` 을 보고 `KIND_STATES` 의 값만 냅니다 —
할일이면 여섯, 책이면 다섯, 상태를 안 쓰는 유형이면 아예 안 엽니다. 지금 값에는 ✔ 가 붙습니다.

| | |
| --- | --- |
| 왜 옵시디언 제안기로 안 하나 | 그건 **볼트 전체에서 그 속성에 쓰인 값**을 보여주고 이미 적힌 글자로 거릅니다. `진행중` 칸을 누르면 `진행중` 하나만 뜹니다 — 고를 것이 없습니다 |
| 어떻게 가로채나 | `[data-property="note.상태"]` 의 클릭을 **capture 단계**에서 받아 `preventDefault()`. 베이스의 칸 편집기는 `defaultPrevented` 를 보고 물러납니다 (obsidian.asar 확인) |
| 어느 노트인지 어떻게 아나 | 같은 줄의 파일 링크(`[data-property^="file"] a.internal-link`)로 찾습니다. **못 찾으면 아무것도 안 막습니다** — 옵시디언 기본 편집이 그대로 뜹니다 |
| 쓰기 | `setProps` 하나로만 씁니다. 다른 속성과 주석줄은 안 건드립니다 |

- **칩이 안 보이면 플러그인이 옛 코드입니다.** 옵시디언은 `.base`·스니펫은 바로 다시 읽지만
  **플러그인은 다시 켜야 바뀝니다** (설정 → 커뮤니티 플러그인에서 Claude 를 껐다 켜도 됩니다).
  명령 팔레트 `상태 칩 — 지금 칠한 칸 세기` 가 0을 내면 그것입니다.
- 빨간 맞춤법 물결선은 CSS로 못 지웁니다 — 칠할 때 그 칸의 `spellcheck` 를 끕니다.
- **색 규칙에는 `!important` 를 답니다.** 모양 규칙과 색 규칙의 명시도가 같아서, 모양 쪽에
  `:not()` 하나만 더 붙어도 회색이 색을 덮습니다. 실제로 그렇게 만들어서 회색 칩만 떴습니다.
  `author-chips.css` 가 `!important` 를 쓰는 이유도 같습니다.
- 값이 비면 `data-chip-value` 를 **지웁니다.** 빈 알약이 줄줄이 뜨면 안 되니까요.
- **`.obsidian/types.json` 에서 `상태` 를 `multitext` 로 바꾸지 마세요.** 알약과
  드롭다운은 공짜로 얻지만 값이 목록이 되어 `note["상태"] == "완료"` 같은 필터가 전부
  조용히 거짓이 됩니다. 보드 24개가 그걸로 거르고, 칸반 그룹도 같이 깨집니다.
- 색을 더하려면 `styles.css` 에 `[data-chip-value="값"]` 블록을 복사하세요.
  다른 속성도 칩으로 쓰고 싶으면 설정 → Claude → 상태 칩 → `칩으로 그릴 속성`.

### 날짜도 칩입니다 — 남은 날로 색이 바뀝니다

`마감`·`일정` 은 옅은 상자 하나라 카드에서 묻힙니다. `to do` 에 올라온 뒤가 더 중요한데
말이죠. 그래서 같은 기능이 남은 날을 세어 칸에 `data-when` 을 적습니다.

| `data-when` | 언제 | 어떻게 보이나 |
| --- | --- | --- |
| `지남` | 어제까지 | 빨강 + `❗` |
| `오늘` | 오늘 | 주황 |
| `곧` | 사흘 안 | 노랑 |
| `나중` | 그 뒤 | 옅은 회색 |

- 아이콘은 속성이 정합니다 — `마감` ⏰ · `일정` 📅. 칸반 카드에서는 라벨 글자(`마감`)를
  지우고 아이콘만 둡니다. 날짜가 없으면 칩도 안 그립니다.
- 날짜 글자는 칸에 따라 **글자이기도 하고 `<input>` 이기도 해서** 둘 다 읽습니다
  (표는 글자, 칸반 카드는 입력상자입니다).
- 어떤 속성을 이렇게 볼지는 `data.json` 의 `chip.dateProps` 입니다 (기본 `마감`·`일정`).
