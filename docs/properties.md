### `일정` — 해야 할 날. `마감` 과 다릅니다

**할일 고유 속성**입니다 (책의 `저자`·`평점` 과 같은 자리 — `# ── 이외 속성 ──` 아래).
책이나 기업 노트에 "해야 할 날" 은 뜻이 없어서 13종에 넣지 않았습니다.

| 속성 | 뜻 | 달력에서 |
| --- | --- | --- |
| `일정` | **해야 할 날.** 그날 시간을 잡아 두는 것 (`9시에 전화`) | `📅 하는 날` |
| `마감` | **끝내야 하는 날.** 그날까지면 되는 것 | `⏰ 마감` |

예전 칸반의 `일정 있음` · `기한만` 이 이 둘로 갈라졌습니다. `위임함` 은 `담당` 이
이미 그 뜻이라 따로 만들지 않았습니다 — 기다리는 상태는 칸의 `확인 필요` 입니다.

| 예전 칸 | 지금 |
| --- | --- |
| `위임함` | `담당` 에 그 사람 + 상태 `확인 필요` |
| `일정 있음` | `일정` 에 날짜 |
| `기한만` | `마감` 에 날짜 (`일정` 은 비움) |

#### `일정` 은 **그날 꺼내 보라는 표시**입니다 — to do 가 더미가 되지 않게

GTD의 일정표(캘린더)와 인큐베이팅을 이 속성 하나로 합쳤습니다. 날짜를 적어 두면
그날이 오기 전까지 `to do` 칸에서 **빠집니다.** 그날이 되면 저절로 올라옵니다.

| 이런 일 | 이렇게 적는다 | to do 에 언제 뜨나 |
| --- | --- | --- |
| 지금 당장 할 것 | 둘 다 비움 | 늘 |
| 목요일 3시에 전화 | `일정: 그 목요일` | 그날 |
| 10월 안에 끝낼 것 | `마감: 10-31` | **D-14** 부터 (그 전엔 `🌱 묵히는 것`) |
| 10월 1일에 다시 보자 | `일정: 10-01` + `마감: 10-31` | 10-01 |

`📋 프로젝트 보드.base` 의 뷰 셋이 이 규칙을 나눠 맡습니다.

| 뷰 | 무엇이 |
| --- | --- |
| **`🔥 지금 할 것`** | 홈이 띄우는 칸반. `to do` 는 *오늘 손댈 수 있는 것만* |
| `📅 캘박 — 그날 꺼낼 것` | `일정` 이 **앞으로**인 것 |
| `🌱 묵히는 것 — 기한이 아직 먼 것` | `일정` 없이 `마감` 만 먼 것 |

- **거르는 것은 `to do` 칸뿐입니다.** `진행중`·`확인 필요` 는 날짜와 무관하게 늘 보입니다 —
  이미 손댄 일이 날짜 때문에 사라지면 안 됩니다. 필터 첫 줄(`note["상태"] != "to do"`)이 그 뜻입니다.
- 묵히는 기간 **D-14** 는 뷰 두 개의 `today() + "14d"` 를 같이 고치면 바뀝니다
  (`"2w"` `"1M"` 같은 것도 됩니다 — obsidian.asar 의 duration 파서 확인).
- 날짜 계산은 베이스가 직접 합니다 (`날짜 + 기간` 지원, obsidian.asar 확인).
  플러그인이 밤마다 도는 것이 아니라 **볼 때마다 새로 거릅니다.**
- `🗂️ 전체` 는 그대로 **다 보여줍니다.** 뭐가 숨었는지 의심되면 거기서 보세요.
- 홈의 **`⏰ 마감이 가까운 것`**(`🔥 오늘.base`)도 같은 **D-14** 입니다. **안 끝난 일**
  (`to do`·`진행중`·`확인 필요`) 중 마감이 지났거나 14일 안인 것만 뜹니다 — **평소엔 비어 있는 게 정상**입니다.
  예전엔 `완료` 만 뺐고 기간도 없어서, 마감 지난 `히스토리` 가 계속 남고 석 달 뒤 일도 떴습니다
  (2026-09-17). `퍼즈` 는 일부러 멈춘 것이라 안 띄웁니다 — **마감이 지난 채 퍼즈에 두면 아무 데도
  안 보이니** 마감을 지우거나 미루세요. 칸을 더하면 이 필터의 `or` 도 같이 고치세요.

- `.obsidian/types.json` 에 `date` 로 못박혀 있습니다.
- **모든 `유형: 할일` 노트에 칸이 열려 있어야 합니다.** `📅 달력.base` 의 formula 가
  `note["일정"].isEmpty()` 를 부르기 때문입니다. 속성 채우기가 새 할일에 자동으로
  넣고, 기존 34개는 2026-09-15 에 한 번에 열었습니다.
- **다른 유형이 할일로 바뀔 때도 칸을 엽니다** — `📤 PARA로 보내기` · `이 노트 속성 맞추기` · 유형 권하는
  알림 버튼 (`withKindKeys`). 예전엔 속성 13종을 통째로 붙일 때만 열어서, **인박스 노트를 보내 만든 할일에는
  `일정` 이 없었습니다** — 인박스 양식은 `메모` 라 그 칸이 없습니다 (2026-09-17, 패치노트 두 장).
  이미 있는 칸은 값째로 둡니다. 인박스 양식에 `일정` 을 더하지는 마세요 — 할일이 아닌 노트에는 안 만드는 칸입니다.
- 유형이 `할일` 이 아니면 이 속성을 만들지 마세요.

## 유형별 `상태` 값

- **할일** : `to do` `진행중` `확인 필요` `완료` `퍼즈` `히스토리`
  — **진행 상황 순서**입니다. 칸반 칸이 이 순서 그대로입니다.

  | 칸 | 언제 |
  | --- | --- |
  | `to do` | 아직 손 안 댐. 새로 만든 할일의 기본값 |
  | `진행중` | 지금 붙잡고 있는 것 |
  | `확인 필요` | 남의 답·검토를 기다리는 것 (예전 `위임함`) |
  | `완료` | 끝났고 **아직 눈에 두고 싶은 것** |
  | `퍼즈` | 멈춰 둔 것. 접은 게 아니라 나중에 다시 |
  | `히스토리` | 끝났고 **치워둔 것** |

  예전의 `위임함` · `일정 있음` · `기한만` 은 **칸에서 뺐습니다.** 그 셋은 진행 상황이
  아니라 *누가*(`담당`) 와 *언제*(`마감`) 였습니다. 칸은 진행 상황만 나타냅니다.

  **`결정 사항` — 칸이 없는 할일 상태** (2026-09-30 Rin). 회의에서 정한 것(목표 · 기한 · 역할 · 범위)을
  프로젝트 폴더에 두되 **칸반에는 안 띄울 때** 씁니다. 진행할 일이 아니라서입니다. 예: `🐕망고독 R&D 프로젝트 관리/09.30/decisions/`.
  - **값만 바꿔서는 안 숨습니다.** 칸반 플러그인(`kanban-bases-view`)은 목록에 없는 상태를 **맨 끝 새 칸으로 붙이고 보드에 저장**합니다.
    그래서 칸반 보드 11개 맨 위 필터에 `note["상태"] != "결정 사항"` 을 넣었고, 🧠 주간 리뷰의 `멈춰 있는 일` 에도 넣었습니다.
    **보드를 새로 만들면 이 줄이 있는지 보세요** — 플러그인이 만드는 프로젝트 보드는 저절로 넣습니다 (`KANBAN_HIDDEN_STATES`).
  - 플러그인 `KIND_STATES` 에는 들어 있어서 PARA 검사가 "안 맞는 상태" 로 잡지 않고, 상태 고르는 메뉴에도 나옵니다. 칸 목록(`KANBAN_STATES`)에서만 빠집니다.
  - `🔥 오늘` 은 원래 `to do` · `진행중` · `확인 필요` 만 봐서 안 뜹니다. `📅 달력` 에는 `마감` 이 있으면 뜹니다 (결정의 기한이라 일부러 둠).
- **자료 · 레퍼런스 · 아이디어** : `검토 중` `picked` `언젠가·아마도` `히스토리`
  — `히스토리` 는 **다 봤고 치워둔 자료**입니다 (2026-09-28 Rin, 할일의 `히스토리` 와 같은 뜻). 파일은 리소스에 그대로 있고,
  사람이 히스토리 칸을 훑으며 `4.archive` 로 정리해 보낼지 정합니다 — **상태로는 안 옮깁니다.**
  `🪄 리소스 모음집` 의 `🚦 상태 칸반` 은 **이 네 값만** 보여 줍니다 (2026-09-28 Rin). 빈 값은 `🕳️ 상태를 안 정한 것`,
  그 밖의 값(`완료` · `진행 중` · `준비됨` …)은 `⚠️ 상태 안 맞음` 탭에 모입니다 — 칸반에서 사라져도 여기서 셀 수 있습니다.
  그래서 자료 양식(`[조사 목적] 제목.md`)의 `상태` 기본값은 `검토 중` 입니다. 비워 두면 새 자료가 칸반에서 안 보입니다.
  **플러그인(PARA 구역 정리)도 리소스 구역의 상태는 검사하지 않습니다** — 시작할 때 뜨던 "구역과 안 맞는 노트" 목록과
  상태바 `⚠ PARA` 숫자에서 빠집니다. 유형 · 분류는 여전히 검사합니다 (`plugins/claude/main.js` 의 `mismatches`).
- **책** : `구매예정` `구매완료` `독서중` `감상평 작성` `책장보관`
- **휴가** : `승인 완료` (비어 있으면 대기)
- **인박스** : `미처리`
- **상태를 안 쓰는 유형** : `메모` `작품` `기업` `원칙` `양식` `홈` `바로가기` `대시보드`
  — 볼트의 해당 노트 전부(메모 40 · 작품 17 · 기업 15 · 원칙 6 …)가 빈값입니다.
  **유형을 이 중 하나로 바꿨으면 `상태` 를 비우세요.**

#### `상태` 가 비면 칸반에서 사라집니다 — 어긋남으로 잡습니다

빈 상태는 칸반의 어느 칸에도 안 들어가고, `상태` 로 거르는 표에서도 통째로 빠집니다.
쓰다 보면 지웁니다 (속성창에서 지우기가 한 글자입니다). 그래서 **안 보이는 채로 두지 않습니다.**

| 어디서 보나 | 무엇 |
| --- | --- |
| `📋 프로젝트 보드.base` 의 **`🕳️ 상태가 빈 것`** | `note["상태"].isEmpty()` 하나로 거른 표. 그 자리에서 상태를 눌러 채웁니다 |
| 홈의 `🎯 프로젝트 칸반` 칸 안 | 칸반 바로 아래에 같은 표를 붙여 뒀습니다 |
| 상태바 `⚠ PARA` | **PARA 구역 정리** 의 어긋남 목록에 `상태: 비어 있습니다` 로 잡힙니다 |

- 어긋남으로 잡는 것은 **`유형: 할일` 뿐입니다.** 칸반에서 카드가 사라지는 일은 할일에서만
  생깁니다.
- **책·자료의 빈 상태는 잡지 않습니다.** 도서관 책 여덟 권이 원래 비어 있고, 그건 쫓아다닐
  일이 아닙니다 (`요약` 이 빈 26건과 같습니다 — **알려진 빈틈**이지 버그가 아닙니다).
  한 번 그렇게 만들었다가 어긋남 목록이 책으로 뒤덮였습니다. 다시 넓히지 마세요.
- `4.archive` 도 뺍니다. 치워 둔 것에 진행 상태를 물을 이유가 없습니다 (`분류` 와 같은 이유).

### 상태는 속성이 정본입니다 — 폴더와 무관합니다

**상태 폴더를 없앴습니다.** 예전에는 `1. 진행중` `2. 위임함` … `9. 히스토리` 같은 폴더가
있었고 `route.py --tidy` 로 속성과 맞췄습니다. 같은 정보가 두 곳에 있으니 계속 어긋났습니다.

| | |
| --- | --- |
| **상태** | 프론트매터 속성 하나뿐. 칸반에서 카드를 끌면 바로 바뀝니다 |
| **폴더** | 프로젝트·주제 묶음만 나타냅니다. 상태와 아무 상관 없습니다 |
| **보드** | `유형`·`상태` 속성으로만 거릅니다. 파일이 어디 있든 똑같이 뜹니다 |

- `--tidy` 는 **폐지**했습니다. "퇴근 전에 정리해줘" 도 이제 필요 없습니다.
- 파일을 옮겨도 보드는 안 바뀝니다. **바꾸려면 속성을 고치세요.**
- 단 `구역`(PARA)은 다릅니다 — 속성을 고치면 파일이 따라 옮겨집니다. `docs/para.md` 를 보세요.

## 줄끝은 **LF** 입니다 — CRLF 면 속성이 조용히 안 써집니다

프론트매터를 찾는 코드가 `---\n` 으로 시작하는지를 봅니다. 줄끝이 `\r\n` 이면
그 검사가 실패하고 **아무 일도 안 일어납니다** — 오류도 안 나고 값만 안 들어갑니다.
이 볼트에서 제일 나쁜 실패입니다 (안 보이는 채로 틀림).

| 어디서 CRLF 가 들어오나 | 막는 법 |
| --- | --- |
| `git config core.autocrlf` 가 `true` — **다시 클론하면 전부 CRLF 로 내려옵니다** | `.gitattributes` 의 `* text=auto eol=lf` |
| 파이썬 `write_text` — 윈도우에서 `\n` 을 `\r\n` 으로 바꿉니다 | `newline=""` 를 꼭 넘기세요 |
| 다른 편집기에서 저장 | — |

2026-09-16 에 파이썬으로 노트 아홉 장을 고치면서 CRLF 로 만들어 버렸고, 그날부터
그 아홉 장에는 `setProps` 가 한 글자도 못 썼습니다. LF 로 되돌리고, **코드도
CRLF 를 견디게** 고쳤습니다 (`eolOf` · `toLf` · `withEol` — 다루기 전에 LF 로 펴고
돌려줄 때 원래 줄끝으로). 파일과 코드 양쪽을 다 막아 둡니다.

- 노트를 스크립트로 고칠 때는 **반드시** `newline=""`. 안 그러면 조용히 망가집니다.
- 확인은 `node -e '…startsWith("---\n")…'` 한 줄이면 됩니다.

## YAML 공통 규칙 — 이거 틀리면 값이 통째로 깨집니다

- **위키링크는 반드시 따옴표로.** `- [[Claude]]` 는 YAML이 중첩 리스트로 읽습니다.
  항상 `- "[[Claude]]"` 로 씁니다. `담당` `작성자` `커버` `상위` 전부 해당합니다.
- **여러 값 속성은 블록 리스트로.** `분류` `주제` `담당` `작성자` 는 `.obsidian/types.json` 에
  `multitext` 로 못박혀 있습니다. 스칼라(`분류: 웹소설`)로 쓰면 옵시디언이 되돌립니다.
- 요약이 `'` `"` `[` `|` `>` 로 시작하면 큰따옴표로 감쌉니다.
- 값을 고친 뒤에는 `python .obsidian/scripts/route.py --repair` 로 확인합니다. 0이어야 정상입니다.
