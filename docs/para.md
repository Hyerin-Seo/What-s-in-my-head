## 구역은 폴더가 정본입니다 — 자동으로 맞춰집니다

`상태` 와 달리 `구역`(PARA)은 **폴더가 곧 서랍**입니다. 그래서 속성과 폴더를 자동으로 맞춥니다.
직접 만든 `plugins/claude` 의 **PARA 구역 정리** 가 양쪽 방향을 다 봅니다.

| 무엇을 했나 | 무슨 일이 일어나나 |
| --- | --- |
| `구역` 속성을 고쳤다 | 파일이 그 구역 폴더로 **옮겨집니다** (링크는 옵시디언이 고쳐 씀) |
| 파일 탐색기에서 다른 구역으로 끌었다 | `구역` 속성이 **고쳐 써집니다** |
| `분류` 를 고쳤다 (같은 구역) | 그 분류 폴더로 **옮겨집니다** — 이미 그 폴더 안(하위 폴더 포함)이면 그대로 |
| 파일 탐색기에서 같은 구역의 다른 폴더로 끌었다 | `분류` 가 새 폴더 이름으로 **고쳐 써집니다** |
| 같은 분류 폴더 안에서 하위 폴더만 옮겼다 | 아무 일도 없습니다 |
| `상태` 를 고쳤다 | 아무 일도 없습니다 — **상태로는 절대 안 옮깁니다** |

- 방향은 **이벤트로** 가릅니다. 속성이 바뀌면(`metadataCache changed`) 속성을 믿고,
  위치가 바뀌면(`vault rename`) 폴더를 믿습니다. 그래서 두 방향이 서로 싸우지 않습니다.
- 도착 자리는 **구역 최상단**입니다. 단 `분류` 와 **이름이 똑같은 하위 폴더**가 그 구역에
  있으면 거기로 들어갑니다 (예: 분류 `이런게 필요해!` → `3.📦(Resource) 자료/이런게 필요해!`).
  같은 이름이 여럿이면 **제일 얕은 것**이 그 폴더입니다. 깊이까지 같은 것이 둘이면
  그건 진짜로 헷갈리는 것이라 구역 최상단으로 물러납니다.

  예전에는 "**하나만** 있을 때" 였습니다. 그런데 칸반 빠른 추가가 `…/구역/분류` 꼴의
  빈 폴더를 하나 흘리고 가면 후보가 둘이 되고, 그때부터 그 분류의 노트가 전부 조용히
  구역 최상단에 떨어졌습니다 — **틀렸다는 말 한마디 없이.** (2026-09-16,
  `(seo)이용자 사용 시나리오` 가 `🧪 문서 어시스턴트 프로토타입 구현` 대신 최상단으로 갔습니다)
- **같은 구역 안에서도 `분류` 가 들어갈 폴더를 정합니다** (2026-09-17 부터 · 프로젝트·관리 영역·자료).
  예전엔 분류로 폴더를 고르는 게 **구역이 바뀔 때뿐**이라, `🚚 PARA 구축` 에서 만든 노트의 분류를
  `✏️문서 어시스턴트 에디터 목업` 으로 바꿔도 제자리였습니다. 그러면 보드(폴더로 거름)와 분류가 서로 다른 말을 합니다.
  `구역` 과 똑같이 **두 방향**을 맞춥니다 — 한쪽만 있으면 끌어 놓은 노트가 다음 속성 변경 때 옛 분류 폴더로
  도로 끌려갑니다.

  | 무엇을 했나 | 무슨 일이 일어나나 |
  | --- | --- |
  | 분류를 고침 · 분류 폴더 **밖**에 있음 | 그 분류 폴더 맨 위로 옮깁니다 (`planClassMove`) |
  | 탐색기로 다른 폴더에 끌어 놓음 | 분류를 구역 바로 아래 새 폴더 이름으로 (`writeBackClass`). 구역 맨 위로 끌면 폴더를 가리키던 분류만 뺍니다 |
  | 분류 폴더 **안**의 하위 폴더에 있음 | 안 옮깁니다 — 프로젝트 안의 폴더 구조는 사람 몫입니다 |
  | 분류와 같은 폴더가 없음 | 안 옮깁니다 |

  - **인박스와 보관은 뺍니다.** 인박스는 아직 판단 전이고, 보관의 분류는 어디서 왔는지의 기록입니다.
  - 켤 때 `볼트 전체 — 구역 속성대로 옮기기` 가 같이 돕니다. 처음 켰을 때 옮겨진 것은 개발 요청 2장뿐입니다
    (`(개발 요청) 버그리포트 - 자동 작성기` → `🐛 버그 리포트`, `[개발 요청] Inbox - 일괄 PARA 보내기 기능` → `✏️문서 …`).
  - 끄려면 설정 → Claude → PARA 구역 정리 → `같은 구역 안에서도 분류가 폴더를 정한다`.
- **폴더 이름을 바꿔도 분류가 따라갑니다.** `분류` 는 폴더 이름을 글자로 들고 있어서 예전엔 이름을 바꾸면
  끊겼습니다 — 2026-09-17 `문서 어시스턴트 에디터 목업` 에 나중에 ✏️ 를 붙였더니 보내기 창이 옛 이름을
  권했고, 고르면 폴더를 못 찾아 `1.🎯(Project) 프로젝트` 맨 위로 떨어졌습니다. 이름은 하루에도 몇 번씩
  바꾸는 것이라 사람에게 맞추라고 하지 않습니다.

  | 언제 | 어떻게 |
  | --- | --- |
  | 옵시디언 안에서 폴더 이름을 바꿈 | 그 구역에서 그 폴더를 가리키던 분류를 새 이름으로 고칩니다 (이모지만 빠진 옛 글자까지) |
  | 폴더를 찾을 때 | 글자가 똑같은 게 없으면 **이모지·띄어쓰기·대소문자를 빼고** 견줍니다 (`nameKey`) |
  | 밖에서 바뀜 (git pull 등) | 켤 때·폴더가 생길 때, **자기가 든 폴더와 글자만 다른** 분류를 그 폴더 이름으로 맞춥니다 |
  | `📤 PARA로 보내기` 창 | 같은 폴더의 글자 변형을 지금 폴더 이름 하나로 모으고, 노트가 없는 폴더도 보여줍니다. 보낼 때도 지금 폴더 이름으로 적습니다 |

  - 켤 때 맞추기는 **자기 폴더 안의 노트만** 고칩니다. 다른 곳에 사는 노트의 분류는 글자 그대로 두고, 옮길 때
    폴더 찾기가 열쇠로 찾아 줍니다 — 사람이 일부러 다르게 적었을 수도 있어서요.
  - 명령 팔레트 `볼트 전체 — 분류를 자기 폴더 이름에 맞추기 (이모지·띄어쓰기)`.
    끄려면 설정 → Claude → PARA 구역 정리 → `폴더 이름을 바꾸면 분류가 따라간다`.
  - 에이전트가 노트를 만들 때도 분류는 **폴더 이름을 이모지까지 그대로** 씁니다.
- 안 건드리는 것: `!🏠 홈` · `!Template` · 볼트 최상위 파일(`CLAUDE.md`) ·
  유형 `홈`·`대시보드` · 노트에 `PARA정리: 끔` 이 적힌 것.
- **파일만 옮기면 끝이 아닙니다.** `유형`·`상태`·`분류` 는 옛 구역 값 그대로 남습니다.
  보드는 폴더가 아니라 `유형`·`상태` 로 거르므로, 이걸 안 맞추면 옛 보드에 계속 뜹니다.
  그래서 구역이 바뀐 직후 **한 번에 맞추는 창**이 뜹니다.

  | 속성 | 창이 어떻게 채우나 |
  | --- | --- |
  | `유형` | **사람이 고릅니다.** 그 구역에 있을 수 있는 유형만 보여줍니다 — 파일 이름이나 본문으로 추측하지 않습니다 (단 *그 폴더에서 태어난* 노트는 자리가 정합니다 — `docs/new-notes.md` 의 **어느 폴더에서 만들든** 참고) |
  | `상태` | 고른 유형이 실제로 쓰는 값만 보여줍니다. 상태를 안 쓰는 유형이면 비웁니다 |
  | `분류` | **같은 폴더의 다른 노트가 쓰는 값**을 권합니다 (지어내지 않습니다) |

  창을 닫아 버렸거나 예전에 밀린 것은 명령 팔레트에서 찾습니다.

  | 명령 | 무엇 |
  | --- | --- |
  | `이 노트를 PARA로 보내기 (구역·유형·상태 한 번에)` | 인박스에서 내보낼 때. `docs/inbox.md` 의 **인박스에서 나가는 길** 참고 |
  | `이 노트 속성 맞추기 (유형·상태·분류)` | 지금 열어둔 노트 하나 |
  | `구역과 안 맞는 유형·상태·분류 찾기` | 볼트 전체 목록 → 하나씩 맞추기 |
  | `볼트 전체 — 구역 속성대로 옮기기` | 위치만 (옵시디언 켤 때 자동으로 돕니다) |

  **구역 검사에서 아예 빠지는 곳이 둘 있습니다.**

  | 어디 | 왜 |
  | --- | --- |
  | `0.inbox` | **아무것도 정해지지 않은 곳입니다.** 마구 던져 두고 판단은 나중에 하는 자리라서 유형·상태·분류가 안 맞는 게 정상입니다. `상태: 미처리` 도 인박스 전용 값이라 유형별 표에 없습니다 |
  | `4.archive` 의 `분류` | 옛 분류는 **어디서 왔는지가 기록**입니다. 보관은 P·A·R 이 아닌 것이고 이름표를 지울 이유가 없습니다 (유형·상태는 그대로 봅니다) |

  **구역 검사에서 빠지는 유형이 있습니다** — `홈` `대시보드` `양식`.
  `1. project` `3. resource` 같은 구역 대문 노트가 유형 `홈` 이고 각자 자기 구역에 삽니다.
  어느 보드도 이걸 유형으로 안 거르니 "그 구역에 없는 유형" 이라고 할 것이 아닙니다.
  `route.py --repair` 와 **PARA 구역 정리** 가 같은 셋을 예외로 둡니다. **한쪽만 고치지 마세요.**
  이 노트들은 `분류` 도 비어 있는 게 맞습니다 — 묶을 것이 없습니다.

- **구역마다 대문 노트가 하나씩, 다섯 장입니다** (유형 `홈`).
  `!🏠 홈` 의 **🧭 빠른 이동** 이 이 다섯 장을 카드로 냅니다 (`🏠 홈 카드.base`).

  | 구역 | 대문 노트 | 커버 (이 경로에 있는 파일이 곧 카드 그림) |
  | --- | --- | --- |
  | `0.inbox` | `0.📥 인박스/📥 인박스 대시보드` | `0.📥 인박스/이미지/home_inbox.jpg` |
  | `1.project` | `1. project` | `1.🎯(Project) 프로젝트/(Archive) 이미지/home_project.png` |
  | `2.area` | `2. area` | `2.🌱(Area) 관리 영역/이미지/home_area.png` |
  | `3.resource` | `3. resource` | `3.📦(Resource) 자료/(Archive) 이미지/home_resource.png` |
  | `4.archive` | `4. archive` | `4.🗄️(Archive) 보관/이미지/home_archive.png` |

  **대문 커버는 위키링크가 아니라 경로 글자입니다** — `커버: "0.📥 인박스/이미지/home_inbox.jpg"`.
  그래서 그림을 바꿀 때는 **같은 폴더에 같은 이름·같은 확장자로 갈아 넣기만** 하면 됩니다.

  | 커버 값 | 옵시디언에서 이름을 바꾸면 | 파일을 갈아 넣으면 |
  | --- | --- | --- |
  | `"[[…/home_inbox.jpg]]"` 링크 | 링크가 **파일을 따라갑니다** (`alwaysUpdateLinks: true`) | 갈아 넣는 순서에 따라 링크가 옛 파일 쪽으로 가 버립니다 |
  | `"…/home_inbox.jpg"` 글자 | 안 따라갑니다 — **이름이 곧 약속** | 그 이름을 가진 파일이 곧 커버 |

  2026-09-10 에 인박스 그림을 갈아 끼웠더니 커버가 `[[22.jpg]]` 로 바뀌어 있었고,
  `22.jpg` 가 휴지통으로 가면서 카드가 비었습니다. 링크는 이름이 아니라 **파일**을 가리키기 때문입니다.
  옵시디언은 `[` 로 시작하는 프론트매터 값만 링크로 칩니다 (obsidian.asar 확인) — 경로 글자는
  이름이 바뀌어도 절대 고쳐 쓰지 않습니다. 베이스 카드는 글자 커버를
  `getFirstLinkpathDest(값, 노트경로)` 로 풀어서 링크와 똑같이 그립니다.
  **확장자까지 같아야 합니다.** `home_inbox.png` 를 넣었으면 `커버` 도 `.png` 로 고치세요.
  **커버 자동 채우기** 는 이 값을 안 건드립니다 — 대문 본문에는 이미지 임베드가 없어서, 갈아 넣는 사이
  잠깐 파일이 없어도 "본문에 이미지가 없음 — 비워 둡니다" 로 끝나고 아무것도 안 씁니다.

  **인박스만 파일명이 다릅니다.** 인박스의 대문은 **핀보드 그 자체**라서 대문 노트를
  따로 만들지 않고 `📥 인박스 대시보드` 에 유형 `홈` 을 줬습니다. 카드를 누르면
  핀보드가 **바로** 열립니다 — 중간에 거쳐 가는 노트가 없습니다.
  대신 카드 제목은 `🏠 홈 카드.base` 의 `formula.대문` 이 `0. inbox` 로 갈아 끼웁니다.
  파일명을 그대로 쓰면 제목이 `📥 인박스 대시보드` 가 되고, 정렬(`file.name`)도
  이모지 때문에 맨 뒤로 밀립니다.

  | 왜 이렇게 했나 | 근거 |
  | --- | --- |
  | 카드 제목을 링크로 못 쓴다 | 옵시디언이 `.bases-cards-property.mod-title` 에 `pointer-events: none` 을 걸어 둡니다 (obsidian.asar 확인). 제목은 글자일 뿐이고, **카드 아무 데나 누르면 그 줄의 파일**이 열립니다 |
  | 그래서 "다른 노트로 보내는 카드" 는 만들 수 없다 | 카드가 여는 것은 항상 그 줄의 파일입니다. 다른 곳으로 보내려면 **그 파일이 그 줄이어야** 합니다 |
  | 제목만 formula 로 바꾼 이유 | `order` 의 **첫 항목이 제목**입니다 (`toggleClass("mod-title", y === 0)`). 첫 항목을 formula 로 두면 제목 글자만 갈아낄 수 있습니다 |

  `유형: 홈` 은 **인박스 비우기 뷰에서 빼야 합니다.** `🔥 오늘` 의 `📥 인박스` 와
  `🧠 주간 리뷰` 가 `대시보드` 와 나란히 `홈` 도 거릅니다. 안 빼면 핀보드가
