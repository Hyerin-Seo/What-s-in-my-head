## 회의록 — 속기에서 할 일로

| | |
| --- | --- |
| 회의록 노트 | `4.🗄️(Archive) 보관/회의록/` · 유형 `메모` · 분류 `회의록`. 보드 `📝 회의록.base` 의 `+ 새 항목` 으로 만듭니다 |
| 양식 | 같은 폴더의 `!(Template) 회의록.md` — 속기 · 자료 · 결정 · 다음 안건 · 할 일 후보 · 이 회의에서 나온 할 일 |
| 왜 archive | 회의록은 **원문 기록**입니다. 살아 있는 것(할 일)은 배포 때 카드로 나가 프로젝트에 살고, 원문은 P·A·R 어디에도 안 들어갑니다 — 민규 서 결정 (2026-09-21). 예전엔 `2.area` 였습니다 |
| 입력 | **속기**입니다 (2026-09-17). 녹음·전사는 그다음에 붙입니다. 슬랙은 안 씁니다 |

에이전트는 **그때그때 다릅니다.** 그래서 정리·배포의 순서와 규칙은 **스킬 한 곳에만** 적습니다.

> **볼트 맨 위 `skills/meeting-notes/SKILL.md` 가 정본입니다.**
> "이 회의록 정리해줘" · "배포해줘" 를 받으면 그 파일부터 읽으세요. 여기에 다시 적지 않습니다 —
> 두 곳에 적으면 한쪽만 고쳐져서 어긋납니다.

- **회의별 폴더는 없습니다.** 할 일 노트는 각자 프로젝트 폴더에 살고 `상위` 로 회의록을 가리킵니다.
  폴더는 *어느 프로젝트인지*, `상위` 는 *어느 회의에서 나왔는지* — 상태 폴더를 없앤 이유와 같습니다.
  회의록 안의 `이 회의에서 나온 할 일` 보드가 `file.hasLink(this.file)` 로 다시 모읍니다
  (`hasLink` 는 프론트매터 링크까지 봅니다 — obsidian.asar 확인).

## 에이전트 스킬 — 볼트 맨 위 `skills/`

일의 순서·규칙은 **스킬**로 둡니다. 에이전트가 매번 달라도(Claude · Codex · Gemini …) 같은 걸 읽게 하려는 것입니다.
형식은 에이전트 스킬 표준 — 스킬 하나가 폴더 하나이고, 그 안에 `SKILL.md`(프론트매터 `name`·`description`)가 있습니다.

**자리는 볼트 맨 위 `skills/` 하나입니다** (2026-09-17 정함). 사람도 옵시디언에서 열어 봅니다.
한때 `.agents/skills/`(옵시디언에서 안 보임)와 일이 사는 폴더 옆 `skills/` 두 곳이었는데,
사람 눈에 보이게 한 곳으로 모았습니다.

| 스킬 | 언제 |
| --- | --- |
| `skills/editor_mockup_todo_manager/` | 기획·실험 노트를 세부 할 일 노트로 쪼갤 때 |
| `skills/meeting-notes/` | 회의록 정리 · 할 일 배포 |

- 일을 받으면 맞는 스킬이 있는지 먼저 보세요 — `skills/*/SKILL.md` 의 `description`.
- 볼트 루트의 **`AGENTS.md`** 는 `CLAUDE.md` 를 안 읽는 에이전트(Codex 등)의 입구이고 `skills/` 를 가리킵니다.
- 스킬 안의 경로는 **그 파일 기준 상대 경로**입니다. 폴더 안쪽을 가리키는 `./templates/…` 는 스킬 폴더를
  통째로 옮겨도 그대로 살고, 밖을 가리키는 `../../CLAUDE.md` 는 **깊이가 바뀌면 고쳐야 합니다.**
  노트·양식처럼 볼트 안의 다른 파일은 볼트 루트 기준 경로로 적습니다.
- **`skills/` 는 옵시디언 "제외된 파일"에 들어 있습니다** (`.obsidian/app.json` 의 `userIgnoreFilters` 에 `skills/`,
  설정 → 파일 및 링크 → 제외된 파일). 파일 탐색기에는 그대로 보이고, **보드·검색·그래프·속성 목록에서는
  빠집니다** — 베이스가 결과를 모을 때 제외된 파일을 건너뜁니다 (obsidian.asar 확인). 이게 없으면 스킬의
  양식·예시 노트(`유형: 할일` · `구역: 1.project` · `상태: 진행중`)가 프로젝트 보드와 🔥 오늘에 **가짜 할 일로**
  뜹니다. **이 줄을 지우지 마세요.**
- **플러그인도 `SKILL.md` 가 있는 폴더 안을 노트로 보지 않습니다** (`inAgentSkill` — PARA 구역 정리·커버 자동
  채우기). 속성 13종을 안 붙입니다. 2026-09-17 에 이 규칙 없이 만들었더니 `SKILL.md` 에 `구역`·`분류`·`작성일` 이
  붙어 스킬 프론트매터가 망가졌습니다. 폴더 이름이 아니라 `SKILL.md` 로 가리니 스킬이 어디 있든 됩니다.
- 스킬 프론트매터에는 **볼트 속성 13종을 넣지 마세요.** 스킬 표준이 모르는 키입니다.
- **스킬이 만드는 노트도 볼트 규칙을 그대로 따릅니다.** 스킬의 양식·예시에 속성을 적을 때 특히
  `작성자:` 는 목록 + 따옴표 친 위키링크(`  - "[[Gemini]]"`)로. 2026-09-17 `editor_mockup_todo_manager` 의
