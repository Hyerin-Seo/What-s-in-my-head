## `.base` 에 주석을 달지 마세요 — 옵시디언이 지웁니다

`# 이 파일은 …` 같은 줄을 맨 위에 적어 뒀더니, 옵시디언이 보드를 한 번 다시 쓰면서
(칸을 끌거나 뷰를 더할 때) **세 줄이 통째로 사라졌습니다.** 보드는 옵시디언이 YAML 로
파싱했다가 다시 뱉는 파일이라 주석이 살아남지 못합니다. 설명은 `docs/` 의 맞는 문서에
적으세요. 플러그인이 만들어 넣는 뷰에도 주석을 안 답니다.

## 보드 속 경로는 **폴더를 따라갑니다** — PARA 는 폴더가 구역을 옮겨 다닙니다

보드는 경로를 **볼트 기준 전체 경로 글자**로 들고 있습니다. 베이스가 상대 경로를 안 받아서입니다
(obsidian.asar — `newItemMenu.open` 이 `newItemFolder + "/" + 이름` 을 그대로 씁니다).

| 보드 안의 자리 | 무엇 |
| --- | --- |
| `newItemFolder` · `newItemTemplate` | `+ 새 항목` 이 떨어질 폴더 · 베낄 양식 |
| 뷰의 `quickAddFolder` | 칸반 칸 머리 `+` 가 떨어질 폴더 |
| `file.inFolder("…")` | 필터 |
| `cardOrders` 목록 | 칸반 카드 순서 (노트 경로) |

PARA 는 폴더가 통째로 **R → A, R → P** 로 옮겨 다니는 게 정상입니다. 그런데 글자는 안 따라가서,
2026-09-17 에 도서관·UI 레퍼런스를 보관으로 옮긴 뒤 이렇게 깨졌습니다.

- 끊긴 경로로 `+ 추가` → 옵시디언이 **없는 옛 폴더를 다시 만들어** 거기에 넣었습니다 (유령 폴더)
- `newItemFolder` 가 **아예 없는** 보드 → 옵시디언 기본 위치(인박스)로 떨어졌습니다
- `🔥 오늘` 의 도서관 빼기 필터가 옛 경로라 빼기가 안 먹혔습니다

**PARA 구역 정리** 가 글자를 폴더에 맞춥니다.

| 언제 | 무엇을 |
| --- | --- |
| 옵시디언 **안에서** 폴더·파일을 옮김 | `rename` 을 받아 모든 보드에서 옛 경로로 시작하는 자리를 새 경로로. 최상위 프로젝트 폴더면 프로젝트 보드의 뷰 이름도 같이 |
| 옵시디언 **밖에서** 옮김 (git pull 등) | `rename` 이 안 옵니다. **켤 때**, 그리고 폴더나 보드가 생기거나 사라질 때(3초 모아서) 점검합니다 |
| `newItemFolder` 가 없는 보드 | 구역 폴더 **안에 사는** 보드는 보드가 사는 폴더를 넣습니다. 홈 보드는 빼서 인박스로 가게 둡니다 ("모르면 인박스") |

점검은 **같은 하위 경로가 다른 구역에 있는지**로 봅니다 — 구역을 옮겨도 구역 폴더 아래의 모양은 그대로라서요.

| 경로가 | 어떻게 |
| --- | --- |
| 없다 | 다른 구역에 같은 하위 경로가 **하나뿐**이면 그쪽으로 |
| 있긴 한데 보드와 다른 구역이다 | **보드가 사는 구역에 쌍둥이**가 있으면 그쪽으로 — 끊긴 채 `+` 를 눌러 생긴 유령일 수 있어서 |
| 보드와 같은 구역이다 | 믿습니다. 안 바꿉니다 |
| 여럿이거나 어디에도 없다 | 안 바꾸고 알립니다 (사람이 골라야 함) |

- **경로가 적힌 줄만** 바꿉니다. 칸반 카드 순서·칸 색은 한 바이트도 안 건드립니다 (`mapBoardPaths`).
  바꾼 뒤 YAML 로 읽어 보고, 깨지면 안 씁니다.
- **유령 폴더가 있는 동안 홈 보드는 못 고칩니다.** 홈 보드는 구역에 안 살아서 "보드가 사는 구역의
  쌍둥이" 로 가릴 수 없습니다. 유령 폴더를 지우면 그 순간 점검이 돌아 고쳐집니다.
- **거를 수 있으면 경로 말고 속성으로 거르세요.** 홈 `🔖 바로가기` 는 `유형: 바로가기` 하나로만
  거릅니다. 폴더를 안 보니 대문이 구역을 옮겨 다녀도 그대로 뜹니다.
- **보관에 있어도 바로가기는 뜹니다 — 구역으로 빼지 마세요.** 도서관·UI 레퍼런스는 보관으로 갔지만
  홈에서 바로 가는 자리는 그대로 둡니다 (2026-09-17 요청). 한때 `구역 != 4.archive` 로 뺐다가 되돌렸습니다.
  `🎨 UI 레퍼런스 홈` 은 보관으로 옮기면서 유형이 `레퍼런스`·상태 `검토 중` 으로 바뀌어 빠져 있었고,
  `바로가기` 로 되돌렸습니다. **바로가기에서 대문이 사라지면 유형부터 보세요.**
- 명령 팔레트 `보드 경로 점검·고치기 (옮겨진 폴더 따라가기)`. 결과는 개발자 콘솔에 줄줄이 남습니다.
- 끄려면 설정 → Claude → PARA 구역 정리 → `보드 속 경로가 옮겨진 폴더를 따라간다`.

## 보드로 가는 링크는 **`.base` 를 꼭 붙이세요**

`[[💡 브레인스토밍]]` 은 보드를 **절대** 못 찾습니다. 옵시디언의 링크 해석이 이렇습니다
(obsidian.asar 의 `getLinkpathDest` 확인).

```
이름에 `.` 이 있나?  →  그 이름 그대로 찾는다
없나?               →  `<이름>.md` 로만 찾는다      ← .base 는 후보에도 안 든다
```

그래서 확장자를 뺀 보드 링크는 **깨진 링크**가 됩니다. 눌러도 안 열리고, 빨갛게 뜨지도
않아서 (표 안이면 더더욱) 멀쩡해 보입니다. 2026-09-16 에 `3. resource` · `4. archive` ·
`📌 사용법` 에서 열 군데가 그 상태였습니다.

본문에서는 파이프 그대로, **표 칸 안에서는 파이프를 역슬래시로 이스케이프**합니다.
(표로 보여 줄 수가 없어서 코드 블록에 적습니다 — 표 안에서는 맨 파이프를 못 씁니다)

```
본문        [[💡 브레인스토밍.base|💡 브레인스토밍]]
표 칸 안    | [[💡 브레인스토밍.base\|💡 브레인스토밍]] | 74 | … |
특정 뷰로   [[🪄 리소스 모음집.base#🚦 상태 칸반|🚦 상태 칸반]]
```

표 안에서 파이프를 안 escape 하면 마크다운이 그 자리를 **칸 구분자**로 읽어서 표가
깨집니다. `🗺️ 볼트 지도` 가 처음부터 그 모양으로 쓰고 있었습니다 — 그게 맞는 모양입니다.

**폴더 이름과 보드 이름이 같아도 소용없습니다.** 위키링크는 파일만 가리킵니다.
